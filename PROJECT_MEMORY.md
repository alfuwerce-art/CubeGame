## 1. Краткий смысл проекта

- **CubeGame** — новая ПК-игра на **Unity**, эволюционное воссоздание ключевого игрового опыта **Cube World Alpha 2013**, затем дальнейшая самостоятельная **3D voxel/cube-style action RPG** с улучшенными моделями, боем, миром и сюжетами.
- **Не** переносим исполняемый файл/движок Plasma автоматически в Unity. Изучаем логику и данные Alpha, формируем проверяемые **собственные** спецификации и реализуем системы на C# с максимальным использованием штатных возможностей Unity.
- Визуально сохраняем узнаваемый кубический силуэт, но в будущем улучшаем геометрию, текстуры, анимации, освещение, окружение и эффекты. **Нельзя заранее объявлять конечный арт-стиль утверждённым**: образцы принимаются продюсером по мере графической разработки.
- Базовая версия: максимально полное по **поведению** воспроизведение Alpha 2013 (кроме мультиплеера). Позднее — самостоятельные расширения. Unity-пилот не равен перенесённой Alpha.
- Первая версия — **локальный single-player**; мультплеер, пользовательские серверы, моды/плагины и LLM-NPC относятся к последующим этапам. Никакого платного хостинга на старте.

**Точное ТЗ концепции:** [D01–D36](docs/planning/DECISIONS_001-036.md). Не заменять этот документ кратким пересказом здесь.

## 2. Утверждённые игровые принципы (сжатая памятка)

1. **Мир** — большой процедурный по seed, биомы разнообразны; постоянные изменения локаций, уничтоженных лагерей, NPC и фракций сохраняются. Лагеря могут быть заселены заново **только через игровые события**, не произвольный сброс. Локальный мир при закрытии останавливается.
2. **Архитектура** — утверждён **модульный монолит**: игровые правила и состояние отделены от сцены, UI, Unity-рендера и инфраструктуры ([ADR-0001](docs/architecture/ADR-0001-modular-monolith.md)). Варианты остальных технологий в [ARCHITECTURE_PROPOSAL](docs/planning/ARCHITECTURE_PROPOSAL.md) — предложения или проверяемые гипотезы, не все утверждены.
3. **Боёвка/классы** — сначала изучить и воспроизвести Alpha; позднее свободный выбор экипировки и развитие за пределами стартового класса. Не выдумывать поведение, когда оно известно из Alpha.
4. **Прокачка** — максимального уровня нет; большое, но **конечное** дерево пассивных навыков (после полного заполнения не генерировать новые пассивы). Позднее часть способностей развивается использованием. XP/награды после заполнения дерева — будущая детализация.
5. **Города/NPC/квесты** — в будущем расписания, торговля, характер, память, отношения и действия NPC; локальная LLM для общения, но игровые события авторизует обычный код. Цепочки заданий с последствиями; фракции борются за территории, игрок может присоединяться к ним. Не строить сложную глобальную политику без отдельного решения.
6. **Внешний вид** — 3D воксельный, более детализированный. Модели и анимации связаны: **одна переработанная модель → тест старой анимации → одна новая анимация → проверка в Unity**, потом партии. **Каждую модель продюсер утверждает лично.**
7. **QA** — каждый этап: сборка/демонстрация (где применимо), EditMode/PlayMode или эквивалентные реальные тесты, регрессии, производительность и отчёт по ограничениям. `READY_FOR_REVIEW` ≠ `ACCEPTED`; агент сам не принимает этап.

## 3. Роли и исполнительные правила

- **Продюсер (пользователь):** утверждает механики, визуал, начало/закрытие этапов, принципиальные компромиссы.
- **ChatGPT:** архитектор, технический ревьюер, помощник по исследованиям/документации; имеет доступ к репозиторию через GitHub connector **когда он подключён и открыт в конкретном чате**.
- **DeepSeek Harness Desktop:** **основной локальный разработчик**, пользовательский пресет `cubegame-dev` / **CubeGame Dev**. Исследует Alpha, пишет Unity C#, запускает инструменты/тесты, коммитит в ветки, отчитывается.
- **Codex:** возможен сравнительный исполнитель/контролёр качества на этапе моделей, анимаций и графики, **ещё не включён как обязательный агент**.

Для DeepSeek: отдельный workspace CubeGame, **`workspace-write` + `ask`**, без `danger-full-access/never` по умолчанию; не трогать другие проекты/пресеты; не менять `main` force push, не делать самостоятельный merge. `plugins/` локально содержит конфигурацию пресета и **не должен публиковаться целиком** без очистки путей/аудита.

## 8. Порядок для нового чата ChatGPT

## 9. Автозагрузка для DeepSeek

- `AGENTS.md` содержит **обязательную ссылку на `PROJECT_MEMORY.md`**. При старте новой сессии `cubegame-dev` должен сначала прочитать его, затем `docs/ACTIVE_STAGE.md`.
- Рабочий каталог — корень Git-репозитория CubeGame. После обновления `origin/main` агент на своей ветке читает актуальную память; **не переключать ветки с грязным worktree** и не терять локальные изменения.
- После исследования/этапа DeepSeek предлагает в своей ветке изменение памяти, **не записывает себе `ACCEPTED`** и не сливает свою версию памяти в main без ревью.

## 10. Протокол обновления памяти (постоянный)

После каждого **утверждённого** решения или законченного этапа:
1. Обновить `docs/ACTIVE_STAGE.md` (факты, следующий этап, блокеры).
2. Если изменилось требование — создать новую `Dxx` или ADR, не переписывать историю.
3. Обновить **этот файл**: только значимые новые решения, HEAD веток, подтверждённые статусы, текущие блокеры и следующий шаг. Удалять устаревшие статусы, не историю Dxx.
4. Проверить прямые ссылки и реальные GitHub SHA. Разделить `REPORTED`, `VERIFIED_GITHUB`, `TESTED`, `ACCEPTED`.
5. Указать `memory updated date` и краткое описание в коммите. Обновления памяти, сделанные агентом, проходят ревью как любой другой результат.

**Не хранить** здесь пароли, API-ключи, приватные данные, полные логи, огромные каталоги файлов, приватные репаки или закрытые ассеты. Для подробностей — ссылки на свои документы и коммиты.

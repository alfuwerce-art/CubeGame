## 1. Производственный порядок и неизменные условия

1. **Сначала** завершить и принять соответствующие текущие технические стадии Alpha→Unity по D78. На данный момент S05A-2 REVIEW OPEN; S05B NOT_AUTHORIZED.
2. Сохранить точные подтверждённые источники Alpha в независимом baseline. Отдельно маркировать TRANSFERRED_FROM_ALPHA, EMULATED_ALPHA_CODE, RECONSTRUCTED_FROM_EVIDENCE, ORIGINAL_NOT_ALPHA, BLOCKED. Анимированные ключи из Alpha не выдавать за собственную новую механику.
3. Перед массовым производством проверить **одного гуманоида, одну семейную стойку и одно реальное оружие** с репрезентативным противником. Расширять после функциональной и визуальной приёмки образца.
4. Массовое производство — по утверждённым семейным эталонам с партийной проверкой D67. Привязка деталей к основному production-проекту требует отдельного разрешения. Файлы Alpha и производные ассеты не публиковать вопреки правилам проекта.

## 2. Риг и единые инварианты

- Стабильные идентификаторы частей тела и вращений; проверить согласованность локальных/мировых трансформаций и скейла модели в Unity.
- Для предмета: actual primaryGrip и secondaryGrip, геометрия рукояти/гарды/клинка, состояние inHand/onBack/hidden, два хвата для двуручного оружия по D52; IK и процедурная коррекция только как собственный слой поверх доказанного Alpha-клипа.
- Все анимации должны переживать замену совместимой модели, оружия и экипировки. Проверки clipping, foot sliding, резких переходов, отрыва хвата, пересечения клинком тела, сохранения масштаба.
- Общая структура: pose/rig layer + locomotion/state logic + equip/weapon layer + event metadata. Окончательная реализация root motion/code motion OPEN; для контактной боёвки движение корпуса, коллизии и оружия должны использовать согласованную временную шкалу.

## 3. Обычные анимации: полный перечень проектирования

**Эталонный пакет для первого гуманоида (не обязательство сразу сделать все варианты):**
- Idle: спокойная стойка, локальный микродвижения/дыхание, стойка с оружием, переход idle↔combat idle.
- Locomotion: начало/остановка движения, ходьба вперёд/назад/в стороны, бег, спринт, разворот на месте и во время движения, изменение скорости; диагонали и blending.
- Terrain: прыжок (prepare/takeoff/air/landing), падение и тяжёлое приземление, ходьба по склону и ступеням, поворот/стоп на препятствии; плавание, скалолазание и планирование **по соответствующим утверждённым системам, с отдельными зависимостями и доступностью**.
- World interactions: подобрать/положить предмет, открытие/использование контейнера, взаимодействие с дверью/механизмом, разговор и поворот к собеседнику.
- Rest/social: сесть/встать, сон/пробуждение, базовые жесты/эмоциональные реакции для NPC; дополнительные социальные анимации — по отдельным этапам NPC, НЕ преждевременная обязательная масса.
- Equip: достать/убрать оружие, сменить хват, сменить вид экипировки, attach рука↔спина, переходы на месте и в движении.
- Death/non-combat hurt: падение/смерть, повреждение от окружения, воскрешение по D61. Особые расы и типы скелетов — отдельные профили анимаций.

**Утверждение объёма:** каждая группа должна иметь приоритет MUST/SHOULD/LATER в отдельном stage-task; этот каталог — покрытие проектирования, а не требование одномоментно производить все клипы.

## 4. Боевые анимации: покрытие

- CombatIdle, подготовка/подход/отступление с оружием, draw/sheathe.
- LightCombo: windup→active→recovery; очередность и число звеньев задаёт оружие/техника. Промах не блокирует следующее звено при своевременном вводе.
- Heavy: распознавание удержания основной кнопки мыши, windup/charge/active/recovery; порог удержания, запуск, максимальный заряд **OPEN**.
- Короткое продвижение в active, фазовые ограничения перемещения и разворота, сильнее для тяжёлого оружия.
- Roll: переход из любой фазы атаки, cancellation и отсутствие возврата уже потраченной стамины.
- ExhaustedEvadeStep: если стамины ниже цены полного переката, остаток тратится, вместо переката направленный отход; без общей неуязвимости, препятствия блокируют путь и другие враги наносят урон по реальному попаданию.
- Block hold/enter/exit, Parry startup/success/fail/recovery, GuardBreak, Stagger/HitReact (light/heavy), Knockdown/GetUp, Death.
- Различия оружия по D70: меч+щит, одноручный без щита, двуручный, парные клинки, тяжёлые топоры/молоты, боевой посох, магический посох с парированием/барьером; список не претендует на исчерпывающий каталог.
- Magic: cast start/release/maintain/interruption, spell channel, barrier enter/hold/impact/break; отдельная настройка по школам D66/D71.

## 5. Контракты контроллера и данных (предложение)

Каждый action включает идентификатор семейства и вида оружия, provenance, requiredRigParts, clip IDs/rig profile, input events, transition graph, windup/active/recovery phases, hit sweep sample points, canCancelByEvade, stamina spent events, movement & turning limits, grip anchors, stagger/poise parameters, audiovisual cues и зависимости от техник/летописей.

- Движение collider'а персонажа и траектория оружия должны учитывать столкновения и непрерывный контакт (sweep между соседними обновлениями).
- Событие отмены выключает будущие hit checks отменённой атаки, **не откатывает** уже совершённые попадания и расход стамины.
- Одна атака не должна наносить многократный урон одной цели без специального подтверждённого правила.
- При недостаточной стамине блок/парирование ослаблены, но доступны (DRAFT); расчёты ещё OPEN.
- При попадании реакция зависит от силы удара и устойчивости. Приёмы после уклонения зависят от оружия/выученных техник. Без отдельного боевого дерева.
- Отложить создание параметров, которых ещё нет в канонической боевой спецификации, до согласования, не заполнять их произвольными magic numbers.

## 6. Матрица минимальных проверок для будущего пилота

| Сценарий | Условие готовности |
|---|---|
| Idle ↔ Walk/Run ↔ Stop | Нет скачков позы, проскальзывания стоп, невалидных трансформов; стабильные тесты 30/60/120 Гц |
| Направления движения / поворот | Нет резкого разворота корпуса и несовместимых ног, корректное управление на склоне и при остановке |
| Доставание оружия и хват | Совпадение primary/secondaryGrip, без пропажи/телепорта предмета, правильный тип хвата |
| Light tap → combo | Своевременные повторные нажатия продолжают удары и после промаха, без дополнительного урона |
| Hold → heavy | Тяжёлый удар не вызывает побочного light hit, быстрый клик не классифицируется как удержание |
| Hit sampling | Высокоскоростной клинок не проходит через цель между кадрами незамеченным; попадание только при контакте |
| Active cancel → roll | Нет лишнего hit после отмены, стамина не возвращается, стыки визуально приемлемые |
| Insufficient stamina → step | Расход остатка и защитный отход, без глобальной неуязвимости; второй атакующий может попасть |
| Step + wall/corner | Стена не проходится, при отсутствии безопасного пути удар возможен |
| Parry/block/stagger | Реакции синхронизированы с силой/устойчивостью и типом оружия |
| Weapon-specific combo | Уникальный граф для одного конкретного вида, базовые анимации семейства переиспользуются |
| Learned combo after roll | Доступность зависит от оружия и изученной техники; без техники переход запрещён |
| Save/load and equips | Состояние/техника/экипировка сохраняются без битых переходов; точный контракт сохранения — отдельное ТЗ |

Тесты — **будущие критерии**, не заявление об уже полученном PASS. Для игровых моделей, заклинаний, магии и движения живых существ требуются отдельные визуальные просмотры и функциональные тесты.

## 7. OPEN до окончательной приёмки

- Выбор модели распознавания click/hold, доступный порог и тест латентности.
- Правило завершения/отмены заряда тяжёлого удара, анимационный переход в combo.
- Таксономия видов оружия и список обязательных уникальных боевых клипов; общий контроллер не может заменить специальные позы, когда геометрия/хват отличаются.
- Точные тайминги/стамина/реакции и частные правила магии.
- Приоритеты MUST/SHOULD/LATER по обычным анимациям для первого игрового среза, когда будет разрешён stage.
- Художественные эталоны новых анимаций и визуальная приёмка продюсером.

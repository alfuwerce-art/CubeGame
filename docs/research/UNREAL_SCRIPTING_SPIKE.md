# Исследование — Unreal Engine 5.8, скрипты, модели и анимации

**Статус:** `RESEARCH_PROPOSED / NOT_AUTHORIZED_FOR_INSTALL`; проект CubeGame остаётся на Unity. Данный документ не разрешает скачивать UE, менять игровой код, переезжать с Unity. Решение владельца: изучить автоматизацию через скрипты и AI skills независимо от стоимости миграции.

## Гипотеза

Реально ли локальному агенту управлять UE через **Editor Python + C++ + командные проверки** с меньшими трудозатратами и лучшей повторяемостью, чем ручное управление? Может ли он подготовить **один** качественный voxel/pixel asset, риг и базовый клип, пригодные для игры?

## Что проверить до установки

- Версию UE, свободное место, версию Windows, C++ toolchain, лицензии, требования GPU/RAM.
- Отдельную папку **вне рабочего Unity-проекта и без отдельного Git-репозитория для игры**; её содержимое не должно замещать `D:\Projects\CubeGame`. Скопировать результаты/отчёт в CubeGame только после разрешения.
- Ограничения ноутбука (RTX 4060 Laptop 8 GB, RAM 32 GB) — без обещания FPS/VRAM и с измерением.
- Осмысленную базу: C++ Third Person, но **без догматического запрета Blueprint**. Разделить Editor Python от игрового runtime.
- Не подключать платные API/подписки и необязательные MCP/AI плагины без разрешения.

## Тесты последовательно, но без изготовления фабрики

**U0 — preflight:** проверить версию и доступность утилит, систему сборки, создать отдельный минимальный UE-проект (только по разрешению); записать путь, SHA, версии.

**U1 — скриптовое управление:** одноразовый `*.py` выполняется Unreal Editor и создаёт / именует / проверяет три простых объекта (без чужих ассетов); повторный запуск не создаёт дубликатов; выдаёт JSON: asset paths, warnings, errors, duration.

**U2 — минимальный C++ runtime:** маленькая функция игровой логики (например, проверка взаимодействия), компиляция, воспроизводимый игровой тест. Blueprint — по необходимости конфигурации, не считать нарушение при обоснованном использовании.

**U3 — Geometry Scripting:** одна геометрическая voxel-проп-модель с контролем единиц, pivot, размера и материалов; проверка трёх ракурсов и силуэта; никаких массовых генераторов.

**U4 — анимация:** один тестовый гуманоид с реальным скелетом и короткой ходьбой; попробовать Control Rig/IK Retargeter только при совместимой геометрии, проверить клип (контакты стоп, оружейный хват, отсутствие коллапса меша).

**U5 — сравнение:** аналогичный маленький сценарий Unity; измерить человеко-правки, время, token/calls при доступности, стабильность, % выполненных критериев, нагрузку CPU/RAM/VRAM. Сравнение MCP vs scripts только при одинаковой задаче.

## Артефакты

- `docs/reports/UNREAL_SCRIPTING_SPIKE_REPORT.md` — фактические команды, версии, прямые пути, JSON-логи, скриншоты/видео, исходный/конечный результат.
- Для модели: редактируемый источник + пригодный для импорта формат, 3 ракурса, сведения о правах; для анимации — скелет, клип, проверка воспроизведения.
- Результат каждого теста: `PASS / FAIL / BLOCKED / NOT_RUN`. `PASS` скрипта не означает качество арта или выбор UE как движка.

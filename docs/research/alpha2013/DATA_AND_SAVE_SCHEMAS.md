# S00-R02 / пакет L — сохранения, карта, данные (схемы и целостность) Alpha 2013

**Проект:** CubeGame. **Этап:** S00-R02 (D41), партия 1.
**Источники:** `SRC-01` (реальные `Save\*.db` персонажа `S00G0` и мира `G0WORLD`, `data1..4.db`), `SRC-02`.
**Метод:** копии БД в `.scratch/savecopy/` (вне git), чтение Python `sqlite3` + `zlib`; оригиналы в `D:\Games\Cube world` не изменялись. Копии после разбора удалены.
**Граница:** публикуются только **схемы, ключи, размеры и распределения**. Содержимое блобов и ассетов не выгружается.

## L1. Общая схема: «ключ → блоб», а не реляционная модель

Все восемь баз (`Save/characters.db`, `Save/worlds.db`, `Save/world_<мир>.db`, `Save/map_<мир>.db`, `data1..4.db`) имеют **одну** таблицу:

```sql
CREATE TABLE blobs(key TEXT PRIMARY KEY, value BLOB)
```

Создание — `db_openBlobStore` (`004497b0`: `sqlite3_open` + `CREATE TABLE`). Запись — upsert `db_storeBlob` (`004499f0`: `SELECT 1 …` → `UPDATE`/`INSERT`). Чтение — `db_loadBlobByKey` (`00449810`). Ключи — текст, значения — блобы (часто zlib).

**Чего нет:** версий схемы, индексов кроме автоиндекса PK, триггеров, `-wal`/`-shm`, резервных копий, временных файлов. Один файл на мир/карту/персонажей. Транзакции/SQLite-журнал в коде не найдены (`UNKNOWN`, риск при аварийном завершении).

## L4. Мир и карта (частично)

- `world_<name>.db`: `time` (8 Б, игровое время), `mission<x>_<z>` (38 Б), `monster<x>_<z>` (21 Б) по сетке 8×8 в исследованной области. Шаг решётки и связь с блоком — `UNKNOWN` (R01 §3.3 не закрыт).
- `map_<name>.db`: `reg` (60 164 Б), `tile` (6 412…15 334 Б), `land` (304…422 Б), `discovered` — это **blob «открыто/тип тайла»**, который `WorldMap` пишет из массива `world+0x8000BC` (1024×1024), после записи массив обнуляется.
- **Формат `reg` не расшифрован.** Измерения (2026-11-03, read-only копия `map_G0WORLD.db`, локально, затем копия удалена):
  - длина блоба 60 164 Б = 4 байта заголовка (`01 00 00 00`) + **60 160** байт тела;
  - в теле встречаются **только значения 0 и 1** (гистограмма: 56 000 нулей, 4 160 единиц) → это растровая маска, не структура с плавающими числами;
  - `60 160 = 470 × 128 = 940 × 64` — обе факторизации возможны;
  - позиции единиц идут с шагом **14** на протяжении 4096 элементов, затем 64 разрыва по 44 — то есть данные **не** являются сплошным 64×64-растром блока-за-блоком;
  - в блоке 940 байт (гипотеза «строка») около 67 единиц.
  Гипотезы, которые нужно проверить: (H1) маска «исследовано/тип тайла» в другой сетке (не 1 байт на блок); (H2) результат процедурного «рисования» карты (линия реки/дороги), а не попиксельная маска; (H3) упакованная битовая маска с шагом, не кратным 8.
  Проверка: найти в коде читателя/писателя ключей `reg`/`land`/`tile` (дизасм `GameController` вокруг сохранения карты) — это единственный надёжный способ. Для CubeGame формат **не нужен** (см. §L8).
- Редактирование мира игроком сохраняется как «дельты против сгенерированного» (восстановлено `deserializeRegionChunk` `0044cdb0`: запись `0x118` Б состояния + `0x18` позиции + несколько `int32/byte`; второй блок — записи по `0x14` Б). `PARTIAL`.

## L6. Целостность и восстановление

| Аспект | Факт Alpha | Вывод для CubeGame |
|---|---|---|
| Атомарность записи | не найдено транзакций/журнала; запись upsert в открытую БД | нужна атомарная запись: temp-файл + rename, плюс ротация 1–2 бэкапов |
| Бэкапы | отсутствуют | добавить `*.bak` при старте сохранения |
| Версии | тег `11` внутри блоба персонажа; версия записи `7` в `worlds.db` | явный `version` в начале каждого файла + миграции |
| Валидация | не найдено проверки CRC | добавить CRC32/SHA блоба и проверку при загрузке |
| Частичная запись | риск повреждения при вылете | хранить «дельты против сгенерированного», чтобы мир восстанавливался из seed + дельт |
| Что переживает перезапуск | персонажи, список миров, миссии/спавны/время, открытая карта и регионы | такую же границу («что именно сохраняем») зафиксировать в спецификации сохранения |

## L8. Вывод

Сохранения Alpha — простая и надёжная по структуре модель «ключ → сжатый блоб», но **без** защиты от повреждения и без миграций. Для CubeGame разумно взять модель данных (ключи по координатам/сущностям, дельты против генерации), **не** копируя байтовый формат, и обязательно добавить версионирование, атомарную запись и валидацию — того, чего в Alpha нет.

## 1. Метод

1. Прочитана реконструкция `Creature_drawModel` (VA `0x4128F0`, локальная декомпиляция, не публикуется): пролог ходьбы (строки 2214–2420 файла `GameController.cpp`), блоки отрисовки тела, хвоста, головы/волос, кистей, стоп (6096–6311, 7139–7363), сглаживание `array_lerp` (1231, 5766) и обновление фазы в логике существа (102140–102200). Там, где декомпиляция потеряла цель обращения (`arrayElem_stride4` без `this`, см. D58), значение не придумывалось: член помечался UNKNOWN либо проверялся по рантайму.
2. Формулы переписаны как цепочки `mat4_*` в исходном порядке ([`param_walk.joints`](../../../tools/alpha_models/universal/param_walk.py)) — без подгоночных коэффициентов: каждое число — константа кода или поле внешности.
3. Проверка — покадровое сравнение с **уже имеющимися** захватами Alpha (новых запусков Alpha не было): `session2.jsonl` (человек 0x02, игрок), `batch1.jsonl` (WhiteCat 0x20 и PlainRunner 0x3f под ИИ). Для каждого кадра формула получает только фазу, амплитуду и признак ×1.25 этого кадра и внешность вида; сравнивается кадр сустава `J = T(anchor)·M·P⁻¹` (тот же, что хранится в клипах).
4. Использованы **все** годные кадры состояния 0, а не только устойчивый цикл, из которого построены клипы: разгон, торможение, смена ×1.25 — это проверка зависимости от амплитуды, которую клип одной амплитуды проверить не может.

## 2. Восстановленная формула (общая для всех существ)

Входы: внешность (`creature+0x78`) — смещения `offset_body/head/hand/foot/tail`, масштабы `scale_*`, `pitch_tail`, `angle_58`, флаги; рантайм — фаза `φ = creature+0x118c`, амплитуда `a = creature+0x1188`, ×1.25 (ускорение игрока/ИИ + скорость), признак «на земле».

```
c   = sin(φ + π/2)
w   = a · 0.7π · c            ×1.25 при ускорении;  ×0.75 если flags&1;  0 если flags&2 и не на земле
d0  = +1.5·deg(w)   e4 = −1.5·deg(w)          (тангаж конечностей)
bob = 4·|w|                                   (подъём корпуса)
lift_l = 4a·c       lift_r = 4a·(1 − c)       (подъём стоп)
```

| Часть (блок) | Цепочка `J` (порядок кода; база) | Статус |
|---|---|---|
| тело | `T(offset_body) · Rz(deg(w)/2) · S(scale_body)` на базе `T(0,0,bob)` | VERIFIED (3 вида) |
| голова, волосы | `T(offset_head − (0,0,bob/2)) · [T(0,0,−3)·Rx(lean)·T(0,0,3)] · S(scale_head)` на базе `bob` | VERIFIED (человек, кот) |
| хвост | `T(offset_body) · T(offset_tail) · Rx(pitch_tail) · Rz(−deg(w)) · S(scale_tail) · S(scale_body)` на базе `bob` | VERIFIED (кот) |
| кисти, flags&1 = 0 («двуногое») | позиция на окружности `R = hand.x·(1+a)`: `(∓cos w·R, hand.y ∓ sin w·R + 2.1 − 5a, hand.z − 4.1 + 6a)`, без поворота; правая зеркальна `S(−s,s,s)` | VERIFIED (человек) |
| кисти, flags&1 = 1 («четвероногое») | `Rx(e4|d0) · T(±hand.x, hand.y + 2.1 − 5a, hand.z) · Rx(e4|d0) · S` на базе `bob` | VERIFIED (кот) |
| стопа левая | `Rx(angle_58 + d0) · T(−foot.x, foot.y, foot.z + 3|w| + lift_l) · S(scale_foot) · Rx(d0)` на базе `P` (без `bob`) | VERIFIED (3 вида); член `angle_58` — CODE_ONLY |
| стопа правая | `Rx(e4) · T(foot.x, foot.y, foot.z + 3|w| + lift_r) · S(scale_foot) · Rx(angle_58 + e4)` | то же |

Наклон головы (`lean`) — сглаживаемая величина: цель +10° при ×1.25 у существ с flags&1 = 0 (VERIFIED), +5° при ускорении ИИ без ×1.25 (предсказано по той же конструкции кода; VERIFIED проверочным захватом NPC, §3а), иначе 0; шаг `lean += (цель − lean)·(1 − 0.99^dt_мс)` — это точная форма `array_lerp(&f, &1, dt_мс, 0.01)`. Скорость фазы: `dφ/dt = 1.5·|v_xy|·√(0.8/size.x)` — **INFERRED** (аргумент корня потерян декомпилятором; по двум разным размерам 0.96 и 1.2 совпадение с измеренными 1.37/1.22 в пределах 0.3 %); используется только чтобы ступни в Unity не скользили, на позы не влияет.

## 3. Точность относительно Alpha

Формула vs все годные кадры состояния 0 (`pipeline param-walk-validate`; float64 против float32 Alpha). Область формулы: `this[2] = 0`, действие 0, в `creature+0x124` нет битов, кроме 0x40 (ввод ускорения). Кадры первой секунды после выхода из состояния вне области (или от начала захвата, когда предыстория неизвестна) — «переходные»: `drawModel` сглаживает массивы поз (повороты тела/кистей действий) тем же `1 − 0.99^dt_мс`, и остаток предыдущего состояния затухает; такие кадры сравниваются и показываются отдельно, а не скрываются.

| Вид | Установившихся кадров | Амплитуда | ×1.25 / ИИ | Макс. ошибка положения, вокс. | Макс. ошибка поворота, ° | Переходных кадров (макс. ошибка) |
|---|---|---|---|---|---|---|
| человек-игрок 0x02 (тело, кисти, стопы) | 446 | 0.000–0.193 | да/нет | 0.00025 | 0.00040 | 80 (0.0001 / 0.000°) |
| человек-игрок — голова/волосы (прогноз сглаживания) | 446 | | | 0.066 (1 кадр), p95 < 0.001 | 1.27 (1 кадр), p95 0.011 | |
| **NPC-люди 0x02** (3 особи, ИИ) | **1719** | 0.000–0.194 | ИИ | **0.00027** | **0.00032** (голова: p95 0.0002, макс. 1.28 — 1 кадр) | 112 (кисти 0.087 / 0.69°, затухает) |
| WhiteCat 0x20 (7 частей, хвост) | 968 | 0.095–0.191 | ИИ | 0.00034 | 0.00004 | 57 (0.0003 / 0.000°) |
| PlainRunner 0x3f (тело + 2 ноги) | 968 | 0.093–0.194 | ИИ | 0.00021 | 0.00033 | 57 (0.0002 / 0.000°) |

Расхождения выше точности float на установившихся кадрах — по одному кадру у головы (включение ×1.25 у игрока; кадр перехода у NPC): захват пропускает игровые кадры, и сглаженная величина на нём не восстанавливается одношаговым прогнозом; на остальных кадрах сглаживание совпадает (p95 0.0002–0.011°). Переходные кадры NPC — 0.6 с после состояния с `0x124 = 0x84` и начало захвата: ошибка спадает 0.185° → 0.017° за 0.6 с по закону сглаживания и в установившихся кадрах равна нулю.

### 3а. Проверочный захват ИИ-гуманоида (2026-11-05, по согласию продюсера)

Цель — член `head_lean_ai` (+5°), открытый в 22 семействах. Копия Alpha `.scratch\alphatest2` (сохранение скопировано в резерв), вход в мир сценарием `alpha_enter_world.ps1`; `D:\Games\Cube world` не трогался. Разведка `pose_capture --kinds <79 видов с головой и flags&1 = 0>` нашла у дома игрока NPC-людей (0x02 ×2, 0x03 ×2) и игрока. Захват `cap_npc_human.jsonl` (20 с, 3055 записей, SHA256 `ba653e65…5b6`, игра жива после отсоединения). Результат: у идущих NPC (`a·v > 0`, без ×1.25) голова наклонена ровно на **+5.000°** — 1058 кадров в установившемся состоянии (ещё 520 в разведке), сглаживание при разгоне/торможении совпадает с `1 − 0.99^dt_мс` (p95 0.0002°). Член переведён в VERIFIED. Кадры NPC 0x03 вне области (`0x124 = 1` — сидит, `0x124 = 4`) — в проверку не входили; поза сидящего (наклон головы 50°) — состояние вне формулы ходьбы.

Для сравнения: захваченные клипы (подход A) проходят проверку «один цикл отложен» с порогами 0.25 вокселя / 3° и фактически дают 0.13 вокселя / 1.23° (кот), 0.19 / 2.37° (человек) — формула на три–четыре порядка точнее, потому что не интерполирует и не зависит от того, какую амплитуду удалось снять.

Клип из формулы (для старого проигрывателя клипов): ключевание 72 ключа на цикл даёт ошибку интерполяции ≤ 0.0055 вокселя / 0.051°, 144 ключа — ≤ 0.0014 / 0.013°. Драйвер `AlphaLocomotionDriver` вычисляет формулу каждый кадр и интерполяции не имеет.

## 4. Общие механизмы и обоснованные различия

Одна формула подходит всем трём планам тела **без подгонки**: человек (8 частей), кот (7, хвост, лапы как блоки рук/ног), бегун (3) — одни и те же константы. Различия между видами — только значения внешности:

* **флаг bit0 (`flags&1`) — единственное различие, меняющее код**: ×0.75 к размаху и «четвероногое» качание кистей (тангаж у плеча вместо перемещения по окружности), отключение наклона головы. Это не подгонка: ветвь читается в коде (`flags&1` в прологе и блоках кистей), и обе ветви проверены — человек (0) и кот (1). В Alpha bit0 = 1 у 40 из 156 видов (25 из них — `0x31`, как у кота);
* **флаг bit1** — нулевой размах только в воздухе; на земле формула та же (CODE_ONLY: в захватах не встречался);
* **размеры частей тела** входят в формулу только через смещения и масштабы внешности; размер модели — только через якорь (вывод предыдущего этапа, подтверждён снова: модели разных размеров не меняют `J`);
* **`size.x`** влияет только на скорость фазы и масштаб размещения `P` (не на `J`).

Что **не** является частью ходьбы и не моделируется: 73 состояния действий/атак (`this[2] ≠ 0`), действия `O`, `j`, `k`, `0` (мультипликаторы в прологе прочитаны, но не проверены), плавание/полёт/верховая езда (`creature+0x124` биты 0x10/0x400, `+0x11c0`, `+0x128`), экипировка (оружие на спине — слой S05A-2), особые блоки (крылья `slot_9a`, `slot_98`, предметы).

## 5. Какие семейства можно обрабатывать без захвата

Классификатор [`param_walk.classify`](../../../tools/alpha_models/universal/param_walk.py) (`pipeline param-walk-coverage`) определяет для каждого вида, какие члены формулы он использует (`terms_used`), и требует захват **только для непроверенных членов**. Один захват любого вида, у которого член ненулевой, проверяет его для всех видов сразу — формула общая, различаются данные.

Водные существа могут использовать рантайм-флаги плавания (`creature+0x124`), которые ни в одном захвате не встречались — их ходьба по земле проверена формулой, плавание — нет.

## 6. Unity-прототип

* `AlphaParamWalk.cs` — порт формулы (C#), тот же порядок цепочек, выход — кадры `J` Alpha, применяемые существующими `AlphaSpace`/`AlphaRig`.
* `AlphaLocomotionDriver` — компонент: скорость → фаза, амплитуда, ×1.25, ускорение, сглаживание наклона головы; позирует риг каждый кадр без клипов (любая амплитуда, плавный разгон). Динамика амплитуды Alpha не восстановлена — встроенный повторитель помечен `PLACEHOLDER_NOT_ALPHA`, точные состояния задаются амплитудой напрямую.
* `AlphaParamWalkCheck` (EditMode): SPEC, синтетические инварианты, GOLDEN (C# = Python на синтетических внешностях, `TEST_DATA_NOT_ALPHA`), ALPHA (C# против захваченных кадров, если задание указывает захват семейства).

## 7. Ограничения и неизвестное

* Формула покрывает **только локомоцию состояния 0** (ходьба/стояние на земле). Атаки и действия — по-прежнему захват (подход A, S05A-2).
* `angle_58`, bit1 — реализованы по коду, не проверены рантаймом; `angle_48` и `angle_4c/50/54` — UNKNOWN, такие виды формула отклоняет.
* Скорость фазы — INFERRED (две разные `size.x`). Динамика амплитуды — не восстановлена.
* Захватов с ненулевыми углами, в прыжке (bit1), с плаванием не было. Запуск Alpha был один — проверочный захват NPC (§3а) из копии `.scratch`; остальное — имеющиеся захваты.
* Переходы между действиями и ходьбой (затухание массивов поз действий) формулой не моделируются: в первые ~0.6 с после действия у кистей NPC до 0.69°.
* Визуальная приёмка (кадры Alpha ↔ Unity для новых видов) не делалась — доказательство численное; художественная оценка — за продюсером.

# S05A2-D58 — захват действительной структуры существа во время `Creature_drawModel`

**Задача:** продолжить `S05A2-D58` от работающего отладчика: получить реальный адрес структуры
существа в рантайме, определить вектор моделей и связать хотя бы одну модель с её анимационной
матрицей. **Ветка:** `codex/s05a2-channel-binding`. **База:** `c510755`.

**Среда:** локальная копия `Cube.exe` (`.scratch/alphatest2`, SHA256 `84A7A132A84D…`), реконструкция
`CubeWorld-Reversal`, Python 3.13, x32dbg уже установлен (D55), отладчик собственный (ctypes).

## 0. Маркеры

| Маркер | Значение | Пояснение |
|---|---|---|
| `CREATURE_POINTER` | **`VERIFIED`** | `eax` в точке останова = реальный указатель существа (дракон `0x2261F778` и др., 120 снятий) |
| `MODEL_VECTOR` | **`VERIFIED`** | `esi` = глобальный вектор моделей `0x128E3320` (2569 записей), `[esi+4]`/`[esi+8]` = begin/end |
| `MODEL_TO_BODY_PART` | **`PARTIAL`** | индекс→`data1.db` доказан (333→`dragon-body.cub`, 334→`dragon-foot.cub`); семантика всех 8 полей не исчерпана |
| `ANIMATION_CHANNEL` | **`PARTIAL`** | цепочка «слот модели→матрица части→канал» восстановлена статически; значение канала в двух состояниях не снято |
| `UNITY_ALPHA_MOTION` | **`BLOCKED`** | два состояния не захвачены (игрок не локализован в этой сессии), перенос движения named-части не заявлен |

## 1. Точка чтения структуры (найдена и снята)

`Creature_drawModel` = `Cube.exe` RVA `0x128F0`. Восемь `int16`-индексов моделей лежат в полях
существа `+0x8c..+0x9a`; компилятор грузит указатель существа в `eax` через `mov eax,[edi]`
прямо перед каждым чтением, поэтому все восемь читаются одним и тем же регистром `eax`:

| адрес (RVA) | машинный код | поле | слот модели |
|---|---|---|---|
| `0x12A42` | `8b07 0fbf 88 8c000000` | `+0x8c` | `self[0x2f]` |
| `0x12A6C` | `8b07 0fbf 88 8e000000` | `+0x8e` | `self[0x30]` |
| `0x12A9F` | `8b07 0fbf 88 90000000` | `+0x90` | `self[0x33]` |
| `0x12AD2` | `8b07 0fbf 88 92000000` | `+0x92` | `self[0x36]` |
| `0x12B05` | `8b07 0fbf 88 94000000` | `+0x94` | `self[0x31]` |
| `0x12B38` | `8b07 0fbf 88 96000000` | `+0x96` | `self[0x35]` |
| `0x12B6B` | `8b07 0fbf 88 9a000000` | `+0x9a` | `self[0x34]` |
| `0x12B9E` | `8b07 0fbf 88 98000000` | `+0x98` | `self[0x32]` |

Искомые инструкции — `movsx ecx, word ptr [eax+0xNN]`, а не только `movsx`: сканер
`model_read_scan.py` дополнительно проверяет `movzx` (`0F B7`), байтовые варианты
(`0F BE`/`0F B6`) и 32-битный `mov` (`8B /r`) с полным декодированием ModRM/SIB, поэтому
другой вариант загрузки не может быть пропущен. В функции действительно есть ещё три
`mov eax,[esp+0xNN]` (стековые локальные, `0x41EDBC`/`0x42033F`/`0x420357`) — они опознаются
и отделяются от чтений существа по ширине (32 бита) и базе (`esp`).

## 2. Регистры в точке останова (проверено 120 снятиями)

Точка останова `0x12A42` стоит **до** `movsx`, поэтому регистры уже осмысленны:

* `eax` = `*this` — **указатель существа** (стабилен в вызове, меняется между существами);
* `edi` = `this` — объект отрисовки (кадр `0x1730`), `[edi]` = существо;
* `esi` = `param_4` — **глобальный вектор моделей** (загружен `mov esi,[ebp+0x14]` в прологе);
* `ecx` **не** является `self` (подтверждено: меняется и не содержит структуры `+0x8c`).

Это закрывает прежние допущения §9 CODEX: `self` действительно локальная копия, а существо —
`*self` = `[edi]`, доступное в `eax` внутри функции (не на входе).

## 3. Проверенная цепочка указателей

```
Creature_drawModel (this=edi)
  └─ [edi]                          → creature (eax)          ← реальный указатель существа
       └─ [creature + 0x8c..0x9a]   → 8 × int16 индексов      ← 8 индексов моделей
model vector (esi = param_4)
  └─ [esi+4] = begin, [esi+8] = end → 2569 записей (указатели)
       └─ [begin + index*4]         → указатель модели         ← `mov eax,[eax+ecx*4]`
data1.db (blobs, key по rowid)      → имя `.cub`               ← index = ключ data1.db
```

Наблюдение (120 снятий, 3 разных существа):

| существо | индексы (`+0x8c..+0x9a`) | разрешённые модели |
|---|---|---|
| `0x2261F778` | `[-1,-1,-1,334,333,-1,-1,-1]` | `dragon-foot.cub`, `dragon-body.cub` |
| `0x2E308008` | `[-1,-1,-1,-1,2087,-1,-1,-1]` | `silk-shoulder2-random2.cub` |
| `0x22174010` | `[1246,1252,430,432,1,-1,-1,-1]` | `iron-mace1-*`, `entrance-mine`, `entrance-tomb`, `airship` |

Кодировка «индекс = ключ `data1.db`» подтверждена на живом процессе (не случайно: семейства
`dragon-*`, `iron-*` когерентны). Третья запись — предпросмотр мира/предметов, а не существо.

## 4. Модель → матрица → канал (первая доказанная связь)

Статически (реконструкция, строки 2127–2204 и 6089–7346) каждому слоту модели соответствует
матрица части: `self[0xNN]` рисуется матрицей `self[0x3b + k*0x10]` (часть `k`):

| слот модели | матрица части | поле существа |
|---|---|---|
| `self[0x31]` | часть 2 (`0x5b`) | `+0x94` |
| `self[0x2f]` | часть 3 (`0x6b`) | `+0x8c` |
| `self[0x30]` | часть 4 (`0x7b`) | `+0x8e` |
| `self[0x32]` | часть 5 (`0x8b`) | `+0x98` |
| `self[0x37]` | часть 7 (`0xab`) | экипировка `+0xaa8` |
| `self[0x38]` | часть 8 (`0xbb`) | экипировка `+0x990` (предмет, ×0.6) |
| `self[0x33]` | части 9/10 (`0xcb`/`0xdb`) | `+0x90` |
| `self[0x39]`/`0x3a` | части 11/12 | экипировка `+0x878`/`+0x418` |
| `self[0x34]` | части 13/14 | `+0x9a` |
| `self[0x36]` | части 15/16 | `+0x92` |
| `self[0x35]` | часть 17 (`0x14b`) | `+0x96` |

**Конкретная связь для дракона:** `dragon-body.cub` (индекс 333) лежит в `+0x94` → слот
`self[0x31]` → матрица **части 2**, которая строится `mat4_rotateZ(local_16fc·0.5·180/π +
self[0x2a]·0.5)` (строки 6099–6100). `dragon-foot.cub` (334) → `+0x92` → слот `self[0x36]` →
матрицы **частей 15/16** (`mat4_rotateX`/`mat4_rotateZ` от `local_16d4`/`local_16e4`/`local_16d0`).

Итого цепочка **«модель → слот модели → матрица части → анимационный канал»** восстановлена для
двух моделей дракона; канал для предмета (`self[0x38]`→часть 8→`local_15d8[2]`) уже был показан
в §2.3 CODEX. Значение канала в двух моментах времени не снималось.

## 5. Воспроизводимость отладчика

Собственный отладчик перенесён в отслеживаемый `tools/alpha_models/runtime/drawmodel_probe.py`:

* **восстановление инструкции** — байт `INT3` возвращается (`WriteProcessMemory`) перед каждым
  single-step и в `finally`;
* **снятие точки останова** — после последнего снятия байт восстановлен, незавершённый
  single-step доводится до конца (trap-флаг снят) до отсоединения;
* **безопасное отсоединение** — `DebugSetProcessKillOnExit(FALSE)` перед
  `DebugActiveProcessStop`.

Проверено фактом: после прогона на 120 снятий процесс **остался жив** (`CUBE_ALIVE pid=2792`),
в отличие от прежней версии без `DebugSetProcessKillOnExit`/доводки single-step, после которой
игра падала. WOW64-инварианты зафиксированы `self_check()`: `DEBUG_EVENT` = 176 байт, запись
исключения со смещения 16, `INT3`→`0x4000001F`, single-step→`0x4000001E`.

## 6. Не сделано / следующий шаг

1. **Игрок не локализован**: в 120 снятиях только дракон, NPC и предпросмотр. Внешность игрока
   задаётся созданием персонажа (не `creature_generateAppearance`); окно в этой сессии,
   по-видимому, осталось в предпросмотре мира, а не в геймплее с персонажем. Нужна доводка
   навигации `enter_world.ps1` (как в §8.1 CODEX) и скриншот-подтверждение `SOCCO` в кадре.
2. **Два состояния**: для `UNITY_ALPHA_MOTION` надо снять канал (например `local_16fc`) в
   idle и в движении/атаке — это другая точка останова (в расчёте позы, после `0x412A42`).
3. `TRANSFERRED_FROM_ALPHA` **не присваивать**: привязка канала к named-части пока статическая.

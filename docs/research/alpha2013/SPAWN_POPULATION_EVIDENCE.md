# M0-06B — население мира Alpha: что доказывает код клиента (спавн-точки, N-18/N-19)

**Дата:** 2026-11-09. **Автор:** DeepSeek. **Статус:** исследовательская заметка, не приёмка и не `PASS`.
**Источник:** локальный экспорт декомпиляции `.scratch/CubeWorld-Reversal` (в Git не попадает) +
`Cube.exe` sha256 `84a7a132…30bf`. Ничего из ассетов Alpha здесь не публикуется.

## 1. Зачем

Пакет M0-06B по D88 требует «таблицы спавна по биомам». До этой заметки было известно только:
`World_generateNpcSpawnList` — 30 строк, запись 0x118 байт, звёзды 1 %/0.1 %/0.01 %, кламп 4 (N-18),
а связь «уровень/биом → вид» (N-19) помечена `PARTIAL (GAP)`.

## 3. Чего по-прежнему нет (не выдумывать)

1. **N-19 не закрыт.** Не установлено, какой из кодов в дескрипторе — вид существа, а какой —
   фракция/класс/специализация; не установлено, как тип региона (биом) попадает в выбор строки.
2. **Вариант 1..4 в функциях-построителях** (`0x5F51E0`, `0x5F8AD0`) — параметр выбора набора кодов;
   соответствие «вариант → биом/тип региона» не доказано.
3. **Распределение «уровень/биом → вид»** не восстановлено: в клиенте оно задаётся этими
   построителями, но без исполнения/дампа дескрипторов коды нельзя сопоставить с 156 видами каталога.

## 4. Следующий шаг (для решения продюсера/Claude)

Требуется **исполнение** генератора или рантайм-дамп списка дескрипторов региона (в памяти клиента
после генерации зоны), а не дальнейшее чтение декомпиляции: только это даёт пары
«код дескриптора → вид каталога» и распределение по уровням. До такого дампа `IWorldPopulationSource`
не должен содержать придуманных таблиц: пустая зона честнее выдуманного биома.

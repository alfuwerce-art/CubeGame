**Дата:** 2026-11-05. **Исполнитель:** Claude Code (архитектор). **Ветка:** `claude/universal-animation-pipeline` (от `deepseek/s05a2-animation-transfer-review` @ `d8bd51c`).
**Основание:** задание продюсера «универсальный конвейер переноса моделей и анимаций»; D46, D51, D54, D55, D57, D58. **Не S05B**: массовой конвертации не было.
**Статус:** `READY_FOR_REVIEW`. Архитектура — [UNIVERSAL_ASSET_ANIMATION_PIPELINE.md](../../architecture/UNIVERSAL_ASSET_ANIMATION_PIPELINE.md) (DRAFT). Методичка — [UNIVERSAL_TRANSFER_PLAYBOOK.md](../../agents/UNIVERSAL_TRANSFER_PLAYBOOK.md). Результаты прототипа — [UNIVERSAL_TRANSFER_PROTOTYPE_REPORT.md](UNIVERSAL_TRANSFER_PROTOTYPE_REPORT.md).

Обозначения: **ДОКАЗАНО** — байты `Cube.exe` + сверка с рантаймом; **КОД** — прочитано в коде, в рантайме не проверено; **ГИПОТЕЗА**; **НЕИЗВЕСТНО**.

## 1. Главный ответ

**Общий механизм есть, и он один.** В Alpha нет скелетов, клипов и «типов ригов». Каждое существо — игрок, NPC, кот, бегун, слизень, куст — рисуется **одной функцией** `Creature_drawModel` (VA `0x4128F0`), которая получает:

1. **внешность** существа — структура `creature+0x78` длиной `0xAC` байт: 8 слотов моделей, 9 масштабов частей, 7 углов, 6 векторов смещений, флаги, размер;
2. **рантайм-состояние** — фаза/амплитуда ходьбы (`+0x118c`/`+0x1188`), действие (`+0x68`), состояние и время анимации (`this[2]`, `this[1]`), наклон взгляда, экипировка.

Части рисуются фиксированными **блоками отрисовки** (пара `render_uploadModelViewMatrices` + `GameController_draw_mesh`). Блок «кисть» рисует и руку человека, и переднюю лапу кота; блок «стопа» — стопу человека, заднюю лапу кота и ногу бегуна. Поэтому «семейство рига» в Alpha — это **не код**, а **набор значений внешности**. Цепочка:

```
kind (creature+0x64)
  └─ creature_generateAppearance(kind, seed)  ─ статическая таблица, 156 видов      [ДОКАЗАНО]
       ├─ слоты моделей (i16 ×8) ── индекс → вектор моделей → "<имя>.cub"           [ДОКАЗАНО]
       ├─ масштабы/углы/смещения/флаги ── параметры формул drawModel                  [ДОКАЗАНО]
       └─ непустые слоты → блоки отрисовки → части                                   [ДОКАЗАНО]
  └─ рантайм: фаза, амплитуда, действие, состояние, время → формулы drawModel → J    [КОД + захват]
  └─ M = T(−anchor(блок, размер модели)) · J · P(позиция, поворот, size/11.2)         [ДОКАЗАНО]
```

## 2. Где Alpha выбирает модели и части (вопросы 1–3)

| Что | Где | Статус |
|---|---|---|
| Вид существа | `creature+0x64` (`kind`, u32). Аргумент `kindOut` в `creature_generateAppearance(creature+100, creature+0x78, seed)` | ДОКАЗАНО (сверка с захватом: кот `0x20`, бегун `0x3f`, игрок `0x02`) |
| Внешность по умолчанию | `Spawn_initDefaults` (VA `0x428750`, thiscall ECX=внешность): масштабы 1.0/1.01/0.98/0.95…, смещения (0,0,−5) и т.д. | ДОКАЗАНО |
| Внешность вида | `creature_generateAppearance` (VA `0x43F7C0`): `switch(kind)` на 156 веток (0x00–0x9B); раса игрока 0–7 → виды 0–16; вариант модели = `база + seed % N` | ДОКАЗАНО |
| Модели | вектор `Model*`, заполняемый в `GameController_load_game_assets` (VA `0x4EE230`): 2557 загрузок `VoxelModel_load_from_file_or_buffer`, у каждой строка `"<имя>.cub"` и индекс (`vector_at_stride4(idx)` или инлайн `[begin + 4·idx]`) | ДОКАЗАНО: 2548 индексов; 1 конфликт (1300: `orc-head-m01` и `orc-head` в один индекс), 1 не декодирован (29) |
| Слоты → `drawModel` | пролог `drawModel` копирует `creature+0x8c..0x9a` в `self[0x2f..0x36]`; экипировка (`+0x418…+0xaa8`) перекрывает часть слотов | ДОКАЗАНО (захват: `mesh == self[slot]` для каждой части) |

**Раскладка внешности** (`app` = `creature+0x78`), имена — по использованию в `drawModel`:

| Смещение | Поле | Использование в `drawModel` |
|---|---|---|
| `+0x02..04` | цвет волос (RGB) | шейдер |
| `+0x06` | флаги (u16) | бит 0: вариант качания рук/лап (×0.75), бит 1: без шага в воздухе, бит 2, 0x400 — другие ветви (стр. 2246–2420, 3123, 6309) |
| `+0x08` | `size` (3 f32) | масштаб размещения `P` = `size.x/11.2` (проверено: кот/человек 0.0857, бегун 0.1071); `size.z/2` — жёсткое приземление |
| `+0x14` | слоты `head, hair, hand, foot, body, tail, slot_98, slot_9a` (i16) | выбор моделей |
| `+0x24..0x44` | масштабы `head, body, hand, foot, 34, weapon, tail, 40, 44` | `mat4_scaleAxes` в блоках (голова, тело, хвост — прочитано; оружие 0.95 — захват S05A-2) |
| `+0x48..0x60` | 7 углов; `+0x60` — наклон хвоста | `mat4_rotateX(creature+0xd8)` в блоке хвоста |
| `+0x64..0xA0` | смещения `body, head, hand, foot, tail, a0` (vec3) | формула ходьбы (`+0xf4..0x108`), блок хвоста (`+0x10c`) |

Сверка: эмулированная внешность **байт-в-байт** равна снятой из памяти (`0xAC` байт, кроме байта выравнивания 5) — для кота `0x20` и игрока-человека `0x02`. Число вершин моделей из реестра совпало с мешами Alpha для всех 5 частей кота, 2 частей бегуна и тела/головы/кистей/стоп человека. Попутно закрыт старый вопрос S05A-2: игрок рисуется с `body4.cub`, `hand2.cub`, `foot.cub` (раньше считалось неоднозначным).

## 3. Как часть связана с матрицей (вопрос 3)

`drawModel` содержит **27** пар «загрузка матрицы + отрисовка меша». Для каждой пары установлено (байты перед вызовом: `mov ecx,[edi+slot*4]`) и/или подтверждено захватом, **какой слот она рисует**:

| Блок | Адрес отрисовки | Слот | Правило якоря | Статус |
|---|---|---|---|---|
| body | `0x41FD96` | 0x31 | центр | ДОКАЗАНО (человек, кот, бегун) |
| tail | `0x42042E` | 0x35 | `(sx/2, sy, sz/2)` — крепится концом | ДОКАЗАНО (кот) |
| head | `0x4206C2` | 0x2F | центр; **для вида 0x65 — `sy·0.2`** | ДОКАЗАНО (человек, кот) |
| hair | `0x420A38` | 0x30 | центр | ДОКАЗАНО (человек) |
| weapon | `0x421A01` | 0x37 | по подтипу/месту (S05A-2) | ДОКАЗАНО (человек) |
| hand_l / hand_r | `0x423214` / `0x4235B1` | 0x33 | центр, правая зеркальна | ДОКАЗАНО (человек, кот) |
| foot_l / foot_r | `0x423AFA` / `0x423D1F` | 0x36 | центр | ДОКАЗАНО (человек, кот, бегун) |
| slot_9a ×2 (крылья) | `0x42377A`, `0x4238C5` | 0x34 | НЕИЗВЕСТНО | 13 видов: Hornet, Crow, Chicken, Bat, Owl… |
| slot_98 ×2 | `0x420CD2`, `0x420DE1` | 0x32 | НЕИЗВЕСТНО | 10 видов: Minotaur, Troll, Golem, Yeti… |
| экипировка (плечи, шея, левая рука) | `0x42028C`, `0x4200EF`, `0x421DFA`, `0x42231B` | 0x39/0x3A/0x38 | НЕИЗВЕСТНО | броня, щит |
| ещё 10 вызовов (ECX = `esi`) | `0x41F8BD`, `0x41FA92`, … | — | НЕИЗВЕСТНО | вероятно спецмодели (лодка, планер, предметы) |

**Ключевое свойство (проверено скриптом по всем 105 обращениям к размерам моделей в `drawModel`, подтверждено захватами):** в **восьми блоках тела** (тело, хвост, голова, волосы, 2 кисти, 2 стопы) размер модели входит **только** в последний `translate(−size·k)` перед `upload`, т.е. в якорь. Значит для этих частей кадр сустава `J = T(anchor)·M·P⁻¹` не зависит от геометрии, и клип переносится на любую модель вида/семейства. Исключения (24 обращения) — все вне блоков тела:

* блок предмета на спине (стр. 6128): промежуточный поворот вокруг середины модели — `J` зависит от размера (блок не проверен, не используется);
* блок оружия (стр. 6573–6682): якорь через `goto` (учтён в S05A-2), особый случай модели индекса `0x348` (сдвиг −1 к якорю — НЕ учтён, такие модели исключать), и **после** отрисовки — две точки (основание и конец по `sx/2, sy/2, 0|sz`), по смыслу — след удара; на позу других частей в коде не влияют (НЕ проверено в рантайме);
* блок второго оружия (стр. 6791–6877) — те же конструкции, блок не проверен.

## 4. Что общее и что уникально (вопросы 4–6)

**Общее для всех видов:** функция, блоки, правила якорей, структура `M = T(−a)·J·P`, параметры ходьбы (фаза `+0x118c`, амплитуда `+0x1188`), слой ×1.25 при ускорении (у ИИ-кота флаг `0x124&0x40` не выставлен — множителя нет).

**Чем отличаются виды** — только значениями внешности и рантайм-состоянием:

* **план тела** (какие слоты непусты): 156 видов → **19 планов тела**; самые частые: «тело+голова+2 кисти+2 стопы» (42), «только тело» (37: залежи, кусты, рыбы, слизни, манекены), «человек с волосами» (18), «четвероногое с хвостом» (14), «тело+2 ноги» (10: бегуны);
* **параметры движения** (масштабы, углы, смещения, флаги, размер): **106 семейств движения**, 26 из них объединяют несколько видов (Cat/BrownCat/WhiteCat; 4 бегуна; ElfM/ElfF/HumanM/HumanF/LizardM/LizardF/FrogM/FrogF; 9 залежей; 4 слизня; 4 рыбы…);
* **видо-зависимый код в `drawModel`**: `kind == 0x57` (Mole), `0x60` (Zombie) — 6 мест; `0x65` (Dragon) — якорь головы и вектор прицеливания — 2 места. Других сравнений с видом в `drawModel` нет.

**Наблюдение для подхода B (ДОКАЗАНО на 2 семействах):** средний перенос кадра сустава равен смещению из внешности (кот: голова (0, 9, −0.6) при `offset_head` (0, 9, −1); лапы (±3, −4.07, …) при `offset_foot` (3, −4.1, −8.5); хвост (0, −8, …) при `offset_tail` (0, −8, −1)), а масштаб кадра сустава **точно** равен масштабу из внешности (кот: голова 0.9, хвост 1.1; человек: голова 1.01, стопы 0.98). Поза = параметры внешности + функция фазы — то есть формула параметрическая и в принципе переносима на семейства без захвата.

**Зависимости рантайма:** ходьба — функция фазы при постоянной амплитуде (проверено на 3 планах тела: «один цикл отложен» ≤ 0.19 вокселя / ≤ 2.4°); атака — время и состояние (только человек, S05A-2); наклон взгляда — слой головы/оружия (S05A-2); экипировка — слой оружия на спине/в руке (S05A-2). Для негуманоидов атаки, покой, переходы **не сняты**.

## 5. Статика или захват (вопрос 7)

| Данные | Статически (без запуска Alpha) | Нужен захват |
|---|---|---|
| вид → внешность (слоты, масштабы, смещения, флаги) | **да**, эмуляция по байтам, 156/156 видов | — |
| индекс → `.cub`, размер, число вершин | **да**, 2548 индексов | — |
| план тела, части, слоты, правила якорей | **да** для 9 проверенных блоков | для крыльев/slot_98/экипировки — один захват на блок |
| семейство движения (какие виды делят позы) | **да**, точное равенство параметров | — |
| сами позы (J по фазе/времени) | **нет** (формулы не восстановлены, см. §6) | **да, один на семейство** |
| поза для нового вида того же семейства | **да** (клип семейства) — проверено: Cat 0x1e, Elf 0x00 без запуска Alpha | — |

## 6. Можно ли заменить запись кадров алгоритмом (вопрос 8)

**Частично, но не сейчас.** Код `drawModel` (≈ 5700 строк реконструкции) вычисляет позу явными формулами: например, вынос лап `±cos/sin(amp·2.199·sin(phase+π/2))·(offset_hand.x·amp + offset_hand.x)` (стр. 2414–2434), подъём стоп `amp·4·sin(...)`, хвост `rotZ(−swing)`. Наблюдение §4 подтверждает параметрическую структуру. Но:

* формулы перемешаны с состояниями (≈ 73 состояния атак и действий), сглаживанием `local_1730` и ветвями по флагам — полный перенос = переписать `drawModel`;
* без захвата нечем доказать, что переписанная формула совпадает с Alpha (захват остаётся эталоном проверки).

Решение для архитектуры: **гибрид** — захват даёт эталон и клип на семейство (A), параметры внешности позволяют дешёво распространять его на совместимые виды и (в будущем) получить параметрическую формулу ходьбы, проверяемую против захватов (B). Подробно — в архитектурном документе, §4.

## 7. Неизвестное (не выдавать за восстановленное)

* правила якорей и семантика `slot_98`, `slot_9a` (крылья), блоков экипировки, 10 блоков с `ECX=esi`;
* поведение видов 0x57/0x60/0x65 в отмеченных ветвях;
* какая модель оказывается в индексе 1300 (две загрузки), модель индекса 29 (DarkTroll, волосы);
* покой/атаки/переходы негуманоидов; паузы ИИ (кот за 20 с ни разу не стоял);
* равенство поз двух **разных** видов одного семейства в рантайме: доказано статически (равенство параметров + одна функция), но второй вид того же семейства рядом не встретился — отдельного захвата нет.

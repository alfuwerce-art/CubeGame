# §A. P0-A — предметы, экипировка и модели: противоречия устранены

## A.0 Что было противоречивого (r2)

1. Статическая таблица `World::ctor_1` давала `(5,0)=Gloves`, `(6,0)=Boots`, а опубликованные ранее
   `F_items.md` и матрица (`I-09`) — «5 обувь, 6 перчатки».
2. Подтипы оружия: таблица давала `0=Sword, 2=Mace, 3=Dagger, 4=Fist, 7=Crossbow, 8=Boomerang,
   0xe=Arrows`, а `F_items.md` — «1 mace, 2 fist, 3 sword, 4 dagger, 8 crossbow, 0xe boomerang».
3. Не был определён смысл типа `0x15`.
4. В r2 addendum было записано «маска свойств предмета `creature+0x7e`» — требовало проверки.

Причина (1) и (2): два блока декомпиляции печатают значение без переменной-посредника
(`u16string_assignPtrLen(L"...",n)`), и «сдвинутое» чтение воспроизводит именно старые списки. То есть
**одна и та же ошибка чтения** дала оба старых списка. Ниже — независимое разрешение через **имена
моделей**.

## A.1 Разрешение: три независимых источника

| # | Источник | Что даёт |
|---|---|---|
| S1 | `cube::World::ctor_1 @ 0x0058eb00` (`World.cpp:2152-4674`) | `(type, subtype)` → отображаемое имя |
| S2 | `GameController_item_icon_id @ 0x4ec400` (`GameController.cpp:59852-60852`) | `type` → базовый индекс модельного блока |
| S3 | загрузчик ассетов в `GameController_load_game_assets @ 0x4ee230` | индекс модели → имя `.cub` |

для каждого типа предмета можно получить **настоящее имя модели** и сверить с именем из S1.

## A.5 Исправление ошибки r2: `+0x7e` — это слово флагов **существа**, а не маска предмета

В r2 addendum было записано «маска свойств предмета `creature+0x7e`». Проверка потребителей:

* `stat_calcWeaponDamage @ 0x43dc60` (`game_misc.cpp:2986`) читает `self+0x7e`, где `self` — **существо**
  (рядом `self+400` = уровень, `self+0x180` = базовая сила оружия, `self+0x1a8` = звёзды, `self+0x68` = action id);
* `ability_isChanneled @ 0x444680` — тоже `self` (существо);
* `Creature_drawModel` — `self` (существо).

Значит `+0x7e` — **16-битное слово флагов существа**, а не поле предмета. Найденные потребители:

| бит | потребитель | эффект (доказано) |
|---|---|---|
| `0x8` | `0x43dc60` | при отсутствии элементных апгрейдов экипировки добавляет урон: `2^(levelFactor·3)·2^(stars·0.25)·2` |
| `0x10` | `0x43dc60` | то же, множитель `·8` |
| `0x1a00` | `0x444680` | гейт канальных способностей (`0x200|0x800|0x1000`) |
| `0x200` | `drawModel` 7167, 15378, 35997, 40824, 47604, 50045, 52177, 100102 | рисует предмет слота `+0xdf0`; прочие эффекты не разобраны |
| `0x400` | `drawModel` 6309, 50758 | не разобрано |
| `0x2000` | 91315, 95392, `game_misc:16984` | не разобрано |
| `0x100` | 100948, 101063 | не разобрано |
| `0x80` | 34049, 96896 | не разобрано |
| `0x40` | `game_misc:10290` | не разобрано |
| `0x18` | `game_misc:19146` | не разобрано (пара бит) |
| `0x2` | `drawModel` 2270/2387 (совместно с `+0x5c & 1`) | не разобрано |
| `0x1` | `drawModel` 2273, 2414, 5696, 5736, 7139, 7150, 7202, 7215 | поворот/ветка отрисовки |

**Важно:** доказуемо с оружием связаны только `0x8`/`0x10` (урон). Остальные биты — состояние существа;
их семантика `UNKNOWN`, и в контракт M0-00C их переносить нельзя как «свойства оружия».

## B.2 Класс → стартовое оружие (доказано кодом `start_game_mode @ 0x4772b0`, строки 28017-28123)

| класс (`+0x140`) | слот `+0xaa8` (вторая рука) | слот `+0x990` (основная) | предметы в инвентарь |
|---|---|---|---|
| 1 Warrior | `type 3, subtype 0x11` = **Greatmace**, модификатор 2, уровень 1 | — | 2 × `(3,1)` **Axe**, 1 × `(3,0xd)` **Shield** |
| 2 Ranger | `type 3, subtype 6` = **Bow** | — | 1 × `(3,2)` Mace (PARTIAL), 1 × `(3,7)` **Crossbow** |
| 3 Mage | `type 3, subtype 0xa` = **Staff** | — | 1 × `(3,0xc)` **Bracelet**, 1 × `(3,0xb)` **Wand** |
| 4 Rogue | `type 3, subtype 3` = **Dagger** | `type 3, subtype 3` = **Dagger** | 2 × `(3,4)` Fist (PARTIAL), 1 × `(3,5)` Longsword |

Все четыре класса дополнительно получают: `+0xbc0` и `+0xcd8` = тип 9 (**два кольца**, модификаторы

**Что это доказывает:**

1. **Rogue держит оружие в обеих руках** (два `(3,3)` в `+0x990` и `+0xaa8`) — dual wield существует и
   кодируется двумя слотами типа 3.
2. **Warrior получает двуручное оружие** (`Greatmace`, subtype 0x11) в слот второй руки — то есть
   «двуручность» кодируется подтипом предмета (great-*), а не отдельным флагом.
3. **Слот `+0xdf0` = лампа** (`type 0x18`) — закрывает гипотезу r2 (§A.6): «предмет за спиной» — это
   лампа, а не дельтаплан.
4. Маг получает посох (0xa), палочку (0xb) и браслет (0xc) — согласуется с таблицей P0-A.

Замечание: у Ranger/Mage/Rogue один из предметов инвентаря задан `CONCAT11`-хаком декомпилятора —
подтип прочитан из байта, поэтому помечен `PARTIAL`.

## C.3 Генерация регионов: формула найдена, семантика спорна

**Место генерации** — `GameController.cpp:87960-87995` (создание региона):

```
srand(masterSeed(+0x800188) + z*0x400 + x)     // детерминированный сид на регион
Region = new (0x15a28 байт); cube::Region::ctor_0()
Region+0x0c = FUN_005a4710(x, z)               // тип
Region+0x10 = 0; if (тип > 4) Region+0x10 = rand() % 5     // вариант
Region+0x14 = rand() & 3                        // ориентация
```

**Формула `FUN_005a4710 @ 0x5a4710`** (единственный вызов — строка 87982):

```
если (x == 512 && z == 512) → 1
иначе                      → 2 + trunc(0.75 · sqrt((512−x)² + (512−z)²))
```

Это **точная, проверяемая** формула, а не догадка. Она объясняет, почему в таблице имён
`World::ctor_1` ключ — пара `(тип, вариант)` и почему вариант берётся `rand()%5` только при `тип > 4`.

**Однако остаётся противоречие:** формула не ограничена сверху (до ~545 на краях сетки 1024×1024), а
имена в таблице есть только для типов `{1,2,3,4,6,7,8,0xb,0xc,0xd,0xf}` и вариантов 0…9. Значит либо
`Region+0xc` — не «биом», а полоса/класс удалённости (и тогда утверждение r1 «biome = FUN_005a4710»
неточно), либо имя берётся не напрямую по `+0xc`. Статус: `PARTIAL`; шаг закрытия — найти всех
потребителей `Region+0xc` (начать с `GameController_show_region_name @ 0x4e5320`, который считает
имена по мировой позиции).

**Имена типов регионов** (из `World::ctor_1`, пара `(тип, вариант)`):
1 Village, 2 Mountain, 3 Forest, 4 Lake, 6 Canyon, 7 Valley, 8 Crater, 0xb Rock, 0xc Tree, 0xd Peak,
0xf Island; отдельно `Ruins` для пары `(0, 5)`-варианта (строки 4135-4141).

**Конвейер генерации (функции идентифицированы, содержимое не декодировано):**
`Region_scatterProps @ 0x5ad320`, `World_populateRegionDecorations @ 0x5cc510`,
`WorldInfo_placeStructure @ 0x5f0ce0`, `WorldInfo_scatterObjectsInArea @ 0x5f56c0`,
`dungeon_splitRegion_recursive @ 0x5c52a0`, `WorldMap::ctor_1 @ 0x5fae40` (выделяет массивы
`discovered`), `Region::ctor_0 @ 0x5c3ac0`.

**Таблица «климат → объекты» (~660 строк)** — `WorldInfo_scatterObjectsInArea` существует, но таблица
в этом проходе **не выгружена** → `UNKNOWN` (P1-7 сохраняется).

## C.4 Отрицательные результаты P0-C

1. **Правила смерти/штрафа нет** — есть только сброс состояния и функция выбора точки появления.
2. **Деспавна/реактивации по дистанции нет** ни в одном имени функции; лимит популяции не найден.
3. **Таблица климат→объекты** не выгружена.

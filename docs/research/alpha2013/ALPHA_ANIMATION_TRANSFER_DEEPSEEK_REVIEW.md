## 4. Дефекты автоматизации и их устранение

До правки `run_transfer.ps1` имел три дефекта, способных дать **ложный PASS**:
1. **Stale-результаты не удалялись** — `selftest.txt` и `transfer_report.txt` не очищались перед прогоном (удалялся только `playmode.txt`); маркер прошлого успешного прогона мог быть прочитан заново.
2. **Exit-коды Unity не проверялись** — `$e1/$e2/$e3` собирались, но не влияли на итог; авария Unity (например `0xC0000005`) с уцелевшим старым маркером давала PASS.
3. **Единственный источник вердикта — файл**, без проверки свежести.

Исправление: перед прогоном `TransferOutput` переносится в `TransferOutput_history/<timestamp>`; каждая фаза проверяется функцией `Resolve-Verdict`, которая требует **одновременно** `маркер == PASS` **и** `exit == 0`. Ключ `-Test` прогоняет 10 негативных тестов этой логики (PASS-маркер с exit 1/2/3/крэшем → FAIL; отсутствующий файл/маркер → FAIL; FAIL-маркер → FAIL; изоляция stale-каталога) — **10/10 PASS, exit 0**, без запуска Unity.

## 6. Оценка ограничений (не маскируются ослаблением тестов)

### 6.1 Интерполяция быстрого удара
При ~70 кадр/с между соседними кадрами оружие в пике удара поворачивается ~104° за ~28 мс; линейная интерполяция между ключами даёт отклонение до **4.43 вокс / 29.7°** от непрерывной позы (`interpolated`, 2200 пар). Сам Alpha детерминирован: кадры с равным игровым временем расходятся лишь на **0.041 вокс / 0.21°** (72 пары). Это ограничение **плотности съёма**, а не ошибка переноса; для точного пика нужен либо более частый захват, либо аналитическая кривая фазы, а не линейная интерполяция.

### 6.2 Влияние наклона взгляда
Голова/волосы получают `Rx(pitch)` вокруг шеи, оружие — `Rx(pitch/2)` вокруг хвата; клипы хранятся при наклоне 0, слой восстанавливается `AlphaClipPlayer.lookPitchDeg`. Проверено при 0° и −3.78° (остаток 0.0002 вокс / 0.02°) и −31.6° (голова 0.00°). **Не закрыто:** хвост атаки после ~1400 мс дополнительно «целится» по наклону (до 64° при −31.6°) — этот слой не нормирован, поэтому клип корректен только вблизи наклона ≈0 (клип снят при |наклон| ≤ 0.005°).

### 6.3 Tint волос
Тинт не восстановлен (в Unity белая маска); меш волос игрока Alpha (2244 вершины) не совпал ни с одной `human-hair-*` — открытый вопрос, наследуется из S05A-1/S05A-2. На перенос анимаций не влияет (матрица волос всегда равна матрице головы), но визуальный паритет цвета — `PARTIAL/UNKNOWN`.

### 6.4 Точность положения второй кисти
Основная кисть на точке хвата — 0.0002 вокс (рукоять в центре кисти, D52). Вторая кисть всю атаку лежит на оси рукояти: радиальное отклонение ≤ **2.30 вокс** при полуразмере кисти 2.5–3, диапазон вдоль рукояти `[-3.84, 1.85]`. То есть обе кисти на оружии, но вторая кисть **не привязана к фиксированной точке хвата** — её положение вдоль рукояти определяется снятой позой Alpha. Порог проверки 2.5 близок к фактическому 2.30 (запас 0.2 вокс) — это самая «нагруженная» из автоматических проверок.

## 8. План пакетного конвейера (подготовка; S05B NOT_AUTHORIZED)

### 8.1 Категория A — тот же риг `alpha_humanoid_v1` (можно пакетировать сразу)
Модели: перебрать ключи `.cub` из `data1.db` (body*/human-head-*/human-hair-*/glove/foot/оружие 15/16/17) → сформировать `models.*.json` → для каждого:
```powershell
python -m tools.alpha_models.transfer.prepare_unity --db ... --project ... --clips ... --models <models.json>
& tools\alpha_models\transfer\run_transfer.ps1 -Project ... -Models <models.json>
```
Критерий: `PREPARE_RESULT=PASS` и маркеры Unity `PASS` + exit 0. Проверка совместимости (`check_model_compatibility`) встроена. Это безопасная пакетная петля, не затрагивающая Alpha и production.

### 8.2 Категория B — та же риг, новые анимации (пакет по одной)
Каждая анимация — отдельная партия: ввод → `pose_capture` → `summary` (новый state/action) → `build --state S --action A --name N` → `compare` со вторым захватом → `prepare_unity` + `run_transfer.ps1` → визуальное сравнение. Статус `TRANSFERRED_FROM_ALPHA` только при доказанных позах. Боттлнек — интерактивный захват Alpha.

### 8.3 Категория C — новые риги (исследование, не масштабирование)
Существа/не-гуманоиды: снять `--target <ptr>`, определить адреса отрисовки частей (`draw_site`) и правила якорей по коду, завести новый модуль рига (`humanoid_rig.py` → новый модуль), затем A/B. Требует согласования с архитектором.

### 8.4 Готовность к пакетному переносу
Конвейер **технически готов** к пакетной обработке моделей категории A (петля над `models.json` + обновлённый `run_transfer.ps1` с защитой от ложного PASS) и к последовательным партиям анимаций категории B. **Массовая обработка всей библиотеки не запускается**: S05B остаётся `NOT_AUTHORIZED` до отдельной приёмки и решения продюсера.

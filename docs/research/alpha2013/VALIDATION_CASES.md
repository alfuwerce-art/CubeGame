# S00-R02 — VALIDATION_CASES: воспроизводимые проверки механик Alpha ↔ CubeGame

**Проект:** CubeGame. **Этап:** S00-R02 (D41). **Обновлено:** 2026-11-03 (review-fix R02: FIX-01, FIX-04, FIX-06).
**Смысл:** каждый случай — конкретный вход, действие и ожидаемый результат, который можно **фактически** выполнить. Статус `PASS` ставится только после реального прогона с записанным результатом; иначе `NOT_RUN`.
**Важно (исправление FIX-01):** `stat_calcAttackDamage` — это **максимум HP**, а не урон; урон оружия — `stat_calcWeaponDamage`. `+0x060 == 0` — **роль «игрок»**, а не форма персонажа. Прежняя редакция `VC-CMB-01…04` трактовала эти формулы неверно и заменена; проверка — `tools/alpha_combat_reference.py --check`.

## Легенда

| Поле | Значение |
|---|---|
| `SRC` | откуда взято ожидание (`SRC-01/02/03/04`) |

## Правила

- `PASS` — только с командой/датой/выводом. Скриншот без параметров (seed, уровень, экипировка, хеш копии) не считается доказательством.
- `ALPHA_RUNTIME`-случаи нельзя выполнять без разрешения продюсера; игра запускается **только из копии установки**, оригинал `D:\Games\Cube world` — read-only. Визуальное перемещение само по себе не считается доказательством изменения координат в сейве.
- Результаты прогонов писать в `R02_REPORT.md` (партия) и обновлять `STATUS` здесь.
- Для `+0x70` не использовать формулировку «текущая цель»: доказан числовой счётчик; точная семантика — OQ-24 (`PARTIAL`).

# Alpha 2013 — boot, start screens, save selection and input context

**Дата:** 2026-11-11 · **Этап:** M0 P0 · **Ветка:** `deepseek/m0-full-port-p0`
**Источник:** `D:\Games\Cube world\Cube.exe`, SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf`
(32-bit MSVC 2012, без PDB). Оригинал строго read-only.
**Метод:** реконструкция `.scratch/CubeWorld-Reversal` (Ghidra-декомпиляция, адреса = VA `Cube.exe`) как указатель;
поведение сверялось с телами функций, со строковой таблицей UTF-16 самого `Cube.exe` и с реальными
`Save/characters.db` / `Save/worlds.db`, прочитанными read-only через `sqlite3 mode=ro&immutable=1`.
Копии БД для разбора лежали в `.scratch/notes/savecopy` (вне git) и в репозиторий не попадают.

Метки достоверности: `ALPHA_CODE_STATIC` — прочитано в декомпиляции и подтверждено вызовами/смещениями;
`ALPHA_DATA` — проверено на реальных файлах сохранения; `LIVE` — наблюдалось в запущенном оригинале (P1);
`UNKNOWN` — не установлено.

## 1. Boot

`GameController` создаётся при старте клиента и в своём конструкторе:

1. Загружает `gui.plx`, `quest-tag.plx`, `help.plx` в узлы `+0x800884`, `+0x800214`… и `start.plx` в корневой узел
   стартового экрана `+0x800874` (`GameController_load_widget_file`). `ALPHA_CODE_STATIC`.
2. Находит в `start.plx` узлы `cubeworld`, `picroma`, `star1..4`, `landname`, `blackwidget`, `button`, `button2`,
   `smallbutton`, `preview`, `equippedpreview`, `leftbutton`, `rightbutton`, `upbutton`, `downbutton`,
   `scrollbutton`, `edit`, `itemselector`, `combopoints`. `ALPHA_CODE_STATIC`.
3. Создаёт экранные виджеты: `StartMenuWidget` (`0x583270`) для стартового меню, `OptionsWidget` (`0x4CF3C0`),
   `SystemWidget` (`0x587660`) для внутриигрового меню, а также HUD-виджеты. `ALPHA_CODE_STATIC`.
4. Открывает `Save/characters.db` и читает ключ `num`; для каждого индекса `0..num-1` создаёт `Creature` и
   десериализует запись (ключ = десятичный индекс). Затем то же для `Save/worlds.db` (`WorldInfo`, 0x28 байт).
   `ALPHA_CODE_STATIC` + `ALPHA_DATA` (в установленной игре обе базы содержат `num` и `0`).
5. Строит кнопки-шаблоны стартовых экранов: `Create Character`, `Create World`, `Back`,
   `Multiplayer Worlds...`, `Connect to server`, `Connect`, поля `charactername`, `worldName`,
   `worldSeed` с подписями `Name`, `World name`, `Seed (must be a number)`. `ALPHA_CODE_STATIC`
   (строки найдены в UTF-16 таблице `Cube.exe`, смещения файла `0x2ff118…0x2ff200`).
6. Начальное состояние — стартовый экран (`+0x800874` видим), остальные экраны скрыты флагами видимости.
   `LIVE` (P1: при запуске виден стартовый экран, автоматического перехода нет) + флаговая модель ниже.

Автоматического входа в редактор или в мир нет: любой переход инициируется кликом по пункту стартового меню
(`0x47B600`, pass 0 = LMB). `ALPHA_CODE_STATIC`.

## 2. Модель экранов и индексов

Alpha не имеет «лобби-панели»: экраны — это узлы дерева Plasma, у каждого есть флаг видимости
(`node+0x3c → +0x94[+0x68]`). Используемые узлы:

| Узел | Экран |
|---|---|
| `+0x800874` | стартовое меню (`start.plx`) |
| `+0x800880` | редактор персонажа |
| `+0x800888` | список персонажей |
| `+0x80088C` | список миров |
| `+0x800890` | создание мира |
| `+0x800894` | подключение к серверу (multiplayer) |
| `+0x800A00` | Options |

Отдельные индексы выбора: `+0x800A0C` — выбранный персонаж, `+0x800A10` — выбранный мир.
Запрошенный мир: `+0x800A50` (seed), `+0x800A54` (имя). `ALPHA_CODE_STATIC`.

## 3. Стартовое меню (`StartMenuWidget`)

`0x583320` рисует ровно три пункта и хранит индекс под курсором в `+0x160` (по умолчанию −1):
`Start Game`, `Options`, `Exit`. Подсветка пункта меняет цвет текста; вертикальные позиции 30/80/130,
зоны попадания по X 10..40 / 60..90 / 110..140. `ALPHA_CODE_STATIC`.

`0x47B600` (vfunc_7, pass 0) при индексе ≥ 0:
* 0 → скрыть `+0x800874`, показать `+0x800888` (список персонажей);
* 1 → показать `+0x800A00` (Options);
* 2 → выставить байт выхода из игры. `ALPHA_CODE_STATIC`.

## 4. Список персонажей (`0x49D650`)

Строит строки из вектора моделей `+0x800984…+0x800988`: число строк = `count + 1`, где последняя — запись
«нового персонажа» с моделью `0`; строка клонируется из узла списка, содержит `CharacterPreviewWidget`
(живая модель персонажа, `0x424E80`), высота строки `0xE6 = 230`, первая строка `y = 0x32 = 50`.
`ALPHA_CODE_STATIC`.

## 5. Выбор персонажа (`0x483E70`)

Скрывает список персонажей, читает `+0x800A0C`:

* индекс < 0 или ≥ числа персонажей → это строка нового персонажа: камера/редактор сбрасываются
  (`+0x1B0 = 90°`, `+0x1C0 = +0x1BC = 5`), показывается редактор `+0x800880`, вызывается
  `Player_resetFull`, очищаются имя/поворот/скорость/HP и карта внешности, затем
  `CharCreation_reset_defaults` (`0x42BD90`) и `CharCreation_refresh_model` (`0x42C080`);
* иначе персонаж десериализуется в текущее существо и показывается список миров `+0x80088C`.
  `ALPHA_CODE_STATIC`.

## 6. Редактор и подтверждение (`0x42BD90` / `0x42C080` / `0x4821A0`)

Поля редактора и диапазоны моделей уже восстановлены в [C1](C1_ALPHA_HERO_CREATION.md): раса 0..7, пол 0/1,
класс 0..3 (существо `+0x140 = класс + 1`), лицо/причёска — индексы в диапазоне вида, палитра волос 16×7 = 112
цветов, имя ≤ 15 символов. Круговой индекс: `< 0 → последний`, `≥ количества → 0`. `ALPHA_CODE_STATIC`.

Подтверждение `0x4821A0`:
1. скрывает редактор `+0x800880`, показывает список миров `+0x80088C`;
2. копирует текст узла `edit` в имя существа `+0x1168`;
3. ставит уровень `+0x190 = 1`;
4. пишет в `characters.db` ключ `num` = (число персонажей + 1);
5. `saveEntityBlob(count, player)` — запись нового персонажа по десятичному ключу;
6. копирует существо (инвентарь/экипировка/внешность), добавляет копию в вектор и перестраивает список.

То есть персонаж записывается **до** выбора мира, и мир с персонажем не связан. `ALPHA_CODE_STATIC`.

## 7. Список миров (`0x4A23D0`)

Строки — из вектора миров `+0x8009DC…+0x8009E0`, число строк `count + 1` (последняя — «Create World», модель 0),
высота 230, `y = 50`. Для каждой записи проверяется префикс имени `online_`; показываются только записи,
совпадающие с текущим режимом (`+0x8009B0`: 0 — одиночные, 1 — сетевые). Кнопка
`Multiplayer Worlds...` / `Singleplayer worlds...` переключает режим (`0x484230`). `ALPHA_CODE_STATIC`.

## 8. Выбор мира (`0x484170`)

Скрывает список миров, сбрасывает камеру, читает `+0x800A10`:

* индекс меньше числа миров → `GameController_reloadServerList(seed мира, имя мира)` — мир сразу запрашивается;
* иначе → показывается экран создания мира `+0x800890`. `ALPHA_CODE_STATIC`.

## 9. Создание мира (`0x482530`)

Скрывает экран создания мира, сбрасывает камеру, пишет `worlds.db:num` = (число миров + 1), читает два узла
`edit` (имя и seed), разбирает seed оператором `wistream >> int` **без проверки диапазона**, создаёт
`WorldInfo` (0x28 байт), выбирает его (`+0x800A10`), сохраняет через `saveStructureBlob`, перестраивает список и
запрашивает мир тем же общим путём. `ALPHA_CODE_STATIC`.
Следствие: `uint`-валидация seed — не Alpha-правило; нечисловой ввод даёт 0 (поле `+0x20` инициализировано 0).

## 10. Запрос мира (`0x46F620`)

Записывает seed и имя в объект внешности персонажа (`+0x24` = seed, `+0x28` = имя), в поля запроса
`+0x800A50/54`, затем уничтожает все сущности, кроме игрока (сброс старого мира). `ALPHA_CODE_STATIC`.

## 11. Загрузка мира (`WorldInfo::ctor_0`, `0x46A8A0`)

Потоковый шаг, вызываемый каждый кадр:

1. Если запрошенные seed/имя совпадают с активными — обычный streaming (поиск отсутствующих зон в квадрате ±3,
   порог `768²`, `Sleep(20)`).
2. Иначе — смена мира: очистка сетки, `World_open(seed, name)`; если записи мира в `worlds.db` нет, она
   создаётся (seed + имя) и сохраняется; затем поиск позиции персонажа в его персональной карте
   `(seed, имя) → 6 dword`:
   * запись найдена → позиция и поворот персонажа берутся из неё;
   * записи нет → позиция берётся из **стартовой точки мира** (`world+0x8003D4`, три float, `×65536`), то есть
     новому для персонажа миру соответствует старт мира;
3. после установки позиции последняя позиция дублируется в `+0x1350…`, скорость обнуляется.

`ALPHA_CODE_STATIC`. Для P0 это правило и реализовано: существующий мир → сохранённая позиция, новый → старт мира.

## 12. Back (`0x4814F0`)

Единая функция возврата, порядок проверок:

`создание мира (+0x800890)` → список миров;
`список миров (+0x80088C)` → список персонажей;
`редактор (+0x800880)` → список персонажей;
`список персонажей (+0x800888)` → стартовое меню (+0x800874);
`подключение (+0x800894)` → список миров.
`ALPHA_CODE_STATIC`.

Esc **не** является Back в стартовых экранах: `0x47E1B0` обрабатывает Esc только во время игры.

## 13. Выход из мира (системное меню)

`SystemWidget` (`0x587710`) рисует три пункта: `Options`, `Start Menu`, `Exit Game` (индекс `+0x160`).
Обработчик клика (в `vfunc_8`/`0x47DFxx`):

* 0 → показать Options `+0x800A00`;
* 1 → **сохранить персонажа** `saveEntityBlob(charIndex, player)` и **мир** `saveStructureBlob(worldIndex, world)`,
  отключиться от сервера, показать стартовое меню `+0x800874`, сбросить запрос мира (seed/имя пустые) и камеру;
* 2 → выход из игры (без отдельного сохранения).

Отдельного «paused» состояния у Alpha нет: системное меню — оверлей, мир продолжает идти. `ALPHA_CODE_STATIC`.

## 14. Ввод и контекст

* `GameController::vfunc_1 0x47F1D0` — «GUI активно»: истина, если открыт текстовый ввод, карта, любой из
  HUD-панелей/окон и любой стартовый экран (включая стартовое меню и Options). Пока GUI активно, игра не
  получает мышь/атаку/движение камеры.
* `0x47E1B0` (нажатие клавиши) сначала проверяет видимость пяти стартовых экранов
  (`+0x800880`, `+0x800890`, `+0x800888`, `+0x800894`, `+0x80088C`) и текстовый ввод; если открыт любой из них,
  игровые клавиши не обрабатываются вообще.
* Игровые клавиши: `B`/`I` → инвентарь (`0x488C00`), `M` → карта, `C` → крафт, `O`, `V`, `X`, `Tab`, `F`, `G`;
  `Esc` → сброс карты и переключение флага GUI-панелей (`+0x8008F2`), то есть открытие/закрытие системного меню.
* Мышь: `0x47B600` при активном GUI направляет LMB/RMB в виджеты; RMB вне виджета закрывает панели.
  `ALPHA_CODE_STATIC`.

## 15. Options (`options.cfg`, `OptionsWidget` 0x4CF3C0)

Строки интерфейса (UTF-16 таблица `Cube.exe`): `Mode` (`Windowed`/`Fullscreen`), `Resolution` (`W x H`),
`Anti-aliasing` (`Disabled`…), `Render Distance`, `Sound FX Volume`, `Music Volume`, `Camera Speed`,
`Camera Smoothness`, `Invert Y Axis`, `FPS Limit`, `Language`. Кнопки: `Apply`, `OK`, `Cancel`
(три цели подключения в конструкторе). `ALPHA_CODE_STATIC`.

`options.cfg` установленной игры (порядок ключей совпадает с `OptionsWidget_initDefaults` `0x4CE660`):

```
fullscreen 0
resolutionX 1920
resolutionY 1080
antiAliasing 0
renderDistance 50
soundVolume 100
musicVolume 100
cameraSpeed 50
cameraSmoothness 80
language 9
invertY 0
minTimeStep 9
```

Умолчания `initDefaults`: `50,100,100,50,80,0,0,9` для полей 4..11. `ALPHA_DATA`. Точные наборы значений
(`Anti-aliasing`, `Language`, `FPS Limit`) и семантика `minTimeStep` — `UNKNOWN`; в порте они показаны как
числовые/дискретные значения, сохраняются в том же формате и не выдают себя за доказанный Alpha-набор.

## 16. Форматы сохранений (проверено на файлах)

`Save/characters.db` и `Save/worlds.db` — одна таблица `blobs(key TEXT PRIMARY KEY, value BLOB)`, ключи
`num` и десятичные индексы; значения — zlib. `ALPHA_DATA`.

`worlds.db` запись (`saveStructureBlob`/`loadStructureBlob` `0x4878A0`/`0x480B60`):
`uint nameLength`, `name` (nameLength байт), `int32 seed`, `int32 field24`, `int32 dx,dy,dz` превью,
`uint previewLength`, zlib-превью (воксельная модель карты). Реальный мир установки:
`nameLength=7`, `G0WORLD`, `seed=666666`, `field24=1`, превью `32×32×12`.
**Поправка к R01:** «версия записи 7» — это длина имени мира; отдельного поля версии в записи нет.

`characters.db` запись — блоб персонажа версии 11 (порядок полей подтверждён тремя путями, см.
[DATA_AND_SAVE_SCHEMAS](DATA_AND_SAVE_SCHEMAS.md)), в конце:
`uint mapCount`, `mapCount × (int32 seed, uint nameLength, name, 24 байта значения)`, `int32 lastSeed`,
`uint lastNameLength`, имя, `int32 ability`, `int32 versionTag=11`, `int32[11] ранги`.
Значение карты — позиция (3 × fixed-point int64) и поворот. Реальный персонаж `S00G0` содержит одну запись
`seed=666666`, имя `G0WORLD`, позицию из трёх fixed-point значений. `ALPHA_DATA`.

Точка, в которой текущая позиция персонажа попадает в карту при сохранении, отдельно не дизассемблирована —
`UNKNOWN`; в порте она пишется явно в момент сохранения (семантика «позиция на мир» проверена по данным).

## 17. Что остаётся неизвестным

* Точные наборы значений Options (`Anti-aliasing`, `Language`, `FPS Limit`) и смысл `minTimeStep`.
* Текст и компоновка строки списка персонажей/миров (рисуется `CharacterPreviewWidget`/`WorldPreviewWidget`,
  их `vfunc_1` не восстановлены); в порте строка показывает имя/класс/уровень и имя/seed.
* Вращение модели в редакторе мышью (`CharacterStyleWidget`) и точная камера превью.
* Точка записи текущей позиции в карту миров при сохранении.

## 2. Предмет → модель (исполнение `GameController_item_icon_id`, VA 0x4EC400)

Выбор модели — это **не имя предмета**, а исполненная функция: `item_icon_id` возвращает индекс в
общем векторе моделей, который затем индексируется блоками отрисовки. Тип/подтип/материал/seed
читаются из структуры предмета (0x118 байт), поэтому «железный меч» и «золотой меч» — разные модели
одного класса.

| подтип | модель (material 0, seed 0) | подтип | модель |
|---|---|---|---|
| 0 sword | `iron-sword1.cub` | 13 shield | `iron-shield01.cub` |
| 1 axe | `iron-axe1.cub` | 14 quiver | `quiver.cub` |
| 2 mace | `iron-mace1.cub` | 15 greatsword | `iron-greatsword1.cub` |
| 3 dagger | `iron-dagger1.cub` | 16 greataxe | `iron-greataxe1.cub` |
| 4 fist | `iron-fist1.cub` | 17 greatmace | `iron-greatmace1.cub` |
| 5 longsword | `iron-longsword1.cub` | 18 pitchfork | `pitchfork.cub` |
| 6 bow | `bow.cub` | 19 pickaxe | `iron-pickaxe1.cub` |
| 7 crossbow | `wood-crossbow1.cub` | 20 torch | `torch.cub` |
| 8 boomerang | `wood-boomerang1.cub` | 21–25 | алиасы меча (`iron-sword1.cub`) |

## 4. Точки крепления (anchor) и переход «спина ↔ рука»

`M = T(-anchor) · chain · B`, то есть `anchor` — точка сетки модели, которая садится на сустав.
Закон линеен по габаритам модели:

```
anchor(size) = (coeff_x·sx + const_x, coeff_y·sy + const_y, coeff_z·sz + const_z),  mesh · scale
```

`anchor_probe` (измерение d(anchor)/d(size) исполнением `drawModel` дважды) видит только линейную
часть; константы выведены из кода ветки и проверены тем, что точка хвата попадает **внутрь кисти**.
Это разные источники, и они дают согласованный результат.

### 4.1 Оружие в руке (`weapon`, 0x421A01; ветка 6580–6662)

| подтипы | law | coeff | const | scale | статус |
|---|---|---|---|---|---|
| 0,1,2,3,5,10*,11,13,14,15,16,17,18,19,20,21–25 | `weapon_generic_in_hand` | (0.5,0.5,0) | (0,0,4) | 1 | CODE_DERIVED_MEASURED |
| 4 fist | `weapon_fist_in_hand` | (0.5,0.5,0.5) | — | 1 | CODE_DERIVED_MEASURED¹ |
| 6 bow | `weapon_bow_in_hand` | (0.5,1,0.5) | (0,−1.5,0) | 1 | CODE_DERIVED_MEASURED |
| 7 crossbow | `weapon_crossbow_in_hand` | (0.5,0,0.5) | — | 1 | CODE_DERIVED_MEASURED |
| 8 boomerang | `weapon_boomerang_in_hand` | (0.5,0,0) | (0,2,4) | 1 | CODE_DERIVED_MEASURED |
| 9 arrow (модель `arrow.cub`) | `weapon_arrow_in_hand` | (0.5,0,0) | (1,−0.5,−1) | 1 | CODE_DERIVED |
| 12 bracelet | `weapon_bracelet_in_hand` | (0.5,1,0.5) | (0,−1,0) | 0.6 | CODE_DERIVED_MEASURED |

`*` staff (10) отличается только константой: `(0.5,0.5,0)`, const `(0,0,10)`.

¹ у кулака закон совпадает с `center`, поэтому ветка «спина/рука» по anchor неразличима — см. §4.4.

Двуручные 15/16/17 используют **тот же** общий закон, что и одноручное оружие; «двуручность» в Alpha
не меняет точку крепления оружия, она выбирает цепочку атаки `57 → 67 → 58`
(`combat_selectAttackAnim`, 0x445020) и оставляет левую руку свободной. Куда ставить левую кисть на
рукояти — **решение проекта** (D52, `CharacterGrip.cs`), а не данные Alpha.

### 4.2 Левая рука в руке (`offhand_b`, 0x42231B; ветка 6805–6850)

| подтипы | law | coeff | const | scale |
|---|---|---|---|---|
| 3 и прочие | `offhand_generic_in_hand` | (0.5,0.5,0) | (0,0,4) | 1 |
| 4 fist | `offhand_fist_in_hand` | (0.5,0.5,0.5) | — | 1 |
| 6 bow | `offhand_bow_in_hand` | (0.5,1,0.5) | (0,−1.5,0) | 1 |
| 7 crossbow | `offhand_crossbow_in_hand` | (0.5,0,0.5) | — | 1 |
| 12 bracelet | `offhand_bracelet_in_hand` | (0.5,1,0.5) | (0,−1,0) | 0.6 |
| 13 shield | `offhand_shield_in_hand` | (0.5,0,0.5) | (0,3,0) | 1 |
| 8 при основном 8 | `offhand_boomerang_main_in_hand` | (0.5,0,0) | (0,2,4) | 1 |

Отдельная зависимость: если **основное** оружие — бумеранг (подтип 8), левая рука использует закон
бумеранга; иначе — общий. Это исполняемая ветка кода, а не эвристика.

### 4.3 За спиной

Оба блока в ветке «спина» используют `anchor = center = (sx/2, sy/2, sz/2)` — измерено на покое для
всех подтипов (D64 + повторная проверка).

### 4.4 Когда предмет в руке, а когда за спиной

```
weapon_on_back(action, subtype, flag124) =
    (action ∈ BACK_ACTIONS  или  flag124 & 0x10)  и  subtype ∉ {4, 12}

offhand_on_back(action, subtype) =
    action ∈ BACK_ACTIONS  и  subtype ∉ {20, 4, 12}
```

`BACK_ACTIONS` = `{0, 0x15, 0x6d, 0x6a, 0x6b, 0x69, 0x5b, 0x60, 0x50, 0x52, 0x55, 0x4f, 0x53, 0x51, 0x54}`
(то есть 0, 21, 109, 106, 107, 105, 91, 96, 80, 82, 85, 79, 83, 81, 84) — список из `drawModel`
(строки 6547–6554 / 6698–6706), совпадает с `humanoid_rig.WEAPON_ON_BACK_ACTIONS`.

Следствия, проверенные исполнением:

* при действиях 80/81 (расходник) оружие **за спиной**, а предмет — в руке (`held_item`);
* при атаке 57/58/67 оружие в правой руке, левая рука показывает `offhand_b` (щит, второй клинок,
  лук — любой подтип), а в покое тот же предмет висит за спиной (`offhand_a`);
* кулак/браслет/факел (4/12/20) держатся в руке **и в покое**, поэтому `offhand_b` виден без атаки;
* флаг `creature+0x124 & 0x10` (планер/лодка) принудительно отправляет оружие за спину;
* кольца не рисуются, слот `+0x300` без потребителя.

### 4.5 Как это проверено

1. **Линейная часть** каждого закона: `anchor_probe` на исполненном `drawModel` (изменение габаритов
   модели на 4 вокселя по каждой оси) — совпадение с объявленными коэффициентами до 1e-4.
2. **Константы**: из ветки кода + проверка «точка хвата внутри bbox кисти» (`hand_r` для оружия,
   `hand_l` для левой руки) на кадре атаки.
3. **Предикат «спина/рука»**: для каждого действия выборки измерен коэффициент anchor по Z
   (0.5 = спина, 0.0 = рука) и сравнён с предикатом; расхождений нет (см. отчёт).
4. **Условия слотов**: ламп/планер/питомец/расходник проверены на границах (флаг есть/нет, действие
   0/80/81/82, `timer` = 0 / cooldown−1 / cooldown / cooldown+1).

Инструменты: `tools/alpha_models/catalog/item_layer.py` (проверка + контракт + evidence),
`tools/alpha_models/universal/item_attach.py` (законы и предикаты), коммитнутые числа —
`tools/alpha_models/catalog/item_layer_evidence.json` (только индексы, имена моделей, адреса).

## 5. Предметно-зависимые действия (что требует контроллер)

Тело анимируется одинаково; предмет меняет **какие блоки** рисуются и где. Контракт
`cubegame.item_layer/1` (в evidence) содержит 101 действие с полями:

| поле | смысл |
|---|---|
| `state` | состояние `drawModel`, выбранное резолвером (для 48/93 зависит от экипировки) |
| `weapon` | `IN_HAND` / `ON_BACK` по предикату §4.4 |
| `offhand` | `IN_HAND` / `ON_BACK` |
| `heldItem` | действие 80/81 — предмет из `+0x1e8` в `held_item` |
| `petItem` | действие 82 — предмет из `+0x1020` в `pet_item` |
| `weaponOnly` | 23 кода, которые ИИ запускает только с оружием (D64) |
| `twoHandedChain` | 57/67/58 — цепочка двуручного оружия |

Практические правила для Unity-контроллера (проверяемые данными, не догадки):

* **Двуручное** (15/16/17): один блок `weapon`, второй кисти на рукояти — по геометрии модели
  (D52), не по Alpha. Парный слот при этом должен быть пуст, иначе `offhand_b` нарисует второй предмет.
* **Парное** (4/12/20 и вообще два предмета типа 3): `weapon` + `offhand_b`, обе руки заняты;
  при атаке второй клинок виден в левой руке (проверено для кинжала/кулака/факела/щита/лука).
* **Расходник**: действия 80/81, модель из `+0x1e8`, показывать `held_item` пока
  `timer < itemCooldown`; оружие в это время за спиной. Тело-анимация питья в Alpha **не доказана**
  (поза не извлекалась) — это остаётся `UNKNOWN`.
* **Питомец** (82): `pet_item` из `+0x1020`.
* **Лампа** (24): `lamp_item` только при флаге 0x200; **планер/лодка** (23) — только при 0x10.

## 6. Динамические части (R-8): камень голема найден

Действие 108 у големов (0x6f/0x70/0x71) в состоянии 71 рисует **не слот экипировки**, а блок
`offhand_b` с фиксированной моделью `iron-deposit.cub` (реестровый индекс 2101, габариты 11×11×15),
anchor — общий закон левой руки. Это ровно те данные, которых не хватало R-8: блок, модель, anchor
и состояние. Осталось инженерное: скрытая часть рига + проигрыватель (M0-06E), это не данные Alpha.

Черепаха 0x19, действие 72: в проверенном домене состояний нового блока **нет** — отрицательный
результат, R-8 для неё остаётся открытым (нужен другой источник состояния/поз).

# Захват анимации из работающей Cube World Alpha (журнал)

**Задача:** `S05A2-MIGRATION-ANIMATION-01`, блок B. **Основание:** [D53](../../decisions/D53-original-animation-extraction-priority.md), [D54](../../decisions/D54-internal-alpha-research-prototype-policy.md), [D55](../../decisions/D55-animation-tooling-and-interactive-capture.md).
**Статус:** `PARTIAL` — окно и мышь под контролем, клавиатура пока не доходит до игры; анимация ходьбы не наблюдена в движении.
**Среда:** `D:\Projects\CubeGame\.scratch\alphatest2` (копия, SHA256 `Cube.exe` = `84A7A132A84D…`, совпадает с `D:\Games\Cube world\Cube.exe`); оригинал не изменялся, `Save` копии восстановлен после сессии.

## 1. Проблема фокуса: решена

Ранее `SetForegroundWindow` из фонового процесса возвращал `false` (Windows foreground-lock). Применён штатный приём, не требующий установки ПО:

```
ShowWindow(hwnd, SW_MAXIMIZE);
AttachThreadInput(currentThread, foregroundThread, true);
keybd_event(VK_MENU, …, tap);      // снимает foreground-lock
SetForegroundWindow(hwnd);
AttachThreadInput(currentThread, foregroundThread, false);
```

Результат проверки: `SetForegroundWindow=True`, `GetForegroundWindow()` = PID игры (`match=True`). После этого **клики мышью доходят**: игра прошла меню → выбор персонажа → выбор мира и загрузилась в мир.

## 2. Что реально наблюдено

| Действие | Результат |
|---|---|
| Синтетические клики (меню, START GAME, персонаж, мир) | **работают** — игра загрузила персонажа `SOCCO, LVL 1 WARRIOR` в мир `земли Arulon` |
| Синтетическое нажатие `W` (`keybd_event` без скан-кода) | **не работает** — персонаж не сдвинулся, кадры ходьбы идентичны idle |
| Съёмка окна через `GetWindowRect` + `CopyFromScreen` | **работает**, 12 кадров 1936×1048 (окно развёрнуто) |

Кадры: `.scratch/s05a2/alpha_walk/lambda-00-menu.png`, `lambda-10-ingame.png`, `lambda-walk-00..05.png`, `lambda-11-afterwalk.png`.

Вывод: **фокус и мышь больше не блокер**; блокер сместился на **синтетическую клавиатуру**. Наиболее вероятная причина — игра читает клавиатуру через DirectInput/raw input, а `keybd_event` с нулевым скан-кодом такой поток не генерирует. Следующие шаги: `keybd_event`/`SendInput` с реальными скан-кодами (`MapVirtualKey`), `SendInput` с `KEYEVENTF_SCANCODE`, либо штатный ввод через интерактивный сеанс.

## 3. Инструменты

Ничего нового не устанавливалось: выявленный блокер (фокус окна, затем клавиатура) не требует Ghidra/отладчика/трассировщика — все шаги выполнены имеющимися средствами Windows API и PowerShell. Установка специализированного ПО отложена до появления блокера, который без него не решается (согласно D55 «не устанавливать весь список без необходимости»).

## 4. Что это означает для переноса

* Наблюдение оригинальной ходьбы **не получено** → статус клипа ходьбы остаётся `ORIGINAL_NOT_ALPHA`, не `TRANSFERRED_FROM_ALPHA`.
* Тайминги фаз атак из кода (`combat_getAttackWindup/Timing/ReloadFrames`) по-прежнему единственная подтверждённая величина Alpha: 100/200/300/400/800/1000 мс, формула `base_ms/(haste×speed)`.
* Клавиатурный канал нужно дожать (скан-коды), после чего снимать idle → W → отпускание и атаку правой кнопкой мыши.

## 5. Следующий конкретный шаг

1. Повторить запуск, отправить `W` с реальным скан-кодом (`KEYEVENTF_SCANCODE`), проверить, что персонаж сдвинулся хотя бы на один блок.
2. Снять серию 10–15 кадров цикла и измерить длительность шага по кадрам.
3. Нажать кнопку атаки, зафиксировать замах и контакт, сопоставить с таймингами из кода.
4. Только после этого присваивать `TRANSFERRED_FROM_ALPHA` / `RECONSTRUCTED_FROM_EVIDENCE` самим позам.

## 6. Правовые ограничения

## 8. Управление восстановлено (S05A-2 D57 CONTINUE)

**Причина прошлой неудачи найдена и устранена:** структура `INPUT` была объявлена без union-выравнивания
(`cbSize` ≠ 40), поэтому `SendInput` возвращал 0 и события не вставлялись. Исправлено:

* полный `INPUT` c `INPUTUNION` (`MOUSEINPUT` / `KEYBDINPUT` / `HARDWAREINPUT`), `[StructLayout(LayoutKind.Explicit)]` для union;
* `Marshal.SizeOf(typeof(INPUT))` = **40 байт** (x64) — проверено в рантайме;
* `MapVirtualKey(vk, 0)` + `KEYEVENTF_SCANCODE`, отпускание в `finally` с `KEYEVENTF_KEYUP`;
* журналирование `SendInput` и `GetLastError()`.

**Проверка в обычном текстовом поле** (WinForms `TextBox`, реальное окно): фокус получен (`True`), нажатия A и B
доставились — поле получило символы `фи` (активная раскладка — русская, скан-коды корректны).

**Проверка в Cube World Alpha** (локальная копия `.scratch/alphatest2`):

| Шаг | Результат |
|---|---|
| Фокус окна (`AttachThreadInput` + Alt + `SetForegroundWindow`) | `True`, foreground PID = PID игры |
| Клики меню → персонаж → мир | работают, персонаж загружен |
| `SendInput` W down / up | `sent=1 err=0` для обоих событий |
| Фактическое смещение персонажа | **подтверждено**: центроид области волос смещается `(609, 931)` (idle) → `(757, 845)` → `(957, 748)` и далее до `(951, 673)`, площадь силуэта меняется 12 156 → ~1 400 пикселей — персонаж пошёл вперёд и камера последовала за ним |

**Кадры:** `.scratch/s05a2/alpha_walk4/i-10-idle.png`, `i-walk-00..07.png`, `i-11-stop.png` (10 шт.).

**Итого по вводу:** клавиатура и мышь полностью под контролем; наблюдение реальной ходьбы Alpha стало возможным.
Следующий шаг — снять полный цикл с временными метками и извлечь позы (S/D/A/D, диагонали, idle-переходы), затем
атака правой кнопкой и сопоставление с таймингами `combat_get*`.

**Статус переноса поз:** пока `PARTIAL/BLOCKED` — движение наблюдается, но формулы поз ещё не восстановлены;
`TRANSFERRED_FROM_ALPHA` не присвоен.


## 9. Полный захват ходьбы (S05A2-D57-CONTINUE-02)

Скрипт `.scratch/s05a2/alpha_walk_capture.ps1` (исправленный `SendInput`, кадры + монотонные метки времени в
`frames.jsonl`), анализ `.scratch/s05a2/analyse_walk.py`. Копия Alpha из `.scratch/alphatest2`, `Save` восстановлен,
оригинал не изменялся (`Cube.exe` `84A7A132A84D…`).

**Снимки (48 кадров, окно 1936×1048):**

| Фаза | Кадров | Интервал по меткам, мс | Центроид волос: x | y |
|---|---|---|---|---|
| idle | 8 | 24 029…25 481 | 608…608 | 932…932 |
| walkW | 24 | 25 691…30 444 | 608…963 | 932…654 |
| idleAfter | 6 | 30 708…31 746 | 946…954 | 745…773 |
| walkS | 10 | 31 976…33 864 | 967…968 | 773…830 |

Выводы:

* **Idle идеально статичен** (центроид не меняется ни на пиксель за 1.45 с) — значит измерение чувствительно к движению.
* **Ходьба подтверждена количественно**: при удержании W центроид волос уходит на 354 px по X и 278 px по Y, персонаж
  удаляется от камеры; после отпускания (`idleAfter`) движение прекращается.
* S работает так же (смещение продолжается в другую сторону кадра).
* **Фактическая частота съёмки — 4.8 кадра/с** (207 мс между кадрами вместо заданных 90): полноэкранный
  `CopyFromScreen` слишком медленный. При такой частоте шаг (~0.5–0.8 с на цикл) **алиасится**, поэтому позы
  конечностей по этим кадрам не восстанавливаются: за 4.75 с зафиксировано 6 вертикальных минимумов (≈1.26 события/с),
  что даёт лишь оценку «≈0.8 с на шаг», но не фазовую картину.

**Конкретный блокер и его решение:** нужна съёмка ≥30 кадров/с. Быстрый путь — снимать только область персонажа
(например, 400×400 в центре) вместо окна целиком, либо использовать `BitBlt` из GDI вместо `CopyFromScreen`.
Это техническая задача следующей сессии, а не отсутствие доступа.

**Статус:** движение и частота подтверждены; позы (`TRANSFERRED_FROM_ALPHA`) не получены — нужен более быстрый захват
и/или runtime-выборка матриц из процесса.

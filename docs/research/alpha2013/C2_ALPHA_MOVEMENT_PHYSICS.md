# C2 — движение героя Alpha 2013 по байтам Cube.exe (волна 1, D88)

**Дата:** 2026-11-09. **Исполнитель:** Claude Code. **Ветка:** `integration/m0-all`. **Статус:** `READY_FOR_REVIEW`, не ACCEPTED.
**Метод:** дизассемблирование `Cube.exe` (capstone) по адресам, найденным через реконструкцию `.scratch/CubeWorld-Reversal`; каждое число ниже прочитано из байтов (`DIRECT`). Псевдокод Ghidra использовался только как указатель — в нём потеряны аргументы (`arrayElem_stride4()` без индексов), поэтому прежнее исследование [I_movement](BEHAVIOR_SPECS/I_movement.md) не смогло связать скорость с позицией.

## 1. Единицы скорости — OQ-23 закрыт

| Шаг | Адрес | Что делают байты |
|---|---|---|
| dt | `0x60C83D…0x60C862` | `dt = (float)elapsed_ms · 0.001` → секунды |
| смещение | `0x61AEB4…0x61AEDB` | `d = (velocity[+0x34] + extra[+0x4C]) · dt` (`0x412280` сложение vec3, `0x451510` умножение на скаляр) |
| в позицию | `0x61B4D9…0x61B51B` | `pos_i(int64 @+0x10) += ftol(d_i · 65536)` (`0x42C580` × 65536, `0x42C9B0` add/adc) |
| блок | `0x42F040 vec3i64_toIntFloor` | координата блока = `pos / 0x10000` (используется для `world_getColumnData`) |

**Итог:** 1 единица скорости Alpha = 1 блок/с. В CubeGame 1 блок = 1 единица Unity ([WorldLayout](../../../Assets/CubeGame/Features/World/WorldLayout.cs)), значит скорости Alpha переносятся как есть, в ед. Unity/с.

## 2. Горизонтальное движение героя

| Величина | Значение | Адрес |
|---|---|---|
| Ускорение от клавиши направления | +80 блок/с² по оси камеры за каждую клавишу (диагональ не нормализуется) | `0x4A6B8B` (f80), сложение в `[+0x40]` `0x4A70DF…0x4A714E` |
| То же при «жёстком приземлении» | 8 | `0x4A6BA1 call 0x444650` → f8. Условие `physics_isLandingHard` не разобрано — **PARTIAL**, не перенесено |
| Скорость → | `v += a · dt` | `0x618F44` |
| Предел `max` | база **6.0**; босс/флаг `+0x7E&0x200` 8.0; `+0x60==5` 12.0; вода × навык плавания | `0x619234` и далее (`decomp 100100…100114`) |
| Бег (флаг действия 0x40) | `max ×= 2.0` → **12 блок/с** | `0x619DB8` (условия: не лазание у стены, не планирование в воздухе) |
| Кламп | `|v_xz| ≤ max` после сложения | `0x61AA49…0x61AAFC` |
| Медленно / быстро | `+0x134≠0` → ×0.5, `+0x138≠0` → ×1.5 | `0x61A918…0x61A94A` |
| Режим 20.0 | только если у мира бит `+0x84 & 1` (писатель не найден) | `0x619457` — **не** обычная скорость героя; прежняя запись «игрок 20.0» уточнена |
| Трение на земле | каждую мс `v += (0 − v)·k`, `k = 0.005`; при ненулевом ускорении `k = 0.0025` | `0x61D19E`, `0x61D1CF`, цикл `0x605950` (вызов `0x61D73D`) только при `contact & 1` |
| Сброс ускорения | `[+0x40] = 0` в конце тика | `0x61EBDA` |

Следствие: бег держит ровно 12 блок/с при любой частоте кадров (после трения следующий кадр снова упирается в кламп), остановка без ввода — экспонента с постоянной 200 мс (≈2.4 блока выбега с бега).

## 3. Клавиши (WinMain `0x4C91F2`, таблица DirectInput)

| Байт GameController | DIK | Клавиша | Использование |
|---|---|---|---|
| `+0x0B / 0x0C / 0x0D / 0x0E` | 0x11 / 0x1F / 0x1E / 0x20 | W / S / A / D | направления |
| `+0x12` | 0x39 | Пробел | прыжок; в планировании — флаг 0x40 при стамине > 0 |
| `+0x13` | 0x1D | левый Ctrl | флаг 0x1 «лазание» (`0x4983F4`) |
| `+0x14` | 0x2A | **левый Shift** | флаг 0x40 = `Shift НЕ нажат` (`0x498303 sete`) → **бег по умолчанию, Shift — шаг** |
| `+0x11 / 0x0F / 0x10` | 0x12 / 0x13 / 0x14 | E / R / T | не разбирались в C2 |

Закрывает U6 из I_movement (клавиши по умолчанию).

## 4. Прыжок — P-20 закрыт (`0x4A8C8A…0x4A8DDE`)

1. Пока пробел удерживается, таймер нажатия `+= ms`; при отпускании — 0.
2. Если таймер < **200 мс**, герой на твёрдом блоке (`contact & 1`) или `[+0x128] ≠ 0`, и `vz ≤ 0`: `vz = min(|v_xz| + 2, 10)`, таймер подкачки = **100 мс**.
3. Пока подкачка > 0, пробел нажат и `vz < 10`: `vz += 0.08 · ms` (80 блок/с²), потолок **10**.
4. Подкачка `−= ms` каждый кадр.
5. В воде (`contact & 2`) при нажатом пробеле: `vz += 0.001 · ms` до 10 — всплытие (не перенесено, пакет плавания).

Гравитация **30** блок/с² (`0x61AC2B…0x61AC43`), в планировании/«жёстком» режиме `30 · 0.1` (`0x61ABBB`).
Пример (расчёт по правилу, шаг 1 мс, пробел удерживается): с места — старт 2, подкачка до ≈7, высота ≈ **1.27** блока, в воздухе ≈0.62 с; с бега 12 блок/с — старт 10, подкачка держит 10 ещё 100 мс, высота ≈ **2.65** блока, ≈0.85 с.

## 5. Стамина `+0x1194` — поправка к прежней записи

Байты `0x619CF9…0x619D59`: стамина **не расходуется бегом по земле**. Расход `−0.0002/мс` — только при `флаг 0x10 (планирование) && не на земле && флаг 0x40`, т.е. пробел в полёте на дельтаплане; восстановление `+0.0001/мс` — во всех остальных случаях, кроме лазания у стены в воздухе (там отдельный расход `(1 − climbingPower) · 0.0005/мс`, `decomp 100183`). Прежние формулировки «спринт −0.0002/мс» (I4, P-18) — неверная привязка флага 0x40; исправлено в матрице.

# S00 — статический анализ Alpha 2013: найденные источники и рекомендованный метод

**Статус:** RESEARCH_REFERENCE / NOT APPROVED AS IMPLEMENTATION SPEC.  
**Дата:** 2026-11-02.  
**Контекст:** локальный агент в ветке `stage/s00-alpha-g0` подтвердил запуск Alpha, но ее происхождение неофициальное; побитовое совпадение с официальным дистрибутивом не установлено.

## 1. Существенная находка

Публичный исследовательский проект: https://github.com/qad3n/CubeWorld-Reversal

Его автор заявляет реконструкцию **декомпилированного псевдокода** `Cube.exe` и `Server.exe` Alpha 2013 (вариант с исправлением параплана), полученного через Ghidra 12.1.2. В репозитории есть разделы `world/`, `entity/`, `ai/`, `db/`, `ui/`, `render/`, `control/`, `server/`, общие типы и анализ неназванных функций. **Это не исходный код автора игры, не собираемый проект и не Unity-код**. Метки и предположения могут быть ошибочными.

Указания из README автора: `data1–4.db` — SQLite key/value-хранилища ресурсов по именам; `.plx` — формат объектных потоков движка Plasma. **Подтвердить на конкретной установленной копии** (например, сигнатуры, sqlite schema) до принятия как факт.

## 2. Что исследовать по файлам сначала

1. Сопоставить доступные метаданные локального `Cube.exe`/ `Server.exe` с описанной сборкой: PE timestamp, исполняемые функции/идентификаторы и архитектуру. SHA-256 чужой копии без обнародованного эталона не доказывает идентичность.
2. На *копиях* в изолированном каталоге, только чтение оригинала, исследовать структуру `data1–4.db`: сигнатура SQLite, перечень таблиц, формат ключей, типы ресурсов, без экспорта закрытых ассетов в репозиторий.
3. Анализировать `Save/*.db` (SQLite, согласно локальному отчёту): схему, персонажа, мир, предметы и идентификаторы. Сопоставить два состояния сейва, полученные из известных игровых действий.
4. Составить карту подсистем: `world`, `Creature`, AI, бой, предметы, прокачка, интерфейсы, сериализация и генерация.
5. Выделить механики, фактические правила, форматы и неопределённости в виде собственных **описаний/тестов**, не переносить исходный декомпилированный текст напрямую в Unity.
6. Запуск/игровой тест применять **точечно** для подтверждения неоднозначностей, логики действий, анимаций и проверки гипотез; G0 уже подтвердил работоспособность копии.

## 3. Границы достоверности, безопасности и прав

- Декомпиляция C++ даёт приближённый псевдокод, а не чистые оригинальные исходники. Заявление стороннего автора «восстановлены все функции» не равно 100% проверенной семантике.
- Исследовательский репозиторий не предоставляет права копировать защищённые игровые реализации в коммерческую CubeGame. В README явно указаны права владельцев Cube World и условие легитимного владения копией игры. **Не копировать файлы декомпиляции/оригинальные ассеты в публичный CubeGame**, а также не считать ссылки лицензией на повторное использование.
- Установленная локальная Alpha взята из непроверенного репака; Defender «угроз нет» не гарантирует чистоту. Прежде чем запускать неизвестные EXE/инструменты вновь, использовать изолированное окружение и ограниченные права, решить отдельный антивирусный инцидент.
- Ghidra: https://github.com/NationalSecurityAgency/ghidra (официальный инструментарий статического анализа). Не требуется устанавливать сразу: сначала исследовать доступные описания/структуру.
- Чётко маркировать `BINARY_STATIC`, `RECONSTRUCTED_SOURCE`, `SAVE_OBSERVED`, `ALPHA_DIRECT` и `UNKNOWN`; выводы подтверждать независимым наблюдением, когда оно принципиально важно.

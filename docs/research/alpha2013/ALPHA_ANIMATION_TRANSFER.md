## 1. Почему прежний путь застрял и что сделано вместо него

Прежние сессии (ALPHA_POSE_EXTRACTION, CODEX_CHANNEL_BINDING, CREATURE_RUNTIME_CAPTURE, HUMANOID_MOTION_D58) пытались пройти цепочку «состояние → канал → часть тела» статически, а в рантайме — найти игрока по шаблону памяти. Блокеры: каналы живут в стековом кадре, их потребитель безымянный; игрок не был загружен в мир.

Новый путь: **снимать результат, а не восстанавливать формулу.** В `Creature_drawModel` каждая часть заканчивается парой вызовов `render_uploadModelViewMatrices(M)` + `GameController_draw_mesh()` (thiscall, `ECX` = меш). Таких пар 27 (адреса найдены сканированием `E8 rel32` в диапазоне функции). Точки останова на этих 54 вызовах, включаемые только пока рисуется игрок, дают **готовую матрицу части и её меш** в каждом кадре.

Дополнительно решено:
- **Вход в мир**: меню в окне 784×561 вертикальное (`START GAME` → карточка персонажа → `SELECT` → мир `SELECT`); каждый шаг проверяется снимком, слепых кликов нет (`alpha_enter_world.ps1`).
- **Игрок**: указатель `*(gameController + 0x8006D0)` читается в `0x4A6B93`; автоподбор «по 5 моделям» ловил NPC (эльф с причёсками) — отказались.
- **Безопасное отсоединение**: при выходе сначала возвращаются все исходные байты, потом доигрываются события в полёте с откатом `EIP`; первая версия однажды уронила игру, исправленная — 4 захвата подряд, игра жива (`CUBE_ALIVE=True`).

## 2. Что снимается и как устроена поза (доказательства)

| Величина | Источник | Проверка |
|---|---|---|
| матрица части `M` | аргумент `[esp]` у вызова `render_uploadModelViewMatrices` | — |
| меш и его размер | `ECX` у `GameController_draw_mesh`; `mesh+0x3c` вершины, `+0x44` размер сетки | 8 частей: 10×8×10, 18×16×16 ×2, 13×13×33, 5×6×4 ×2, 5×8×4 ×2 |
| размещение существа `P` | `local_14e0` (= `esp + 0x1740 − 0x14e0` в теле функции) | `[esp+0x20] == this` во всех 4000+ кадрах (`frame_check`) |
| состояние / время | `this+8` / `this+4` (мс) | атака: состояние 2, время 0…1914 мс |
| действие, ввод, наклон, масштаб оружия | `creature+0x68`, `+0x40`, `+0x58`, `+0xb0` | действие 57; масштаб оружия 0.95 = `creature+0xb0` |
| фаза/амплитуда ходьбы | `creature+0x118c` / `+0x1188` | амплитуда 0.192, цикл 0.397 с |

**Формула части** (по блокам отрисовки, строки реконструкции 6108, 6270, 6327, 6528–6663, 7162, 7229, 7337, 7373): `M = T(−anchor(size)) · J · P`. `anchor` = центр сетки для всех частей тела, для оружия в руке подтипов 15/16/17 — `(sx/2, sy/2, 4)`, на спине — центр. Поэтому кадр сустава `J = T(anchor) · M · P⁻¹` не зависит от модели. Обратная сборка `T(−a)·J·P` даёт исходную `M` с ошибкой 2.8e-14.

**Геометрия совпадает с Alpha**: число вершин меша Alpha (`mesh+0x3c`) = 4 × открытых граней по нашему правилу для тела (1984), головы (1976), кистей (496), стоп (584) и оружия (`wood-greatmace02`, 4504). Исключение — волосы (§7).

**Пропорции Alpha** (масштабы частей в `J`): голова и волосы ×1.01, стопы ×0.98, тело ×1.00, кисти ×1.00 (правая зеркальная −1), оружие ×0.95 (= `creature+0xb0`). Прежний «×0.6» относится к другому подтипу оружия (`'\f'`), не к двуручному.

## 3. Найденные зависимости позы (и как они учтены)

1. **Наклон взгляда `creature+0x58`**: голова и волосы — `Rx(pitch)` вокруг шеи (в кадре сустава опора на `3/s`), оружие в руке — `Rx(pitch/2)` вокруг хвата (`GameController.cpp:6253, 6299, 6607, 6785`). Клипы хранятся при наклоне 0, слой можно вернуть в Unity (`AlphaClipPlayer.lookPitchDeg`). Проверено на захватах с наклоном 0 и −3.78°: остаток 0.0002 вокселя / 0.000° (голова), 0.02° (оружие); и с −31.6°: голова 0.00°.
2. **Ходьба с вводом**: при удерживаемом движении (`|creature+0x40|² > 0.1`) значение шага ×1.25 (`GameController.cpp:2246–2256`). Кадры после отпускания W давали выбросы до 17° — отфильтрованы.
3. **Сглаживание атаки**: состояние 2 задаёт целевые углы по фазам (`combat_getAttackWindup` → `getAttackTiming`), отрисованная поза догоняет цель с коэффициентами 0.01/0.04 (`local_1730`). Следствия: первые ~50 мс зависят от предыдущей позы (до 17.5°), а сама запись слегка зависит от частоты кадров. Клип — запись реального прогона Alpha при ~70 кадр/с.
4. **Фаза удержания после ~1400 мс**: руки и оружие дополнительно ориентируются по наклону взгляда (при −31.6° расхождение до 64°). Нормировка этого слоя не выведена; хвост клипа корректен для наклона ≈0 (клип снят при |наклон| ≤ 0.005°).

## 4. Повторяемость (Alpha ↔ Alpha)

| Проверка | n | Макс. смещение | Макс. поворот | Примечание |
|---|---|---|---|---|
| Ходьба, один цикл отложен (сессия 2, 9 циклов) | 1744 | 0.189 вокс. | 2.37° | p95 0.36°, среднее 0.012 вокс. |
| Ходьба: клип сессии 2 ↔ кадры сессии 3 | 752 | 0.164 | 2.01° | независимая сессия |
| Атака: два запуска сессии 3, равное время, > 50 мс | 72 пары × 8 частей | 0.041 | 0.21° | детерминизм |
| Атака: начало (< 50 мс) | 24 | 0.0003 | 17.6° | смешивание с предыдущей позой |
| Атака: клип ↔ кадры сессии 3, интерполяция | 2200 | 4.43 | 29.7° | удар: ~104° за 28 мс между соседними кадрами |

Вывод: Alpha воспроизводит позу детерминированно; разброс в «интерполяции» — следствие частоты съёма в самом быстром месте удара, а не неточности переноса.

## 7. Открытые вопросы

- **Волосы игрока**: меш Alpha 2244 вершины не совпал ни с одной `human-hair-*` (в т.ч. после исключения маркерных цветов) — модель/обработка волос не установлена (`PARTIAL`). Анимации не касается: матрица волос всегда равна матрице головы.
- **Тинт волос** по-прежнему не восстановлен (белая маска в Unity).
- **Точный `.cub` кистей/стоп/тела игрока** неоднозначен по числу вершин (десятки моделей с тем же счётом); для примера взят набор S05A-1.
- **Хвост атаки** зависит от наклона взгляда (§3.4); состояния 37/3 (продолжение комбо) сняты в черновом захвате, но клипы не собраны.
- Камеру Alpha не удалось повернуть автоматически (колесо/мышь не действуют), поэтому визуальное сравнение сделано с камеры сверху.

## 8. Для каких моделей технология подтверждена

| Тип модели / анимации | Статус | Основание |
|---|---|---|
| Человек (гуманоид 8 частей), покой | **ПОДТВЕРЖДЕНО** | захват + Unity PASS |
| Человек, ходьба (фаза, ввод удерживается) | **ПОДТВЕРЖДЕНО** | 9 циклов, 2 сессии |
| Человек, двуручная атака 57 (меч/топор/булава, подтипы 15/16/17) | **ПОДТВЕРЖДЕНО** (снято с булавой, применено к мечу; код выбора атаки и якоря одинаков для 15/16/17) | захват ×4, Unity ×2 |
| Тот же риг с другими моделями тех же частей (другие головы/тела/кисти) | **ОЖИДАЕТСЯ, НЕ ПРОВЕРЕНО** вне двух наборов | `J` не зависит от размера; проверены 2 набора оружия |
| Другие гуманоидные расы (эльф, гном, орк …) | **НЕ ПРОВЕРЕНО** | вероятно тот же путь `drawModel`, но масштабы/смещения головы могут отличаться |
| Комбо 37/3, бег, прыжок, блок, умения, лук/посох/одноручное | **НЕ ПРОВЕРЕНО** | нужен свой захват; для оружия других подтипов — своё правило якоря |
| Броня с наплечниками, предметы на спине, щит | **НЕ ПРОВЕРЕНО** | другие вызовы отрисовки (из 27), не размечены |
| Существа с 1–2 частями (дракон, слизень и т.п.) | **НЕ ПРИМЕНИМО без нового рига** | другой набор частей; захват возможен тем же инструментом (`--target`) |

## 9. Воспроизведение

```powershell
# 1. Alpha (локальная копия): вход в мир и захват
& tools\alpha_models\runtime\alpha_enter_world.ps1
& tools\alpha_models\runtime\alpha_capture_session.ps1 -Out D:\Projects\CubeGame\.scratch\s05a2\cap\session2.jsonl -Seconds 16
# 2. клипы
python -m tools.alpha_models.anim.alpha_clip build .scratch\s05a2\cap\session2.jsonl --out-dir .scratch\s05a2\clips --idle --walk --state 2 --action 57 --name attack_2h_a57
python -m tools.alpha_models.anim.alpha_clip compare .scratch\s05a2\clips\attack_2h_a57.alphaclip.json .scratch\s05a2\cap\session3.jsonl
# 3. Unity
& tools\alpha_models\transfer\run_transfer.ps1
# 4. тесты
python -m unittest discover -s tools/alpha_models/tests -t .
```

# S05A2-D58 (продолжение): от указателя существа к движению гуманоида

**Задача:** первая воспроизводимая оригинальная анимационная трансформация части человеческого
персонажа (SOCCO) в Unity. **Ветка:** `codex/s05a2-channel-binding`. **База:** `10ab05a` → `191518e`.

**Среда:** копия `Cube.exe` (`.scratch/alphatest2`), реконструкция `CubeWorld-Reversal`, собственный
ctypes-отладчик, Python 3.13.

## 1. Инструментарий: два дефекта устранены (DONE)

### 1.1 Восстановление байта при сбоях

`run_probe` переработан (`tools/alpha_models/runtime/drawmodel_probe.py`): запись `INT3`, цикл
отладки и восстановление байта обёрнуты в общий `try/finally`, поэтому исходный байт
восстанавливается **всегда** — включая отказ `DebugActiveProcess`, исключение в цикле и
нормальное завершение. `DebugSetProcessKillOnExit(FALSE)` + `DebugActiveProcessStop` вызываются
только если отладчик реально подключился; пропуск модуля (`exe_base → None`) обрабатывается без
записи байта. `kernel`/`base`/`module` инъектируемы — ядро можно тестировать без живого процесса.

### 1.2 Настраиваемый тестовый путь (PASS/FAIL/SKIP)

`test_model_read_scan.py`: путь к `Cube.exe` берётся из `CUBEWORLD_ALPHA_EXE` (иначе дефолт
`D:\Projects\CubeGame\.scratch\alphatest2\Cube.exe`). Файл отсутствует → `SKIP`, восемь чтений
найдены → `PASS`, иначе `FAIL`; состояния явно разделены.

### 1.3 Тесты аварийного завершения

`test_drawmodel_probe.py` (фейковое ядро kernel32, без живого процесса):
`restores_byte_on_debug_attach_failure`, `module_not_found_raises_without_writing`,
`clean_detach_sequence` (kill-on-exit до detach), `restores_and_detaches_on_loop_exception`.

Прогон: `python -m unittest discover -s tools/alpha_models/tests -t .` → **97/97 OK**.
Коммит `191518e`.

## 2. Поиск гуманоида — BLOCKED (диагноз)

Точка останова `0x12A42` (`movsx ecx, word ptr [eax+0x8c]`) работает: 800 снятий, 7 уникальных
существ, игра жива после отсоединения (`CUBE_ALIVE`). Но среди них **нет игрока**:

| существо | `+0x8c..+0x9a` (индексы → `data1.db`) | `+0x68` (тип) |
|---|---|---|
| `0x2DA06A60` | `bush`, `cactus1`, `cactus-potion`, `bunny-foot` | `0x00` |
| `0x2DA04B58`, `0x2D9FEE40` | `dragon-body`, `dragon-foot` (×2 дракона) | `0x00` |
| `0x2DA02C50` | `elf-hair-m01..m04`, `elf-hair-f10` (5 причёсок) | `0x00` |
| `0x22154550` | `silk-shoulder4-random1` | `0x00` |
| `0x32CE8A20` | `carpet2`, `carpet3`, `carrot` | `0x00` |
| `0x21C9DAF8` | `iron-mace1`, `entrance-mine`, `entrance-tomb`, `airship` | `0x00` |

Все сущности имеют тип `0x00` (`+0x68`), тогда как реконструкция рисует особые типы
(`0x11/0x5/0x14/0x30/0x5d`) отдельной веткой (`GameController.cpp` 50060–50120). Игрок, судя по
всему, **не отрисовывается в текущем состоянии мира**: его модели (`body1`=71, `glove`=537,
`foot`=472, `human-head-m01`=738, `human-hair-m01`=717, `iron-greatsword`=1109) не встречены ни в
одном из 800 снятий.

### 2.1 Причина (установлена по фактам)

* `alpha_walk6.ps1` (проверенный D57-скрипт навигации) выполняется `RESULT=ok frames=290`, но
  загружает мир с драконами/эльфом/NPC/пропсами, а не кадр с SOCCO — то есть «ок» скрипта не
  означает присутствие игрока.
* Поля внешности (`+0x14..+0x22`, `+0x40..+0x50`) у захваченных существ — мусор/нули, то есть
  предполагавшаяся в CODEX §7.1 раскладка appearance для живого существа не подтверждается.
* Плейер либо не заспаунен в текущей позиции камеры, либо рисуется иным путём/смещениями, которые
  по восьми полям `+0x8c..+0x9a` не опознаются.

### 2.2 Конкретный блокер

Отсутствует визуальная обратная связь (нельзя прочитать кадр), поэтому итеративная доводка
навигации меню идёт вслепую: состояние «главное меню/создание персонажа/мир» приходится
восстанавливать косвенно через точку останова и пиксели, что не даёт однозначного результата.
Это технический блокер навигации/состояния сохранения, а не поломка отладчика.

### 2.3 Указатель игрока найден (новое в этой сессии)

В `GameController_renderCreature` (`0x4A6B50`) локальный игрок лежит в глобале как
`*(int*)(gameController + 0x8006D0)` (`pThis[0x2001b4]` в декомпиляции); чтение — инструкция
`mov ecx,[edi+0x8006d0]` по адресу **`0x4A6B93`** (RVA `0xA6B93`), 9 таких обращений в функции.
Точка останова на этой инструкции даёт указатель игрока напрямую, без сканирования памяти.

Снято (backup4, после навигации): `gameController=0x1282F020`, `player=0x21FBEA30`, и у этого
объекта `+0x8c..+0x9a = [1246,1252,430,432,1]` = `iron-mace1`/`entrance-mine`/`entrance-tomb`/
`airship` — то есть тот же «набор пропсов», что снимается точкой останова `Creature_drawModel`.
Это прямо подтверждает: **игра находится на экране предпросмотра мира (главное меню), а не в
игровом мире**, и `pThis[0x2001b4]` в этот момент указывает на объект предпросмотра, а не на
существо SOCCO.

Дополнительно установлено расхождение навигации: меню (синие кнопки) в текущем окне
1936×1048 находится в полосе **Y≈130–520** (по пикселям окна), тогда как D57-клики
`(958,609)/(958,403)/(1114,462)/(1129,462)` бьют в Y 403–609, то есть ниже списка кнопок.
Поэтому прежние клики попадали в зону предпросмотра и не продвигали меню. Точная раскладка
кнопок (какой пункт = «продолжить/играть») требует визуального подтверждения, которого в этой
сессии нет.

### 2.4 Проверено: `alpha_walk6.ps1` НЕ загружает SOCCO

Прогон `alpha_walk6.ps1` (проверенный D57-скрипт) завершается `RESULT=ok frames=290`, но после
него точка `0xA6B93` по-прежнему даёт `player → +0x8c..+0x9a = [1246,1252,430,432,1]`
(`iron-mace1`/`entrance-mine`/`entrance-tomb`/`airship`) — тот же объект предпросмотра, а не
существо. Причина теперь ясна (§2.5): D57-клики били по «вертикальной» раскладке и попадали в
предпросмотр, а не по горизонтальным кнопкам меню.

### 2.5 Меню — горизонтальное; «Start Game» найден (исправление §2.3)

Прежний вывод о «вертикальном списке» был неверен. Код `StartMenuWidget` (`ui/StartMenuWidget.cpp`)
рисует **три горизонтальные** кнопки «Start Game» / «Options» / «Exit» на одной строке
(widget x=30/80/130, y=18; размер виджета 200×100). Эмпирически (развёртка X при Y=330): клик
`X=1200` закрывает игру → это «Exit»; следовательно «Start Game» ≈ `(500,330)`, «Options» ≈ `(800,330)`.

Клик «Start Game» `(500,330)` **переводит на экран выбора персонажа** (не-рендерящий, точка
`0xA6B93` даёт 0 попаданий). В памяти этого экрана найдены строки `1 Warrior`, `MP 7`, `HUM 37%`,
`Create Character`, `Back`, `Start` → это карточка SOCCO (LVL 1 WARRIOR). Осталось нажать «Start»
на этом экране (его точная позиция ещё не найдена; клики по низу карточки `(400,500…620)` не
сработали).

## 3. Что осталось для следующей сессии

1. **Нажать «Start» на экране выбора персонажа** (единственный оставшийся блокер): карточка
   SOCCO подтверждена (`1 Warrior`, `MP 7`, `HUM 37%`), кнопка «Start» есть в памяти, но её
   точная позиция не найдена. По клику «Start» **проверить точкой `0xA6B93`**, что
   `pThis[0x2001b4]` стал указывать на существо (а не на пропсы).
2. Как только `player=…` укажет на существо — прочитать его `+0x8c..+0x9a` (seed-производные,
   не обязательно `body1`=71), затем снять `local_16fc`/`local_15d8` (каналы матриц частей) в
   idle и ходьбе и прогнать через `CharacterPoseAdapter`.
3. `TRANSFERRED_FROM_ALPHA` не присваивать; `S05B`/`S04` не затрагивались; merge в `main` не выполнялся.

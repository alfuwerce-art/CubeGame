# S00-R02 / пакет J — подземелья, боссы, задания, награды (Alpha 2013)

**Проект:** CubeGame. **Этап:** S00-R02 (D41), партия 2.
**Источники:** `SRC-01`, `SRC-02`. **Проверено лично:** `dungeon_splitRegion_recursive` (`005c52a0`), таблица типов целей (`_library/crt_stl.cpp:5404-5477`), `creature_isBossType` (`004445d0`), чтение `mission<x>_<z>` (`deserialize_struct_0x28` `0044cb50`).
**Граница:** собственные описания и константы.

## J1. Подземелья

- Генератор подземелий физически находится в `World_populateRegionDecorations` (`005cc510`) — **имя в реконструкции ошибочно**. Вызывается из `WorldInfo_generateBiomeContent` (`005e4850`) при `kind == 3` (подтип берётся из записи структуры `+0x19`) и `kind == 5` (принудительно подтип 3). Подтипов **0…5**, у каждого свой жёсткий список связей комнат.
- Планировка: **решётка 3×3×3 комнат с шагом 7** (циклы `0…0x15`), дрожание позиций `rand()%3`, связи комнат заданы таблицами по 6 int (координаты A/B в 0…2).
- **Уточнение R01/B:** `dungeon_splitRegion_recursive` (`005c52a0`) — **не BSP**, а прорубание L-коридора с дверью между двумя боксами (до 3 сегментов, каждый с проходом 1–2 клетки по `rand()%2`).
- Клетка подземелья — **2 байта**: `[0]` тип (`0` пусто, `3` проход, `4` особое), `[1]` флаги (`|1` при прорубании, `|4` = точка спавна монстра). При записи применяются поворот (`+4`, 0…3) и зеркало (`+8`).
- Вход в подземелье — модели `overground-dungeon01` (0x980), `underground-dungeon01` (0x981), `entrance-stairs` (0x988).
- Освещение: в генераторе логики света/факелов **нет** (есть модели `torch.cub` 0x3ce/0x914, `door.cub` 0x3d5/0x944) → `UNKNOWN`.

## J2. Боссы

- Босс определяется **только по типу существа**: `creature_isBossType` (`004445d0`) — `+0x64 ∈ {0x65, 0x6b, 0x6c, 0x6d, 0x72, 0x73, 0x74, 0x75, 0x76, 0x77}`.
- Второй маркер — «хозяин подземелья»: `spawn+0x10E8 → creature+0x1d38`; цель типа 5 (подземелье) засчитывается только по существу с `+0x1d38 != 0`.
- Награда: опыт `max(1, curve_level05(level + quality)·20)`; для босса **×20** (итого ≈×400 от базы уровня), флаг `+0x7e & 0x200` → ×10, `0x800` → 0.
- **Деньги за убийство/цель не начисляются** — `+0x1304` меняется только продажей предметов (`+ item_valueByType()`).

## J3. Сундуки

- Сундук подземелья: `rand()&7 == 0` → спавн «вид 6, id 0x8f», уровень зоны; `World_applyDropTableToEntities` выдаёт **ровно 10** сгенерированных предметов (`vector<Item>(10)` + 10× `Item_generateStats`).
- Модели сундуков: `gold-chest` (0x4c7), `obsidian-chest` (0x4c2) и др.
- Важно: слово «Chest» в остальном коде — это **слот брони** (`ChestArmor`), а не контейнер; не путать.

## J4. Задания («миссии»)

- Задание **не выдаётся NPC**, а существует как запись **на клетку региона** (8×8 клеток на регион, запись `0x68` байт с базой `+0x14018`):
  `+0x18` id, `+0x24` уровень, `+0x25` вид маркера, `+0x34` тип, `+0x41` состояние (`0` спящая, `1` активная, `2` выполнено), `+0x44` прогресс, `+0x48` требуемое.
- Таблица типов (`cell+0x34`): `1` monster, `2` rareboss, `3` villagemonster, `4` villagerareboss, `5` dungeon, `7` invasion, `8` sceneryinvasion, `9` villageinvasion, `10` caveinvasion, `11` riverinvasion, `12` gang, `13` gangboss; `6` — нет цели.
- Жизненный цикл: создаётся генерацией мира → активируется по дистанции (состояние 0→1) → выполняется обработчиком убийства: типы 1…5 и 0xd — мгновенно; 7…0xc — счётчик до `+0x48`. Повторной выдачи/сброса нет. Звук завершения — `missioncomplete.wav` (id 0x1e).
- Гейт уровня подтверждён: `|cellLevel(+0x24) − playerLevel| > 2` → диалог с NPC отменяется (`GameController_interactNpc`).

> **Важное предупреждение (исправление трактовки).** Функции с именами `quest_*` в реконструкции **не про квесты**: `computeQuestScore` (`004df9c0`) — стоимость **респека 11 рангов навыков** (`Σ weight(level)·Δ·10 + 100·weight` при смене специализации), `questStateChanged` — детект изменения рангов, `quest_checkItemThreshold` — лимит стака (≤49), `quest_hasActiveItemReq` — список эффектов предмета. Это подтверждает вывод `D_character` §D5.3: прокачка в Alpha — **покупка за деньги**, а не «очки за уровень».

## J5. `mission<x>_<z>` (38 байт)

- Читатель — `deserialize_struct_0x28` (`0044cb50`): 4+4+4+4+4+1+1+4+4+8 = **38 байт** — это и объясняет размер записи.
- Ключ: `"mission" + x + "_" + z`, где `x = (cell + region·8)·0x800 + 0x80` — центр клетки; рядом `"monster" + x + "_" + z` (21 байт).
- Найден **только читатель** (загрузка состояния региона, флаг `+0x15a18`). Раскладка полей — гипотеза (тип / прогресс / требование / уровень / состояние).

## J6. Дома и точки интереса

- Дом: объект `0x74` байта, **всегда 3×3×4**, стиль в `+0x60` (1…5), клетки по 12 байт, мебель — жёсткие индексы моделей `0x88d…0x8ef`, `frame-house01.cub` = 0x8a2.
- Дома создаются только внутри генератора деревень `Chunk_generateObjects` (`005af170`).
- «Осмотреться» (scenery/explored): тип цели 8 (sceneryinvasion) и проверка колонки мира (`getVoxelColumn8(x>>3, y>>3)`, `+0x18 != 0`) — точное условие зачёта `UNKNOWN`.

## J8. FEATURE_ID

### FEATURE_ID: J1.dungeon-generation
CONFIDENCE: PARTIAL→STRONGLY_SUPPORTED (структура и константы), UNKNOWN (точные размеры объёма)
CUBEGAME_DECISION: PROPOSED — генерировать подземелья собственным алгоритмом (комнаты 3×3×3 — хорошая отправная точка), не копируя таблицы.
UNITY_MAPPING: own-game-logic; сборка сцены — пул `GameObject`/`Prefab`, свет — Unity Lighting.
GAPS: точные размеры объёма (аргументы `Dungeon::ctor_0` потеряны, косвенно 21×21×21); число «хозяев» на подземелье; свет/факелы.

### FEATURE_ID: J4.objectives
CONFIDENCE: STRONGLY_SUPPORTED (модель состояния и типы), PARTIAL (условия зачёта)
CUBEGAME_DECISION: PROPOSED — «цели на клетку региона» с состояниями 0/1/2 и счётчиком прогресса — простая и проверяемая модель; тип «подземелье» засчитывать по «хозяину».
UNITY_MAPPING: own-game-logic; UI — Objectives-виджет → UI Toolkit.
GAPS: кто активирует цель по дистанции (точный радиус), условия scenery/explored, награда за завершение.

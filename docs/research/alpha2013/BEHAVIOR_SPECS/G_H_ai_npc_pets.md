# S00-R02 / пакеты G+H — AI, NPC, питомцы (Alpha 2013)

**Проект:** CubeGame. **Этап:** S00-R02 (D41), партия 1.
**Источники:** `SRC-01`, `SRC-02` (коммит `e6e906e4`). **Проверено лично:** структура `Behavior`-vtable, ветки `CombatBehavior` (порог зелья 25 %, сброс агро 20 с), таблица иконок навыков (`pet-taming`/`pet-riding`), призыв питомца (фракция 3, лимит 2), таблица имён навыков.
**Граница:** собственные описания; декомпилированные тела не переносятся.

## G1. Дерево поведений

- Базовый интерфейс — **три слота vtable**: `[0]` тик, `[1]` **клон (deep copy)**, `[2]` деструктор с флагом. Клон нужен потому, что дерево живёт в шаблоне `Spawn+0x109c`, а у существа — его копия (`creature+0x13e4`).
- `SequentialBehavior` — композитор «ИЛИ»: перебирает детей, первый вернувший `true` «съедает» тик; если никто — обнуляет желаемую скорость существа (`+0x40/+0x44/+0x48`).
- `RandomInteractionBehavior` — **лист**, не композитор (опровергает распространённое предположение).
- Типичные сборки: горожанин/моб = `Sequential[Combat(20.0), LookAtPlayer, WalkPath(10.0), RandomWalk]`; игрок/питомец = `Sequential[Combat(20.0), Companion]`.
- **Тик ИИ — не каждый кадр**: аккумулятор `+0x13c4 += dt`, порог **31 мс (~30 Гц)**; при стане (`+0x12C ≥ 1`) тик полностью пропускается. Это важно для воспроизведения «отзывчивости» Alpha.

### FEATURE_ID: G1.behavior-tree
CONFIDENCE: STRONGLY_SUPPORTED
CUBEGAME_DECISION: PROPOSED — дерево данных + собственный раннер (не тащить сторонний Behavior Designer); клон через `ICloneable`-подобный метод.
UNITY_MAPPING: own-game-logic; навигация — `NavMeshAgent` (AI Navigation), анимации — `Animator`.
GAPS: смысл ряда служебных состояний (`'O'`, `'j'`, `'I'`, `'V'`, `'W'`, `'Y'`, `'H'`, `'l'`, `'_'`).

## G2. CombatBehavior (враг/моб)

Состояние и id атаки — **одно поле** `+0x68` (0…0x77); отдельного enum нет. Ключевые шаги тика (собственное описание):

1. Сброс «зависшего» состояния при `+0x6c > 10 000` мс.
2. Ранний выход при касте/уклонении (`+0x128 != 0`).
3. **Питьё зелья**: если `HP < 0.25·MaxHP` и таймер атаки истёк — берётся расходник из сумки `+0x11dc`, `state = 'P'`, прыжок в случайную сторону. (Это же — независимое подтверждение, что `stat_calcAttackDamage` = MaxHP, см. `D_character.md` §D4.2.)
4. **Цель** = топ угрозы из дерева `+0x13a4`; если нет — пересканирование сущностей региона с фильтрами (жив, не себе, фракция ≠ 5, приоритет своему уровню через `pow(1.5, levelDiff)`).
5. **Дистанция остановки** = `2·r_self + r_цели` с модификаторами 10/20/50 по типу/состоянию.
6. **Скорости**: 80 м/с далеко, 40 м/с близко (в собственных единицах сценария), путь — до 10 итераций поиска и 50 узлов.
7. **Затухание угрозы**: `threat[target] *= 0.9` за тик — из-за этого агро «остывает», если цель не бьёт.
8. **Сброс агро**: если цель недостижима > 20 с — дерево угрозы очищается, пересканирование через 3 с.
9. **AI-додж**: `rand()%10 == 0`, не босс, радиус < 2 → кувырок в одно из 4 направлений, `+0x128 = 600` мс.
10. **Серия ударов**: счётчик комбо `+0x70` < 5 → замах (`state 'n'`); иначе «финишер» с двумя записями удара (тип 8 и 20 000 мс).
11. Спец-ветки по типу существа (0x65, 0x74, 0x76, 0x77, 0x2f/0x6f/0x70/0x71) — списки атак, часть собирается из экипировки.
12. Вода/полёт — отдельные ветки с дистанцией 60 м и круговым стрейфом (cos/sin, радиус 1.5).

CUBEGAME_DECISION: PROPOSED — сохранить «затухание угрозы», «сброс агро», «додж по вероятности», лимит узлов пути; списки атак — данные.

## G3. Питомцы (пакет H)

- `CompanionBehavior`: владелец — пара id `+8/+0xc`; поиск владельца в дереве региона.
- **Скорость**: 5 «единиц» обычный догон; при отставании — 30 (нормализация + ×30). **Телепорта при отставании нет** — отрицательный результат, проверено чтением функции.
- **Реген**: у фракции 5 (дружелюбные) `HP += MaxHP · 0.10/с` с клампом.
- **Призыв** (способность id `0x5c`): фракция `3` для игрока, **лимит 2 уже призванных**, HP = MaxHP, дерево `Sequential[Combat, Companion, RandomWalk]`, `+0x198/+0x19c` = id игрока.
- **Приручение**: отдельных функций `tame/food` нет. Есть навыки с id 0 и 1 (`pet-taming.png`, `pet-riding.png`) и модели `pet-box.cub`, `egg1.cub`. Механика приручения — `UNKNOWN` (кандидат: применение предмета к существу).
- **Езда**: только состояние `'R'` + поля `+0x1020 == 0x14`, `+0x1021` и поза `(0.8, 0, 0.5, 1)`. Функции «посадить/спешиться» не найдено — `UNKNOWN`.

## G4. NPC, город, расписания

- `SpawnLocationBehavior`: записи точек (stride `0x20`) с полем **времени**; выбирается последняя запись с `time <= worldTime`; при смене — «домой»; по достижении пишется «точка спавна» `+0x1c0…+0x1d4` (её же использует `RandomWalkBehavior` как «поводок»).
- `WalkPathBehavior`: патруль по точкам (stride `0x18`), пауза `rand()%4000 + 2000` (2…6 с), до 21 попытки найти проходимую точку.
- `RandomInteractionBehavior`: подходит к объектам типов **16/18/68** (мебель/кровати — `HYPOTHESIS`), состояния `'S'/'T'` (сон/отдых, реген 5 %/с), и **расписание**: при `worldTime` вне `[21 600 000, 82 799 999]` (6:00…23:00) используется один набор точек, иначе другой.
- `LookAtPlayerBehavior`: находит ближайшего игрока в радиусе 8, поворачивает «взгляд» (`+0x160/+0x164/+0x168`).
- Диалоги: `GameController_interactNpc`; «innkeeper» — тип сущности `0x84`; **гейт квеста**: если уровень региона отличается от уровня игрока более чем на **2**, точка квеста отбрасывается. Торговля — вкладка инвентаря `Vendor`; цены — `computeCraftPrices` (`PARTIAL`).

## G5. Спавн мобов

- `World_generateNpcSpawnList`: **30 строк уровней**, уровень строки из обратной кривой `curve_inverse20p1`, запись 0x118 байт.
- **Звёзды**: `+1` с шансом 1 %, ещё `+1` с 0.1 %, ещё `+1` с 0.01 %, **кламп 4**. Это ключевое правило «редкости элит».
- Лимит живых мобов в регионе **не найден** (`UNKNOWN`).
- Лимиты пути: 50 узлов, 10 итераций на тик.

## G6. Тексты и квесты

- `Speech` грузит словарь из `data4.db` (`dict_<lang>.xml`), деобфусцирует блоб, парсит XML в наборы строк и шаблоны `QuestText`.
- `QuestText::parseTemplate` — самодельный шаблонизатор: `{}` — группа (kind 2), `[]` — группа (kind 3), `|` — альтернатива, `}` закрывает два уровня, `]` — один; токены `#name` и `$name` — два разных набора подстановок; пунктуация — отдельные узлы.
- `generateQuestText` детерминирован seed'ом точки квеста (`srand(point.seed)`).
- **Типы задач**: `scenery`/`explored` (осмотреться), `creature`/`food`/`petfood` (существо/еда/корм), `itemvendoritem` (5 вариантов предмета у вендора), `monster` (11 id), `random:1..30`.
- Цена «прокачки»/квеста — `computeQuestScore`: `Σ pow2(level)·Δ·10` по 11 счётчикам + бонус за смену специализации.

### FEATURE_ID: J6.quest-text
CONFIDENCE: STRONGLY_SUPPORTED (грамматика), PARTIAL (семантика подстановок)
CUBEGAME_DECISION: PROPOSED — не копировать самодельный шаблонизатор; использовать собственный шаблонный движок (или Unity Localization) с теми же **возможностями** (группы, альтернативы, подстановки).
UNITY_MAPPING: `Localization` package (если разрешат) или собственный резолвер строк; UI — UI Toolkit.
GAPS: что именно подставляется в `#`/`$`; полная таблица `monster`/`random`.

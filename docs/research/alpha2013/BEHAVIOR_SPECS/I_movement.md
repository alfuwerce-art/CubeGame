# S00-R02 / пакет I — движение, физика, камера (Alpha 2013)

**Проект:** CubeGame. **Этап:** S00-R02 (D41), партия 2.
**Источники:** `SRC-01`, `SRC-02`. **Проверено лично:** фрагменты тика `GameController_updateSubsystems` (`0060c510`), обработчик ввода `004a6b50`, `Options`-функции.
**Граница:** собственные описания и константы; тела функций не переносятся.

> **Главное ограничение пакета:** почти все тела движения деградированы в псевдокоде (потеряны аргументы и регистры), а **масштаб float-единиц скорости → блоки/с не восстановлен**. Поэтому числа ниже — `DIRECT` как константы, но их перевод в «блоки в секунду» остаётся `UNKNOWN` (см. §I7, U1). Без него нельзя честно заявить «скорость бега как в Alpha».

## I1. Гравитация и вертикаль

| Величина | Значение | Статус |
|---|---|---|
| Гравитация | **30.0 ед/с²** (`velY -= dt·30`) | DIRECT |
| «Планирование» (дельтаплан/падание с флагом `+0x7e&2`) | **3.0** (0.1 × 30) | DIRECT |
| Подъём/всплытие | `velY = min(sqrt(vx²+vz²) + 2, 10)` + накопление `+0.001/мс`, затем `+0.08/мс` до потолка **10.0** | PARTIAL |
| «Жёсткое приземление» | определяется флагом `+0x124&0x10`, `velY ≤ 0`, «на земле», нет стана | PARTIAL |

## I2. Скорости: не «ходьба/бег», а цепочка множителей

База **6.0** → босс **8.0** → существа с `+0x60 == 5` **12.0** → **игрок 20.0** → спринт **×2.0** (флаг `+0x124&0x40`) → состояния атак **40 / 50 / 60 / 8 / 0.1 / 0** → у стены **×0.5**, бафф **×1.5**; затем жёсткий кламп `|v_xz| ≤ множителя`.

Те же множители используются и для AI: `CombatBehavior` задаёт 40 (близко) / 80 (далеко), `CompanionBehavior` — 5 и 30 при отставании (`G_H` §G3). Это подтверждает: «скорость» в Alpha — это **одна шкала множителей**, а не отдельные константы на действие.

## I3. Ввод → движение

- 4 цифровых направления (`GC+0x0b…0x0e`) и две аналоговые оси (`GC+0x124`, `GC+0x128`, формат 15.16 → деление на 32768) дают **добавку** к скорости по направлению камеры.
- Масштаб добавки: **80**, при жёстком приземлении — **8**.
- **Рывок (dash)**: импульс 40 по горизонтали + 5 вверх, таймер **600 мс**, цена **0.25** стамины.
- Состояние персонажа хранится в `+0x68` (id, ~40 значений), таймер — `+0x6c` (мс).
- Флаги контакта `+0x5c` пересчитываются каждый тик: `1` на твёрдом блоке, `2` в воде, `4` упор, `0x10` воздух над головой.
- Флаги действий `+0x124`: `0x1` лазание, `0x10` воздух/дельтаплан, `0x40` спринт, `0x200` факел, `0x400` прицел.

## I4. Стамина

- Шкала `+0x1194` = 0…1: спринт −0.0002/мс (≈5 с), реген +0.0001/мс (≈10 с), рывок −0.25.
- Вторая шкала `+0x1190` (0…1, ±0.0005/мс) — связана с «равновесием/выносливостью» (см. `E_combat` E1).

## I5. Спецспособы перемещения

| Режим | Как включается | Что меняет |
|---|---|---|
| Плавание | навык `SkillSwimming` = 4, стат `@swimmingspeed` | множитель скорости × `curve_diminishingHalf`; подъёмная сила `30 · погружение` |
| Лазание | `SkillClimbing` = 2, `@climbingpower` | × `curve_diminishingN1`, расход стамины |
| Дельтаплан | `SkillHangGliding` = 3, `@flyingspeed`, предмет `HangGlider` (тип 0x17, подтип 0) | гравитация 3.0 вместо 30, × `curve_diminishingx3p15` |
| Лодка | `SkillBoatDriving` = 5, предмет `Boat` (0x17/1) | механика **не найдена** (`UNKNOWN`) |
| Езда | `SkillPetRiding` = 1 | механика **не найдена** (`UNKNOWN`) |

Важно: режимы — это **навыки с рангами** (система `0x1138`), а не отдельные кнопки. Ранг масштабирует эффективность через общие кривые.

## I6. Камера

| Параметр | Значение | Статус |
|---|---|---|
| FOV_Y | **50°**, при прицеливании (`+0x124&0x400`) — **30°** | DIRECT |
| Near / Far | **0.1 / 2000** | DIRECT |
| Pitch | `GC+0x1B0`, в градусах, кламп **0…180** (90 = горизонт) | DIRECT |
| Yaw | `GC+0x1B8`, старт **180°** | DIRECT |
| Мышь | `yaw/pitch ±= cameraSpeed · 0.005 · dt` (при `cameraSpeed = 50` → 0.25°/ед.) | DIRECT |
| Инверсия Y | опция `invertY` (`+0x194`) | DIRECT |
| Зум | `GC+0x1C0`: ±2 за шаг колеса, кламп **0…14**, по умолчанию **5.0**; альт-режим мультипликативный (×0.9, кламп 0.01…10) | DIRECT |
| Сглаживание зума | `1 − 0.99^dt_ms` | DIRECT |
| Коллизия камеры | **не найдена** (все raycast-вызовы — прицел/снаряды/движение) | STRONGLY_SUPPORTED (отрицательный результат) |

Положение: yaw используется и для направления движения. Точная дистанция/высота камеры от зума — `UNKNOWN` (U3/U4).

## I7. options.cfg ↔ код (сопоставлено)

Индексы 0…11: `fullscreen, resolutionX, resolutionY, antiAliasing, renderDistance(=50), soundVolume(=100), musicVolume(=100), cameraSpeed(=50), cameraSmoothness(=80), invertY(=0), language(=0), minTimeStep(=9 мс)`.
`cameraSpeed` читается как `GC+0x18C`, `invertY` — `+0x194`, блок опций — `GameController+0x170`. Функция `0046f390` (в реконструкции названа «set_camera_transform») на деле применяет опции — имя ошибочно.

**Замечание:** `cameraSmoothness` в восстановленном коде нигде не читается (`UNKNOWN`, U2) — то есть сглаживание камеры, вероятно, реализовано иначе или в невосстановленном участке.

## I8. Коллизия

- **Воксельная swept-коллизия**, не капсульная: шаг ≤ 1 единицы по 16.16-позиции, пробы ±1 блок; твёрдость: `(blockType & 0x1F) != 0 && != 2` (2 = вода). Позиция сущности в сейве — тройка `int64` с компонентами 0/1/2; по данным `map` компоненты 0/1 — кандидаты горизонтали, компонент 2 — вертикали, но порядок x/z не доказан (OQ-22).
- `World_raycastVoxels` (`005a35d0`): сетка 256 ед./блок, ≤ 500 шагов. `Entity_stepToward` (`0059ee90`).
- Отдельных порогов «высота капсулы», «step-up», «slide» в восстановленном коде **нет** (`UNKNOWN`, U9/U10) — следствие воксельной модели: персонаж скользит по осям.

## I10. Unity-маппинг

| Требование Alpha | Unity 6.3 builtin | Own code |
|---|---|---|
| Воксельная коллизия с шагом и «упором» | `CharacterController` (капсула + `stepOffset`/`slopeLimit`) или `Rigidbody`+`BoxCollider` на чанк | решение: для CubeGame **не** повторять swept-воксель; проверить `CharacterController` на воксельном меше и замерить |
| Гравитация 30 / планирование 3 | `Physics.gravity`, `Rigidbody.useGravity` | режимы и множители |
| Скорости-множители | `CharacterController.Move`, `NavMeshAgent.speed` для NPC | таблица множителей и состояний |
| Спринт/стамина | — | ресурс и правила расхода |
| Камера (FOV 50/30, pitch 0…180, зум 0…14) | `Camera` (или Cinemachine после отдельного решения) | правила, сглаживание, прицел |
| Ввод | `Input System` (новый) | действия и биндинги |
| Дельтаплан/плавание/лазание | — | собственные режимы поверх `CharacterController` |

**Не переносить:** воксельный swept-код, ручной raycast по сетке 256 ед., камеру на «углах» — в Unity это решается стандартными средствами; логика режимов и множителей — наша.

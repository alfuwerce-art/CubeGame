## B1. Единицы и координаты (исправление гипотезы R01)

> **Исправление к R01 (`GENERATION_MOVEMENT_SPEC.md` §1).** R01 утверждал «1 блок = 65 536 единиц». Это верно только для **одной грубой единицы** (16.16 от 256-сетки): у рельефа и сеток — **256 единиц на блок** (`0x100`), а позиция сущности в raw — **2^24 единиц на блок** (`256 · 65 536`, см. `0x1000000`). Обе системы сосуществуют, и смешивать их нельзя.

| Величина | Значение | Доказательство | Уверенность |
|---|---|---|---|
| Грубая мир-единица (рельеф, сетки) | **256 на блок** (`0x100`) | `regionX·0x4000` при регионе 64 блока → `0x4000/64 = 0x100`; шаг `0x800` = 8 блоков; `+0x1000000` = 1 блок в 16.16 (`gc:88026, 88058, 88087`) | DIRECT |
| Точная единица (сущности, props) | **65 536 на грубую единицу; 1 блок = 256 · 65 536 = 2^24 raw** (16.16 от 256-сетки) | сборка пары `x<<16` в `world/WorldInfo.cpp:8200-8203, 8297-8300`; `__alldiv(...,0x10000)`, затем `>>8` (÷256) в `gc:88087-88093`; `+0x1000000` = 1 блок (`gc:88026, 88058, 88087`) | DIRECT (единица), PARTIAL (семантика конкретного поля) |
| Регион | **64×64 блока**, шаг `0x4000` грубых единиц | `world/WorldInfo.cpp:851-864` (`x>>6` — регион, `x&0x3f` — блок); `gm:47321-47325` (`>>0xe`) | DIRECT |
| Сетка регионов | **1024×1024** (`0x400`), массив указателей `world+0xbc + (rx·0x400+rz)·4` | `gc:87957-87959`, `world/WorldInfo.cpp:853-854` | DIRECT |
| Мир | **65 536×65 536 блоков** (0…65535) | границы `<0x400` регионов × 64 блока; проверка `<0x10000` в `world_getRegionCell64` | DIRECT |
| «Voxel column 8» | **8×8 блоков**, 64 записи по `0x68` на регион | `gc:8294-8295` (`>>0xb` = 8 блоков); `world/WorldInfo.cpp:1551-1559` (индекс по `&7`) | DIRECT |
| «256-клетка» (chunk-cell) | **256×256 блоков**, сетка `Field[65536]` по `0x20` Б (2 МБ) | `gc:12661` `(bx + bz·0x100)·0x20 + base`; `ChunkBuffer.cpp:705`; `world/WorldInfo.cpp:251,254` | DIRECT (формула), HYPOTHESIS (имя) |

Следствие для CubeGame: **не** копировать fixed-point; достаточно целочисленных блоков + `Vector3` на границе представления. Но если когда-нибудь понадобится сверка с Alpha по координатам, нужно помнить про две единицы.

## B3. Шум (проверено лично)

`perlinNoise2D_cosInterp` (`004c0ef0`) — **не классический Perlin**: value-noise на хэшированной решётке.

1. Узлы: `h = (i + j·0x39)`; затем `h ^= h·0x2000` для каждого из 4 узлов.
2. Значение узла: `v = 1 − (((h²·0xEC4D + 0x131071F)·h + 0xD208DD0D) & 0x7FFFFFFF) · 2^−30` → диапазон `(−1, +1]`.
3. Интерполяция — **косинусная**: `w = (1 − cos(frac·π))/2` по обеим осям, билинейно.

Проверка: прочитал `GameController.cpp:53853-53889` — константы и структура совпадают с описанием. Это **портируется 1:1** (~30 строк C#), если понадобится бит-совместимый рельеф.

## B4. Форма рельефа (`generateBiomeContent`, `005e4850`, фрагмент `WorldInfo.cpp:1639-1729`)

1. `base` — из климат-клетки региона/соседей (`World_getRegionCellPtr`).
2. `m` — «гористость/масса» 0…1.
3. Две «складки» (ridge): `a = noise(x·0.04+432, z·0.08+432)`, `b = noise(x·0.08+432, z·0.08+432)`; `r1 = 1−|a + 0.05b|`; `r1 = 1−r1³`; `t1 = r1²`. Аналогично `c,d` (смещения 4234/234, 423432/54352) → `t2 = r2² + t1`.
4. Для особых клеток (типы 0xC/0x1A) — «купол»: `d2 = 1−dist²`; `k = 1−(1−(2·d2)²)²`; `bump = smoothstep(noise(x·0.01+985, z·0.01+98584)·1.3+1)·k·0.4`.
5. `height = ((noise(x·0.01+34432, z·0.01+8992) + 1.5)·60)·m + t2·8 + base`; `surfaceY = int(height)`.
6. Кромки/плато — ограничение `±1` от `base + 20·noise` и `smoothstep((1−frac)⁷)`.

Константы (432, 4234, 423432, 54352, 34432, 8992, 985, 98584, 234, 60.0, 8.0, 0.4, 1.25) — `DIRECT`; **порядок** операций — `PARTIAL` (Ghidra местами потеряла `ftol`/float-переменные). Численно «в лоб» не воспроизводить.

Вторая функция (`WorldInfo_sampleTerrainHeight`, `005f9340`) — «лёгкий» сэмплер для размещения объектов: `h = |n1(x·0.01, z·0.01)·0.1 + n2(x·0.001, z·0.001)|·((n3+1)·0.1+0.8) + max(0, (1−0.75·findNearestObject)²·0.05) + «купола» + base`.

## B5. Вода

Уровень воды **не глобальная константа**: он хранится в 256-клетке: `cell+0x10` — поверхность (Y), `cell+0x1C` — мощность слоя, `cell+0x18` — массив материалов по слоям. Правило: `y < +0x10` → вода; `+0x10…+0x10+0x1C` → материал из массива; выше — воздух; ниже — камень по умолчанию.
`DIRECT` для чтения (`WorldInfo.cpp:1903-1922, 5511-5527`, `ChunkBuffer.cpp:664-751`); **где вычисляется `+0x10` — `UNKNOWN` (U3)**.

## B6. Пещеры

Если `surfaceY > roof`, где `roof = base + (noise(x·0.01+435, z·0.01+847)+1)·20`, вырезается слой между «полом» (`base + t2·width·6 + noise`) и `roof`; переход плавный по `f = (surfaceY−roof−20)/10`, маска «пузырей» `1−|n|⁴`; для крутых колонок (`>0.5`) ставится материал 6. `PARTIAL`, константы `DIRECT`.

## B7. Seed и PRNG (важно для воспроизводимости)

- PRNG — CRT `rand()` (LCG `state = state·214013 + 2531011`, результат `(state>>16)&0x7FFF`).
- Мастер-сид → `srand(master)`; далее `rand()%100000` в поля: seed мира `+0x800188`, сдвиги шума `+0x800168/16C/170/174` и ~20 таблиц `+0x80018C…+0x8001E0` (`crt_stl.cpp:11431-11459`).
- **Три независимых потока** (каждый переинициализирует `rand`):
  1. `srand(seed + rz·0x400 + rx)` — при создании региона (`gc:87971`, проверено лично);
  2. `srand(seed + z·0x10000 + x)` — при генерации контента 64×64 (`WorldInfo.cpp:1531`);
  3. `srand(rx + 0x108A + rz·0x400 + seed·3)` — климат-клетка региона (`gc:87676`).
- Следствие: воспроизвести мир Alpha можно только повторив **все три** потока в том же порядке вызовов. Для CubeGame это **не требуется** (см. B12), но объясняет, почему «один seed → один мир» в Alpha хрупок при многопоточности.

## B9. Структуры

- **Dungeon**: сетка `sx·sy·sz` по **2 Б** на клетку; нарезка 3D-BSP `dungeon_splitRegion_recursive`: если A и B пересекаются по X — режут по `mid = B.size/2 + B.pos` (кламп в границы A), иначе по Y; «джиттер» стенок `rand()&1`. `DIRECT` для алгоритма, `HYPOTHESIS` для разложения 2 байт.
- **House**: сетка по **0xC Б** на клетку + 6 векторов частей; правил постановки в этих файлах нет (`UNKNOWN`).
- **Повороты структур**: 4 ориентации через `param_3 & 3` + swap осей по `&1`; footprint проверяется против 256-клетки и уровня поверхности.
- **Spawn**: только шаблон существа (радиус `200.0f`, дефолты внешности); правил размещения в `Spawn.cpp` нет.
- **«Что растёт»** (`scatterObjectsInArea`, `005f56c0`): ветвление по влажности/температуре/уровню; полная таблица — ~660 строк кода, требует отдельной выгрузки (U6).

## B10. Стриминг, сериализация, карта

- **Стриминг**: `WorldInfo::ctor_0` — фактически кадровый апдейтер (не конструктор): раз в ~1000 мс освобождает регионы дальше порога (`|dx| < 3`, `< 5` регионов), вызывая `destroyBlockObjectAt` → `destroyCellObject` → `freeCellPtr`. Всё под двумя `CRITICAL_SECTION` (`world+0x8000c0`, `+0x8000d8`). `world+0xb4` — флаг «клиент/сервер».
- **Сериализация региона** (`deserializeRegionChunk`, `0044cdb0`): поток → поле `int32`, `count`, далее записи: `0x118` Б «entity state» + `0x18` (3×8: две 16.16-позиции + float) + `int32×3` + `byte`; принимаются записи с `0 < id < count_types−3`; второй блок — `count2` записей по `0x14` Б. `PARTIAL` (поля читаются, семантика нет).
- **`World_serializeCellData` (`005f6e20`) — не сериализация**, а «посев» декора: `rand()%0x32==0` → редкое событие; иначе `rand()%3` выбирает вид объекта; масштабы 2.0/1.0/1.57; варианты 0xC…0xF со смещением ±1 блок.
- **Меш/AO/свет**: `ChunkBuffer::ctor_0` (`0049d910`) — обход 256-клеток, отсечение скрытых граней, AO по соседям (`004c1510`), заливка солнечного света от `0xFF` вниз (`0059a0e0`). `PARTIAL`.
- **Карта**: два массива 1024×1024 по 4 МБ (тип тайла / «открыто»); спрайты `map-tile-*.cub` (`plains/village/forest/mountains/hills/skull`); сохранение — blob с ключом **`"discovered"`** в БД мира; после записи поле обнуляется; именованные метки — RB-tree `(x,y) → wstring`; имена регионов генерируются процедурно (слоговые таблицы).

## B12. Что это значит для CubeGame

1. **Не копировать бит-в-бит.** Лицензионно (закрытые ассеты/код) и практически (деградированный псевдокод, U1–U10) это невозможно и не нужно. Нужна **похожая по ощущениям** генерация: та же иерархия ощущений (регион 64 блока ≈ «локальный биом», 256-клетка ≈ климатическая зона), те же принципы (value-noise + ridge + климат), но собственные константы и собственный PRNG.
2. **Seed-иерархия** — обязательна: мастер-сид → регион → клетка, каждый со своим экземпляром RNG (никакого общего `UnityEngine.Random`). В Alpha это три CRT-потока; в CubeGame — `Unity.Mathematics.Random` с явными ключами.
3. **Вода per-cell**, а не глобальный уровень — важное отличие от типичных voxel-движков; при переносе это решение надо принять осознанно (продюсер).
4. **Карта** = битовая маска «исследовано» + тип тайла по биому + именованные метки; сохраняется отдельным blob'ом.
5. **Рендер-часть Alpha не переносится**: меш-билдер, AO и sunlight-заливка заменяются Unity Mesh API + Jobs/Burst (см. `UNITY_REUSE_MAP.md`).

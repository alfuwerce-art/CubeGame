## 2. Что найдено в Alpha (N-21)

Серверный тик `GameController_updateSubsystems` `Server.exe 0x5322D0` (decomp ≈ строка 2160): существо с ролью ≠ 0 и ≠ 5, живое, **удаляется**, если ни в его списке угроз нет игрока ближе 512 блоков (`262144 = 512²`), ни ближайший игрок не ближе `creature+0x1D2C + 20` блоков. Смысл поля `+0x1D2C` не установлен → правило записано, но не перенесено; радиусы C6 — `CUBEGAME_CONTRACT`. Лимит живых (N-20) и время повторного появления убитых — не найдены.

## 4. Codex (D89) — основная рука NPC и уточнение N-21

`SpawnDefinition.MainHandWeapon` передаёт доказанный raw ID основной руки из записи спавна
в `CreatureCombatDriver`. Тип 3 даёт ИИ тип и подтип для C-29 и проверки R-2. Пустое поле
и другие типы оставляют безоружную ветку. `Equipment` остаётся перечнем предметов. R-1
требует источника доказанных назначений оружия конкретным NPC.

N-21: в байтах `Server.exe` значение `Creature+0x1D2C` инициализируется числом 200.0
(`0x4068CC`) и может переопределяться из записи спавна `+8` (`0x535F1B`).
`0x534044` читает это поле для порога удаления из §2. Радиус по умолчанию получается
220 блоков. До переноса правила остаются разбор значений в записях спавна и исключение по угрозе.

Проверка `FullM0CreatureAiTests` 7/7 в Unity EditMode. Три кейса покрывают отсутствие
предмета, предмет другого типа и оружие. Сценовая проверка P17 отложена по D88.

## 5. Codex (D89) — дома и записи W-18 в игровом мире

Новые миры получают `cubegame.alpha_terrain/5`. Генератор вызывает `AlphaZoneContentProvider`
после рельефа. Дома D3 входят в воксельные колонки и используют те же меши и коллизии, что рельеф.
Сохранения с `/4` выбирают прежний генератор по записанному идентификатору. Оба варианта хранят
его в существующем `generatorId`.

`D3ZonePopulation` передаёт записи W-18 в канал 1. Статичные записи проходят через визуал,
боевые — через существующий драйвер ИИ и Core. Записи домов остаются геометрией. Канал 0
сохраняет отдельный источник D1. Состав кандидатов берётся из каталога, поэтому установка
локальных моделей не меняет сгенерированный мир.

Вход W-18 исправлен по `Cube.exe 0x5EB27B…0x5EB2B2`, `0x5EB46C…0x5EB48C`.
Третий аргумент — первый воксель воздуха или воды при проходе от основания колонки, а не
уровень существа. Вход приближён выборкой в центре зоны. На проверенной поверхности W-18
выбирает существ. Пассивный маршрут используется при наличии статичной записи. Позиции и
плотность сохраняют статус `CUBEGAME_CONTRACT`, форма дома — реконструкция D3.
Сервисы города, сундуки и входы в данжи остаются отдельными стыками.

Unity EditMode `FullM0PopulationTests` 8/8. Проверены обе версии в файле слота, наличие
крыши дома в `/5` при прежнем рельефе `/4`, выгрузка и повторное заселение с теми же ID.
Сценовая проверка P19 отложена.

## 6. Codex (D89) — координаты данжа D3

Провайдер данжей запрашивал 27 комнат при пределе 25 и строил план от мирового
нуля. Теперь допустимый лимит берётся из планировщика, сетка центрируется в
выбранной зоне, а якоря комнат и сундуков используют высоту вырезанного прохода.
Правило глубины `CUBEGAME_CONTRACT` оставляет один воксель до самой низкой
поверхности над планом. Точный алгоритм размещения Alpha ещё требуется подтвердить.

Unity EditMode `AlphaDungeon` 12/12. Регрессия на зоне `(32810, 32810)` сравнивает
колонки до и после вырезания и проверяет, что записи сундуков внутри комнат.
Игровой выбор зон данжей, входы, открытие сундуков и лут остаются отдельными стыками.

## 7. Codex (D89) — совместимость после слияния регистрации D3

Первый полный прогон после слияния `8854ed8` выявил, что старый генератор `/4`
забирал провайдеры из глобального реестра. После теста регистрации старый мир
получал шесть записей заселения в контрольной зоне. Фабрика `/4` теперь строит
генератор рельефа без провайдеров. Тест проверяет это при заполненном реестре
и восстанавливает состояние после проверки. `/5` использует свой явный набор.

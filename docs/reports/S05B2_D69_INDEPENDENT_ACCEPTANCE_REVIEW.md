## 1. Независимое техническое ревью

### 1.1 Пассивные объекты и растительные монстры
* Собственный проход по всему `.text` `Server.exe` (Capstone, `skipdata`) — все записи фракции 6
  (`mov dword [r+0x28], 6` / `mov byte [r+0x60], 6`): **10** мест; в доказательствах D69 было **6**.
  * `0x5066F5`, `0x506A5A`, `0x506DC6` — ещё три места спавна вазы `0x8F` той же формы (новое, не меняет вывод).
  * `0x5270B4` — **чучела-мишени**: `cmp [ebp+0x18],0xa` / `setne al` / `add eax,0x8d` / `mov [edx+0x2c],eax` →
    вид `0x8D` (Aim) или `0x8E` (Dummy) с фракцией 6. D69 относил их к `SAME_OBJECT_CLASS` (политика);
    теперь это `ALPHA_CODE_SPAWN`. **Исправлено** в `catalog/spawn_roles.py` + `spawn_role_evidence.json`
    (`SPAWN_ROLE_RESULT=PASS passive_kinds=26`), тест обновлён: доказано 22 = растения 0x78–0x80, 0x82;
    руды 0x83–0x85, 0x87–0x8A; 0x8C, 0x8D, 0x8E, 0x8F, 0x90; по политике 4 = `0x18` Egg и `0x81` FirTree
    (правило продюсера D67), `0x86`, `0x8B` (семейство руд). Для этих четырёх в `Server.exe` нет ни одной
    непосредственной записи вида (проверено поиском `mov [r+0x2c], imm`).
* Потребители фракции 6 подтверждены: `0x5360AE cmp byte [esi+0x60],6 / je 0x53612A` — пропускаемый блок
  содержит `call 0x41CB90` (конструктор `RandomWalkBehavior`); `0x53E2A8 cmp byte [esi+0x60],6 / je 0x53E357`.
* Игровое решение не изменилось: 26 видов `STATIC_OBJECT`, матрица 1438 строк с прежними счётчиками
  (KEEP 990, DISABLE_IN_GAME 234, ADD_MISSING 212, FIX 1, UNKNOWN 1). Меняется только основание 0x8D/0x8E в тексте.
* **0x45–0x49** (PlantCreature, RadishCreature, Onionling ×2, Devourer): `spawn_roles.game_policy` → `CREATURE`;
  в матрице у каждого 5 действий `TRANSFERRED`, 2 `KEPT`, 1 `DEFERRED_TO_M0` — действия не выключены.
  В `Server.exe` нет записи фракции 6 рядом с этими видами.

### 1.2 Dragon 0x65
* `DragonEndToEndTests` (в прогоне 337/337): итоговая матрица каждой части, собранная из данных Unity
  (`T(-якорь) · J · P`, якорь `head_0x65 = (sx/2, sy·0.2, sz/2)`), совпадает с матрицей исполненного
  `drawModel` оракула для 2 состояний опоры × 3 фаз/амплитуд, ошибка < 1e-3 вокселя / < 1e-2°.
  Зеркало правила в C# (`AlphaRig.Anchor`) сверено тестом по исходнику.
* Отсутствие крыльев — по коду D69 (`dragon-wing.cub` только загружается); новых доказательств обратного
  нет → не дефект.
* Unity: `sides_0x65_s0-0_actions.png` — голова на месте, не вдавлена. **Наблюдение:** между туловищем и хвостом виден зазор. Это не дефект переноса: тест сверяет итоговую матрицу **каждой** нарисованной части, включая хвост, с исполненным `drawModel` Alpha (ошибка < 1e-3 вокселя). Значит, в Alpha хвост стоит там же. Живьём дракон в Alpha не наблюдался (`LIVE_UNOBSERVED`) — оценку оставляю продюсеру.

### 1.3 14 видов и 56 действий
* `contract.D69_MERGED_LAUNCHES`: 14 профилей D60 (гуманоиды 0x00, 0x01, 0x03, 0x07, 0x08, 0x0D, 0x0E;
  коты 0x1E–0x20; бегуны 0x3F–0x42), каждому добавлены ровно `[37, 40, 42, 43]` → 56.
* Источники запуска независимо дизассемблированы в `Cube.exe`:
  * `0x4455D7 mov [esi+0x68], al` ← `call 0x445020`: при `class(+0x140)==3` возвращает `0x28` (40) или,
    при `spec(+0x141)==1`, `0x2A` (42);
  * `0x4458A0 mov [esi+0x68], cl` ← `call 0x4452A0`: при `class==3` `mov eax,0x25` (37) / `mov edx,0x2B` (43) по `spec`.
  Это совпадает с `npc_trigger_evidence.json` (`37,40 → [3,0]`, `42,43 → [3,1]`). Выдуманных триггеров нет;
  условие класса/специализации NPC — из записи спавна мира, поэтому игровой триггер `DEFERRED_TO_M0` (честно).
* `_merge_d64_into_d60` перезаписывает `launch_conditions` только добавленными действиями — проверено, что у
  профилей D60 этого поля раньше не было (ничего не потеряно). Замечание (не дефект): у исходных действий D60
  условия класса не записаны, они срабатывают в любом состоянии — так и было доказано в D60.

## 2. Дефект кодировки — исправлен
* Причина: в `tools/alpha_models/catalog/d69_catalogs.py` сами строковые литералы содержали UTF-8, однажды
  прочитанный как cp1251 (`РЎРІРѕРґРєР°` вместо «Сводка», `вЂ”` вместо «—»; символы `0x98` сохранены как
  управляющие C1). Любая регенерация воспроизводила mojibake.
* Исправление: обратимое преобразование cp1251→UTF-8 только испорченных строк (44 строки генератора);
  документы пересозданы генератором. Проверка неизменности данных: новые `.md` **побайтно равны** исходным
  после того же преобразования текста; JSON-каталоги (`.scratch/d69/catalog`) **равны по содержимому** после
  преобразования строк. Счётчики: 156 видов (130/26), 1438 строк.
* Поиск по всем отслеживаемым `.py/.md/.cs/.json/.ps1/.txt/.csv`: других файлов с mojibake нет.
* Тест `tests/test_d69_catalog_encoding.py` (5 проверок): читаемые заголовки обоих документов, отсутствие
  характерных последовательностей в генераторе и документах, `write_text(..., encoding="utf-8")`.
  На старом состоянии — 4 из 5 падают; на исправленном — 5/5.

## 1. Что было неверно

| Утверждение пакета D1/D2 | Что на самом деле |
|---|---|
| `World_generateMonsterSpawnList` / `NpcSpawnList` дают «таблицу спавна: вид, уровень, вес» | Это **товары торговцев**. Запись 0x118 — структура предмета (`+0` тип, `+1` подтип, `+4` модификатор, `+0xC` редкость, `+0xD` материал, `+0x10` уровень). `0x5C9B30` вызывается сразу после записи класса NPC `0x80` (`0x5BCE42`/`0x5BCE53`), `0x5CA0A0` — после классов `0x81` и `0x83` (`0x5BD1FA`/`0x5BD20B`, `0x5BD3D6`/`0x5BD3E7`). Перехват оракула стоял на `GameController_addItemToInventory` |
| поле `+0x04` — вес вероятности | модификатор предмета (случайное число внешнего вида/статов), не вес |
| «звёзды 1 % / 0,1 % / 0,01 %» — редкость элитных мобов | редкость **предмета** в лавке (`+0xC`) |
| сложение записей пяти seed в общую weighted-таблицу — механика Alpha | не имеет смысла в Alpha; статус `EMULATED_ALPHA_CODE` относился только к сырым записям |
| `AlphaWorldPopulation` выбирает вид существа из таблицы | выбирались **подтипы оружия/формул** 0…0x17 — как номера существ это расы игрока |
| `Chunk_generateObjects` — «проход спавнеров», типы 1…5 — «типы спавн-точек» | `0x5AF170` — генератор **деревни/руин**; «тип» — назначение дома `cube::House+0x60` (1…5) |
| «позиция точки — случайный элемент массива vec3» = точка спавна | массив — центры клеток комнат конкретного дома; NPC ставится в случайную комнату **один раз при генерации** |
| существа есть только в зонах колонок Village/Ruins, остальные пусты | шаблон существа создаётся в **35 местах 7 функций**; дикие существа — сетка 3×3 в самом генераторе зоны |
| патруль и расписание Alpha неизвестны (N-13/N-14) | восстановлены: `SpawnLocationBehavior`, `WalkPathBehavior`, окно `RandomInteractionBehavior` |

## 2. Модель Alpha

```
генератор зоны 0x5E4850 (и 6 других функций)
   └─ new cube::Spawn (0x10F0 байт, ctor 0x5ADB20)  ── шаблон существа, хранится в векторе зоны (+0x18)
        позиция +0x10, фракция +0x28, вид +0x2C, класс/спец. +0x30/+0x31, уровень +0x34,
        окно времени +0x40/+0x44, id +0x48, поворот +0x54, 13 предметов +0x120,
        дерево поведения +0x109C, расписание точек +0x10A0, имя +0x10CC
серверный тик 0x60C510, для каждого шаблона загруженных зон:
   таймер +0x38 -= dt                                              (0x60DF9F)
   если окно времени содержит время суток
      и нет живого существа с id шаблона
      и (таймер == 0  или  день смерти +0x3C != текущий день)
      и игрок ближе радиуса +0x08 (200)        → new Creature, копия полей и клон дерева поведения
   существо дальше 512 от всех игроков          → удаляется (шаблон остаётся)
смерть существа (0x596C30): шаблон.+0x38 = 1 200 000 мс, шаблон.+0x3C = текущий день
```

Для NPC: `шаблон.+0x10A0 (расписание)` → `SpawnLocationBehavior` выбирает запись по времени суток →
существо идёт к точке → точка становится домом (`+0x1C0`) для `RandomWalkBehavior`; торговцы и
служебные NPC вместо этого ходят по точкам `WalkPathBehavior`.

## 4. D2 — движение NPC

| Механика | Правило | Статус |
|---|---|---|
| `SpawnLocationBehavior` | список `{позиция, время суток}` шагом 0x20; активна **последняя** запись с `time <= worldTime`; при смене — путь к точке; по прибытии точка пишется в дом `+0x1C0…+0x1D4` | `ALPHA_DECOMPILED`; чтение времени `+0x80015C` — байты |
| `WalkPathBehavior` | точки шагом 0x18; пауза убывает на dt; ближе радиуса (2.0 у деревенских NPC) — стоп, пауза `rand()%4000 + 2000`, индекс `(i+1) % n`; до 21 высоты при поиске опоры | пауза — байты, остальное `ALPHA_DECOMPILED` |
| `RandomInteractionBehavior` | дневной набор точек при `06:00 <= t < 23:00` | `ALPHA_CODE_STATIC` (`0x4DB404`, `0x4DB411`); содержимое наборов — `PARTIAL` |
| Состав деревьев | `LIVE_ONE_CAPTURE`: жители класса `0x88` — `Combat, LookAt, SpawnLocation, RandomInteraction, RandomWalk`, расписание 4–10 записей; классы `0x80–0x87`, `0x89` — `Combat, LookAt, WalkPath` | одно наблюдение |

Прежняя формулировка отчёта G_H «время вне [21 600 000, 82 799 999]» уточнена: сравнение `< 82 800 000`.

## 7. PARTIAL / UNKNOWN

1. Последовательность `rand()` генератора зоны не воспроизведена → координаты и состав конкретной зоны Alpha не совпадут; воспроизводится только структура.
2. Не смоделированы условия клетки сетки: пропуски по влажности/температуре `< 0.2`, маска ориентира, запрет ближе 20 к ранее поставленным объектам, проверки высоты, подмена вида на растения по типу грунта, флаг `0x200` (1 %).
3. Условия и содержимое 22 мест вне сетки (деревня, руины, постройки, данжи): известны только константы фракции/вида/класса.
4. Смысл классов `0x85…0x89`, байта `+0x58`, битов `+0x7A`.
5. Содержимое расписаний и точек `WalkPath` в сгенерированной деревне; наборы точек `RandomInteraction`.
6. Сохранение таймера шаблона при выгрузке зоны и в сейве; уход 512 и радиус стаи 8 не закреплены байтами.
7. Правила экипировки NPC (R-1).
8. Терминология типов зон (п. 5 задачи): в тестах комментария «zone type 3 (settlement)» в текущей ветке нет; имена `AlphaZoneRecord.Town = 1` / `Settlement = 3` в `AlphaRegionGenerator.cs` (код мира Codex) описывают запись сетки зон региона — это **другая таблица**, чем тип колонки ориентира (`LandmarkType`, 1 = Village, 5 = Ruins). Смысл «Settlement» первичным источником в этой работе не проверялся, переименование не выполнялось — открытый вопрос для интегратора.

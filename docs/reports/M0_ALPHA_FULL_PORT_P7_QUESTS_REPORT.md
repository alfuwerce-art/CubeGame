## Что заменено

F3 держал «региональную охоту» как `CUBEGAME_CONTRACT`: ближайший враг в радиусе 32 блоков становился целью. Её больше нет. Миссии создаются, активируются и засчитываются по коду Alpha.

Найдено попутно:
- `0x5D9AD0`, `0x5D8750`, `0x5D9460`, `0x5F7820` и `0x5F7400` в реконструкции названы функциями деревьев, растительности и буферов. Это ошибка имён. Комментарий `AlphaVegetationSelector` исправлен; строка происхождения сохранена, её проверяет тест старого планировщика, который в игровом пути не используется.
- Декомпиляция показывает, что ветка миссий ориентиров не пишет тип. Байты `0x5D92FE → 0x5D9319` это опровергают.
- Флаг `0x2000` выставляется во всём коде ровно в одном месте — `0x5D9730`.

## Поведение Alpha, перенесённое как есть

- Деревенские миссии (типы 3, 4, 9) генерируются, но целей с флагом у них нет — в одиночной Alpha они **не завершаются**.
- Тип 5 завершается убийством хозяина данжа (`+0x1D38`). В CubeGame хозяина данжа ещё нет (данжи P7), поэтому миссия остаётся активной.
- Типы 2, 7, 8, 10, 11, 12, 13 генератором не выбираются; ветки перенесены.
- Для типа 3 Alpha передаёт координаты колонки в поиск по сетке регионов (`0x5D9223`); вне сетки получается `0x6C` без `rand()`. Сохранено.

## CUBEGAME_CONTRACT и PARTIAL

| Пункт | Решение |
|---|---|
| Поток `rand()` | Alpha — глобальный CRT; CubeGame — свой поток на регион (`RegionSeed`), регион всегда даёт те же миссии при том же уровне героя |
| Регион прохода | регион, в котором стоит герой (Alpha выбирает его через поиск ближайшего региона) |
| Хранение | блоки миссий в `.session` (`alphaMissions`, `alphaMissionRegions`); Alpha хранит их в `world_*.db` (`mission<x>_<z>`). Старое поле `huntMissions` читается и игнорируется |
| Босс | 2 предмета экипировки, внешность и поведение `Sequential[Combat(20), RandomWalk]` из `0x5D9460` не перенесены — `PARTIAL`; убитый босс не возвращается (дельты популяции) |
| Равные веса зон | первый по порядку обхода; introsort Alpha для 64 элементов нестабилен — `PARTIAL` |

# Срез B: данж Alpha в игре (14 ноября 2026) — `READY_FOR_PRODUCER_REVIEW` / `PARTIAL`

- Генератор `0x5CC510` перенесён на C# (`AlphaDungeonGenerator`, `AlphaDungeonZoneWriter`, `AlphaDungeonContents`); ход работы — `docs/research/alpha2013/P7_MISSIONS_TRACE.md`, разделы P7-B.
- `AlphaDungeonZoneProvider` — первый поставщик содержимого зоны в мире `cubegame.alpha_terrain/9`: запись 3 → подтип = sub записи, `flag = 0`; запись 5 → подтип 3, `flag = 1`; уровень = уровень записи (`zone+0x80`), качество = класс записи (`zone+0x84`), вид мебели = sub (`zone+0x79`) — Alpha копирует 16-байтную запись в зону по `+0x78` (`0x5E6BA1…0x5E6BC0`).
- Спавны: сундуки (`chest_static`, объект 10), хозяин (`alpha_dungeon_master`), существа комнат (`alpha_dungeon_creature`) — канал 1, стабильные индексы; актёры создаются тем же путём, что и прочие враги.
- `MissionJournal`: убийство героем спавна-хозяина в зоне колонки с миссией типа 5 → миссия завершена (как `0x59642A`: тип 5 и `+0x1D38`).
- Сохранения: формат не менялся. Новые миры — `/9`; миры `/8` загружаются со своим генератором (меню мира требует поддерживаемый id, а не совпадение с текущим).

Проверка: `FullM0P7DungeonRuntimeTests` (мир `/9`, сид 666666, зона 32812/32796: состояние CRT на входе = Alpha, 49 спавнов = Alpha по позиции/виду/уровню/роли/хозяину; мир `/8` без Alpha-данжа; убийство стража не завершает миссию, убийство хозяина — завершает), `FullM0P7DungeonContentsTests`, полный EditMode: 838 из 840 (2 пропуска — локальные дампы). Windows Player — не проверялся.

`PARTIAL`: маршруты патруля, свита и экипировка хозяина/существ не переданы в ИИ и снаряжение; содержимое сундука создаётся при открытии (`CUBEGAME_CONTRACT`), а не из потока данжа; подтипы 4/5; хозяева `0x5DC6E0` (патрули ориентиров) и `0x5AF170` (поселения) не перенесены.

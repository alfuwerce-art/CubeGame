## 1. Главный вывод о механизмах Alpha

Alpha не хранит ни скелетов, ни клипов, ни отдельных форматов для предметов: **всё** — это воксельные `.cub`
одного формата в ОДНОМ общем векторе моделей, который заполняет одна линейная функция
`GameController_load_game_assets` (0x4EE230). Что из него рисуется, решают три **исполняемых селектора**:

1. **внешность существа** — `creature_generateAppearance` (0x43F7C0): вид × seed → индексы 8 слотов + параметры движения;
2. **предмет** — `GameController_item_icon_id` (0x4EC400; в декомпиляции ошибочно назван «icon id»): предмет → индекс модели;
3. **рендерер существа** — `Creature_drawModel` (0x4128F0): рисует части внешности, **заменяя** модели блоков body/hands/feet моделью надетой брони и **добавляя** блоки экипировки.

Анимация всех существ и всей экипировки — одна функция `drawModel` от состояния; запуск действий — ИИ
(`CombatBehavior::vfunc_0`), ввод игрока и события. Поэтому принцип «исполнять байты» покрывает весь каталог:
отдельные адаптеры нужны не по форматам, а по **селекторам** — и все три теперь исполняются.

## 3. Исправленные блокеры DeepSeek

### B-3 — реестр моделей (OrcMale 0x0b, DarkTroll 0x6d) — **ИСПРАВЛЕНО**
- **0x0b:** индекс 1300 загружается дважды (`orc-head-m01.cub` @0x4F1B95, затем `orc-head.cub` @0x4F34CA). Загрузчик пишет **в элемент вектора**, функция линейная (счётчик состояния исключений `local_8` монотонен через все 2557 загрузок) → в Alpha остаётся **последняя** загрузка. Раньше два имени склеивались через `|` → `MODEL_NOT_IN_DB`.
- **0x6d:** индекс 29 = `dark-troll-eyes.cub`, загрузка с **флагом 0** (`push 0`): декодер принимал только `push 1`. Глаза тролля стоят в слоте волос, флаг 0 → маркерные цвета прозрачны (правило D61).
- **Ещё:** индекс 2564 (`sphinx01.cub`) после цикла-генератора — берётся последний вызов вектора перед загрузкой, только если между ними нет другого вызова.
- Старый `registry_sizes.json` не содержал 29 и 1300 — поэтому у OrcMale «пропадала» голова. Пересобран (`.scratch/catalog/registry_sizes.json`).
- Флаг загрузки теперь извлекается для **каждого** индекса и совпадает с таблицей D61 (0 расхождений).
- Модель, отсутствующая в БД, — `ALPHA_EMPTY_MODEL` (загрузчик при неудачном `db_getBlobInto` данные не ставит), а не блокер.

### B-2 — `KIND_SPECIFIC_CODE` (Mole 0x57, Zombie 0x60, Dragon 0x65) — **ИСПРАВЛЕНО**
Ветки этих видов находятся **внутри** `drawModel`, который оракул исполняет; формула ходьбы для них совпала
с исполнением точно (0.0). Блок снимается **только** доказательством `ORACLE_VERIFIED` в
`catalog/walk_oracle_evidence.json`; без него вид, как и раньше, `NEEDS_RESEARCH` (тест). Ветка 0x65 по
адресу GameController.cpp:5924 — ось вращения при оглушении (вектор `creature+0x34`), а не поза.

### B-4 — `PASS_FORMULA_ONLY` — **ОПРЕДЕЛЕНА ОБЛАСТЬ ДОВЕРИЯ**
`ALPHA_FORMULA_VERIFIED` ≝ формула вида совпадает с **исполненным** `drawModel` на собственной внешности вида
(все варианты, меняющие параметры движения; 5 точек фаза/амплитуда × на земле/в воздухе; ≤1e-4 вокселя, ≤1e-3°).
Оракул ранее совпал с живыми захватами трёх разных семейств до точности float. Результат: **156/156**.
Пакетный итог теперь `PASS_ORACLE_VERIFIED` (формула = код Alpha, `live_check=NOT_CAPTURED` сохраняется);
`PASS_FORMULA_ONLY` останется только для вида без такого доказательства.

**Найденный дефект:** у InsectGuard 0x36 — единственного вида с кистями и `angle_48 ≠ 0` (−45°) — формула
давала кистям наклон корня; в `drawModel` кисти получают только подъём `bob`. Расхождение было ровно 45°.
Исправлено в `param_walk.py` и в рантайме Unity `AlphaParamWalk.cs`; Unity-прогон 0x36 — 7/7 PASS.

### B-1 — триггеры действий без живого NPC — **МЕТОД РЕАЛИЗОВАН**
Регион выбора атаки ИИ, кроме входов мира, читает ровно: класс `+0x140`, специализацию `+0x141`, оружие
`+0xaa8/+0xaa9`, левую руку `+0x990/+0x991` (журнал чтений при исполнении). В `Server.exe` класс приходит из
**записи спавна мира** (0x535DF7: запись+0x30/+0x31 → существо+0x140/+0x141), затем поправки по виду
(0x522719: вид 0x68 → класс 2/спец 1, вид 0x56 → класс 3/спец 1). Это данные генерации мира, а не свойство
вида. Поэтому NPC-состояние сделано **явным условием**: для каждого вида исполняются 280 состояний
(класс 0..4 × спец 0..1 × без оружия/26 подтипов оружия; щит), и каждое действие записывается с условиями,
при которых его запускает код Alpha. Живой захват не требуется; ничего не предполагается о классе конкретного NPC.
**Прогон каталога триггеров по всем 156 видам на момент коммита ещё выполняется** (`trigger_catalog`, 10 процессов); на выборке он даёт: 0x4c безоружно → 3/4/6/54, с мечом → 1/54/59/60, класс 3 → 40/37; Mole → 6; Dragon → 51. Итоговые числа и `npc_trigger_evidence.json` — отдельным коммитом в этой же ветке.

  Действий с собственной позой (состояние ≠ 0) — по резолверу; итог — в `anim_catalog.json` после каталога триггеров.
- **Позы** любого состояния любого вида — выпекание исполненным `drawModel` (`EMULATED_ALPHA_CODE`). Проверено на

- **Иные рендереры моделей** (15 функций с `render_uploadModelViewMatrices`): существа (`drawModel`), предметы
  на земле (`renderDroppedItem`: поворот `item[8]×90°`, масштаб `item[9]/sx` — размещение, не анимация),

  движение снарядов и эффектов — игровая симуляция, а не анимация модели (§7).

## Диспетчер и исполнение

- **`ALPHA_CODE_STATIC`.** Из `Cube.exe` SHA-256 `84a7a132a84d4282338e7ea45a1940d32066d64e39cbafed8f2418d5a6dc30bf` разобраны таблица индексов `0x622CCC` и 18 адресов обработчиков по `0x622C84`. `0x611E04` читает `creature+0x68`, вычитает 1 и выбирает case для `0x01–0x6E`. [Реестр](M0_ALPHA_FULL_PORT_P4_ACTION_COVERAGE.tsv) включает 110 ID диспетчера и отдельный idle `0x00`. Для каждого приведены вход, контекст, тайминг, поза, обработчик, Unity-маршрут и статус. У 12 ID, попадающих в общий хвост `0x615EC0`, назначение ещё `UNKNOWN`.
- `CombatSystem` принимает `AttackPlan` с явным ID и маршрутом. В `AuthoritativeActionState` хранятся actor, target, aim, yaw, контекст рук, снимок входа урона, serial, начало, elapsed, фаза, счётчики окон и попаданий, исход завершения. В Pilot открываются 48 ID, включая `0x50`. Неподдерживаемые ID отклоняются до `ActionStarted`. Выбор ИИ больше не зависит от наличия клипа. У естественных акторов сохранён доказанный выбор P3 для котов и бегунов. У legacy AI остаётся `0x4452A0` с ограничениями C-29. Для дальнего дракона `0x65` путь `0x42DEC3` выбирает `0x25` от 8 до 60 блоков. PlayMode Showcase проверяет выбор и передачу ID в hook. Ближняя ветка полёта дракона и экипированные состояния естественных акторов остаются открытыми.
- `0x43CAA0` даёт windup, `0x447310` даёт reload, а третья таблица `0x43D804` добавляет время к разрешению следующей атаки в `0x43D1A0`. Сверка windup с генерированной таблицей `AlphaCombatRuntimeData` дала совпадение всех 106 строк для основной ветки. Runtime отдельно учитывает условную ветку подтипа `0x0C`. Неподтверждённые значения haste экипировки и баффов, `+0x17C`, `+0x70` и полная ready/hold логика `0x445410` / `0x49C272` остаются `PARTIAL`. Коэффициент haste по звёздам NPC `0.75 + 0.0625·stars` взят из `0x447700`. Универсальный таймер `400 / 600 / 800` удалён.
- `GameVisualSink` получает состояние из `CombatSystem` и сэмплирует позу по elapsed. Перед первым strike событие фазы с тем же serial выставляет pose cursor. Ретайм опирается на windup исходного клипа и runtime windup. Контекст позы и масштаб скорости могут отличаться от оригинала. При отсутствии клипа регистрируется `ANIMATION_PARTIAL`. Старый автономный контроллер клипов используется в просмотрщиках.
- Смерть в windup прерывает действие, выгрузка снимает регистрацию и удаляет снаряды владельца. После смерти снаряды владельца удаляются по `CUBEGAME_CONTRACT`, точный Alpha lifecycle после release открыт. Таймлайн и полёт живут в координатах мира и в памяти сессии. Форматы `.sav`, `.session` и `.world` сохранены.

## Семейства действий

| Семейство | Найденный потребитель и граница переноса |
|---|---|
| Melee | `0x612357` → `0x612B4B` / `0x6137F7` → `0x614411`. Базовое окно от `windup + max(0, reload/2−100)` до `windup+reload/2`. Для `0x05` есть повторы через `reload/3`. Центр смещён по yaw, размеры зависят от ширин тел, вертикальный допуск учитывается отдельно, проверяется видимость. Один вызов на допустимую цель за окно. Unity использует адаптацию координат центра и дискретную проверку луча. Частные окна, ближние гейты и матрица фракций остаются `PARTIAL`. |
| Bow / crossbow | Hero `0x445020` выбирает `0x16`; у AI есть зарядка `0x18/0x19` и переходы, а `0x4452A0` выдаёт `0x17` для ветки варианта. Выпуск стрелы `0x6171DB` при пересечении windup, `100` блоков/с, `g=7.5`, время жизни `5000` мс, `size=0.5`. Для `0x17` доказан особый член формулы с зарядом. Его текущая модель урона `PARTIAL`. Координаты центра в Unity и расчёт столкновения дискретными шагами `CUBEGAME_CONTRACT`. |
| Boomerang | `0x1A` использует общий выпуск со стрелой. `0x620BF6–0x620C65` задаёт цель скорости `5·(owner + aim − position)`, интерполяция `0.05` за миллисекунду. Возврат к владельцу после 800 мс, притягивание после 1100, удаление после 1200. `+0x13B4 > 0` добавляет отдельное окно `windup+300`. Точный масштаб aim и заряженный выпуск открыты. |
| Wand / bracelet | `0x25–0x2E` → `0x617A21`. Открывающая атака wand `0x26/0x2C` и bracelet `0x28/0x2A` выбирается из специализации. `+0xAA9==0x0C` даёт скорость 100 вместо 50. `0x2D/0x2E` могут выпускать повторно через `reload/3`. У `0x6C` отдельный payload type 4 и другой урон, маршрут отмечен `UNSUPPORTED`. Заряд, атакующая рука, исходные смещения и серия открыты. |
| Staff | `0x1E/0x20` используют радиус 3, повтор `reload/6`. `0x1F/0x21` используют радиус 5, повтор `reload/12`. Адреса `0x612D85–0x612E84`, `0x613947–0x613981`, `0x613A42`, `0x61427C`. Цель проходит прямую проверку объёма в `CombatSystem` в каждом окне. Положение зависит от aim, а проверка линии смещена относительно центра объёма в Alpha. Множители `0.4/0.6` из `0x43EC90` применяются к существующей базе CubeGame. Полные `stat_pow`, LOS origin и эффекты специализаций `PARTIAL`. |
| Hitscan | `0x1C/0x5E/0x5F` → `0x615C68`. `0x615FBB` ограничивает дальность 200 блоками. `0x615EE0` проверяет повтор через 200 мс у `0x1C/0x5F`. Muzzle `0x446BB0`, точная трассировка вокселей, величина эффекта и расход ресурса открыты. След Unity помечен `PLACEHOLDER_NOT_ALPHA`. |
| Bomb | **Два разных пути.** Alpha-слот type 1/subtype 7 идёт из `0x4A2780` в запись типа 1, создаёт объект kind `0x90`, faction 6 (`0x6111FA`). Его HP уменьшается на `0.025·dt_ms` (`0x611B91`). При смерти и нулевом `+0x6C` запускается взрыв `0x60EBD8`, с радиусом `8 + 0.7·width_target` и взаимодействием с вокселями. AI пишет `0x68` при удержании shield action `0x08` и достижении порога заряда. Игрок пишет `0x68` по отпусканию слота, если текущее действие `0x08` (`0x49BEE9`, таймер сбрасывается). Таблица отправляет `0x68` в `0x612357`. Сравнения с этим же ID есть в отдельном лучевом обработчике, их достижимость открыта. Использование бомбы из сумки и shield release в Unity остаются открыты. |
| Block / dodge | `0x444590` разрешает блок при `+0x130 ≤ 0` для `0x08/0x47/0x48/0x62`, а также для `0x3B/0x3F` при raw class/spec `1/1`. `+0x174` восстанавливается на `dt/2000` вне блока и расходуется на `dt/1200` со щитом в левой руке (type 3/subtype 13), иначе на `dt/600`. `0x596D30` при допустимом попадании отнимает от защиты `incoming/stat_calcSpellPower`. Удержание `0x08` даёт эффекты `0x6121F4`. Полный маппинг ввода, направление защиты и Unity-путь открыты. AI dodge `0x42E44D…0x42E525` выбирает поперечную или продольную скорость величины 20, прибавляет 5 к вертикальной скорости и пишет `600` в `+0x128`. Потребитель урона проверяет это поле. Путь игрока `0x4A6CD6…0x4A800C` использует `controller+0x0A`, гейты направления, порог `+0x1194 ≥ 0.25`, импульс 40 по выбранному направлению и +5 по вертикали. Ветки снимают 0.25, ставят `+0x128=600` и обнуляют `+0x68`. Открыты внешний маппинг кнопки, поза, точные гейты движения и Unity-интеграция. |
| Abilities / special states | 16 имён из `AlphaContentTables.Abilities` присутствуют в реестре. Вход игрока по слоту проходит `0x49B673 → 0x43E5A0`: `+0x12C < 1` или Bulwark, ресурс `+0x170` по `0x444AE0` и счётчик по ID в `+0x139C`. Счётчик инициализируется из `0x43E6A0` и убывает на `dt_ms`. Отдельная таблица стамины `0x444270` не заменяет эти два гейта. `0x43C9C0/0x43ED60` связывают ID со слотами рангов 6–8 и формулой `p = 1 − 1/(1 + 0.1·rank)`. В `0x595850` Camouflage, Swiftness, Bulwark, War Frenzy и Mana Shield пишут отдельные статусы длительностью 8–30 с с параметрами по `p` и Power. Intercept и Smash имеют отдельные ветки скорости, а Healing Stream копирует свой ID цели при запуске. Открыты раскладка class/spec→ID, точные условия большинства эффектов и их Unity-пути. Для `0x50` Alpha тикает HP каждые 200 мс, существующий Unity-эффект мгновенного лечения остаётся `CUBEGAME_CONTRACT`. |

`ACTION_COVERAGE` означает `known/implemented/partial/unknown`. `known` — все 110 ID таблицы, `implemented` — 48 маршрутов, доступных диспетчеру Unity. Статусы строк реестра — 2 `PASS_CANDIDATE`, 96 `PARTIAL`, 12 `UNKNOWN`, 1 `NOT_APPLICABLE` для idle. Состояние `PARTIAL` для `AUTHORITATIVE_ACTION_STATE` отражает действия, которые ещё не проходят через общий исполнитель, включая блок, перекат и эффекты способностей. Для способностей `p` — коэффициент ранга из `0x43ED60`. `counter` — значение карты по ID из `0x43E6A0`. `0x444860` — отдельный lookup, у которого подтверждён вызов в подготовке попадания. Полный жизненный цикл повторного использования способности требует проверки.

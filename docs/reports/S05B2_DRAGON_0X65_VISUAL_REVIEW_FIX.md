## 1. Воспроизведение и диагностика (изоляция слоёв)

Метод: исполнить `drawModel` оракулом для 0x65 в покое и на фазах ходьбы, снять матрицы частей, наложить на
реальные вокселы моделей `.cub` из `data1.db` и измерить мировые координаты (центры вокселей, оси Alpha: `z` вверх,
`y` вперёд). То же — для эталонов: человек 0x02 и кот 0x1E.

| Часть | Модель | Alpha 0x65 (покой): `y` | `z` | Кот 0x1E: `z` | Человек 0x02: `z` |
|---|---|---|---|---|---|
| корпус | dragon-body 14×24×14 | −11.5…11.5 | **−8.5…1.5** | −7.5…−0.5 | −9.5…−0.5 |
| хвост (×0.8) | dragon-tail 9×28×14 | **−38.0…−16.4** | −3.2…4.8 | −7.9…0.7 | — |
| голова (×0.51) | dragon-head 16×44×14 | 8.3…30.2 | −2.8…3.8 | −5.0…3.0 | −0.6…6.5 |
| передние лапы (×1.5) | dragon-foot 5×10×7 | −0.7…11.3 | **−3.5…5.5** | **−12.0…−5.0** | (кисти) |
| задние лапы | dragon-foot | −8.5…−0.5 | **−2.0…4.0** | **−12.0…−5.0** | ступни **−12.0…−10.0** |

* У всех законченных существ низ лап/ступней в покое на одной плоскости `z = −12` (общий `placement`); у дракона
  лапы висят на 8.5–10 вокселей выше, а корпус свисает ниже них → «перекошенный» силуэт, лапы скрыты в корпусе.
* Ближайшие центры вокселей корпус↔хвост: **5.19** (кот: хвост входит в корпус на ~0.9).
* Слои проверены по отдельности:
  * **исходная модель** — вокселы `.cub` прочитаны напрямую, размеры = `data1.db`;
  * **конвертер/риг** — тест D69 сверяет `T(−якорь)·J·P` с матрицей исполненного `drawModel` для **каждой** части
    (< 1e-3 вокселя), якорь меша = якорь клипа для всех видов;
  * **анимация/viewer** — в Unity дефект виден одинаково в покое и во всех действиях, т. е. он уже в позе покоя.
  Вывод: Unity честно рисует то, что вычисляет код Alpha.

## 2. Корень причины — данные Alpha

Ветка `kind 0x65` в `creature_generateAppearance` (`Cube.exe`, переход по таблице `0x443CA0[0x65] → 0x442E91`),
дизассемблировано:

| Поле внешности | Запись в коде | Значение |
|---|---|---|
| `offset_head` `+0x70` | `0x442EC1…0x442ED6` | (0, 12.5, 0.5), `scale_head` 0.51 |
| `offset_body` `+0x64` | `0x442EE2…0x442EF7` | (0, 0, −2) |
| `offset_hand` `+0x7C` (передние лапы) | `0x442F03…0x442F18` | (3, 4, **1**), `scale_hand` 1.5 |
| `offset_foot` `+0x88` (задние лапы) | `0x442F27…0x442F3C` | (3, −4, **1**), `scale_foot` 1.0 |
| `offset_tail` `+0x94` | `0x442F59…0x442F6E` | (0, **−16**, 4) |
| хитбокс `+0x08` | не записывается | остаётся стандартным человеческим (0.96, 0.96, 2.16) |
| модель крыла `0x1AC` | ни в один слот | подтверждает D69: крыльев нет |

Дополнительно: прямой записи вида `0x65` (`mov [r+0x2c]/[r+0x64], 0x65`) нет ни в `Server.exe`, ни в `Cube.exe`;
живьём дракон не наблюдался (`LIVE_UNOBSERVED`). Это похоже на **незаконченный контент Alpha**; утверждать, что
игра его никогда не показывала, нельзя (вид может приходить из таблиц).

## 3. Проверка слепых зон оракула
* **Размеры моделей.** Объекты моделей в эмуляторе — нули, кроме размера `+0x44`; трассировка чтения показала, что
  для дракона `drawModel` берёт только указатели моделей. Контрольный опыт: подмена размеров 425/426/427/429 меняет
  матрицы всех частей → размеры действительно читаются (по пути, который трасса не видит). Слепой зоны нет.
* **Внешность.** Оракул исполняет те же `Spawn_initDefaults` + `creature_generateAppearance`, что и игра; значения
  §2 совпадают с дизассемблированием побайтно.
* **Живой эталон** отсутствует — это остаётся ограничением (новые запуски Alpha без разрешения не делались).

## 4. Предложение визуальной коррекции `dragon_0x65_v1`

### 4.1 Что меняется (и только это)
| Поле | Alpha | Предложение | Правило |
|---|---|---|---|
| `offset_hand` | (3, 4, 1) | (3, 4, **−7.5**) | низ передних лап на плоскости `z = −12` в покое, как у кота/человека |
| `offset_foot` | (3, −4, 1) | (3, −4, **−9**) | то же для задних |
| `offset_tail` | (0, −16, 4) | (0, **−11**, 4) | корень хвоста ~1 воксель внутри корпуса, как у кота (0.9) |

Голова, корпус, масштабы, модели, якоря и **все** формулы анимаций — без изменений (тест: матрицы головы/корпуса
совпадают с Alpha до 1e-5). Числа выведены из правил законченных четвероногих Alpha, а не подобраны «на глаз»;
но это **не Alpha-паритет** и требует решения продюсера.

### 4.2 Как устроено (без маскировки)
* `tools/alpha_models/universal/visual_correction.py` — реестр предложений. **Выключено по умолчанию**: без явного
  включения внешность побайтно равна выходу генератора Alpha; включение — полем задания
  `"visual_correction": "dragon_0x65_v1"` или `with active(...)`.
* Подмена — в одной точке (`alpha_static.AppearanceEmulator.run`) **после** генератора Alpha; поэтому оракул
  `drawModel`, клипы действий, формула ходьбы и контракт видят одну и ту же исправленную внешность — части
  согласованы во всех клипах. `apply` отказывается патчить, если исходное значение не равно задокументированному
  значению Alpha (другая сборка `Cube.exe` не будет «исправлена» молча).
* Происхождение: `visual_correction.json` рядом с данными Unity, поля `visualCorrection*` в контракте, запись в
  манифесте библиотеки действий, пометка в причинах профиля действий; ключ кэша библиотеки включает имя коррекции.
* Профиль действий дракона закреплён за семейством рига Alpha (`ccddb0483c`); исправленная внешность даёт другое
  семейство (`95251fe7e5`). Защита сохранена: профиль принимается для нового семейства **только** при активной
  коррекции, которая явно объявляет этот профиль и семейство Alpha, на которое накладывается (`keeps_profiles`).
  Триггеры ИИ от смещений ног не зависят; позы перепекаются оракулом на исправленной внешности.
* Viewer/камера/масштаб не менялись; общие преобразования других существ не тронуты.

### 4.3 Найденный и исправленный дефект в процессе (настоящая слепая зона)
Первый прогон «после» прошёл проверки, но лист действий выглядел как Alpha. Причина: `action_baker` печёт позы в
отдельных процессах (`ProcessPoolExecutor`), которые **не наследуют** активную коррекцию — идентификатор рига
посчитан родителем с коррекцией, матрицы — рабочими без неё. Исправление: имя коррекции передаётся каждому
рабочему, и рабочий **сверяет своё семейство рига с семейством манифеста** (`WORKER_FAMILY_MISMATCH`). Тест печёт
действие в настоящем отдельном процессе и проверяет, что задние лапы опущены ровно на 10, голова не изменилась, а
рабочий с чужим семейством отказывает.

### 4.4 Проверки (измерено, оракул, вокселы `.cub`)
| Проверка | Alpha | Предложение |
|---|---|---|
| низ 4 лап в покое (`z`, норма −12) | −3.5 / −2.0 | **−12.0** все четыре |
| корпус↔хвост, ближайшие центры | 5.19 | **0.99** (ходьба 1.07) |
| корпус↔передняя / задняя лапа | 0.15 / 0.71 | 0.35 / 0.71 |
| голова, корпус | — | матрицы = Alpha |
| ходьба: нижняя точка опорной лапы | — | −14.7 (кот на тех же фазах −13.1; лапы дракона ×1.5 длиннее — это формула ходьбы Alpha) |

## 8. Решение продюсера — D83: коррекция принята
1. **Принято (2026-11-09):** `dragon_0x65_v1` — облик дракона в игре. Статус коррекции —
   `VISUAL_CORRECTION_APPROVED_NOT_ALPHA` (утверждённое отклонение, не Alpha-паритет).
   Реализация решения:
   * `visual_correction.py`: `approval` (D83), `game_family = alpha_creature/95251fe7e5`, `GAME_DEFAULTS = {0x65: …}`,
     `game_default(kind)` (только утверждённые коррекции);
   * `transfer_planner.job_for`: игровое задание 0x65 получает `visual_correction`; `find_action_library` берёт
     только библиотеку, испечённую с коррекцией и её ригом (Alpha-библиотека отклоняется);
   * Alpha-паритет не тронут: оракул, тесты дефекта, D69-проверка — без коррекции;
   * тесты `GameDefaultTests` (4), Python `352 passed, 109 subtests`. Unity не перезапускался: игровое задание
     совпадает с проверенным заданием `0x65_after` (PASS), а Unity-код статус коррекции не читает.
2. Хитбокс дракона в Alpha — человеческий (0.96×0.96×2.16); в коррекцию не включён (игровое правило, M0).

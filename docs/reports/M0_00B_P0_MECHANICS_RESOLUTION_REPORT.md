## §A. P0-A — предметы, экипировка, модели (ЗАКРЫТ)

### A.1 Как разрешён конфликт

Три независимых источника: таблица имён `World::ctor_1`, базовые индексы моделей в
`item_icon_id @ 0x4ec400`, и таблица «индекс → `.cub`» из загрузчика ассетов. Для каждого типа
предмета вычислен его модельный блок и сопоставлен с именем файла:

```
type 4 → 0x464 iron-chest1.cub        type 7 → 0x47d iron-shoulder1.cub
type 5 → 0x496 iron-hand1.cub         type 8 → 0x61c gold-amulet1-random1.cub
type 6 → 0x4af iron-foot1.cub         type 9 → 0x653 gold-ring1-random1.cub
```

Отсюда: **5 = Gloves, 6 = Boots**, и правило «значение принадлежит своей вставке» верно (это же
подтверждает устройство `World_MapInsertChunk`: вставка создаёт пустое значение, заполняет следующее
присваивание).

### A.2 Исправленные ошибки

1. **`I-09` матрицы и `F_items.md`** — сдвиг на один подтип. Старый список `1 mace, 2 fist, 3 sword,
   4 dagger, 8 crossbow, 0xe boomerang` неверен; верный — в §A.1 evidence-документа.
2. **`AI-10`/addendum** — `+0x7e` принадлежит существу, а не предмету. Перенос «маски свойств оружия»
   в контракт M0-00C запрещён до разбора семантики бит.
3. **Тип `0x15`** — не «Special-слот», а квестовые предметы.

### A.3 Воспроизводимая проверка

`python tools/alpha_research/verify_item_type_model_consistency.py` — 34 утверждения, из них:
6 (типы 4…9 → модели), 6 (таблица имён ↔ типы), 15 (подтипы оружия → модели), 2 (3-символьные имена),
1 регрессионный сторож (старый список `F_items.md` обязан оставаться опровергнутым), 4
(арифметика таблицы, тип `0x15`, словарь мебели).

Фактический прогон: **`CHECKS=34 FAILED=0 RESULT=PASS`** (stdout — в
[evidence §A.3](../research/alpha2013/M0_00B_P0_MECHANICS_EVIDENCE.md)).

### A.4 Что осталось `UNKNOWN` (P0-A)

`A-U1` подтип оружия `0x00`; `A-U2` подтип `0x12`; `A-U3` семантика бит `+0x7e` кроме `0x8/0x10`;
`A-U4` слот `+0x300`; `A-U5` где хранится маска апгрейдов оружия. Все — с адресами и планом закрытия

### A.5 Что **не** изменилось в Unity

## §B. P0-B — действия героя и движение (ЗАКРЫТ ЧАСТИЧНО)

**Доказано:**

1. **Цепочка расходника** целиком, кроме применения эффекта: событие (`0x4a2780`) → action `0x50`/`0x51`
   → встроенный предмет `creature+0x1e8` → отрисовка модели в руке (`0x4128f0`, 6408-6436) → кулдаун
   (`0x4c6b80`). Где списывается предмет и применяется лечение — не найдено (`B-U1`).
2. **ИИ-зелье**: `CombatBehavior.cpp:280-288` — пьёт при `HP < 0.5 × входящий урон`, только фракция 3,
   предмет жёстко `(type 1, subtype 4)`. **Исправляет `C-24`** («HP < 25 % MaxHP»).
3. **Класс → стартовое оружие** (`start_game_mode`, строки 28017-28123): Warrior — Greatmace (0x11) +
   2 Axe + Shield; Ranger — Bow (6) + Crossbow (7); Mage — Staff (0xa) + Wand (0xb) + Bracelet (0xc);
   Rogue — **два Dagger (3) в `+0x990` и `+0xaa8`** (dual wield). Все классы: два кольца (тип 9),
   **лампа (тип 0x18) в слоте `+0xdf0`**, 5 × LifePotion.
4. **Слот `+0xdf0` = лампа** — гипотеза r2 «за спиной» закрыта как «лампа».
5. **Множители навыков движения** доказаны формулами: riding `P1`, climbing `N1`, flying `x3p15`,
   swimming `Half`, boat `x3p1`, все в процентах `100·curve(rank)`; посчитана таблица рангов 0…10.
6. **Стат `@boatspeed` существует** → уточнение: у лодки есть скоростная характеристика, но ветки
   управления нет.

**Отрицательные результаты:** прыжок (ни функции, ни константы), перекат игрока, класс → набор
способностей (в коде нет; вероятно, данные `data1.db`), физическое применение множителей навыков.

## §C. P0-C — жизнь игрового мира (ЗАКРЫТ ЧАСТИЧНО)

**Доказано:**

1. **Возрождение = полный сброс состояния** (`Player_resetFull @ 0x446330`,
   `Player_resetState @ 0x4465c0`): HP-блок, таймеры, списки, контейнеры, стамина = 1.0, stagger = 0.
   Правило (штраф/точка/таймер) — по-прежнему `UNKNOWN`; найдена отдельная функция выбора точки
   появления `GameController_pickSpawnPoint @ 0x4d4de0` — конкретный следующий шаг.
2. **Вне-экранное состояние** — это **сохранение блобов по близости**, а не симуляция:
   `World::updateNearbyEntities @ 0x4690a0` → `saveEntityBlob @ 0x487520`; ключи `"mission"`,
   `"monster"`, `"discovered"` подтверждены в сериализаторах. Явно разделено: «живые NPC вне экрана» —
   требование CubeGame, а не свойство Alpha.
3. **Генерация региона** найдена с точной формулой: `srand(masterSeed + z·0x400 + x)`, тип
   `FUN_005a4710(x,z) = 1 при (512,512), иначе 2 + trunc(0.75·dist)`, вариант `rand()%5` при типе > 4,
   ориентация `rand()&3`.

**Остаётся спорным:** диапазон формулы не ограничен (до ~545), а имена типов в таблице есть только для
`{1,2,3,4,6,7,8,0xb,0xc,0xd,0xf}` — значит `Region+0xc` может быть «полосой удалённости», а не биомом.
Статус `PARTIAL`, шаг закрытия — потребители `Region+0xc` (`GameController_show_region_name @ 0x4e5320`).

**Отрицательные результаты:** деспавн/реактивация по дистанции и лимит популяции не найдены; таблица
«климат → объекты» (~660 строк) не выгружена.

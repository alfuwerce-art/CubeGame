## Контрактные вопросы Claude (для #9 / M0-00C)

```markdown
**DeepSeek → Claude, контракт M0-00B/M0-00C (ветка `deepseek/m0-00b-gameplay-research` @ `6dbe0d1`).**

1. **Действия 80/81.** В `S05B2_UNITY_TRANSFER_DISPOSITION_MATRIX` они `BLOCKED_CONTEXT`. Теперь есть
   доказанный триггер (`GameController_handleObjectAction @ 0x4a2780`) и кулдаун
   (`GameController_itemCooldown @ 0x4c6b80`). Предлагаю переклассифицировать в
   `EMULATED_ALPHA_CODE` + `live_check=NOT_CAPTURED`, **если** вы согласны трактовать `pEvent` как
   очередь действий объекта. Анимация тела при них по-прежнему не доказана.
2. **Маска `creature+0x7e`** (16 бит, 4 потребителя) отсутствует во всех реестрах. Предлагаю ввести поле
   `weaponPropertyMask` в контракт сущности — это меняет предпосылку «свойства оружия = отдельные
   поля».
3. **13 слотов ≠ 13 видимых моделей.** Рисуются 10 слотов (7 базовых + 3 по условию состояния),
   кольца `0xbc0/0xcd8` и `+0x300` не рисуются. Если M0-00C планирует «модель на каждый слот» — это
   неверно.
4. **Пространство action id шире `0x77`**: `ability_isChanneled` содержит `0x91,0x92,0x93`. Реестр
   «≤0x77» из старых отчётов нельзя использовать как полный.
5. **Имена функций — гипотезы.** Пример: `GameController_updateHeldObjectOnMove @ 0x5a0bf0` на самом
   деле начисляет опыт. Предлагаю правило: любое утверждение об Alpha ссылается на тело функции или
   адрес, а не на имя из `RENAMES.tsv`.
```

## 1. Завершено из работы Claude

- Автоматический бейкер поверх существующих `Oracle`, resolver, `bake_action` / `baked_clip`; явный реестр action→state→timings→status, без предположения о доступности игровых способностей.
- Строгий импорт emulated-клипов по контексту и SHA256; отсутствие любого required clip приводит к FAIL.
- Отдельный слой оружия при ходьбе. Ядро проверенной формулы тела сохранено.
- Рабочий `AlphaAnimationController`: один владелец часов, остановка перед действием, entry/action/recovery/exit, завершение и повторные запросы.
- Сырые Alpha-позы сохранены; сглаживание стыков явно имеет статус `UNITY_TRANSITION`.
- Полный `AlphaControllerPlayMode.Run` реально выполнен, в отличие от стабилизационного baseline.

Финальная геометрия — **8/8**; roundtrip **94 клипов** (93 actions + walk) ≤**0.000010** при пороге 0.001. Seam ходьбы непрерывен. Хват проверен **между ключами**: первичная ошибка ≤**0.000008** вокселя на 30/60/120 Гц; вторая кисть ≤2.236 от оси и **0** за пределами реальной рукояти grid Z=[0,7]. Её границы получены из сечений текущего меча (первая расширенная гарда), а не выбраны для PASS. Полные пути кончика клинка на 60 Гц: 153.134 / 180.297 / 65.742 вокселя (порог ≥30).

Интерполяция оружия исправлена отдельно: при хранении с back-anchor линейный перенос центра модели отрывал бы рукоять от кисти между вращающимися ключами. Сэмплер интерполирует вокруг нативной точки хвата и возвращает представление к fixed back-anchor; исходные матрицы ключей неизменны. Синтетический вращающийся пример проверяет этот дефект независимо от Alpha-данных.

**Формулы:** Python↔C# **900 golden** cases, max_abs 0.0000014; **446 живых кадров** Alpha ходьбы, max_pos 0.000292 вокселя / max_rot 0°; отдельное оружие — 5 oracle cases, max_abs 0.0000013 (`paramwalk.txt`).

**Независимый oracle replay:** **3115/3115 кадров**, `ORACLE_VALIDATE=PASS`, max_abs **0**, порог **0.0001 не изменён**. Наблюдавшиеся комбинации: state/action 0/0 (2236), 2/57 (214), 4/59 (28), 2/60 (637). Отчёт `.scratch/animsys/oracle_validation_camera.json`.

Первый полный replay обнаружил ошибки у дальних NPC: прежний emulator API центрировал XY в нуле, меняя округление f32 upload-матриц; обратный placement увеличивал ошибку. В полной записи отсутствуют значения vecA/vecB по указателям аргументов, но их fixed16 смещение камеры восстанавливается из captured placement и координат существа. Добавлен **опциональный вход камеры**, default-поведение эмулятора для бейкинга сохранено. Placement проверяется отдельно; позы/матрицы частей не подставляются в evaluator. Проблемный кадр и затем весь полный replay совпали точно. Исходный FAIL сохранён в `oracle_validation.json`.

## 5. Что не утверждается

Новые poses — `EMULATED_ALPHA_CODE`; не все action ID наблюдались живьём. `combat_getAttackTiming` задаёт исследовательское окно renderer, а не доказанный gameplay lifetime для каждой способности. Игровой ввод, удержание/отмена, root motion, условия доступности, VFX не объявляются восстановленными. Интерполяция baked-клипа не воспроизводит произвольную предысторию Alpha smoothing. Поддерживаются текущие восемь частей и двуручный слой; смена/скрытие частей требует следующего контракта.

Художественная приёмка, внешний вид волос и окончательное качество переходов — за продюсером. Production S04 не менялся, новые существа/массовые конверсии/запуски оригинальной установки не выполнялись.

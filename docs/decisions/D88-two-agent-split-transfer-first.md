# D88 — Перенос игры двумя агентами: сначала перенос, потом проверки, визуальный осмотр отдельно

**Дата:** 2026-11-09. **Решение продюсера:** «утверждаю» на предложение Claude (разделение работы, отдельный каталог DeepSeek, порядок этапов). **Статус:** APPROVED. Не означает ACCEPTED какого-либо результата.

## 1. Было → стало

- **Было (D87 + решение «один агент», 2026-11-09):** одна общая папка `D:\Projects\CubeGame`, ветка `integration/m0-all`; затем все зоны переданы Claude. Каждый пакет: код → полные EditMode/PlayMode → сборка → скриншоты.
- **Стало (D88):**
  1. Работают **два агента**: Claude и DeepSeek Harness. Итог — вся игра Alpha 2013 (кроме мультиплеера) в одном Unity-проекте.
  2. **Каталоги раздельные:** Claude — `D:\Projects\CubeGame`, ветка `integration/m0-all` (общая ветка, интегратор — Claude). DeepSeek — свой существующий worktree `D:\Projects\CubeGame-deepseek`, ветка `deepseek/m0-content`, созданная от общей ветки. Причина: в общей папке незаконченный код одного агента ломает компиляцию другому, Unity открывает проект только одним процессом. Этот пункт заменяет раздел «одна рабочая папка» D87.
  3. **Порядок этапов:** (1) перенос — перед каждым коммитом только компиляция без ошибок и адресные тесты по необходимости; (2) проверки — полные EditMode/PlayMode, сквозные сценарии, исправления; (3) **визуальный осмотр отдельным этапом** — набор игровых срезов (город, данж, бой с разными существами, экипировка, биомы и т. д.) со скриншотами/видео и сценой для ручного просмотра, продюсер оценивает всё за один раз. Исключение для этапа 1: правила с числами Alpha (урон, HP, генерация) получают тест сразу вместе с кодом; полный прогон — на этапе 2.

## 2. Разделение работы

**Claude — правила игры, состояние героя и мира, интеграция в одну игру:**
M0-03 персонаж (создание: раса/класс/внешность; ходьба/прыжок/плавание/лазание/планер/лодка; камера; опыт и уровни), M0-04 предметы (инвентарь, экипировка, подбор/лут, расходники, крафт, сохранение экипировки), M0-05 бой (блок, уклонение, комбо, мана/ресурсы, способности классов, смерть, награды/дроп), M0-06D постоянное состояние существ, M0-07C/D торговля/кошелёк/диалоги как игровые действия/задания и их прогресс, M0-08 интерфейс, мир (генератор, стриминг, изменения мира — уже реализованы), подключение работы DeepSeek в сцену и общая ветка.

**DeepSeek — содержимое мира, существа, визуал:**
M0-02C наполнение мира (растительность, объекты, вода/пещеры через `WorldContentSource`; один путь размещения), M0-06A/B/C/E существа и NPC (таблицы спавна по биомам, выбор атаки Alpha C-29, атаки NPC с оружием R-1/R-2, питомцы/боссы), M0-07A/B поселения и данжи (города, деревни, данжи, сундуки, данные NPC-сервисов и торговцев), визуал (броня/предметы на модели, эффекты/снаряды R-3, динамические части R-8, смерть существ, иконки, звук).

**Граница:** DeepSeek поставляет данные и поведение через интерфейсы `Assets/CubeGame/Features/Contracts` (владелец — Claude): кого/где спавнить, какую атаку выбрать, как выглядит. Применение последствий — HP, урон, лут, инвентарь, деньги, сейв — только у Claude (Core S02–S04). Изменение интерфейса — запись `API` в журнале до кода.

## 4. Git и связь

- Claude коммитит в `integration/m0-all` и пушит. DeepSeek коммитит и пушит только `deepseek/m0-content`.
- Интеграция: DeepSeek пишет `REPORT` с SHA → Claude сливает `deepseek/m0-content` в `integration/m0-all`, проверяет компиляцию, пишет SHA в журнал. DeepSeek подтягивает общую ветку командой `git merge origin/integration/m0-all` в своей ветке, когда Claude публикует SHA.
- Связь — `docs/agents/AGENT_COORDINATION.txt` (только дописывание): `QUESTION`, `ANSWER`, `API`, `HANDOFF`, `REPORT`, `CONFLICT`, `DECISION`. Время — по системным часам ПК.
- `main`, force-push, публикация ассетов Alpha — запрещены. Право ACCEPTED — только у продюсера.

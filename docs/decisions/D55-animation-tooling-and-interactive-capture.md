# D55 — разрешение специализированного ПО и интерактивного исследования Alpha

**Дата:** 2026-11-05. **Решение продюсера:** разрешить DeepSeek использовать подходящее специализированное ПО, ранее запрещённое общим ограничением, для исследования, вычисления и локального переноса оригинальных анимаций Cube World Alpha; дать агенту возможность самостоятельно запускать игру, пользоваться клавишами **W/A/S/D** и действиями персонажа, наблюдать, записывать и анализировать анимации, если фактический доступ к графическому сеансу позволяет. **Статус:** `ACCEPTED` как уточнение разрешений к D53–D54; не приёмка S05A-2.

## 1. Приоритет

Начать с **ходьбы**, поскольку это самая простая воспроизводимая анимация через WASD, затем испытать **одну двуручную атаку**. Анализ исходного поведения проводится по двум каналам: **(a) наблюдение кадров/тайминга в работающей Alpha**, **(b) исследование соответствующих state/time → pose/bones/matrices в исполняемом коде/оперативной памяти/графическом потоке**. Цель — один проверяемый механизм переноса (первый POC walk, следующий POC attack), а не очередная ручная proxy-анимация. Статус `TRANSFERRED_FROM_ALPHA` возможен только при доказанном соответствии исходным данным/формулам и проверке Unity.

## 2. Разрешённое ПО — в пределах задачи

DeepSeek может использовать уже установленную Ghidra и при необходимости самостоятельно скачать/установить и использовать **бесплатные** инструменты из официальных источников:

- **x32dbg/x64dbg** — отладка 32/64-битных процессов, наблюдение state/bone/transform/таймеров и вызовов, без сохранения изменённого оригинального EXE.
- **Microsoft Sysinternals Process Explorer** — модули/загруженные DLL, определить графический API и разрядность.
- **apitrace** — трассировка поддерживаемых OpenGL/D3D API (в том числе D3D9), если фактически используется; трасса сама по себе не доказывает присутствие bone matrices.
- **OBS Studio** — запись кадров/ввода и сравнение траекторий, если установленный Windows Capture подходит и не даёт чёрного экрана.

Применимость другого GPU-debugger (например, RenderDoc) **проверить по фактическому API** прежде чем использовать; не считать универсальной поддержкой D3D9. Не скачивать инструменты из сторонних зеркал, торрентов, неизвестных скриптов. Зафиксировать названия, версии, ссылки/происхождение и хеши скачанных файлов где возможно. **Бесплатное ПО из этого списка можно установить без повторного согласования с продюсером**; любые платные инструменты, драйверы ядра, операции с правами администратора, антивирусные исключения и инструменты вне этого списка требуют отдельного разрешения.

## 3. Управление игрой

- Запускать Alpha только из отдельной локальной копии в `.scratch`, не менять оригинальную установку/сохранения, не запускать `Server.exe`.
- Работать **в интерактивной пользовательской сессии Windows**, не пытаться посылать WASD из фонового процесса без подтверждённого фокуса. Проверять foreground PID/window, реальное движение на экране и активность игры по кадровому захвату.
- Допускается ограниченная диагностика/восстановление фокуса через штатные Windows API `ShowWindow`, `SetForegroundWindow`, `AttachThreadInput` / синтетический Alt в пределах собственной сессии. Ограничения песочницы и отсутствие прав не обходить скрытно; если GUI-канал не допускает ввод, точно записать причину и потребовать интерактивного запуска через доступный агенту UI-инструмент/минимальную ручную помощь продюсера. **Нельзя выдавать скриптовый вызов SendInput за подтверждённое перемещение**, пока нет кадров движения.
- Порядок: idle → W (вперёд) → S (назад) → A/D (вбок и/или разворот — определить по наблюдению) → смена направления/остановка → одна двуручная атака с выделением частей движения.
- При отладке/перехвате использовать только собственный исследовательский экземпляр и его процесс, минимальное время захвата. Не модифицировать/патчить EXE, не воздействовать на другие процессы.

## 4. Требуемые результаты

1. Журнал воспроизводимых входов (кнопка/состояние/время), кадры с видимым движением либо документированный блокер.
2. Техническая карта `input → state → time → bone transforms → renderer`: какие фактические данные получены, адрес/функция/регистры/матрицы/система координат, какие гипотезы остаются.
3. POC **ходьбы** на одном гуманоиде Unity на основании извлечённых данных/формул, затем POC **атаки**, если первый путь доказан; честная категория достоверности для каждой анимации.
4. Закрыть существующий блокер PlayMode `-pilotAttack`, разделить метрики ходьбы и атаки и воспроизводимо проверить 40 кадров/exit 0; не считать текущий FAIL PASS.
5. Код, тесты и текст в GitHub; извлечённые Alpha-позы/матрицы, трейсы, видеокадры и ассеты **только локально** в `.scratch`. Для выпуска — отдельное решение по правам и ресурсам.

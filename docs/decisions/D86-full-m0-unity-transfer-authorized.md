# D86 — Разрешение на полный перенос Cube World Alpha 2013 в Unity

**Дата:** 2026-11-09.
**Источник:** прямое распоряжение продюсера «давай начнем переносить игру полностью в юнити», после его возражения против ограничения реализации одним боем/героем.
**Решение:** FULL_M0_IMPLEMENTATION_AUTHORIZED. Не означает ACCEPTED ранее непринятых результатов или автоматическое принятие будущих сборок. M0-00D: рабочий исполняемый план описывается в отдельном документе D86; спорные изменения принятого Core, инвентаря и схемы сейвов — только после совместимого контракта и решения продюсера.

## 1. Замена приоритета

**Было:** D85 открывал прямую интеграцию D72 в Unity, но фактическое рабочее задание #12/#13 ограничивалось первым срезом «герой — меч — удар/HP», остальные игровые системы были отнесены в неопределённое «дальше». Историческая дорожная карта D66 требовала дополнительного решения, чтобы открыть M0-01+.

**Стало:** продюсер прямо разрешает **реализацию всего M0-01…M0-09**, а не отдельных тестовых стендов. Приоритет — воспроизвести согласованный одиночный игровой цикл Cube World Alpha 2013 в одной существующей Unity-игре. Исполняемый план: docs/stages/M0_FULL_GAME_EXECUTION_D86.md. Обе задачи #12/#13 охватывают ВСЕ M0-01…M0-09; первый вертикальный сценарий — контроль интеграции, НЕ предел работ и НЕ повод остановиться после боя.

D86 отменяет только старые ограничения «реализацию M0-01+ не начинать» и «первоочередная боевая демо-сцена = объём задачи» в рамках настоящего приказа. Сохранены техническое ревью и личная приёмка продюсера, запреты на изменение main, публикацию Alpha-ассетов, force push, перезапись чужого worktree, необоснованные изменения S02–S04.

## 2. Что входит в M0

1. M0-01: единая игра, меню, сессия, часы, ввод, запуск/выход, сохранения.
2. M0-02: процедурный мир Alpha, биомы Alpha, рельеф, чанки, пещеры/вода, стриминг, дельты.
3. M0-03: создание персонажа, расы, классы, визуал, управление, навыки перемещения, прогрессия.
4. M0-04: база предметов, 24 типа/подтипы, экипировка/инвентарь, добыча/крафт/расходники, стойкие состояния.
5. M0-05: полный бой с классами, магией/умениями Alpha, анимациями, хитами/эффектами/снарядами, смертью/наградой.
6. M0-06: существa/NPC/питомцы/боссы, спавн, фракции, базовый AI, offscreen/persistence.
7. M0-07: города, поселения, постройки, данжи, торговцы/сервисы, задания и события Alpha, взаимодействия.
8. M0-08: интерфейс, создание персонажа, инвентарь, карта, журнал заданий, настройки, звук и feedback.
9. M0-09: интеграционная одиночная сборка, контроль всех цепочек, производительность, исправление регрессий и личная приёмка.

Мультиплеер и новые системы M1/M2 (переделанные графика/биомы/LLM-NPC/новая боевая система) не включены. Предложения улучшений не выдавать за поведение Alpha. Пользовательские каталоги будущих 9 биомов/41 микробиома не подменяют базовые биомы Alpha в M0.

## 3. Реальные агенты и границы

**Claude — системная сторона**: GameSession/GameClock, жизненный цикл игры и сцена, процедуры мира/seed/чанки/стриминг/дельты, герой и перемещение, доменные инвентарь и бой с существующим S02–S04, постоянное состояние, квестовые состояния/экономические транзакции, UI и конечная сквозная интеграция.

**DeepSeek — содержимое и механики существ**: Unity-перенос моделей/анимаций/риг/оружейных креплений, данные биомов/декора/воды/пещер, процедурное размещение структур, видовые профили и спавн существ, AI и поведение в пределах выделенного модуля, города/данжи, предметные базы и рецепты/сервисы, звуки/эффекты и проверочные визуальные инструменты.

Возможны участки Claude→DeepSeek (контракт → реализация) и DeepSeek→Claude (контент/AI → интеграция) без перезаписи общих файлов. Каждый агент **пишет код**, проверяет в Unity и предоставляет SHA. Предметный контент и правила инвентаря — разные владельцы. Нет одной общей редактируемой сцены у двух агентов.

**Границы файлов на старте**:
- Claude: Assets/CubeGame/Features/{Session,World,Character,Items,Combat,Quests,Economy,Persistence}/**, Assets/CubeGame/Presentation/{Gameplay,UI}/**, Assets/Scenes/Pilot.unity и bootstrap (единственный редактор), C# Game API и интеграционные тесты с префиксом FullM0.
- DeepSeek: Assets/CubeGame/{AlphaModels,AlphaModels.Import,Content}/**, Assets/CubeGame/Features/{AI,Creatures}/** с отдельным контрактом, Presentation/Visual/**, свои визуальные тесты и соответствующие инструменты конвертации.
- Общие asmdef, Core, сейв-схемы, настройки Unity, сцена и Git merge — управляемая последовательная интеграция, не параллельная запись.

**Рабочие каталоги** — прежние D71: D:\Projects\CubeGame (Claude) и D:\Projects\CubeGame-deepseek (DeepSeek); ветки claude/d85-gameplay-unity и deepseek/d85-visual-unity остаются рабочими, новые worktree не создавать. Текущее ТЗ D86 получать из coordination-ветки planning/d85-direct-unity-two-agents и GitHub Issues #12/#13.

## 4. Порядок: всё M0, не одна боёвка

Зависимости из docs/planning/M0_FULL_ALPHA_INTEGRATION.md сохраняются: нельзя считать мир или сейв готовым без проверки его связей. Допустима параллельная работа над независимым содержимым и контрактами будущих систем. Стартовать сразу подготовку модулей всего M0, не запускать наугад чужие тяжёлые Unity тесты. Первая игровая сборка должна хотя бы создать мир/героя, перемещаться и сохраняться; следующие наращивают содержание и взаимодействия **в той же сборке**. Нельзя заменять весь мир heightfield-демо, а полноценный NPC — одной моделью с клипом, обозначая это Alpha parity.

Перед каждой необратимой миграцией (enum чисел, 24 item types, 13 slots, v2-сейв) — отдельное решение с тестом обратной совместимости. До решения использовать adapter/mapping и сохранять проверенную S04 семантику. Данные Alpha со статусом PARTIAL/UNKNOWN не домысливать: локальный адресный эксперимент, документированный CubeGame placeholder или блокер.

## 5. Приёмочные проверки

Все ветки игры должны участвовать в сквозных сценариях, а не в нескольких изолированных тестах:
new world → character creation → world streaming → exploration/movement → NPC/creatures → combat → loot/equipment → town/trader → dungeon/quest → save/exit/reload → продолжение той же игры. Дополнительно dungeon rewards, изменение чанка и восстановление, NPC state offscreen, разные классы, способности, инвентарь/торговля/крафт, карта/UI, управление/звук, long-run FPS/stability.

По каждому модулю: реализованные файлы, Unity EditMode+PlayMode фактический лог и воспроизводимые действия, Alpha reference и тип доказательства, отклонения, локальные ассеты, отчёт, SHA. Контрольная точка — техревью, **не** автоматическое ACCEPTED. Не проходить тесты подменой Alpha-эталона или ослаблением порогов.

## 6. Что нельзя считать уже выполненным

На дату решения полная игровая реализация M0 ещё не показана. Отсутствие кода по M0-02/06/07/08 нужно исправлять реализацией, а не повторными отчётами. GitHub-issue/ветка/разрешение не запускают локальный Claude Code или DeepSeek автоматически. Исполнение агентами начинается, когда им дано соответствующее задание в локальном harness; факт запуска подтверждается коммитами/Unity-логами.

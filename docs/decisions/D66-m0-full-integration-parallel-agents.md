# D66 — M0 Full Alpha Integration: утверждение структуры и ограниченной параллельности агентов

**Дата:** 2026-11-07  
**Автор решения:** продюсер CubeGame  
**Статус:** APPROVED (планирование и безопасное разделение работ); **M0 IMPLEMENTATION — NOT_STARTED**  
**Предшественник:** D65, `stage/d65-full-catalog` — `READY_FOR_REVIEW`, личная визуальная приёмка не завершена.
**Канонический план:** [M0_FULL_ALPHA_INTEGRATION.md](../planning/M0_FULL_ALPHA_INTEGRATION.md)

## Решение

1. После ревью S05B-2 планируем **перенос всей Cube World Alpha 2013 в одну играбельную Unity-игру** (без первоначального мультиплеера), а не только моделей/анимаций/отдельных тестовых сцен.
2. Утверждена последовательность `M0-00`…`M0-09` (10 крупных этапов, 40 подэтапов): подготовка → единая игровая основа → мир → герой → предметы → бой → NPC/AI → контент → UI → комплексная приёмка.
3. Старые S02–S05 не обнулять и не перенумеровывать: существующий код использовать, тестировать и интегрировать. Старое изложение M0 в `ROADMAP_DRAFT.md` остаётся историческим описанием и заменяется по исполнимой детализации новым документом.
4. Claude Code отвечает за исследование, контракты, архитектурный аудит и ревью; DeepSeek Harness — за реализацию Unity/C#, анализ Alpha, интеграционные тесты и отчёты. Для каждого подэтапа основной исполнитель указан в плане.
5. Разрешена **ограниченная параллельность независимых read-only исследований/отчётов Claude и реализации DeepSeek**, когда Claude **не пишет** в `D:\Projects\CubeGame`, не переключает его Git-ветку, не запускает конкурирующую Unity и ведёт свой результат через отдельную удалённую ветку/доступный GitHub API. Если необходима локальная запись, правка общего кода, `.scratch`, запуск Unity или изменения контрактов — только последовательная передача по `MULTI_AGENT_WORKFLOW.md`. **Без дополнительных клонов/worktree.**
6. Нельзя принимать существование технически выпеченной анимации за подтверждённую игровую способность. Декоративным растениям, цветам, кустам и яйцу не назначать ходьбу или атаки в будущей игре; настоящих растительных монстров классифицировать отдельно. Разрешённые действия подтверждать Alpha или продюсерским решением; исходные результаты конвейера сохранять.
7. На границе каждого подэтапа: регрессии предыдущей функциональности, интеграционный запуск, сохранения/seed/стабильные ID, ревью по опубликованному SHA и приёмка продюсером. Изменения генератора и сохранений без совместимости/миграции запрещены.

## Границы авторизации

- **Сейчас можно:** подготовительные исследования, планы и документацию `M0-00A/00B` без правок игровой сборки; продолжение визуального аудита S05B-2.
- **Пока нельзя:** объявить S05B-2 `ACCEPTED`, запускать кодовую реализацию `M0-01`…`M0-09` без полного ТЗ `M0-00D` и решения продюсера, выдавать прототипы за полную игру.
- Не менять `main`, S04, чужие ветки; не публиковать оригинальные или производные ассеты Alpha; не делать force push/merge без разрешения.
- Архитектура: остаётся утверждённым принцип модульного монолита (ADR-0001); `ARCHITECTURE_PROPOSAL.md` как целое **не утверждён** и не легализуется этим решением.
- После отдельного принятия M0 наступают M1 (графика, модели и текстуры), затем M2 (новые RPG-механики), M3 (сеть/релиз).

## Последствие

Обновить актуальную дорожную карту, межчатовую память, статус этапа и протокол двух агентов. Данное решение **не утверждает визуал S05 и не является результатом тестирования M0**.

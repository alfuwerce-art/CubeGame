# D60 — авторизация S05B-A: исследование и перенос анимаций действий NPC

**Статус: `PROPOSED / NOT_AUTHORIZED`** — проект на утверждение продюсеру. До утверждения не исполняется, статусы авторизации не меняются.

**Основание:** [D59](D59-s05a2-limited-acceptance-s05b1-authorization.md) (после S05B-1 — отдельный план действий NPC); план [S05B_NPC_ACTIONS_PLAN_DRAFT](../stages/S05B_NPC_ACTIONS_PLAN_DRAFT.md) ред. 2; уточнения продюсера в чате 2026-11-06 (7 пунктов); [отчёт S05B-1](../reports/S05B1_LOCOMOTION_BATCH_REPORT.md).

## 1. Решение (предлагается)

Авторизовать **S05B-A** — восстановление и перенос оригинальных анимаций действий NPC для 15 видов S05B-1 — в две части с обязательным шлюзом между ними:

* **Часть A — исследовательский пилот трёх семейств:** Cat 0x1e → (после подтверждённого результата) гуманоид-NPC семейства `e66d96be5a` → PlainRunner 0x3f.
* **Часть B — пакетный перенос** на 15 видов S05B-1 — только после подтверждения трёх профилей действий и успешных тестов (шлюз A→B, план §5).

Порядок дальше: после S05B-A — S05B-2 (ходьба остальных семейств), **отдельным решением**.

## 2. Что разрешается

1. **Контролируемые запуски исследовательской копии Alpha** из `.scratch` для захвата NPC в бою (инструменты D55): наблюдение запущенных действий, экипировки и захват итоговых матриц частей. Только копия; `D:\Games\Cube world` — только чтение.
2. Статическое исполнение байтов ИИ-выбора атак (`CombatBehavior_chooseAttack` и связанные ветки) эмулятором; вычисление поз оракулом `drawModel`.
3. Перенос **всех подтверждённых** оригинальных анимаций действий вида, **включая оружие**, если NPC его использует.
4. Изменения конвейера из плана §4: профили `creature_ai`, `ai_trigger.py`, допуск `action_baker`, захват NPC, режим контроллера `ACTIONS` с источником `creature_ai`, тестовый драйвер PlayMode.
5. Только изолированные локальные Unity-проекты в `.scratch`, Unity 6000.3.27f2.

## 3. Обязательные правила

1. **Provenance.** Клип из исполнения исходных байтов — `EMULATED_ALPHA_CODE` **всегда**, в том числе после совпадения с живым захватом; совпадение фиксируется отдельным полем `live_check` (`MATCHED`/`MISMATCH`/`NOT_CAPTURED`). `TRANSFERRED_FROM_ALPHA` — только клипы из непосредственно захваченных матриц.
2. **Запуск по виду.** Набор действий доказывается для каждого вида отдельно; одинаковое семейство drawModel не переносит запуск на другие виды. Действия видов с неподтверждённым запуском **не импортируются** (вид остаётся `LOCOMOTION_ONLY` с причиной).
3. **Экипировка.** Неподтверждённые типы экипировки — отдельные блокеры `BLOCKED: EQUIPMENT_UNVERIFIED`, без заглушек и подмены другим типом.
4. **Шлюз A→B.** Запись `BATCH_AUTHORIZATIONS` для S05B-A добавляется только после подтверждения трёх профилей, всех тестов PASS и регрессии HumanMale 98/98 с прежними числами; результат части A — отчёт `READY_FOR_REVIEW`.
5. **Пороги** оракул↔захват — как у ходьбы (≤ 1e-3 вокселя, ≤ 0.05°); не ослаблять.

## 4. Что не разрешается

* S05B-2 и иные виды вне 15 видов S05B-1; Mole/Zombie/Dragon и прочий видо-зависимый код, боссы, ездовые/питомцы, безногие объекты — отдельная очередь.
* Игровой ИИ, боевые правила, урон, снаряды, эффекты; изменения S04.
* Публикация оригинальных/конвертированных ассетов, поз, захватов Alpha; данные — только в `.scratch`.
* Merge в `main`, force push, удаление удалённых веток.
* Сторонние инструменты сверх D55, права администратора, драйверы, платные сервисы — отдельно.

## 5. Статусы, которые решение не меняет

* **S05B-1 — `READY_FOR_REVIEW`** до отдельной приёмки продюсера (D60 его не принимает).
* S05A-2 — `ACCEPTED (LIMITED)` по D59, без изменений; открытые вопросы OQ-01/02/22/23/24/25/26 и 51/80 `BLOCKED_CONTEXT` — без изменений.
* Технический `PASS` ≠ художественное одобрение; переходы — `UNITY_TRANSITION`; скорости — `PLACEHOLDER_NOT_ALPHA`.

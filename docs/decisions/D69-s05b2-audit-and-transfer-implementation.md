## Обязательная последовательность работы Claude Code

1. **Оригинальная игра — независимый эталон.** Запустить оригинальную Cube World Alpha 2013, изучить все доступные виды моделей/объектов/существ, оригинальные анимации и контексты их применения. Инвентарь заполнять из Alpha, не из Unity/D65. Код и ассеты Alpha дополняют проверку; live и code-only доказательства не смешивать. Для недоступного — `LIVE_UNOBSERVED`, не догадка.
2. **Сравнение — реестр расхождений.** Проверить в нашем Unity-переносе геометрию, цвета, оси, части и все соответствующие оригиналу анимации. Для каждой пары модель/действие: `KEEP / DISABLE_IN_GAME / FIX / ADD_MISSING / UNKNOWN_NEEDS_RESEARCH`.
3. **Инженерный план переноса.** Для каждого `FIX` или `ADD_MISSING` выявить конкретный необходимый механизм: парсер, загрузчик, конвертер, pivot/rig/part hierarchy, динамические части, координаты, тайминг, переходы, attachment/weapon, эффект/снаряд или контроллер. Указать источник данных, изменения API/Unity, зависимости и способ проверки. **Не останавливаться после исследования.**
4. **РЕАЛИЗОВАТЬ.** Claude лично расширяет существующий конвейер Alpha → Unity, пишет/исправляет C#/Python/инструменты и Unity-просмотр/адаптеры в своей stage/review-ветке; переносит отсутствующие модели/варианты/анимации и устраняет подтверждённые дефекты. Не переписывает работающие подсистемы без технической причины и не генерирует фиктивные действия ради формального PASS.
5. **Интеграция и проверка.** Запустить исправленный конвейер, импортировать результат в Unity, сравнить с эталоном Alpha, проверить геометрию, движения/тайминги, анимационные состояния, предписанные неактивные действия и регрессии D65/S02–S04. Дать реальные тесты и локальные визуальные доказательства. Нет доказательства — честный `BLOCKED` с причиной.
6. **Результат:** два каталога (Alpha и матрица Unity), таблица `requirements → code change → test → verdict`, изменённый рабочий конвейер, Unity-проверка, финальный отчёт со статусом `READY_FOR_REVIEW`. В финальном отчёте отдельно: `FIXED`, `TRANSFERRED`, `DISABLED_IN_GAME`, `DEFERRED_TO_M0`, `BLOCKED`.

## Границы

- **Декоративные растения, цветы, кусты и яйцо** в будущей игре не ходят и не атакуют; отключать **использование** этих действий, не удалять исследовательские данные и не отрицать факты оригинала. Растительные враги — отдельная категория.
- **Допускается:** изменение конвертера, анимационного пайплайна, адаптера, редактора просмотра, данных/схем ролей, тестов в границах S05B-2. Допускаются минимальные работающие Unity-хуки/контракты анимаций, чтобы доказать перенос, но **не** реализация полноценного мира/NPC AI/квестовой механики из M0.
- Если анимация зависит от ещё не реализованной игровой системы (падение предмета, эффект/снаряд, триггер AI), перенести **саму визуальную анимацию и рабочий метод её вызова** на тестовой сцене, а подключение к конкретной игровой механике обозначить `DEFERRED_TO_M0` с контрактом. Нельзя называть перенос завершённым, если сама анимация/эффект ещё отсутствует.
- При доказанной технической невозможности — зафиксировать `BLOCKED`, самостоятельные попытки решения и минимальный требуемый следующий шаг; не фабриковать `PASS`. Не приписывать результатам происхождение `TRANSFERRED_FROM_ALPHA` без реального переноса.
- Один рабочий каталог `D:\Projects\CubeGame`, Claude получает эксклюзивный локальный слот для реализации/Alpha/Unity; DeepSeek одновременно не работает в нём, никакого дополнительного clone/worktree без решения. Ветка своя; `main`, принятый S04 и чужие ветки не менять; без force-push/merge; исходные/производные ассеты Alpha только локально, не публиковать.

# D72 — Проверка и исправление переносимых систем непосредственно в Unity

**Дата:** 2026-11-09. **Статус:** APPROVED_BY_PRODUCER (методика и ограниченный Unity-проверочный контур; не приёмка M0/S05).

## Решение продюсера

1. **Новых Git worktree не создавать.** Использовать существующие `D:\Projects\CubeGame` (Claude) и `D:\Projects\CubeGame-deepseek` (DeepSeek). То, что две сессии ранее использовали один worktree, не считать доказательством поломки или поводом требовать дополнительный worktree; опубликованные результаты независимы. Перед Git-командами проверять рабочее дерево и активные процессы; не сбрасывать и не перезаписывать чужие изменения. Согласовывать операции checkout/commit, если обе сессии используют одну директорию.
2. **Перенос в Unity оценивается в самом Unity.** Для всех реализуемых Alpha-механик обязательна цепь: исходный эталон (код/данные/позы/доказательства Alpha) → C#/Unity реализация → фактический EditMode/PlayMode тест и/или визуальная сцена → сравнение с эталоном → исправление в Unity → повторная проверка. Проверки Python/Mono являются входными, но **не заменяют Unity-валидацию**.
3. Область включает **предметные модели, якоря/слоты, анимации, бой и численные формулы**, затем доступные движения, мир/seed/region, NPC, сохранения и другие подтверждённые механики. Поза предмета и поза тела, расчёт урона и фактическое изменение HP, модель NPC и его действие — проверяются совместно, где связь уже доступна.
4. Два подготовленных пакета DeepSeek — `deepseek/m0-00b-item-layer` @ `1de4bb54` и `deepseek/m0-00-full-systems-preparation` @ `15bd9891` — соединяются только в отдельной **интеграционно-проверочной Git-ветке**, без merge в `main` и без признания их ранее принятыми.
5. **Разрешена предметная Unity-интеграция и проверка в существующем Unity-проекте в отдельной ветке**, с тестовой сценой/контролируемыми адаптерами и откатом изменений внутри своей ветки. Это отдельная проверочная задача **M0-00U**, а не автоматическое разрешение production-этапов M0-01…M0-09; M0-00D остаётся DRAFT, S05B-2 — не ACCEPTED до решения продюсера.
6. Экземпляры Alpha-ассетов остаются локальными в `.scratch` и не публикуются в Git. Оригинальная Alpha — read-only; повторный запуск оригинальной игры отдельно согласовывать. Если прямого эталона нет — статус `PARTIAL/UNKNOWN`, нельзя объявить `ALPHA_PARITY_PASS` по собственному тесту.
7. Пока Claude выполняет регрессию, DeepSeek может реализовывать и тестировать независимый Unity-проверочный контур при отсутствии одновременной записи в одни файлы и конкуренции Unity/Library/ресурсов. Нельзя менять/закрывать результаты Claude без handoff. Ревью Claude и приёмка продюсера — отдельно.

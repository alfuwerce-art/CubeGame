# D63 — полный пакетный проход по моделям и анимациям Alpha без ручных шлюзов между семействами

**Дата:** 2026-11-06
**Статус:** **ACCEPTED** — решение продюсера: «я думал мы сейчас будем переносить сразу все». 
**Исполнитель:** DeepSeek Harness. **Базовая техническая версия:** D61 TECHNICAL-FIX `31799a90d399bc31a99af89286beeeab86d80e1d`; инфраструктурное разрешение D62 сохранено.
**Приоритет над D62:** отменяется требование **остановиться после одного нового семейства и ждать ручной приёмки перед следующей партией**. При этом сохраняются автоматические проверки, периодические отчёты, provenance, ограничения на публикацию и индивидуальная визуальная приёмка перед включением в готовую игру.
**ТЗ:** [S05B2_DEEPSEEK_BATCH_SPEC.md](../stages/S05B2_DEEPSEEK_BATCH_SPEC.md), раздел «D63 полный каталог».
**Исходная ветка D63:** `review/d63-full-catalog-bulk-transfer`. Рабочая ветка DeepSeek — `stage/s05b2-deepseek-batch` от этого HEAD либо безопасно интегрировать D63 в уже созданную stage-ветку (без потери локальных правок).

## 1. Поручение: ВСЯ локально доступная библиотека, а не очередной пилот

1. **Полностью инвентаризовать** каталог оригинальной Alpha, в том числе все модели `.cub` и их ссылки/варианты из `data1–4.db`. Исторический S00-R01 подсчёт — 2857 `.cub`; проверить актуальное реальное число, не считать подсчёт готовыми моделями. Включить персонажей, NPC, монстров, животных, боссов, оружие, броню, предметы, пропсы и объекты окружения, если их исходные модели доступны. Разделить реестр сущностей и реестр статичных моделей; не требовать «анимацию» у статичного пропса.
2. **Автоматически прогнать** максимум поддерживаемых исходных моделей через конвертер для локальных Unity-пилотов, сохранять исходную геометрию/цвета/маркеры/tint/part flags. Для всех анимируемых сущностей попробовать восстановить и проверить применимые idle/walk/actions/equipment/visibility/lifecycle на основании доказанного кода/семейства. Никаких обещаний 100% завершения и никаких выдуманных анимаций.
3. Прогон **всего каталога в одну задачу**, но с внутренним разбиением на управляемые партии/семейства, записью manifest, checkpoint, SHA256, resume и сбросом/повтором отдельной неуспешной записи. **Не останавливаться после первого семейства в ожидании продюсера**, продолжать до обработки каждого элемента каталога либо документированного блокера. 
4. Включить **отдельную полную таблицу анимационных состояний** для каждого семейства/существа: тип/код действий, источник и trigger доказательство, успешно перенесено/не подтверждено/не применимо/блокировано. Не считать «все анимации перенесены» на основании успешной ходьбы.
5. Если встречается новый риг/тип модели, автоматически создать отдельный тестовый exemplar и контактный лист для последующего личного просмотра; не делать ручной просмотр обязательной паузой обработки остальных видов.
6. Обрабатывать оружие/броню/предметы/пропсы настолько, насколько позволяет реальный конвертер. Если специальный класс пока не поддерживается (например, rig/attachment), зафиксировать кодируемый блокер; не изобретать совместимость. Разграничить **static geometry imported**, **animated entity in Unity**, **animation recovered** и **gameplay integrated**.

## 2. Исполнительские границы

- Claude Code техническую стабилизацию завершил; DeepSeek отвечает за полный одноразовый прогон и устранение **типовых** ошибок конвейера. Сложные reverse-engineering и архитектурные проблемы направляются в отдельный список для Claude; они не отменяют обработку остальных видов.
- Массовое исполнение разрешено до конца без промежуточного ручного утверждения. **Единственная обязательная ручная приёмка — финальная техническая/визуальная оценка результатов до закрытия S05B-2 и включения в игру**, с возможной последующей точечной доработкой; никаких автоматических ACCEPTED.
- Блокеры вида и анимации нельзя замалчивать; при угрозе корневой порчи данных/регрессии/источника Alpha остановить затронутый этап и обеспечить безопасность, остальные независимые категории продолжать.
- Доказательство `EMULATED_ALPHA_CODE` — из исполнения кода, `live_check=NOT_CAPTURED`, без обязательного поиска NPC в живой Alpha; `TRANSFERRED_FROM_ALPHA` только при реальном capture. `AUTO_READY` не является `UNITY_PASS`.
- Не генерировать фиктивные клипы, не занижать пороги, не утверждать оригинальные скорости, оружие и графику без фактов. Сохранять исправления D61 и регрессии.
- `D:\Games\Cube world` — только чтение. Рабочая папка одна: `D:\Projects\CubeGame`, без одновременного редактирования Claude и DeepSeek. Локальные полученные модели и другие производные данные Alpha остаются в игнорируемой `.scratch`, **не коммитятся/не публикуются/не включаются в конечный дистрибутив**. Код, списки и отчёт — в отдельной stage-ветке. Main/S04/merge/force push не разрешены.

## 3. Результат одного полного массового прогона

- **Модельный манифест:** общая численность, уникальные `.cub`, варианты, категории, декодированы/Unity импортированы/неизвестно/заблокированы/не применимо, точные причины.
- **Анимационный манифест:** виды/семейства/действия со статусом отдельно для ригов, ходьбы, анимаций и экипировки; список неподдержанного и доказательств.
- **Суммарный отчёт:** фактически Unity PASS, частичные, BLOCKED, FAILED и доля охвата; оценка самостоятельных блокеров Claude; Python и Unity регрессии; local contact sheets + viewer, проверяемые seed/параметры, сохранённые логи.
- Git ветка/коммит и отчёт `READY_FOR_REVIEW`, ожидание личной оценки продюсера **после всего прогона**, не между семействами.

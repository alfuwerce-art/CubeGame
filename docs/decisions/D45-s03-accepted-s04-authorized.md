## 4. Границы S04-EQUIPMENT-COMBAT

**Разрешено:** слоты экипировки (MainHand, OffHand, Chest, Gloves, Boots, Shoulders), агрегация характеристик надетых предметов через существующие вычислители, адаптер `CharacterSheet + Equipped Items → CombatAttack`, согласование с HP-моделью, техническая Unity-демонстрация смены оружия/брони.

**Запрещено:** параллельная система статов; двойное масштабирование уровня; подстановка `Armor`/`BlockValue` в бонус HP ради совпадения с числом 268 (OQ-25 `OPEN`); автоматическое включение частичных механик (модификатор попадания по подтипу, множители ID атак); изменение порядка RNG; изменение формата сохранений; инвентарь, drag-and-drop, модели, анимации, VFX, AI, хитбоксы; URP; запуск Alpha; merge в `main`; force push; самостоятельное присвоение S04 статуса `ACCEPTED`.

## 5. Правила достоверности для S04

1. **Никакого двойного `levelFactor`.** `ItemStatsCalculator.WeaponDamage` уже содержит множитель уровня предмета и редкость; `CharacterStats.CalcWeaponDamage` умножает на множитель уровня персонажа. Готовое значение урона предмета нельзя передавать как `WeaponBase`.
2. **Подтверждённый путь (E2):** `stat_calcWeaponDamage = base(0x180)·levelFactor + flags + список item_weaponDamage`. Значит вклад предмета — **аддитивный** член, а не новая база; адаптер CubeGame обязан быть помечен `PARTIAL`, пока порядок не подтверждён полностью.
3. **Защита (E3):** слоты брони добавляют `item_computeBlockValue()`; `item_computeStat_armor` (Armor) — отдельная величина. Смешивать их запрещено; `TargetArmor` формируется только через документированный адаптер.
4. **HP (OQ-25 `OPEN`):** `EquipmentHealthBonus` остаётся явным входом. Если MaxHP не меняется при смене экипировки — это допустимо и фиксируется как ограничение.
5. **Правила двуручного оружия, сочетаний оружия/щита, классовых ограничений и двух атакующих рук не утверждены.** Специальные сочетания не получают автоматического эффекта; вопрос фиксируется как открытый.

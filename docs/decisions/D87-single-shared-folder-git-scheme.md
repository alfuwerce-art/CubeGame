## 4. Протокол координации

Единый канал — `docs/agents/AGENT_COORDINATION.txt`. Форматы записей: `CLAIM` (беру файл/задачу), `RELEASE`, `HANDOFF` (передаю интерфейс/SHA), `QUESTION`, `ANSWER`, `CONFLICT`, `REPORT`. Файл ведётся **только дописыванием в конец**, шапка не переписывается; одновременная правка одного файла двумя агентами запрещена. GitHub issues остаются для внешнего ревью по SHA и не заменяются.

## 5. Git-схема

1. Одна долгоживущая ветка `integration/m0` в `D:\Projects\CubeGame`. Других рабочих веток в этом каталоге не создавать без решения продюсера.
2. Один атомарный пакет работы = один коммит (или небольшая серия) с префиксом агента: `[claude] …`, `[deepseek] …`, `[codex] …`. В сообщении — затронутая подсистема и SHA базы, если пакет длинный.
3. Перед коммитом: `git status` (не должно быть чужих файлов), адресные тесты, запись в координационный файл.
4. Push — своей работы в `origin/integration/m0` после завершённого пакета; чужую работу не пушить и не «дочинять».
5. Слияние веток — только по решению продюсера и только управляемым шагом; `main` не трогать; force-push запрещён.
6. Если у другого агента есть незакоммиченные изменения, второй не делает `checkout`/`merge`/`rebase`/`reset` в общем каталоге.

## 6. Слот Unity и тяжёлые запуски

Unity Editor, `-batchmode` прогоны, генерация локального кэша и импорт ассетов — **по одному слоту**. Захват слота — запись `CLAIM unity` в координационном файле с временем и целью; освобождение — `RELEASE unity`. Пока слот занят, второй агент работает только с текстом/документами, не запускает Unity и не гейтит `Library/`.

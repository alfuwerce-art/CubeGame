# D93 — CubeGame разрабатывается как собственная игра (development pivot)

**Дата:** 2026-11-17
**Решение продюсера:** да — прекращён active target полного переноса Cube World Alpha 2013; CubeGame разрабатывается как самостоятельная игра.
**Источник:** [ROADMAP_DRAFT.md](../planning/ROADMAP_DRAFT.md), коммит `4e36f1539d787e6a03f85d1f9fc92efcb1b64a79`; задача G0 (`docs/ACTIVE_STAGE.md`).
**Статус направления:** `APPROVED`
**Статус записи в реестре решений:** `PROPOSED CHANGE_REQUEST` — см. §5.

## 1. Что решено

1. Alpha 2013 больше не является спецификацией CubeGame. Она используется как источник исследований, алгоритмов, формул и инженерных референсов там, где существует конкретный вопрос CubeGame.
2. Старый `M0 ALPHA FULL UNITY PORT` переводится в `LEGACY / RESEARCH BASE / NOT A RELEASE TARGET`. P7/P8/P9/P10 не продолжаются.
3. Уже созданный код, тесты, отчёты, decompilation evidence и инструменты сохраняются. Главный принцип — `REUSE BEFORE REWRITE`.
4. Порядок этапов — G0…G15 по новой дорожной карте: G0 pivot → G1 Technical Foundation → G2 World Foundation → G3 Character & Creature Factory → G4…G8 gameplay → G9…G12 production → G13…G15 Alpha/Beta/RC.
5. GDD, идея игры и утверждённые игровые решения не пересобираются.

## 2. Что НЕ решено этой записью

- Не изменяется ни один текст `DECISIONS_001-036.md`.
- Не утверждается новая игровая механика, новый визуальный стиль или новая архитектура.
- Не принимается решение о судьбе конкретных legacy-веток кода (merge / rewrite / drop) — это задача G1 и продюсера.
- Не принимается решение о правовом режиме Alpha-производных данных в продукте (таблицы `Content/Generated`, модели `.cubdec`, каталог 93 звуков) — открытый вопрос продюсера.

## 3. Почему D92 больше не является активной схемой

D92 (2026-11-11) объявлял целью M0 полный перенос Alpha в Unity со строгой цепочкой `FIND ORIGINAL CODE → … → COMPARE WITH ORIGINAL`. С 2026-11-17 этот критерий не является обязательным для продукта: он остаётся корректным описанием метода, применённого к legacy-работе, и полезным инструментом, когда конкретный механизм решено воспроизвести (`ALPHA_VERIFIED`).

## 4. Совместимость с D01 / D14 / D20 — открытый пункт

Решения D01, D14 и D20 формулируют первый крупный результат как «максимально близкое соответствие Alpha 2013» и делают parity критерием приёмки первой полной версии. Это положение относится к способу разработки, а не к содержанию игры, и после 2026-11-17 не действует.

По правилу самого реестра («Контроль изменений») правка утверждённых решений вносится только записью `CHANGE_REQUEST` с решением продюсера. Поэтому:

- данный файл фиксирует `PROPOSED CHANGE_REQUEST`;
- текст D01/D14/D20 не изменяется;
- до решения продюсера действует формулировка [planning/README](../planning/README.md) §3: parity-first метод D01/D14/D20 заменён pivot-решением 2026-11-17, игровое содержание D01/D14/D20 сохраняется.

Предлагаемая формулировка правки (на утверждение продюсера):

> D01/D14 — цель первого крупного результата: играбельная CubeGame с собственным вертикальным срезом; степень сходства с Alpha 2013 определяется решениями этапов, а не является обязательным критерием.
> D20 — приёмка первой полной версии идёт по критериям G8/G13 дорожной карты, а не по близости к системе Alpha.

# D44 — S02-CORE-FOUNDATION принят; авторизован этап S03-COMBAT-CORE

**Дата:** 2026-11-03. **Автор решения:** продюсер. **Зафиксировал:** DeepSeek Harness (исполнитель), без самоприёмки.
**Статус:** `ACCEPTED` (решение продюсера, переданное в задаче `S02-CLOSE-AND-S03-COMBAT-CORE-01`).
**Связанные решения:** [D42](D42-alpha-numbers-as-references.md) (числа Alpha как референсы, `ACCEPTED`), [D43](D43-close-s00-s02-core-foundation.md) (закрытие S00 и авторизация S02), [ADR-0001](../architecture/ADR-0001-modular-monolith.md) (модульный монолит).

## 1. Что решено

1. **`S02-CORE-FOUNDATION` → `ACCEPTED`.** Приёмка этапа состоялась 2026-11-03.
2. Результаты архитектурного ревью ChatGPT — `PASS` — приняты.
3. Четыре модуля S02 (Progression, Character Stats, Items Foundation, Persistence Foundation) становятся технической основой дальнейшей разработки.
4. Открытые исследовательские вопросы сохраняются без изменения степени достоверности (OQ-22, OQ-23, OQ-24, OQ-25, OQ-26; неизвестные множители атак; частично подтверждённая seed-арифметика).
5. Авторизуется новый ограниченный этап **`S03-COMBAT-CORE`** — первая партия реализации боевой системы.

## 3. Границы S03-COMBAT-CORE

**Разрешено (только это):**

- Минимальное боевое ядро в `CubeGame.Core` (чистый C#, без UnityEngine): формулы урона, проверка попадания, снижение урона бронёй/блоком, пул здоровья, результат удара.
- Исправление некритичного замечания S02: единая валидация `ItemModifier` в конструкторе `ItemInstance`.
- Минимальная Unity-интеграция и техническая демонстрация удара с выводом в лог.

**Запрещено:** AI/NPC, полная система навыков, новые классы и баланс, анимации и VFX, переделка генерации мира, URP, инвентарь/лут, запуск Alpha без нового разрешения, копирование закрытого кода и ассетов, merge в `main`, force push, самостоятельное присвоение S03 статуса `ACCEPTED`.

## 4. Обязательные ограничения достоверности

| Механика | Статус | Что это значит |
|---|---|---|
| `calcWeaponDamage` (база, `levelFactor`, флаги апгрейдов) | `REFERENCE_VERIFIED` | реализуется как в S02, тесты по эталону |
| Разброс урона `1.25 − 0.5·roll/32767` | `STRONGLY_SUPPORTED` | реализуется, диапазон 0.75…1.25, RNG только через интерфейс |
| Проверка попадания `roll/32767 < chance` | `REFERENCE_VERIFIED` | `chance` передаёт вызывающий код |
| Модификаторы шанса по подтипу оружия (`×0.5`, `×0.3`) | `PARTIAL` | реализуются отдельной функцией с пометкой; семантика ветвей не доказана |
| Множители по числовым ID атак (`0x57 ×50`, `0x5B ×2`, `0x5D ×5`, `0x60 ×3`) | `PARTIAL` | **не** применяются по умолчанию: только по явному флагу вызывающего кода; названия/назначение способностей не установлены |
| Снижение урона `rawDamage − blockFraction·armor`, кламп 0 | `PARTIAL` | контрольный случай 30 / 10 / 0.5 → 25 проверяется как частичная формула |
| Порог блока `int(curve05(L)·100 + 1)` | `REFERENCE_VERIFIED` (формула), `PARTIAL` (полный алгоритм блока) | реализуется функция порога и броска |
| Базовая формула `chance` | `UNKNOWN` (OQ-01) | **не** придумывается: передаётся явно |
| `blockFraction` из боевой серии (`+0x70`, OQ-24) | `PARTIAL` | передаётся явно, автоматическое получение не реализуется |
| Seed-арифметика для больших/отрицательных seed | `PARTIAL` | воспроизводится Python-эталон, не догадка |

## 5. Следствия

1. Активный этап — `S03-COMBAT-CORE`, ветка `stage/s03-combat-core` от принятого коммита S02; статус по завершении партии — `READY_FOR_REVIEW`, не `ACCEPTED`.
2. S02 больше не переоткрывается без отдельного решения продюсера; его дефекты фиксируются как новые задачи.
3. OQ-01/OQ-02/OQ-24/OQ-25/OQ-26 **не закрываются** в S03 без новых доказательств.
4. `main` не затрагивается: merge остаётся отдельным решением продюсера.

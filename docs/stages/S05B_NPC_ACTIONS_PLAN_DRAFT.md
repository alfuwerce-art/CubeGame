# S05B-A — восстановление и перенос анимаций действий NPC (план)

**Статус: `AUTHORIZED` по [D60](../decisions/D60-s05ba-npc-actions-authorization.md)** (утверждено 2026-11-06): часть A — сразу, часть B — после шлюза A→B (§5). Ред. 2 — внесены 7 уточнений продюсера от 2026-11-06.
**Основание:** [D59](../decisions/D59-s05a2-limited-acceptance-s05b1-authorization.md) (план действий NPC после S05B-1); [отчёт S05B-1](../reports/S05B1_LOCOMOTION_BATCH_REPORT.md) — `READY_FOR_REVIEW`, не принят.
**Автор:** Claude Code. **Рабочее имя:** S05B-A. Не путать с S05B-2 (ходьба семейств «только по формуле»), который идёт **после** S05B-A.

## 1. Цель

Для 15 видов S05B-1 (геометрия + риг + ходьба/покой уже в Unity) перенести **все подтверждённые оригинальные анимации действий**, которые Alpha реально запускает у вида: атаки, способности, уклонения, удерживаемые состояния, **включая оружие**, если NPC его использует. Каждая поза и каждый запуск — с доказанным происхождением.

Не цель: игровой ИИ, боевые правила, урон, снаряды, эффекты, звук (игровая логика CubeGame, G2 в [G_H_ai_npc_pets](../research/alpha2013/BEHAVIOR_SPECS/G_H_ai_npc_pets.md) — `PROPOSED`).

## 2. Что уже известно

| Звено | Что есть | Статус |
|---|---|---|
| Поза по состоянию | Одна функция `Creature_drawModel` рисует всех существ; офлайн-оракул ([alpha_oracle.py](../../tools/alpha_models/universal/alpha_oracle.py)) исполняет её байты для **любого** вида и сверен с захватами до точности float | ДОКАЗАНО для ходьбы трёх семейств и действий HumanMale |
| Действие → состояние drawModel | Таблица на 110 кодов действий ([anim_states.py](../../tools/alpha_models/universal/anim_states.py)); входы: действие `+0x68`, оружие `+0xaa8/9`, вторая рука `+0x990/1`, флаг `+0x130`. **Вид в таблицу не входит** | ДОКАЗАНО (исполняются байты Alpha) |
| Длительность и фазы | `combat_getAttackTiming`, таймер `+0x6c`; у гуманоида перенесено 98 действий | ДОКАЗАНО для гуманоида-образца |
| Какие действия запускает ИИ вида | `CombatBehavior_chooseAttack` (`0x4456A0`): серия ударов (порог 5), уклонение, зелье, спец-ветки по видам (0x65, 0x74, 0x76, 0x77, 0x2f/0x6f/0x70/0x71), часть списков — из экипировки | `PARTIAL`: **набор действий по видам не известен** |
| Экипировка NPC | ИИ берёт атаки и из экипировки; в конвейере проверено только двуручное оружие гуманоида | НЕИЗВЕСТНО для NPC |
| Видо-зависимый код drawModel | Mole 0x57, Zombie 0x60, Dragon 0x65 | очередь исключений |

**Вывод:** позы любой пары «вид × состояние» вычисляются кодом самой Alpha. Неизвестно, **какие действия и с какой экипировкой запускает каждый вид**. Поэтому этап начинается с запусков: без них существу можно приписать чужие анимации.

## 3. Три пути доказательства

**П1. Статический запуск (без Alpha).** Исполнить байты `CombatBehavior_chooseAttack` и связанных веток эмулятором (`drawmodel_emu.EmuCPU`), как для таблицы состояний, — не переписывая код вручную. Перебор входов: вид, фракция `+0x60`, дистанция до цели, счётчик серии `+0x70`, таймеры, экипировка. Внешние вызовы (`rand`, путь, дерево угроз) — контролируемые заглушки **входов** эмулятора, каждая перечислена в отчёте. Итог — набор действий вида с условиями и адресом ветки. Ветка, требующая неизвестного состояния мира, — `PARTIAL` с причиной.

**П2. Позы через оракул (без Alpha).** Для каждой пары (вид, действие) из П1 — состояние и поза по кадрам через `drawModel`; проверки [action_baker.py](../../tools/alpha_models/universal/action_baker.py): полный таймлайн, неизменный набор частей (кроме объявленных динамических), конечные TRS, возврат к покою. Неподдержанный участок отрисовки → `BLOCKED`.

**П3. Живой захват (разрешается D60).** Контролируемый запуск исследовательской копии Alpha из `.scratch` (инструменты D55): NPC в бою, захват итоговых матриц частей (как для HumanMale), сравнение с оракулом и наблюдение фактически запущенных действий и экипировки.

### Provenance (уточнение 5)

| Источник клипа | Provenance клипа | Что добавляет живой захват |
|---|---|---|
| Матрицы, непосредственно захваченные из Alpha | `TRANSFERRED_FROM_ALPHA` | — |
| Исполнение исходных байтов (оракул) | `EMULATED_ALPHA_CODE` — **всегда**, и после совпадения с захватом | поле `live_check` = `MATCHED` / `MISMATCH` / `NOT_CAPTURED` со ссылкой на захват и отклонением |
| Формула/тайминги по доказательствам | `RECONSTRUCTED_FROM_EVIDENCE` | — |

Совпадение с захватом не повышает provenance эмулированного клипа; оно повышает **доверие** (`live_check`). Значения — только из `CLIP_PROVENANCE` контракта.

### Статус запуска действия у вида (отдельно от provenance)

| Доказано | `trigger_status` | В Unity |
|---|---|---|
| П1 (ветка с адресом) **для этого вида** + наблюдение в П3 | `TRIGGER_OBSERVED` | импортируется |
| П1 для этого вида, без наблюдения | `TRIGGER_EMULATED` | импортируется |
| Поза есть, запуска у этого вида нет | `BLOCKED: TRIGGER_UNPROVEN` | **не импортируется** |
| Экипировка NPC не подтверждена | `BLOCKED: EQUIPMENT_UNVERIFIED <тип>` | не импортируется, без заглушек |
| Видо-зависимый код / неподдержанная отрисовка | `BLOCKED` с причиной | не импортируется |

**Уточнение 6:** набор действий доказывается **для каждого вида отдельно**. Одинаковое семейство drawModel даёт совместимость поз, но не запуск: например, профиль кота 0x1e не переходит на BrownCat 0x1f/WhiteCat 0x20, пока П1 не покажет для них те же условия запуска.

### Экипировка (уточнение 3)

Если NPC запускает действие с оружием — переносится и оружие: модель, крепление, хват по геометрии (механизм `primaryGrip`/`secondaryGrip` S05A-2). Тип/подтип оружия, отсутствующий в `VERIFIED_WEAPON_SUBTYPES`, сначала проходит отдельную проверку (геометрия, крепление, состояние drawModel); до неё — `BLOCKED: EQUIPMENT_UNVERIFIED`. Заглушки оружия и подмена другим типом запрещены.

## 4. Изменения в конвейере

* **Профили действий** — новые записи `ACTION_PROFILES` с `trigger: "creature_ai"`; `specimens` — **только виды, для которых П1 доказан**. Правила ввода игрока на NPC не переносятся.
* **`ai_trigger.py`** (новый): П1 — исполнение веток выбора атаки; выдача `jobs/<вид>_actions.json` с условиями, адресами веток, заглушками.
* **`action_baker`**: допуск по профилю `creature_ai`; провенанс и `live_check` раздельно.
* **Захват**: инструменты захвата HumanMale для NPC (выбор существа по `kind`, а не игрока).
* **Unity**: контроллер `ACTIONS` с источником `creature_ai`; тестовый драйвер PlayMode проигрывает набор действий вида (покой → действие → покой → ходьба). **Не игровой ИИ**; S04 не трогается.
* **Пакет**: новая область `batch_runner.SCOPES` и запись `BATCH_AUTHORIZATIONS` — **только** после подтверждения шлюза A→B (§5).

## 5. Две части этапа (уточнение 7)

### Часть A — исследовательский пилот трёх семейств

| Шаг | Вид | Что | Шлюз перехода |
|---|---|---|---|
| A1 | Cat 0x1e | П1 → П2 → Unity-пилот → П3 (живой захват в бою) | профиль кота подтверждён (§6), тесты PASS |
| A2 | гуманоид-NPC семейства `e66d96be5a` (конкретный вид выбирается по П1: тот, чей ИИ-запуск исполняется полнее) | то же + оружие, если NPC его использует | профиль подтверждён, тесты PASS |
| A3 | PlainRunner 0x3f | то же | профиль подтверждён, тесты PASS |

Переход A1 → A2 только после подтверждённого результата по коту (уточнение 2). Итог части A — отчёт `READY_FOR_REVIEW` с тремя профилями.

### Шлюз A → B

Часть B начинается только если: три профиля подтверждены; все тесты PASS; регрессия HumanMale 98/98 с прежними числами; продюсер получил отчёт части A. Решение о шлюзе фиксируется в отчёте; запись `BATCH_AUTHORIZATIONS` для S05B-A добавляется только после этого.

### Часть B — пакет на 15 видов S05B-1

Исполнитель как в S05B-1 (SHA256, возобновление, шлюз фаз, сводка, контактные листы действий). Для каждого из 15 видов отдельно — П1; П2 и импорт только для `TRIGGER_OBSERVED`/`TRIGGER_EMULATED`. Виды без доказанного запуска остаются `LOCOMOTION_ONLY` с причиной. Новые захваты Alpha в части B — только для видов, где П1 дал `PARTIAL` и захват может его разрешить, по одному на вид.

**После S05B-A** — S05B-2 (ходьба остальных семейств), отдельным решением (уточнение 4).

**Исключения (вне пакета):** Mole, Zombie, Dragon и прочий видо-зависимый код; боссы (`creature_isBossType`); неподтверждённые типы экипировки; ездовые/питомцы; 39 безногих объектов.

## 6. Критерии подтверждения профиля и приёмки

1. Таблица действий вида: код, адрес ветки П1, условия, заглушки входов, `trigger_status`, provenance, `live_check`. Нет импортированного действия без адреса ветки для **этого** вида.
2. Оракул vs живой захват: ≤ 1e-3 вокселя и ≤ 0.05° на всех кадрах (пороги ходьбы). Расхождение — `MISMATCH` с разбором, порог не ослабляется.
3. Клип: полный таймлайн, конечные TRS, возврат к покою; длительность — из `combat_getAttackTiming`.
4. Оружие NPC: только подтверждённые типы; хват по геометрии, проверка как GRIP S05A-2.
5. Unity PlayMode 30/60/120 Гц: все импортированные действия проиграны, переходы `UNITY_TRANSITION`, дрейф покоя 0.
6. Отказные тесты: вид без профиля не получает клипов; профиль одного вида не применяется к другому виду семейства; `creature_ai` не включает действия ввода игрока; `TRANSFERRED_FROM_ALPHA` у эмулированного клипа — ошибка валидации; неподтверждённое оружие → `BLOCKED`.
7. Регрессия HumanMale — 98/98 при 30/60/120 Гц с прежними числами; S05B-1 — без изменений.
8. Данные Alpha, захваты, кадры — только в `.scratch`; в Git — код, тесты, отчёты.

## 7. Риски

* Ветки ИИ зависят от мира (цель, путь, вода/полёт) — часть наборов останется `PARTIAL`; не заменять догадками.
* Живой захват NPC требует найти и спровоцировать врага в копии Alpha; клавиатура в D56 была `PARTIAL`. Неудачный захват — `live_check = NOT_CAPTURED`, статус честный.
* Экипировка NPC может открыть много новых типов оружия — каждый отдельный блокер.
* Эффекты и снаряды — не позы частей, вне этапа.

## 8. Границы

До утверждения D60 ничего не исполняется; `BATCH_AUTHORIZATIONS` остаётся `(("D59","s05b1"),)`. Всегда: не менять S04, не публиковать ассеты/позы/захваты Alpha, не делать merge в `main`, `Cube.exe` запускать только из копии `.scratch` и только в рамках П3.

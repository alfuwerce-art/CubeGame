# План: восстановление и перенос анимаций действий NPC (черновик)

**Статус: `DRAFT / NOT_AUTHORIZED`.** Это план, а не разрешение. Требуется по [D59](../decisions/D59-s05a2-limited-acceptance-s05b1-authorization.md) после S05B-1 ([отчёт](../reports/S05B1_LOCOMOTION_BATCH_REPORT.md), `READY_FOR_REVIEW`).
**Дата:** 2026-11-06. **Автор:** Claude Code. **Рабочее имя этапа:** S05B-A (действия NPC); номер присвоит продюсер. Не путать с S05B-2 «ходьба семейств только по формуле» из рекомендаций [S05A2_UNIVERSAL_CONTINUATION_REPORT](../reports/S05A2_UNIVERSAL_CONTINUATION_REPORT.md) §7.

## 1. Цель

Для существ, уже перенесённых в Unity (геометрия + риг + ходьба/покой), перенести **анимации действий** (атаки, способности, уклонения, удерживаемые состояния), которые Alpha реально запускает у этого вида, — с доказанным происхождением каждой позы и каждого запуска.

Не цель: игровой ИИ, боевые правила, урон, снаряды, эффекты, звук. Это игровая логика CubeGame, решается отдельно (G2 в [G_H_ai_npc_pets](../research/alpha2013/BEHAVIOR_SPECS/G_H_ai_npc_pets.md) — `PROPOSED`).

## 2. Что уже известно

| Звено | Что есть | Статус |
|---|---|---|
| Поза по состоянию | Одна функция `Creature_drawModel` рисует всех существ; офлайн-оракул ([alpha_oracle.py](../../tools/alpha_models/universal/alpha_oracle.py)) исполняет её байты для **любого** вида и сверен с захватами до точности float | ДОКАЗАНО для ходьбы трёх семейств и действий HumanMale |
| Действие → состояние drawModel | Таблица на 110 кодов действий ([anim_states.py](../../tools/alpha_models/universal/anim_states.py)); входы: действие `+0x68`, оружие `+0xaa8/9`, вторая рука `+0x990/1`, флаг `+0x130`. **Вид в таблицу не входит** | ДОКАЗАНО (исполняются байты Alpha) |
| Длительность и фазы | `combat_getAttackTiming`, таймер `+0x6c`; у гуманоида перенесены 98 действий | ДОКАЗАНО для гуманоида-образца |
| Какие действия запускает ИИ вида | `CombatBehavior_chooseAttack` (`0x4456A0`): серия ударов (порог 5), уклонение, зелье, спец-ветки по видам (0x65, 0x74, 0x76, 0x77, 0x2f/0x6f/0x70/0x71), часть списков — из экипировки | `PARTIAL`: известны шаги, **не известен набор действий по видам** |
| Экипировка NPC | ИИ берёт атаки и из экипировки; в конвейере проверено только двуручное оружие гуманоида | НЕИЗВЕСТНО для NPC |
| Видо-зависимый код drawModel | Mole 0x57, Zombie 0x60 (по 6 проверок `kind !=`), Dragon 0x65 (якорь головы и прицел) | очередь исключений |

**Вывод:** позы для любого пары «вид × состояние» Alpha можно вычислить её же кодом. Неизвестно другое: **какие действия и с какой экипировкой запускает каждый вид**. Сейчас поэтому у 7 видов семейства гуманоида стоит `POSES_FAMILY_COMPATIBLE_TRIGGER_UNPROVEN`, у 148 — `NO_VERIFIED_ACTION_TRIGGER`. Перенос поз без доказанного запуска означал бы приписать существу чужие анимации, поэтому план начинается с запусков.

## 3. Метод: три пути доказательства

**П1. Статический запуск (без Alpha).** Исполнить байты `CombatBehavior_chooseAttack` и связанных веток тем же эмулятором (`drawmodel_emu.EmuCPU`), как уже сделано для таблицы состояний, а не переписывать код вручную. Перебрать входы: вид, фракция `+0x60`, дистанция до цели, счётчик серии `+0x70`, таймеры, экипировка. Внешние вызовы (`rand`, поиск пути, дерево угроз) — контролируемые заглушки; каждая заглушка фиксируется в отчёте. Итог — **набор действий вида** с условиями. Ветка, которую нельзя исполнить без неизвестного состояния мира, — `PARTIAL` с названием причины, не догадка.

**П2. Позы через оракул (без Alpha).** Для каждой пары (вид, действие) из П1: вычислить состояние, затем поза по кадрам через `drawModel`. Проверки — уже существующие в [action_baker.py](../../tools/alpha_models/universal/action_baker.py): полный таймлайн, неизменный набор частей (кроме объявленных динамических), конечные TRS-матрицы, возврат к покою. Неподдержанный участок отрисовки → `BLOCKED`.

**П3. Живая сверка (запуск Alpha — нужно отдельное разрешение).** Один контрольный захват на семейство: NPC в бою в копии из `.scratch` (инструменты D55), сравнение кадров с оракулом. Без П3 позы получают статус `RECONSTRUCTED_FROM_EVIDENCE`, с совпавшим П3 — `TRANSFERRED_FROM_ALPHA`.

| Доказано | Статус действия у вида |
|---|---|
| П1 + П2 + П3 совпало | `TRANSFERRED_FROM_ALPHA` |
| П1 + П2 | `RECONSTRUCTED_FROM_EVIDENCE` (профиль `EMULATED_ALPHA_CODE`, триггер `creature_ai`) |
| Только П2 (поза есть, запуска нет) | `BLOCKED: TRIGGER_UNPROVEN` — в Unity не импортируется |
| Видо-зависимый код / неизвестная экипировка | `BLOCKED` с названием причины |

## 4. Изменения в конвейере

* **Профили действий.** Новые записи `ACTION_PROFILES` с `trigger: "creature_ai"` и списком видов-образцов. Каждый вид получает действия только по своей записи; правила ввода игрока на NPC не переносятся (как сейчас). Ядро формулы ходьбы не меняется.
* **`ai_trigger.py`** (новый): П1 — исполнение веток выбора атаки, выдача `jobs/<вид>_actions.json` с условиями и заглушками.
* **`action_baker`**: допуск по профилю `creature_ai` (сейчас только образец гуманоида); остальная проверка без изменений.
* **Unity**: контроллер в режиме `ACTIONS` с источником `creature_ai`. Тестовый драйвер PlayMode проигрывает набор действий вида по очереди: покой → действие → покой → ходьба. **Это не игровой ИИ**; S04 не трогается.
* **Пакет**: новая область в `batch_runner.SCOPES` и одна запись в `BATCH_AUTHORIZATIONS` — только после решения продюсера.

## 6. Критерии приёмки (измеримые)

1. Для каждого вида пакета — таблица действий: код, источник запуска (адрес ветки), условия, заглушки, статус. Нет действий без адреса ветки.
2. Оракул vs живой захват (A2/A3): ≤ 1e-3 вокселя и ≤ 0.05° на всех кадрах — те же пороги, что у ходьбы.
3. Каждый клип: полный таймлайн, конечные TRS, возврат к покою; длительность — из `combat_getAttackTiming`, не подобрана.
4. Unity PlayMode при 30/60/120 Гц: все действия набора вида проиграны, переходы — `UNITY_TRANSITION`, дрейф покоя 0.
5. Отказы: вид без профиля не получает клипов действий (тест), профиль `creature_ai` не включает действия ввода игрока (тест), подмена вида-образца с другим телом — `SPECIMEN_APPEARANCE_DIFFERS` (уже есть).
6. Регрессия HumanMale — 98/98 при 30/60/120 Гц с прежними числами.
7. Все данные Alpha и кадры — только в `.scratch`; в Git — код, тесты, отчёты.

## 7. Риски

* **Ветки ИИ зависят от мира** (цель, путь, вода/полёт): часть набора действий останется `PARTIAL`. Не заменять догадками.
* **Экипировка NPC** может менять состояние drawModel (таблица учитывает оружие и вторую руку). Без знания, чем вооружён NPC, действие вида — `BLOCKED: EQUIPMENT_UNKNOWN`.
* **Живой захват NPC** требует найти и спровоцировать врага в копии Alpha; клавиатура в D56 была `PARTIAL`. Если захват не получится — честный `RECONSTRUCTED`, без повышения статуса.
* **Эффекты и снаряды** не являются позами частей — вне этого плана.

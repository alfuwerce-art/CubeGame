3. Сформировать jobs через конвейер без ручного моделирования. Сохранить геометрию, риг, координаты/якоря/масштаб, правильные load flags, masking, tint, порядок отрисовки, provenance. Использовать покрытие вариантов моделей там, где реально есть варианты.
4. Сначала idle/walk: покадровые проверки конечности матриц, вершин/габаритов и соответствия контракту; PlayMode в изолированном Unity 6000.3.27f2, снимки/контактный лист локально. Не выдумывать параметрическую ходьбу, если семейство не поддерживается.
5. **Действия** только если trigger доказан по исполняемому коду ИИ конкретного вида/профиля, клип получен кодовым оракулом и контракт/equipment допускают его. Если такого evidence нет — модель/ходьба могут быть PASS, `actions=BLOCKED/NOT_PROVEN`, но никаких фальшивых атак. Неподтверждённое оружие не имитировать.
6. Провести Python и Unity EditMode/PlayMode; проверить, что исправления D61 не регрессировали. Сохранить идентифицирующий визуальный лист/сцену, доступную продюсеру для просмотра.

**Шлюз фазы 1:** отчёт `READY_FOR_REVIEW` + фактический Unity PASS по достигнутому объёму + явные блокеры + визуальные материалы. Продюсер смотрит новое семейство в Unity. **До его замечаний не запускать большие следующие партии**.

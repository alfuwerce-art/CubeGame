# S00 — Исследование Cube World Alpha 2013: техническое задание

**Проект:** CubeGame (рабочее название; финального названия игры нет).  
**Статус:** SPEC PREPARED — **исследование оригинального клиента не начиналось и не считается выполненным**.  
**Предпосылка:** законно полученный и рабочий экземпляр Cube World Alpha 2013 на ПК; продюсер сообщал, что его пока нет и он установит позже.  
**Исполнитель:** локальный ИИ-агент под контролем продюсера и ChatGPT-архитектора.

## 1. Цель и границы

Составить **воспроизводимое описание фактической Alpha 2013** и матрицу соответствия для будущего воссоздания в Unity. Ничего не переделывать «по здравому смыслу» на этом этапе; новые фракции, AI-NPC, прокачка PoE/Kenshi, новая графика и прочие улучшения — для последующих этапов.

**Запрещено заявлять, что функция исследована, если основание — догадка или материал от игры 2019.** Источники отмечать версией и достоверностью. В Alpha нет обязательного финального сюжетного босса: фиксировать реальные типы боссов, данжей и событий, не выдумывать главный финал.

S00 **не** создаёт Unity-игру, не реализует сетевую архитектуру, не извлекает ресурсы для публикации, не копирует чужой исходный код в репозиторий и не запускает платную инфраструктуру.

## 2. Входной чек-лист (S00-G0)

- Рабочий оригинал: зафиксировать путь **локально** (не публиковать личные данные), дату/версию клиента, хеш исполняемого файла SHA-256, ОС и запуск.
- Отдельная папка для локальных снимков/видео/логов исследования, не коммитить оригинальные исполняемые файлы и ассеты в публичный GitHub.
- Запустить и проверить минимум: создание героя и мира, загрузку в мир, одну базовую атаку, инвентарь, сохранение и повторную загрузку.
- Если клиент недоступен, отметить `BLOCKED_SOURCE_GAME_MISSING`, **не подменять первичное наблюдение** внешними описаниями. Разрешён сбор вторичных свидетельств в отдельной таблице.

## 4. Формат каждой записи о механике

- `feature_id`, название, версия Alpha, категория, подмеханика;
- точное наблюдаемое поведение и действия игрока;
- состояние **до**, команда/событие, состояние **после**;
- необходимые стартовые условия (класс, уровень, предметы, seed, время);
- источник: `ALPHA_DIRECT`, `ALPHA_2013_VIDEO`, `ALPHA_2013_DOCUMENT`, `LATER_MEMORY_ABOUT_ALPHA`, `RECONSTRUCTION_CLAIM`, `2019_ONLY`;
- статус знания: `VERIFIED`, `PARTIAL`, `UNKNOWN`, `CONTRADICTORY`;
- ссылка на артефакт доказательства, время в видео либо шаги повторения;
- ожидаемое поведение для будущего теста Unity и допуски, если численные параметры не измерены.

Правило: `2019_ONLY` не служит доказательством механики Alpha. Числовые формулы подтверждать измерением, не выводить по одному наблюдению.

## 5. Базовые сквозные сценарии для проверки

- Создать героя → создать отдельный мир → появиться → определить стартовую экипировку/интерфейс.
- Найти город → поговорить с NPC/торговцем → купить/продать предмет → проверить инвентарь.
- Сразиться с обычным существом → получить опыт/добычу → повысить уровень → применить навык.
- Исследовать альтернативный класс/специализацию и различия оружия/боевых действий.
- Найти задание → пройти локацию/данж → победить подтверждённого босса → получить фактическую награду.
- Получить доступный способ перемещения → проверить его условия, управление и ограничения.
- Создать несколько миров/сохранений → выйти/зайти → установить фактическое сохранение предметов, героя и состояний мира.

Если сценарий невозможно выполнить, не фальсифицировать результат: `BLOCKED` с причиной и альтернативным достоверным источником, если имеется.

## 6. Результаты агента в GitHub

По завершении исследования подготовить в `docs/research/alpha2013/`:
- `ENVIRONMENT.md` — версия, окружение, воспроизводимость;
- `FEATURE_MATRIX.md` — матрица механик/покрытия и доказательств;
- `SYSTEM_CATALOG.md` — подробные правила игровых систем;
- `TEST_SCENARIOS.md` — шаги и ожидаемые результаты для Unity;
- `OPEN_QUESTIONS.md` — неизвестное и конфликтующие свидетельства;
- `S00_REPORT.md` — выполнено, не выполнено, источники, риски, тесты.

К оригинальным бинарникам, моделям и полным видеозаписям **не делать публичных коммитов**; безопасные ссылки на локальные артефакты и метаданные указывать в отчётах. Не использовать чужие оригинальные ассеты как открытый игровой контент.

## 7. Критерии завершения (S00-G1)

- Обязательные пакеты S00-01…S00-12 отражены в матрице, для каждого есть результат или явно подтверждённый блокер.
- Для ключевых циклов (создание героя, исследование, бой, прокачка, лут/крафт, данж/босс, сохранение) имеются воспроизводимые шаги.
- Каждый существенный факт связан с источником, версия Alpha/2019 не смешана; неизвестное не превращено в утверждение.
- Есть перечень того, что возможно/невозможно воссоздать без дальнейшего исследования, и приоритеты неизвестного.
- Архитектор проверил полноту и непротиворечивость материалов; продюсер подтвердил, что результаты достаточно полно описывают исходную игру.
- Агент оформил `READY_FOR_REVIEW`; статус `ACCEPTED` ставится **только после ревью и утверждения**, а не автоматически.

## 8. Передача в S01

Результаты S00 — тестовая матрица требований к Unity. Затем утвердить остальные технические решения (рендер/движок, границы пакетов, сохранения, tick, региональные идентификаторы) и только потом выдавать задачу на кодирование. Визуальный стиль на S01 не фиксировать.

# S05 — план конвертации моделей и анимаций Alpha в Unity

**Статус:** `S05A-0 — ACCEPTED` ([D48](../decisions/D48-s05a0-accepted-s05a1-draft.md)); `S05A-1 — ACCEPTED` ([D50](../decisions/D50-s05a1-accepted-s05a2-planning.md), технический пилот); `S05A-2 — PLANNING ONLY / NOT_AUTHORIZED` (подготовка ТЗ пропорций/креплений/tint одного персонажа); `S05B — NOT_AUTHORIZED`.  
**Решение:** [D46](../decisions/D46-asset-conversion-first.md).  
**Предшествующий этап:** S04-EQUIPMENT-COMBAT — **ACCEPTED** 2026-11-03 (D47); на дату составления плана был READY_FOR_REVIEW.  
**Среда:** Unity 6000.3.27f2; источник D:\Games\Cube world — только чтение.

## 1. S05A-0 — пилот конвертации геометрии

1. Статически изучить каталоги и файлы моделей Alpha, включая .cub. Найти идентификаторы и составные части. Не запускать клиент без нового разрешения.
2. Проверить уже существующие конвертеры и их лицензии. Новый инструмент писать только при обоснованной необходимости.
3. В изолированном локальном каталоге выбрать три реальных образца: персонаж/часть персонажа, существо/враг и оружие/предмет.
4. Извлечь, конвертировать и импортировать в **изолированный** Unity-проект; проверить геометрию, цвета, пропорции, оси, pivot, масштабы, материалы и иерархию.
5. Сохранить воспроизводимые результаты, ошибки и матрицу категорий CONVERTIBLE / PARTIAL / NOT_CONVERTIBLE / NOT_CHECKED. Не выдавать наличие модели на диске за доказательство успешного импорта.
6. Оценить масштаб и трудозатраты **потенциальной** пакетной конвертации, не запускать её.

**Критерии приёмки:** три задокументированных образца с результатами реального Unity-импорта (в том числе честно отмеченными провалами) и версией использованных инструментов.

## 2. S05A-1 — отдельный пилот анимации

1. Выяснить, где реально хранятся анимации и риги; не предполагать, что данные содержатся в .cub.
2. Проверить перенос одной анимации на подходящего конвертированного персонажа с учётом иерархии, трансформаций, крепления оружия и времени клипа.
3. Если перенос невозможен или частичен — записать ограничение и предложить собственный риг/клип.
4. Сохранить утверждённую D32 последовательность: одна собственная/переработанная модель → совместимая старая анимация, когда доступна → одна новая анимация → проверка в Unity.

**Критерии приёмки:** реально воспроизводимый клип в Unity либо детально подтверждённый блокер и предложенный путь решения. Успех mesh ≠ успех анимации.

## 2a. S05A-2 — только планирование ограниченного исследования

По [D50](../decisions/D50-s05a1-accepted-s05a2-planning.md) разрешено **только составить ТЗ**, но не выполнять новую работу: план восстановления подтверждённых масштабов, offsets, pivots, точки оружия, назначения RGB-маркеров и tint/палитры волос для **того же одного персонажа**. Предусмотреть матрицу фактов/гипотез/прокси, статусы `VERIFIED_ALPHA/PARTIAL/UNKNOWN/PROXY_NOT_ALPHA`, критерии фактического сравнения front/side/3⁄4, тесты и отдельное художественное утверждение продюсером по D35. Не запускать Unity, не обрабатывать новые модели, не менять конвертер и не начинать массовую конвертацию на этапе подготовки.

## 3. S05B — масштабирование после отдельного решения

- Только после оценки и приёмки S05A-0 и S05A-1 продюсер определяет, какие категории допускают пакетный перенос для локального тестирования.
- Выстроить пайплайн по персонажам, NPC, существам/врагам, оружию/предметам, зданиям и окружению: имена, размер, pivot, риги, анимации, материалы, импортеры, повторяемые тесты.
- Для распространяемой игры использовать только ассеты, на которые имеются необходимые права; в остальных случаях — собственные модели и анимации.
- По D35 лично показывать продюсеру **каждую** переработанную модель. Массовая генерация финальных моделей до утверждения пилота запрещена.

## 4. Правила и отчёт

- Оригинальные .cub, базы, изображения, экспортированные оригинальные модели и клипы не загружать в публичный CubeGame. Допустимы безопасная документация и собственный код с проверенной лицензией.
- Не менять код и сцену действующего S04, не устанавливать ПО без разрешения, не делать merge в main/force push.
- Результаты проверки фиксировать в будущем **docs/research/alpha2013/MODEL_CONVERSION_PILOT.md**: источники и идентификаторы, версии инструментов, фактические Unity-тесты, статусы геометрии/рига/анимации, ограничения, права и оценка стоимости.
- Финальная отметка исполнителя: READY_FOR_REVIEW; ACCEPTED ставит только продюсер.

**Примечание:** S05 — обозначение будущего визуального направления из черновой дорожной карты, а не автоматическое продолжение текущей технической нумерации. До начала исполнения синхронизировать номера этапов с ACTIVE_STAGE.

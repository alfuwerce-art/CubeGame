## P0 — установка инструментов и подготовка (пока Unity/Blender отсутствуют)

- Проверить фактическое наличие Unity Hub и Editor, версию, свободное место на дисках и учётную запись Unity.
- Если Unity отсутствует: предложить **официальные** Unity Hub + Unity 6.3 LTS (последний подходящий patch) и URP для пилота. Получить явное локальное одобрение на скачивание, установку/повышение прав и принятие условий лицензии; действия, требующие входа в аккаунт, выполняет сам пользователь. Никогда не подставлять пароли и не менять настройки защиты Windows.
- Рекомендуемый путь: установки редакторов можно хранить на диске D: при нехватке места на C:. Выбор и доступность уточнить до установки.
- Visual Studio Code уже есть; системный .NET SDK **не обязателен** для первых Unity C# скриптов (Editor имеет собственную среду компиляции).
- **Blender сейчас не устанавливать автоматически.** Для S01 использовать собственные примитивы. К этапу S05A поставить стабильную Blender LTS после согласования, затем провести пилот переноса анимаций.
- Создавать Unity-проект в **корне** существующего репозитория CubeGame (`Assets/`, `Packages/`, `ProjectSettings/`), не вкладывать ещё один Git/Unity-проект. Проверь `.gitignore` и изменения других веток, не трогай `plugins/`.
- Рабочая версия Unity 6.3 LTS + URP — пробный выбор. Записать точную версию Editor и пакетов из проекта после успешного запуска.

## P1 — минимальная игровая система

1. Только нужные границы модульного монолита: `World/Core` (детерминированная генерация) отделены от Unity-визуала `Presentation`; не строить преждевременно десятки модулей.
2. Один небольшой процедурный voxel-регион от `WorldSeed` и координат; из **собственной** геометрии, с объединением мешей вместо тысяч отдельных GameObject. При отсутствии подтверждённой формулы Alpha помечать алгоритм как временный.
3. Управляемый временный герой (капсула/собственная примитивная фигура), перемещение по земле и коллизия.
4. Камера третьего лица: поворот мышью, следование и ориентация по согласованному тестовому сценарию.
5. Служебный интерфейс: seed, координаты, FPS; минимум, без нового художественного оформления.
6. Не реализовывать на пилоте NPC, квесты, мультиплеер, боевую систему, постоянные сейвы, контентную базу Alpha, импорт исходных платных моделей/ресурсов или Blender pipeline.

## P2 — конкретная приёмка

- Проект Unity открывается без C# compile errors; зафиксирована версия Editor/URP.
- EditMode: одинаковые seed/регион генерируют идентичную геометрию; другой seed даёт значимое отличие.
- PlayMode: герой/камера/земля действуют, коллизия работает, нет критических исключений.
- Есть реальная играбельная демонстрация и понятные действия для ручной проверки, скриншоты собственной Unity-сцены.
- Профиль: время генерации области, FPS / время кадра CPU (и GPU, если доступно), RAM в тестовой сцене. Измерения настоящие, а не выдуманные.
- `docs/stages/S01_PILOT_REPORT.md`: реализовано, тесты (PASS/FAIL/NOT_RUN), ограничения, несовпадения с Alpha, причины временны́х замен, следующий технический шаг.

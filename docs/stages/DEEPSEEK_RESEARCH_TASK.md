## Часть 1 — основной приоритет: R02
1. Прочитай `AGENTS.md`, `docs/ACTIVE_STAGE.md`, `docs/decisions/D41-research-before-port.md`, `docs/stages/S00_DEEP_RESEARCH.md`, `docs/research/alpha2013/REFERENCE_ATLAS.md`, `docs/architecture/UNITY_REUSE_MAP.md`.

3. Создай новую ветку от актуального main: `stage/s00-deep-research` (без затрагивания Unity-пилота).
4. Разбери **все** пакеты A…L в порядке зависимостей. Начни с A/B/C/D/E, затем F…L; публикуй отчёты частями, работай по 1–2 логически завершённым системам за итерацию.
5. Используй локальные данные `D:\Games\Cube world` **только для чтения**; `CubeWorld-Reversal` как реконструкцию с риском ошибок; при необходимости Ghidra — сначала сформулируй точное место, которое реконструкция не объясняет, и запроси согласие на новую установку.
6. На неизвестное: исходные структуры и вызовы → SQLite/сохранения → точечная проверка Alpha → ссылки 2013/архив/wiki → запрос ChatGPT со списком оставшихся гипотез. Не подменяй доказательство уверенностью LLM.
7. Выходные документы и критерии приёмки строго из `S00_DEEP_RESEARCH.md`. Для каждого игрового действия дай C#-контракт/алгоритмическое требование **своими словами**, ссылку на Unity native способ реализации и тест.
8. Никакой записи в оригинал, переустановки ПО без разрешения, копирования чужого декомпилированного текста или игровых ассетов в публичный CubeGame.
9. По завершении каждой партии: факты, UNKNOWN, точные ссылки, пройденные/непройденные тесты, branch+commit, READY_FOR_REVIEW; после двух неудачных попыток устранить один блокер — остановись и сообщи.

**Цель:** подробное исследование и тестовая спецификация, по которой следующая версия CubeGame повторяет функции Alpha на движке Unity, не пересоздавая встроенные функции движка.

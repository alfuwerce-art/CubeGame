# G1 — TECHNICAL FOUNDATION

**Этап:** G1 дорожной карты ([ROADMAP_DRAFT](../archive/ROADMAP_DRAFT.md#g1--technical-foundation))
**Предыдущий этап:** [G0 — DEVELOPMENT PIVOT / BASELINE FREEZE](../ACTIVE_STAGE.md)
**Статус:** `PLANNED` — ТЗ готово к исполнению, реализация не начата
**Цель:** превратить существующий runtime в устойчивую платформу **CubeGame**, а не в «лучший Alpha port».

---

## 1. Цель этапа

К концу G1 должно быть верно:

1. Игра запускается, создаёт/загружает **собственный** save, входит в мир и играет без обязательной зависимости от локального Alpha-контента.
2. Запуск, ввод, тик симуляции, сохранение, события и диагностика имеют явные границы; bootstrap больше не является одним god-классом, который владеет всем.
3. Формат сейва версионирован и имеет механизм миграции, а не только отказ при несовпадении версии.
4. Существует воспроизводимый Windows Player build, на котором прогоняется smoke-сценарий.
5. Есть измерения CPU/RAM/GC, по которым можно планировать G2/G4/G5.

G1 **не** добавляет новые игровые механики и не улучшает визуал.

## 3. Задача G1-00 — решение о базовой линии (блокирующая, до кода)

Это первая задача G1, потому что от неё зависит объём остальных работ.

Что требуется решить продюсеру/архитектору:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Идти от canonical** | чистая, проверенная база; минимум merge-риска; G0-отчёт описывает именно её | теряются P0–P7 runtime-системы (меню, UI HUD, loot/shop, missions), их придётся делать заново |
| **B. Взять цепь P0–P7 как базовую** | максимальный reuse: 29 тыс. строк уже написанного runtime | 278 файлов не в canonical, merge не fast-forward, состояние тестов G0 не подтверждено, часть кода — Alpha-parity (UI Toolkit HUD), который pivot не требует |
| **C. Гибрид**: canonical + выборочный `cherry-pick` полезных P-блоков (loot/shop/missions/profile store), без Alpha-parity UI | сохраняет ценное, не тащит parity-долг | нужна отдельная ревизия каждого блока |

**Решение (2026-11-17, G1-00): выбран OPTION C.** Candidate-ветка `deepseek/g1-00-runtime-baseline-candidate` содержит canonical + pivot-документы + полный runtime P0–P7 (merge `c613ae6`; код равен P7-tip). Проверено: `error CS = 0`; EditMode **853/859** с Alpha-кэшем и 845/859 без; PlayMode **75/75** и 39/75 (3 content-presence fail, 33 skip); Windows Player собран (0 errors) и прошёл сценарии new/load/continue/attack/UI/save в обоих режимах. Отчёт: [G1_00_RUNTIME_BASELINE_SELECTION_REPORT](../reports/G1_00_RUNTIME_BASELINE_SELECTION_REPORT.md).

**Перед слиянием candidate в canonical обязателен ограниченный cleanup:**

- **C1** — пометить 4 content-presence теста как `RequiresAlphaCache` (входит в W9);
- **C2** — не ставить `_screenshotFrame` без `_screenshotPath` (входит в W10);
- **C3** — сделать build-gate независимым от Alpha-кэша (входит в W10);
- **C4** — зафиксировать шрифт UI: собственный TTF либо штатный placeholder (G12, вне G1).

До выполнения C1–C4 работы W1–W12 ведутся от candidate-ветки, а не от canonical.

Выход задачи: решение + candidate-ветка с проверенной базовой линией.

## 4. Что переиспользуем

`KEEP`-системы из [G0 audit](../planning/G0_EXISTING_WORK_REUSE_AUDIT.md):

- `GameSession` state machine + `GameClock` + `GameEventBus`;
- `Ids.cs` / `GameplayEvents.cs` / `WorldContracts.cs` (стабильные ID, типизированные события);
- `GameSlotStore` + `FileSaveStore` (атомарная запись, checksums, pair validation);
- `WorldDeltaStore`;
- контракты визуального слоя (`IEntityVisualSink`, один владелец визуала, `Problems[]`);
- построение мира/стриминга (`BuildWorldViews`, `StreamingWorldView`) как transport;
- `Core/*`: combat/items/progression math (engine-free, без UnityEngine);
- тестовая инфраструктура (`tools/unity/run_pilot.ps1`, `tools/core_check`, `tools/m0_pilots`).

## 5. Что рефакторим

`REWORK`-системы:

- `GameBootstrap` (1 876 + 360 строк) → композиционный корень + отдельные хосты (мир, население, бой, UI, ввод, сохранение);
- отсутствующая input abstraction (19 прямых `Input.*`);
- отсутствие версионирования/миграций сейва;
- статический синглтон `AlphaActorLibrary.Shared`;
- двойная система координат (`WorldLayout` vs `AlphaWorldScale`) — свести к одной (совместно с G2);
- границы симуляции: сейчас тик 30 Гц помечен `PLACEHOLDER`, смешан с `Update`;
- диагностика: нет единого логгера/отчёта о состоянии контента для Player-сборки.

## 6. Alpha-зависимости, которые G1 обязан снять

Не «удалить Alpha», а сделать так, чтобы **техническая платформа не требовала** локального Alpha-кэша:

| Зависимость | Требование G1 |
|---|---|
| `AlphaContentSource` (кэш actors/items/appearance) | при отсутствии кэша игра стартует, играет и явно сообщает состояние контента; placeholder-визуал штатный, а не «ошибка» |
| `AlphaIconAtlas` (`<project>/AlphaOutput/icons`) | не обязателен для UI; отсутствие атласа не ломает панели |
| `AlphaSoundLibrary` (<root>/sounds) | не обязателен; отсутствие звуков не ломает события |
| 14 таблиц `Content/Generated/*.g.cs` | остаются как данные для legacy-механики, но платформа не должна считать их «истиной мира»; решение об их судьбе — G2/G3 |
| `.scratch/m0` дампы (oracle) | только dev-регрессия, не runtime |

Обязательный тест G1: **запуск без `CUBEGAME_ALPHA_CONTENT` и без `.scratch`** — мир создаётся, герой двигается, сейв пишется и читается, ошибок в логе нет (только диагностические сообщения о placeholder-контенте).

Полный список зависимостей и классификация (temporary dev dependency vs production blocker) — в [G0 reuse audit §13](../planning/G0_EXISTING_WORK_REUSE_AUDIT.md#13-alpha-runtime-dependencies-сводка).

## 7. Работы (work packages)

Порядок обязателен: W0 → W1 → (W2, W3, W5 параллельно) → (W4, W6, W7) → (W8, W9) → W10 → W11.

### W0 — Базовая линия (см. §3)

Выход: decision record + зафиксированный commit.

### W1 — Композиционный корень и разбиение bootstrap

- Ввести явный composition root (ручная композиция, без DI-фреймворка).
- Разделить `GameBootstrap` на: `GameEntry` (жизненный цикл), `WorldHost`, `PopulationHost`, `CombatHost`, `PlayerInput`, `UiHost`, `SaveHost`.
- Сохранить текущий порядок инициализации и все текущие события.
- Тесты: существующие PlayMode-сценарии проходят без изменения поведения; новый тест — «повторный вход в мир после выхода не создаёт дубликатов систем».

### W2 — Input abstraction

- Один слой ввода (`IGameInput`): действия вместо клавиш, один владелец контекста (UI/gameplay/pause).
- Убрать 19 прямых `Input.*` из `GameBootstrap`, `PlayerMotor`, `OrbitCameraController`, `GameplayLoop`.
- Тесты: EditMode-тест маппинга действий; PlayMode-тест «ввод не протекает в UI и наоборот».

### W3 — Границы симуляции и обновления

- Явный фиксированный тик симуляции (частота — решение этапа, по умолчанию сохранить текущее поведение) и отдельный рендер-апдейт.
- Разделить `GameSession.AdvanceFrame` на “симуляция” и “презентация”.
- Определить, что происходит при паузе/меню/загрузке.
- Тесты: детерминизм тика (N тиков → одинаковое состояние), пауза не двигает симуляцию.

### W4 — Данные и стабильные ID без Alpha-смещений

- Обернуть API seed/климата именованными полями CubeGame (Alpha-смещения остаются внутри как provenance).
- Зафиксировать контракт ID-space в одном месте и проверить его тестом.
- Тесты: публичный API не принимает «сырые» Alpha-смещения; обратная совместимость чтения существующих миров сохраняется.

### W5 — Save/load foundation: версия + миграция

- Ввести явную схему версий и цепочку миграций `v1 → vN` с тестами на каждый шаг.
- Политика: слот новой версии читается, старый — мигрируется, повреждённый — отклоняется с точной причиной.
- Тесты: миграция каждого шага на подготовленных фикстурах; отказ не удаляет данные пользователя.

### W6 — Независимость от Alpha-контента

- Штатный путь «контента нет»: placeholder-модели/иконки/звуки, диагностический отчёт, отсутствие исключений.
- Убрать жёсткий dev-path `<project>/AlphaOutput` из runtime-путей UI.
- Тесты: PlayMode «игра без Alpha-кэша»; EditMode «диагностика честно сообщает состояние».

### W7 — Границы событий

- Зафиксировать контракт событий (кто публикует, кто потребляет, порядок, ошибки обработчиков).
- Запретить визуальному слою менять gameplay-состояние.
- Тесты: обработчик, бросающий исключение, не ломает тик; повторная подписка не дублирует эффект.

### W8 — Диагностика и логирование

- Единый логгер с категориями и уровнями; отчёт о состоянии контента/мира/сейва при старте Player-сборки.
- Тесты: отчёт формируется и содержит ожидаемые поля (без запуска Player).

### W9 — Тестовая инфраструктура

- Разделить тесты на «не требуют внешнего контента» и «требуют dev-кэш»; вторые не должны молча пропускаться в CI-режиме — они должны быть явно помечены как `RequiresAlphaCache`.
- Добавить multi-seed регрессионный gate (N seed × K зон, хеш содержимого).
- Тесты: сам gate проходит на текущем генераторе и падает при искусственном изменении константы.

### W10 — Windows Player pipeline

- Один воспроизводимый скрипт: build → запуск → smoke → лог/скриншот → результат.
- Убрать конфликт двух scene builder'ов, пишущих один и тот же `Pilot.unity` (сейчас `run_pilot.ps1` перезаписывает игровую сцену).
- Тесты/проверка: чистая сборка + smoke-прогон на Player с фиксацией результата.

### W11 — Профилирование

- Замеры: время старта, время входа в мир, генерация зоны, чанки/вершины при движении, память, GC-alloc на кадр.
- Выход: таблица измерений как вход G2/G9.

## 8. Тесты и проверки

Обязательный набор к концу G1:

| Проверка | Критерий |
|---|---|
| Компиляция | `error CS = 0` |
| EditMode | все тесты проходят; пропуски только явно помеченные `RequiresAlphaCache` |

| Windows Player | сборка + smoke-прогон с логом |

## 9. Windows Player verification (обязательный сценарий)

`launch → main menu → создать персонажа → создать мир → войти → пройти/стримить 200+ вокселей → ударить существо → подобрать лут → открыть инвентарь → сохранить → выйти → загрузить → продолжить`

Дополнительно:

- запуск **без** `CUBEGAME_ALPHA_CONTENT` — игра не падает, визуал placeholder, диагностика в логе;
- запуск **с** dev-кэшем — визуал существ/предметов присутствует;
- длинная сессия 15 минут движения — без утечек и деградации.

## 10. Definition of Done

G1 завершён, когда:

1. W0–W11 закрыты;
2. все обязательные проверки §8 зелёные;
3. Player-сборка воспроизводится одной командой и проверена;
4. платформа работает без обязательного Alpha-контента;
5. есть версионирование сейва с миграцией;
6. есть профиль и документ измерений;
7. `PROJECT_MEMORY.md`, `ACTIVE_STAGE.md` и отчёт этапа обновлены;
8. статус не выше `READY_FOR_PRODUCER_REVIEW` до решения продюсера.

## 11. Blockers и риски

| Риск | Влияние | Митигация |
|---|---|---|
| Не решена базовая линия (canonical vs P0–P7) | вся реализация может пойти не в ту ветку | W0 до кода; при отсутствии решения работать от canonical |

## 12. Что НЕ входит в G1

- Новые биомы, растительность, структуры, вода, погода (G2/G9).
- Combat-механики, способности, dodge/block (G4).
- NPC AI, pathfinding, расписания, фракции (G5).
- RPG-баланс, экономика, крафт, магазины (G6).
- Новый UI/HUD/UX (G12).
- Character/Creature Factory и модели (G3/G10).
- Контент, квесты, города, данжи (G11).
- Масштабная чистка legacy-кода «ради чистоты»: удаляем только то, что мешает платформе, и только по решению.

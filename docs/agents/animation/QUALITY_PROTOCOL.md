# Animation quality protocol — mandatory
## Before editing
Keep cubegame-rig-animation primary across every operation; art-validation is subordinate. Resume checkpoint before any action, even open/view/PIE. Recover authorized editor using [editor recovery](EDITOR_RECOVERY.md). For new/replacement families run [SEARCH and staged selection](SOURCE_SELECTION.md) before production adaptation; compare base cycles and obtain owner visual direction before starts/stops. A direct owner request to continue a specific accepted family does not require repeating the gate. For EDIT preserve scope; do not turn local fixes into a new asset search.
Read the current checkpoint; verify Git and actual UE project/asset paths, active runtime clip names, rig revision, input/controller and candidate. Never equate a local branch from a report with a remote branch. Record immutable baseline asset copies or restorable version (including untracked UE packages), restore procedure, existing defects and protected tracks, rig, mesh, sockets, settings and unrelated clips. Keep last owner-accepted version distinct from latest unaccepted candidate. Test restoration on a safe copy, never reset another workspace.
Convert every owner request into a stable ID, original wording/source, target, expected visible result, acceptance check, mode and scope. Separate new, continuing, superseded (only explicit owner change), verified candidate and owner-accepted. Keep deferred items with reason; no disappearance. For this task put each in the gate contract; unresolved items outside scope remain in checkpoint. If owner says continue, resume the last verified checkpoint, not a new experiment. If missing local state, report BLOCKED with exact missing item.
## During editing
Source assets and rejected/last accepted candidates are immutable. New motion from a different source uses a separately named candidate with source family, target and revision; never repurpose a source-named package for unrelated content. Keep explicit mapping of original -> candidate -> active test -> owner-accepted. For authorized local edit use existing target with restorable snapshot; no unsolicited permanent duplicates. Verify actual loaded package after restart.
Reproduce each defect with frame/time, camera and state/input; distinguish source, rig, keys, runtime graph, controller, mesh deformation and presentation. Choose smallest affected layer; do one logical change then inspect before next. Preserve unaffected tracks including root, timing, interpolation, curves, notifies and other metadata unless explicitly scoped. Avoid global smoothing, whole-clip replacement or increased blend time merely to hide defects. After two failed attempts, diagnose alternate cause/tool or BLOCKED.
Export normalized track data from saved/reloaded UE baseline and candidate, not intended input arrays. For existing clip edits include every track/channel plus clip metadata (length, sample rate, root policy, notifies/curves etc.) in a stable key map. For each export pair use a protected baseline file and explicit allowed keys. Keep same extractor, coordinate convention, sampling and canonical numeric representation; no tolerance/rounding that hides unintended changes. Compare protected files with existing gate; track comparison checks exact exported values, not unseen runtime state. Store before/after snapshots outside public repo if private. If export impossible, report BLOCKED before editing protected tracks; do not fabricate.
## Five independent checks
- Technical: load saved assets, verify expected skeleton/keys, no invalid transforms, all active runtime assets resolved.
- Motion: full action, timing, phase, contacts (horizontal drift and vertical floor clearance), loop seam and acceleration, visible range of motion, pose/velocity changes and coherent root/capsule. Smoothness needs both upper bound for spikes and lower/target range of expression from reference/baseline; no universal angle threshold.
- Visual: actual rendered mesh, front/side/back/gameplay camera, 1x and slow speed; reference and baseline comparison, identify timestamps and observed silhouette, rhythm, limb gaps, intersections, shoulders, fingers. Inspect recordings or dense ordered frames plus time series; image/contact sheet alone cannot prove temporal quality. Idle must look alive at game scale; finger motion must be visible on deformed hand, not just key values. Check camera close-up as well as gameplay distance; if motion deliberately imperceptible, obtain explicit owner direction.
- Gameplay: real PIE with actual input and active clip/phase/weights/capsule trace; starts from current pose, walk-run and run-walk, stop, interruption, turn; no sliding before the first push, root double movement, abrupt vertical jumps, forced transition restart. Use existing forward locomotion with free camera when confirmed in local checkpoint; WASD directions do not require strafe/backward clips. No new product mechanic.
- Regression: compare same view/time/input baseline vs candidate; all protected tracks/files, unrelated animations, accepted body form and other mannequin; verify affected transitions and actual active asset after editor reload. Existing unrelated issues remain listed, never silently change them.
All required domains PASS, every scoped ID PASS with evidence and no regression before READY_FOR_OWNER_REVIEW. Gameplay SKIP only for isolated assets with explicit scope/reason and no runtime claim. Owner ACCEPTED is separate. NOT_RUN/FAIL/BLOCKED => PARTIAL/BLOCKED. Evidence needs actual inspected observation, camera and time range, plus file; recording generated but not viewed is NOT_RUN. Numeric measurements do not establish artistic quality. Gate validates structure, coverage and export equality, not agent truth or ability to see.
## Handoff / checkpoint
Attach actual start/check commands and outputs, contract/receipt/result, snapshot diff, inspection log with frame/time/camera and candidate comparison; redact private paths before shared publication. If these are absent, do not claim the Harness ran. For source selection record each checked library and alternatives rejected, rationale, source version and license status. Distinguish shortlist, preview, owner direction approval and final acceptance.
Keep one small local checkpoint per active workstream, outside tracked private materials; use the template in RUN02_CHECKPOINT. Include owner remarks unchanged, scope, baseline/candidate versions and restoration, active project/asset IDs, references and origin method, tools, evidence and per-ID status. Update after every iteration and owner decision. Do not commit large binaries or licensed sources. Update shared memory only with scoped factual decision/status, no claim of runtime verification without evidence.

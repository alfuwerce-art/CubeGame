# CubeGame — настройка DeepSeek Harness на Windows

**Статус:** инструкция для настройки пользователем/локальным агентом; реальные изменения на ПК **не выполнены** из ChatGPT.  
**Среда из прежней настройки:** DeepSeek Harness Desktop 0.2.1-rc.2, Windows 11; стандартный профиль Desktop в `C:\Users\bow\.dsh\profiles\desktop\cordis.patch.yml`. Проверить текущую фактическую версию на ПК: она могла измениться. Старые пресеты других проектов не трогать.

## Цель

Создать **отдельный** рабочий каталог CubeGame и агентский пресет `cubegame-dev`. DeepSeek — исполнитель; ChatGPT — архитектор; пользователь — продюсер. DeepSeek сначала проверяет Alpha, затем на отдельных утверждённых этапах пишет Unity-проект, запускает тесты, работает с GitHub. Codex проверяется позднее при создании моделей и графики.

## 1. Рабочий каталог (предлагаемый путь)

`C:\Users\bow\Desktop\CubeGame` — **предложение**, не уже существующий путь. Альтернатива — любой отдельно выбранный пользователем каталог.

Безопасная команда PowerShell (без перезаписи существующей папки):

```powershell
$repo = Join-Path $HOME 'Desktop\CubeGame'
if (Test-Path -LiteralPath $repo) {
    if (-not (Test-Path -LiteralPath (Join-Path $repo '.git'))) {
        throw "Папка уже существует и не является Git-репозиторием: $repo"
    }
    git -C $repo remote -v
    git -C $repo status --short --branch
} else {
    git clone https://github.com/alfuwerce-art/CubeGame.git $repo
}
```

После клонирования в DSH Desktop: **Add workspace / Добавить рабочую область** → выбрать эту папку → создать новую сессию. Workspace должен указывать на репозиторий, **не на папку оригинальной игры**.

## 2. Пресет

В настройках DSH открыть раздел Agent Presets; выбрать **Creator**, если он есть в установленной сборке, и запросить создание пользовательского пресета **`cubegame-dev`**. Включить Coding Tools, если настройки текущей сборки требуют этого. Если Creator отсутствует, временно использовать отдельную стандартную сессию с coding/terminal tools и рабочими правилами из `AGENTS.md`, НЕ редактировать руками `cordis.patch.yml` наугад.

Пресет должен обеспечивать:
- File tools: read, search, edit только для workspace CubeGame.
- PowerShell terminal / jobs: проверять git, Unity Hub/Editor, запускать C# Editor/тесты и читать логи; выполнение по разрешениям.
- Git/GitHub: работа в собственных ветках, commit/push результатов и отчётов.
- Чтение `D:\Games\Cube world` для S00 через **явное разрешение** на доступ за пределы workspace. Не выдавать права записи/удаления/изменения оригинальной игры. Запуск игры — только после проверки происхождения, безопасности и согласования разрешений.
- Начальный sandbox: `workspace-write` или эквивалент ограниченных прав, approval `ask` для рискованных операций. Не активировать постоянный `danger-full-access`.
- Не копировать или переопределять пресеты `ai-freelancer-v1`, `rogalik-dev`, общие секреты и профили других задач.
- Предпочитать уже настроенную модель DeepSeek и учёт расходов; никаких новых ключей/платных подключений без согласия.

**Предлагаемый текст заявки Creator:** «Создай изолированный пресет cubegame-dev для workspace CubeGame. Исполнитель DeepSeek, файловые операции, PowerShell, Git/GitHub, позже Unity/C#. Сначала выполняй AGENTS.md и ACTIVE_STAGE.md. Безопасность: workspace-write, ask; оригинальная Alpha только read-only по явному разрешению; не менять другие DSH-пресеты; не создавать сервер/не использовать платное API самостоятельно. Не запускать разработку Unity, пока S00 и архитектурный gate не утверждены. При создании пресета покажи его фактические инструменты, конфигурацию и успешно пройденный smoke test».

## 3. Smoke test (первая сессия)

Попросить агента:
1. Сообщить свою реальную версию DSH/пресет/рабочий каталог, доступные инструменты и активный режим approval.
2. Прочитать `AGENTS.md`, `docs/ACTIVE_STAGE.md`, `docs/decisions/D38-alpha-client-available.md`, `docs/decisions/D39-deepseek-developer.md`.
3. Проверить `git status`, remote, рабочую ветку и возможность чтения документов.
4. Проверить наличие `Unity Hub`, Unity Editor, `git`, PowerShell и .NET/C# без установки и без изменения компьютера; если Unity отсутствует — только отчёт.
5. Получить явно согласованный **read-only** доступ к `D:\Games\Cube world`, выполнить S00-G0 по техническому заданию.
6. Записать фактические результаты в `docs/research/alpha2013/` отдельной ветки, commit/push; не помечать G0_PASS без запуска игры и тестов.

## 4. Unity и дополнительные плагины

На S00 Unity можно только **обнаружить**, не создавать игровой проект. После утверждения S01 использовать штатные Unity Editor batchmode/`-executeMethod`/логирование и C# Editor scripts. Это не требует отдельного платного MCP или облачного сервера. Если DSH умеет подключать Unity CLI/MCP и это проверено на реальной версии Unity, оценить позже и только как дополнительный инструмент, а не обязательное условие.

Для официальной Unity CLI см. https://docs.unity.com/en-us/unity-cli/replace-mcp-server-unity-cli; для batchmode https://docs.unity3d.com/6000.0/Documentation/Manual/CommandLineArguments.html . Старый встроенный MCP AI Assistant был заменён Unity CLI MCP, сторонние MCP не затронуты.

## 5. Контроль бюджета и секретов

API-ключ остаётся в секретном хранилище DSH; не коммитить ключи или `.env`. Не менять модель и бюджет без уведомления. Длинные исследования разбивать на задачи с отчётом по расходам, если DSH показывает статистику; при неизвестных лимитах явно сообщить об этом.

## 6. Признак успешной настройки

Отдельная сессия CubeGame использует нужный workspace; умеет читать документы, выполнить безопасную PowerShell-проверку и Git; версия Unity определена либо помечена отсутствующей; путь Alpha обнаружен или причина недоступности указана; чужие проекты и профили не менялись. После этого отдельной командой запускать S00-G0.

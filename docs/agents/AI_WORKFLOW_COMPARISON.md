# Работа над CubeGame через ИИ — сравнение трёх подходов

**Статус:** аналитическая основа, не новый утверждённый геймдизайн. **Источник:** предоставленные владельцем 21.11.2026 скриншоты и транскрипты трёх роликов, а также сопоставление с CubeGame. Исходные транскрипты — пользовательский материал; оценки авторов не считать доказательством производительности.

## 1. Подход №1 — игровая документация и Git

Автор: Markdown в Obsidian, верхний `concept-doc` → подробные `game-design`, `art-direction`, `architecture`, `roadmap`, `quality-attributes`, `attachments`, `ai-generated`; `AGENTS.md`, Git, частные skills/pipelines, отдельные сессии и compact, метарепозиторий знаний.

Применение:
- **`docs/CONCEPT.md`** — карта, а не копия GDD.
- **`docs/GDD.md`** — игровые правила, **`docs/art/ART_DIRECTION.md`** — художественные стандарты, **`docs/ROADMAP.md`** — выпуск G0–G15; **`docs/QUALITY_ATTRIBUTES.md`** — измеримость качества. Принятые Dxx не придумывать заново.
- **`docs/architecture/ADR-0001-modular-monolith.md`** и ADR-0002 (отдельный открытый PR #1) — модульный монолит и data-driven слои; **это не доказательство их полного исполнения в коде**.
- Obsidian — **необязательный** локальный Markdown-просмотрщик, [инструкция](OBSIDIAN_WORKSPACE.md).
- Референсы и AI-generated — не складывать бездумно в Git; отдельные лицензии, происхождение, приватность и статус `REFERENCE / APPROVED / REJECTED`.
- **Отдельный meta-repository не создавать**: решение D95 — только CubeGame как проектный источник истины. Переносимые skills хранятся здесь; глобальная независимая библиотека возможна только отдельным решением владельца.

## 2. Подход №2 — Harness²

Автор: компактный always-on prompt; профильные skills по требованию; скрипты для точных вычислений; hooks для обязательного исполнения; subagents для изолированных узких задач; улучшение по циклу Propose → Probe → Compose + проверенный опыт.

Применение: [HARNESS_ARCHITECTURE](HARNESS_ARCHITECTURE.md), [HARNESS_EVALUATION](HARNESS_EVALUATION.md), [EXPERIENCE](experience/README.md), [DSH setup](DEEPSEEK_HARNESS_SETUP.md). Человеческий `AGENTS.md` не является системным sandbox. Hook-образец **неактивен**, пока не проверен на реальном DSH и Windows.

Сравнительные числа из видео не переносить на DeepSeek или CubeGame без собственной фиксированной оценки. Сильная обвязка помогает, но сама по себе не делает слабую модель равной Claude.

## 3. Подход №3 — Unreal + скрипты

Автор рекомендует UE 5.8, C++ Third Person, Claude Code (альтернатива — Qwen), словарь точных имён, архитектуру, дорожную карту зависимостей, скрипты вместо постоянного MCP. Тезисы «скрипты бесплатны и в 3 раза быстрее», «Blueprint запрещён», «на Godot нельзя сделать хорошую игру» — **не подтверждены**.

Подтверждаемые технологии Unreal:
- Python Editor Scripting — редактор, импорт, ассеты, автоматизация; **не** Python для игрового Windows runtime.
- Unreal C++ — логика игры; Blueprint допустим по конкретной задаче, не вводить тотальный запрет без эксперимента.
- Geometry Scripting — геометрия через Python/Blueprint; Control Rig, IK Rig и Retargeter — риг/анимации с границами применимости.
- Скрипты экономят ручной труд, но ИИ, запускающий их, всё ещё расходует токены; MCP и CLI могут дополнять друг друга.

**Решение:** исследовать Unreal только в **отдельном изолированном пилоте**, без изменения Unity, основного Roadmap, игрового C# или прежнего конвейера моделей. ТЗ [UNREAL_SCRIPTING_SPIKE](../research/UNREAL_SCRIPTING_SPIKE.md).

## 4. Сравнение с CubeGame

| Параметр | Уже есть | Требуется |
|---|---|---|
| Концепция и GDD | GDD и действующие реестры | Один компактный вход и отсутствие дублей |
| Художественное руководство | исторический Art Direction и пользовательские референсы | актуальный каталог правил/эталонов без фиктивного ART_APPROVED |
| Архитектура | ADR-0001, ADR-0002 в отдельной ветке | проверка реализации и dependency map |
| План | G0–G15 | зависимости внутри конкретных заданий, не абсолютный линейный порядок |
| Правила ИИ | AGENTS, память, active, revью | проверяемые хуки, краткие skills, предсказуемый handoff |
| Технические имена | код и asset references | генерируемый индекс + сверка с исходниками, не ручная фантазия |
| Модели/анимации | цель и референсы | один реальный качественный образец, оценка Blender/Unity/Unreal отдельно |

## 5. Приоритеты

1. Закрыть противоречия D95/#18 и обвязку #19, затем принять согласованный пакет.
2. Проверить skills и preflight в реальном `cubegame-dev`.
3. Повторяющаяся Unity-задача → замер baseline и quality gate.
4. Отдельно провести сравнительный **Unreal / Blender scripting spike**; решить по результату, а не по видео.
5. Пока нет принятого образца модели, никаких массовых пакетов генерации, самовольных технологий rigging или параллельной Factoria.

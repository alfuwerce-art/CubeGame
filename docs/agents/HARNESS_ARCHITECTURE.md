# CubeGame — двухуровневая обвязка ИИ-агентов

**Статус:** кандидат процесса для ревью. **Не** означает установки или включения хуков в локальном DSH. Основа: обсуждение владельца 2026-11-21, транскрипт о Harness²; научные утверждения исследователей не заменяют собственные измерения CubeGame.

## 1. Назначение

Не наращивать `AGENTS.md` при каждой ошибке. Разделить:
- **Всегда:** короткие обязательные принципы `AGENTS.md`, `ACTIVE_STAGE.md`, актуальная память и запреты D95.
- **По необходимости:** `SKILL.md` для конкретной повторяющейся работы; документация предметной области.
- **Автоматизируемое:** скрипт для подсчётов, git-проверок, ссылок, тестовых отчётов и структурированных сверок.
- **Необходи́мое каждый раз:** проверяемый хук/техническое ограничение в профиле агента, CI, правах workspace; текстовое правило не является блокировкой.
- **Параллельная подготовка:** субагент с собственной сессией может вернуть краткую проверенную сводку, но не менять файлы без отдельного scope и не принимать результат.

## 2. Два уровня

**Project-level — общий для ChatGPT, DeepSeek Harness, Codex.** Единственная цель: самостоятельная CubeGame на Unity. Источники истины: Concept → GDD / Decisions / Art / Architecture / Roadmap → AGENTS / Active Stage. Все агенты соблюдают запреты D95 и полномочия владельца независимо от запуска DSH.

**DSH-only — локальный runtime.** Пресет `cubegame-dev` с workspace `D:\Projects\CubeGame`, ограниченными правами, файловыми skill-каталогами `.dsh/skills`, проверяемыми скриптами и потенциальным pre-tool hook. Не включать плагины/хуки автоматически на другом проекте или профиле. Конкретные возможности проверять на фактически установленной версии, до установки/правки конфигурации делать backup.

## 3. Маршрутизация задачи

1. Прочесть `PROJECT_MEMORY.md`, `ACTIVE_STAGE.md`, `AGENTS.md`, `CONCEPT.md`; затем **только релевантные** разделы GDD / ADR / Decisions / Skills.
2. Сопоставить запрос с действующим scope: не разрешено исполнять старые M0/Alpha задачи и закрытый конвейер автоматически. Для противоречия — report/block only.
3. Записать короткий TASK contract: цель, критерии, `allowed_paths`, запрещённые операции, исходный SHA, ветка, проверки, доказательство, решение владельца.
4. Перед записью выполнить `node tools/harness/preflight.mjs` (если Node доступен); failure → block, не менять защищённую ветку.
5. Выбрать профильный skill при необходимости; если задача единичная, не создавать новый skill.
6. Делать минимальные изменения по контракту, unit/EditMode/PlayMode/Windows Player — по фактическим требованиям задачи. Скрипты для больших подсчётов и consistency checks, не «угадывать» сводку на глаз.
7. Итог: diff, SHA, тесты, реально запущенная сборка или `NOT_RUN`, ограничения, `READY_FOR_OWNER_REVIEW`; merge/ACCEPTED — только владелец.

## 4. Защитные границы

- Не подключать платные внешние API и облачные сервисы без разрешения, включая Google Cloud/Vertex AI, упомянутые в видео.
- Не активировать старый Factoria/ComfyUI/Tripo/auto-rig pipeline; это не «AI harness», а закрытая производственная технология.
- Запрещено подменять scope задач инициативным рефакторингом, стирать историю Git, трогать секреты и сторонние каталоги.
- `tools/harness/hook-pretool.mjs` — **дополнительный эвристический барьер, не изоляция ОС**: shell можно обфусцировать, неизвестные инструменты не покрыты. Настоящая граница — sandbox/permissions, рабочие ветки, профиль DSH и контролируемый merge.
- `.dsh/hooks.example.json` — **неактивный образец**. Подключать через совместимый DSH hook-bridge только после локальной проверки установленной версии и отрицательных тестов. Сам файл не включает ничего.
- Отчёт об отсутствии срабатываний хуков не является доказательством безопасности.

## 5. Улучшение обвязки

Применять [Propose → Probe → Compose](HARNESS_EVALUATION.md) только к повторяющимся ошибкам, на изолированных копиях/ветках и при фиксированном тестовом сценарии. Самостоятельная правка `AGENTS`, хуков, прав доступа, GDD или профильных инструкций **не разрешена** агентам. В библиотеку `experience` заносить только подтверждённые результаты испытаний. Не обещать выигрыша качества или экономии токенов без измерений.

# CubeGame — архитектура AI Harness
**Постоянный контекст:** AGENTS, PROJECT_MEMORY, ACTIVE_STAGE. **По задаче:** нужные части GDD, решения, ADR и один skill. **Проверки:** scripts/CI, журналы и Windows Player. Архив не загружается автоматически.

Цикл: запрос владельца → TASK contract → git/preflight → минимальное изменение → тесты и факты → diff/отчёт → приёмка владельцем. Успешные тесты сами по себе не принимают игровой результат.

Нужная автоматизация оформляется в `tools/harness`, специализация — в `.dsh/skills`. Не раздувать AGENTS, не копировать историю экспериментов в память. При улучшении обвязки сравнивать одинаковые входы, число ошибок, исправлений, время и ручное вмешательство.

Права DSH задаёт владелец. Локальная проверка скрипта hook не доказывает, что hook реально подключён; при `HOOKS_ACTIVE=UNKNOWN` действуют только обычные Git/CI/операционные ограничения. Не изменять локальные профили, секреты, настройки ОС или чужие каталоги без задачи.

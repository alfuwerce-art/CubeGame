# Методичка: перенос моделей и оригинальных анимаций Alpha 2013 в Unity (для DeepSeek)

**Статус технологии:** проверена на **одном** гуманоиде (человек-воин SOOGO) и трёх клипах — `idle`, `walk`, двуручная атака `attack_2h_a57`. Отчёт с числами: [ALPHA_ANIMATION_TRANSFER.md](../research/alpha2013/ALPHA_ANIMATION_TRANSFER.md). Этап: S05A-2 (D51/D57/D58), **READY_FOR_REVIEW**, не ACCEPTED. **S05B (массовый перенос) не разрешён** — эта методичка готовит его, но не запускает.

**Главное правило:** анимацию Alpha не реконструируем по каналам и не подбираем «на глаз». Мы снимаем **те матрицы частей, которые Alpha сама отправляет в GPU** в момент отрисовки, и воспроизводим их в Unity. Всё, что не снято, — не `TRANSFERRED_FROM_ALPHA`.

## 0. Что нужно знать, чтобы не исследовать заново

| Факт | Где доказано |
|---|---|
| Анимация Alpha — код, а не клипы: `Creature_drawModel` (VA `0x4128F0`) строит матрицу каждой части и рисует её: `render_uploadModelViewMatrices(M)` → `GameController_draw_mesh()` (thiscall, `ECX` = меш). Внутри функции **27** таких пар вызовов. | `pose_capture.py`, `humanoid_rig.py` |
| Гуманоид рисуется **8 частями**: тело, голова, волосы, оружие, 2 кисти (одна модель, правая зеркальная `scale(-s,s,s)`), 2 стопы (одна модель). Каждая часть опознаётся по адресу вызова отрисовки. | `humanoid_rig.PARTS` |
| Вершины меша Alpha лежат в координатах воксельной сетки `.cub` (0..размер); наш построитель даёт **то же число вершин** (проверено по полю меша `+0x3c`). | отчёт §3 |
| Матрица части: `M = T(-anchor(size)) · J · P` (строки-векторы). `P` — размещение существа (`local_14e0`), `anchor` — точка сетки на суставе: центр `size/2` для всех частей тела; у оружия в руке подтипов 15/16/17 — `(sx/2, sy/2, 4)`, на спине — центр. | код блоков отрисовки, `humanoid_rig.py` |
| **`J` не зависит от размера модели** → клип, снятый на одной модели, применим к совместимой модели другого размера. | самотесты, вариант «меч вместо булавы» |
| Указатель игрока: `*(gameController + 0x8006D0)`, чтение в инструкции `0x4A6B93`. Не выбирать существо «по числу частей» — это ловит NPC. | `pose_capture.py --target player` |
| Наклон взгляда `creature+0x58` (градусы) добавляет к голове/волосам `Rx(pitch)` вокруг шеи (опора `3/s` в кадре сустава) и к оружию в руке `Rx(pitch/2)` вокруг хвата. Клипы хранятся при наклоне 0. | `alpha_clip.pitch_layer`, остаток 0.0002 вокселя |
| Ходьба: поза = функция фазы `creature+0x118c` при постоянной амплитуде `+0x1188` **и удерживаемом вводе** (`|creature+0x40|² > 0.1` → множитель ×1.25). После отпускания клавиши — другая поза. | `alpha_clip._steady_walk` |
| Атака: состояние `drawModel this[2]`, время `this[1]` (мс). Целевые углы по фазам (замах/удар/возврат), отрисованная поза плавно догоняет цель (`local_1730` 0.01/0.04) → лёгкая зависимость от частоты кадров и предыдущей позы (первые ~50 мс). | `GameController.cpp:2639`, отчёт §4 |
| Двуручные мечи/топоры/булавы (подтипы 15/16/17) получают **одну и ту же** цепочку атак: действие 57 → 67 → 58 (`drawModel` состояния 2 → 37 → 3). | `combat_selectAttackAnim` 0x445020 |

## 2. Порядок работы (одна анимация или одна модель)

### Шаг A. Войти в мир

```powershell
& tools\alpha_models\runtime\alpha_enter_world.ps1
```
Проверить **глазами** `.scratch\s05a2\nav\enter_3_world.png`: HUD, персонаж `SOOGO LVL 1 WARRIOR`. Если меню выглядит иначе — открыть `enter_0..2_*.png`, поправить координаты (они заданы в клиентских координатах окна 784×561 и масштабируются).

### Шаг B. Снять матрицы

```powershell
& tools\alpha_models\runtime\alpha_capture_session.ps1 -Out D:\Projects\CubeGame\.scratch\s05a2\cap\<имя>.jsonl -Seconds 16 -WalkMs 4000 -Clicks 1
```
Сценарий: покой 2 с → W (`-WalkMs`) → покой 2.5 с → `-Clicks` кликов ЛКМ через `-ClickGapMs`. Для другой анимации — скопировать сценарий и заменить ввод (клавиша/кнопка), не трогая запуск `pose_capture`.

Обязательные признаки успешного захвата (в выводе):
- `player_resolved=True` — снят именно игрок;
- `parts/record=8` — все 8 частей;
- `CUBE_ALIVE=True` — игра пережила отсоединение отладчика.

Прямой вызов без сценария: `python -m tools.alpha_models.runtime.pose_capture <pid> out.jsonl --seconds 10`.

### Шаг C. Посмотреть, что снято

```powershell
python -m tools.alpha_models.anim.alpha_clip summary .scratch\s05a2\cap\<имя>.jsonl
```
`runs` — последовательность (`state`, `action`, `walking`). Новая анимация = новый `state`/`action`. `problems` должен быть пустым; `sizes` — по одному размеру на часть.

### Шаг D. Собрать клипы

```powershell
python -m tools.alpha_models.anim.alpha_clip build <capture.jsonl> --out-dir .scratch\s05a2\clips --idle --walk --state 2 --action 57 --name attack_2h_a57
```
- `--walk`: клип по фазе из **всех** устойчивых циклов; проверка «один цикл отложен»;
- `--state S --action A --name N`: клип по времени для первого непрерывного запуска состояния; обрезается там, где движение прекращается (`hold_from_ms`);
- `--idle`: один кадр покоя.

### Шаг E. Независимая проверка вторым захватом

Снять ещё одну сессию (шаг B) и сравнить:
```powershell
python -m tools.alpha_models.anim.alpha_clip compare .scratch\s05a2\clips\<клип>.alphaclip.json .scratch\s05a2\cap\<второй>.jsonl
```
Смотреть `same_time_pairs` (кадры разных запусков с одинаковым игровым временем) — это и есть повторяемость Alpha. `interpolated` в быстром ударе велико по природе (оружие поворачивается на ~100° за 28 мс между кадрами) — это не ошибка переноса.

### Шаг F. Подготовить Unity-данные

Описать набор моделей (`tools/alpha_models/transfer/models.*.json`): часть → ключ `.cub` в `data1.db`, `weapon_subtype`. Затем:
```powershell
python -m tools.alpha_models.transfer.prepare_unity --db .scratch\alphatest2\data1.db --project <UnityProject> --clips .scratch\s05a2\clips --models <models.json>
```
`PREPARE_RESULT=PASS` обязателен. Проверка совместимости модели встроена (`check_model_compatibility`).

### Шаг G. Unity: самотесты, перенос, PlayMode

```powershell
& tools\alpha_models\transfer\run_transfer.ps1 -Project <UnityProject> -Models <models.json>
```
Скрипт сам создаёт изолированный проект, копирует код (`tools/alpha_models/transfer/unity/{Runtime,Editor}` → `Assets/AlphaTransfer/Scripts`), готовит данные и запускает три метода. Итог — только по файлам `<UnityProject>\TransferOutput`:

| Маркер | Файл | Что значит |
|---|---|---|
| `SELFTEST_RESULT=PASS cases=19` | `selftest.txt` | математика осей, разбор клипов (отказы), якоря, построитель меша, сцена, слой наклона — на синтетике |
| `TRANSFER_RESULT=PASS` | `transfer_report.txt` | GEOMETRY (вершины = ожидаемые), ROUNDTRIP (сцена → матрица Alpha ≤ 1e-3), SEAM (шов цикла), GRIP (хват) + снимки |
| `PLAYMODE_RESULT=PASS` | `playmode.txt` | реальные кадры PlayMode (шаг 1/60 с): ходьба двигает стопы, атака доигрывается до конца, поза рига = поза клипа |

### Шаг H. Визуальное сравнение с Alpha

```powershell
. tools\alpha_models\runtime\alpha_window.ps1
Focus-Alpha; Mouse-Alpha left 60; Save-AlphaBurst .scratch\s05a2\visual\alpha_<клип> 60 15
```
Затем в `<UnityProject>\TransferOutput\compare_request.json` указать клип, моменты (`times`), `lookPitchDeg`, ракурс и выполнить метод `CubeGame.AlphaTransfer.Editor.AlphaTransferEditor.RenderCompare`. Получится `compare_unity_sheet.png`; склеить с листом кадров Alpha (пример в отчёте). Изображения — только в `.scratch`.

### Шаг I. Отчёт и статус

В отчёте для каждого клипа: статус, число ключей, длительность, `validation` из клипа, результат `compare`, маркеры Unity, ограничения. Затем `git status` (в индексе не должно быть ничего из `.scratch`), коммит, push своей ветки. Статус этапа — `READY_FOR_REVIEW`.

## 3. Форматы

**Захват** (`pose_capture`, JSONL, одна строка = один вызов `drawModel` игрока): `t` (сек, QPC), `this_hdr` (`+4` время мс, `+8` состояние), `creature_hdr` (первые 0x180 байт существа: `+0x40` ускорение, `+0x58` наклон, `+0x68` действие, `+0xb0` масштаб оружия), `fields` (`amp_1188`, `phase_118c` …), `placement` (16 float, `local_14e0`), `parts[]` (`draw_site`, `upload_site`, `matrix` 16 float, `mesh_hdr`: `+0x3c` вершины, `+0x44` размер сетки).

**Клип** (`*.alphaclip.json`): `format=cubegame.alpha_clip/1`, `rig=alpha_humanoid_v1`, `status`, `param` (`time_ms` | `walk_phase`), `loop`, `duration`, `parts[]` (имя, `captured_size`, `anchor`, `mirrored`, `draw_site`), `keys[]` (`x`, `m{часть: J 16 float}`), `source` (хеш захвата, состояние/действие, амплитуда, скорость фазы, диапазон наклона…), `validation`.

**Unity-клип** (`Assets/AlphaTransfer/Data/clips/*.json`): те же данные в плоском виде для `JsonUtility` (`parts[]`, `capturedSizes[]`, `keys[].m` = 16×N float в порядке `parts`).

**Риг** (`rig.json`): `rig`, `variant`, `weaponSubtype`, `parts[]` (`name`, `model`, `file`, `size`, `anchor`, `mirrored`, `expectedVertices`).

**Пространства:** Alpha — строки-векторы, X вправо, Y вперёд, Z вверх, единица = воксель сетки. Unity — `U = C·Aᵀ·C`, `C` = перестановка Y↔Z (единственное место — `AlphaSpace.ToUnity`). Вершина `.cub (x,y,z)` → Unity `(x,z,y)`. Риг плоский: `root → part_<имя> (поза J) → mesh (localPosition = −anchor)`.

## 4. Пороги проверок

| Проверка | Порог | Фактически (эталон) |
|---|---|---|
| Обратная реконструкция `T(-a)·J·P = M` (Python) | ≤ 1e-9 | 2.8e-14 |
| Ходьба, «один цикл отложен» | ≤ 0.25 вокселя, ≤ 3° | 0.19 / 2.37°, p95 0.36° |
| Атака, кадры с равным временем (после 50 мс) | ≤ 0.1 вокселя, ≤ 0.5° | 0.041 / 0.21° |
| Unity GEOMETRY | вершины = ожидаемые | 8/8 |
| Unity ROUNDTRIP | ≤ 1e-3 | ≤ 8e-6 |
| Unity GRIP | основная кисть ≤ 0.05; вторая кисть до оси ≤ 2.5 | 0.0002 / 2.30 |
| PlayMode | атака до конца, размах стопы ≥ 4, путь клинка ≥ 30, поза = клип (≤ 1e-3) | см. отчёт |

Если порог нарушен — не ослаблять его, а найти причину (раздел 5).

## 5. Типичные ошибки и исправления

| Симптом | Причина | Исправление |
|---|---|---|
| Снят не тот персонаж (5–7 частей, эльфийские волосы) | автоподбор по числу частей | `--target player` (по умолчанию) |
| Игра падает после захвата | точка останова сработала во время отсоединения | уже исправлено (`_drain`: сначала вернуть все байты, затем доиграть события с откатом EIP); если повторится — не запускать захват дольше нужного и сообщить |
| `frame_check=False` | другая сборка `Cube.exe` (смещения кадра стека) | проверить SHA256 копии; при другой сборке адреса не переносить вслепую |
| Ходьба: выбросы 10–17° у стоп | в «устойчивые» попали кадры после отпускания W | фильтр по вводу уже встроен; снимать с удержанием W ≥ 3 с |
| Голова/оружие отличаются между сессиями на несколько градусов | разный наклон взгляда | нормировка уже встроена; проверить `look_pitch_deg_range` |
| Атака сильно расходится после ~1400 мс | в фазе удержания руки/оружие «целятся» по наклону | снимать при наклоне ≈0 (камера не трогается мышью), хвост клипа помечать |
| Unity падает `0xC0000005` при выходе | явный `EditorApplication.Exit` вместе с `-quit` | в пакетных методах не вызывать `Exit` — вернуть или бросить исключение |
| PlayMode «ничего не проигрывает» | batch-режим идёт с 2000+ кадров/с | `Time.captureDeltaTime = 1/60` (уже в `AlphaPlayModeProbe`) |
| `WEAPON_SUBTYPE_NOT_VERIFIED` | подтип оружия вне 15/16/17 | не подменять: найти блок отрисовки оружия этого подтипа, добавить правило якоря в `humanoid_rig.weapon_anchor` с доказательством |
| `GEOMETRY_MISMATCH` | не та модель или маркерные воксели | сверить ключ `.cub`, исключение маркеров не делать без решения |
| Камера Alpha не крутится колесом/мышью | известно; ракурс задаётся игрой | для визуального сравнения подбирать ракурс в Unity под кадр Alpha |

## 6. Как перенести следующую анимацию того же гуманоида

1. Найти ввод, который её вызывает (клавиша/кнопка), и снять сессию (шаг B).
2. `summary` → новый `state`/`action`. Названия брать из кода: `combat_selectAttackAnim` (0x445020) для атак, `switch(self[2])` в `drawModel` для состояний.
3. `build --state S --action A --name <понятное_имя>`; если оружие в анимации на спине — `build_time_clip(..., on_back=True)` (добавить флаг в CLI при необходимости).
4. Шаги E–I. Статус `TRANSFERRED_FROM_ALPHA` — только если все ключи сняты в Alpha и проверка повторяемости пройдена; иначе `PARTIAL` с причиной.

## 7. Как применить технологию к другой модели

**Совместимая модель** — гуманоид из тех же 8 частей (тело, голова, волосы, оружие, кисть, стопа), рисуемый тем же путём `drawModel`. Тогда достаточно нового `models.json` (шаг F): клипы не меняются, якоря пересчитываются по размеру новой модели. Проверено: тот же клип на двуручном мече `iron-greatsword` (3×13×37) и на булаве `wood-greatmace02` (13×13×33).

**Несовместимая модель** (дракон, слизень, существа с 1–2 частями, броня с наплечниками): нужно сначала снять её захват (`--target <ptr>`), выяснить адреса отрисовки её частей (`draw_site`) и правила якорей по коду, завести **новый** риг (`humanoid_rig.py` → новый модуль) и лишь затем переносить. Это исследование, а не масштабирование — согласовать с архитектором.

## 8. Ограничения (не обходить молча)

- Подтверждено: один гуманоид, 8 частей, `idle`, `walk` (амплитуда 0.192, фаза), атака 57 двуручного оружия. Не подтверждено: состояния 37/3 (продолжение комбо), бег/прыжок/блок/способности, другие классы оружия, броня/наплечники/предметы на спине, переходы между клипами.
- Сглаживание позы в Alpha зависит от частоты кадров: клип — запись реального прогона при ~70 кадр/с, а не «идеальная» функция.
- Тинт волос не восстановлен (белая маска `human-hair-m01`), меш волос игрока в Alpha (2244 вершины) не совпал ни с одной моделью `human-hair-*`.
- Только локальный исследовательский прототип (D54): данные Alpha не публикуются; перед релизом — собственные или лицензированные модели и анимации.

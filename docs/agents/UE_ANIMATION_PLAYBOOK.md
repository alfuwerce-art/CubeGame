# UE 5.9 — animation adaptation, correction and validation
Operational reference for cubegame-rig-animation. Applies to the current authorized CubeGame character/creature; not a new animation architecture or product decision. Adapt rules for non-humanoid rigs and artistic reference; do not impose biped constraints on creatures.

## 1. Sources and selection
- Local: `D:\Projects\скачанные анимации` — read-only inventory. Record accessible files, format, clip names, skeleton and provenance; inspect real contents, not filename alone. No modification or bulk upload.
- [Game Animation Sample](https://dev.epicgames.com/documentation/unreal-engine/game-animation-sample-project-in-unreal-engine) — inspect start, loop, stop, turn, traversal and responsive capsule-driven locomotion. Inspect the actual installed version and animation assets. Migrate only selected dependencies if allowed.
- [Lyra](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-in-lyra-sample-game-in-unreal-engine) — study state logic, starts/stops, distance matching and stride warping; do not copy shooter-specific behavior indiscriminately.
- [Content Examples](https://dev.epicgames.com/documentation/en-us/unreal-engine/content-examples-sample-project-for-unreal-engine) — study IK, blends, root motion and editor workflows.
- [Third Person Template](https://dev.epicgames.com/documentation/en-us/unreal-engine/third-person-template-in-unreal-engine) — baseline animation assets and movement integration.
- [Quaternius viewer](https://quaternius.com/animviewer.html), [Universal Animation Library](https://quaternius.itch.io/universal-animation-library), [Library 2](https://quaternius.itch.io/universal-animation-library-2) — compare stylized locomotion, combat, actions. The named libraries are CC0; verify exact pack/version and included files/license. Viewer is for inspection, not an assumed download API.
- Cube World — visual inspiration only; use authorized references, do not extract proprietary assets or replace the approved project art direction.
Before choosing, make short candidate comparison: phase, silhouette, tempo, responsiveness, contacts, compatibility, availability and licensing. Record chosen source and why. For external Epic assets check applicable license and engine-use restrictions. Unverified rights => reference-only. Do not download full libraries if a local clip suffices. Record source clip/URL and derivative path; do not pretend to have previewed missing assets.

## 2. Native UE tool selection
Use actual installed 5.9 API/editor capabilities, verify plugins and project settings. Prefer editor UI/MCP if callable; otherwise verified Python editor APIs or scoped C++ editor utilities, with real output validation. Do not assume every editor action has a Python or MCP endpoint. Do not change engine installation, install unapproved plugins or bypass permission gates.
| Tool | Use |
|---|---|
| IK Rig / IK Retargeter / Retarget Pose | Source/target chains, rest offsets, bone axes, target proportions, contact goals; inspect retarget preview |
| FK Control Rig / Control Rig + Sequencer | Bake eligible clip to controls, correct affected channels at keyframes, inspect neighboring frames, bake to Animation Sequence |
| Curve Editor / Animation Sequence Editor | Tangents, interpolation, phase, duration, loop seam, root curves, key-by-key inspection |
| Animation Modifiers / editor data controller | Repeatable curve extraction, contact markers and verified batch edits; idempotence, backup, verify actual written keys |
| AnimBP / State Machines / Blend Space / Sync Groups | Responsive state transitions and phase alignment |
| Distance Matching / Stride Warping | Correct acceleration/braking distance and contact vs capsule speed where suitable |
| Inertialization / Dead Blending | Preserve continuity at state changes; not a substitute for good source poses |
| Rewind Debugger / Animation Insights / Pose Watch | Record actual PIE, inspect states, weights, poses, player positions and movement; diagnose exact defect frame |
| Pose Search / Motion Matching | Study for future broader clip coverage; no forced migration on current mannequin |
| Motion Warping | Target-dependent root-motion actions where existing action contract requires it; not a generic locomotion fix |

## 3. Retargeting and repair procedure
1. Inspect source animation without target. Establish action direction, contact intervals, key poses, period, root motion and intended style. Inspect target skeletal hierarchy, rest transforms, actual visible geometry, scales/units, bone orientations, weights or rigid attachment. Record protected head/body/limbs and their offsets, not absolute final mannequin dimensions.
2. Map chains deliberately; do not infer mapping by name alone. Check root/pelvis handling, source vs target rest pose, rotation/translation policy, unsupported or missing joints. For floating visible modules use compatible virtual/control chains or custom control mapping only when needed. Preserve gaps and rigid silhouettes; no automatic limb-length stretching, connecting geometry or body rebuild. Avoid solver goals that pull detached parts into the body.
3. Preview retarget with same clip/time. If feet slide, inspect root displacement, retarget scaling, contact phase and actual capsule velocity; test speed planting/contact curves only for suitable rig. If shoulders and arms counter-rotate incorrectly, inspect reference axes, chain mapping, local/component space and upper-arm rotation before changing keys.
4. For a local correction use FK/Control Rig or verified editing API; preserve unaffected tracks and accepted poses. Correct keys in the affected time range and neighboring continuity, inspect interpolation/overshoot and shortest-path rotation; bake then verify saved sequence, not just temporary rig preview. Validate affected equipment sockets. For systematic fixes apply a versioned reversible modifier or scoped script; compare before/after after reload. Do not hide with excessive smoothing, slower playback or camera changes.
5. For original animation, define readable contact/passing/extreme poses and timing, animate intentional acceleration and recovery, then adjust curves and overlap in the approved style. CubeGame mannequin should not become heavy realistic mocap by default; assess lightness, responsiveness, restrained pelvis movement, coherent shoulder/arm swing, short natural stance and stable intentional gaps against owner reference. Do not invent universal limb gap or final body measurements.

## 4. Locomotion transitions
Inspect actual AnimBP graph, current movement component, root motion policy, input/velocity/acceleration/deceleration and existing clips. For capsule-driven locomotion avoid double root movement; for root motion keep capsule and mesh coherent. Do not switch policy without scope.
Recommended starting pattern (not mandatory redesign):
Idle -> Start -> RunLoop -> Stop -> Idle. Also support Start -> Stop/Idle on release; Stop -> Start/Run on renewed input; direction changes and speed changes within scope. Use separate start/stop clips if needed, not merely idle/run crossfade. Select left/right foot variant by actual contact phase when available. Sync markers for cyclical states; explicit transition timing/conditions, speed hysteresis and interruption behavior. Evaluate travel distance to stop with actual movement settings, then match stop clip distance if supported. Prefer the simplest correct blend; consider inertialization if pose velocity continuity fails. No hardcoded blend times as acceptance requirements; tune and record measured latency, phase and visual result. Inspect blend weights, time remaining and player position in Rewind Debugger. Stop ends at idle with stable feet, no rebound or forced completion while player resumes running.
Motion Matching is optional when sufficient compatible clips and project approval exist; do not replace the current state machine merely because the sample uses it.

## 5. Mandatory evidence and artifact checks
Before edits reproduce defect and record exact asset, time/frame/state, bone/module, camera, speed, input sequence and suspected layer. Use baseline and final clips with same cameras, frame sampling and runtime input. Full playback plus dense samples at native key times and between keys; loop at least three cycles. Capture front, side, rear and actual gameplay camera. View at 1x and slow speed; use contact sheets including start/end, extremes, blend boundaries and flagged frames. If visual analysis is unavailable mark NOT_RUN, ask for review only if necessary; no inferred visual PASS from numeric data.

| Defect | Diagnostic / repair focus |
|---|---|
| Foot sliding / floating during stance | World-space foot travel and height during declared contact; actual capsule motion; retarget scale, phase, speed/stride/contact correction |
| Floor penetration or excessive lift | Foot sole vs test floor, contact phase, pelvis and IK settings; distinguish planned swing |
| Stretch, collapsed or disconnected parts | Reference and frame transforms, bone lengths/scales, rendered gap, joint axes; rigid part integrity, intended separation allowed |
| Limb/body intersection, crossed legs | Multi-angle silhouette and module bounds/mesh checks; correct keys/IK goals; bounds overlap is a candidate, not proof of visible collision |
| Shoulder/arm mismatch, twist, jitter | Sample local/world angles, angular velocity, accelerations, signs and continuity; inspect axes, tangent overshoot, conflicting layers |
| Loop pop | Last-to-first pose and velocity discontinuity; compare contact phase; test repeated loop and exported/reloaded clip |
| Start/stop jerk, idle snap, delay | State/weight/time trace + speed/distance, first visible response, contact continuity, actual input-to-motion and stop-to-idle time |
| Root/capsule drift, double movement | Compare actor/capsule vs mesh root displacement, root policy and gameplay movement |
| Weapon/hand mismatch | Socket and grip trajectories and visual contact; only when equipment in scope |

Quantify in actual units: max stance drift (cm and ratio to foot length), max floor error, unexpected scale/length deviation vs baseline, min/maximum intentional gap by phase, adjacent pose changes (cm/deg) and root displacement, transition response/settle (ms), state/phase traces. Evaluate known intended offsets, rotations and root translations, not generic human limits. Establish thresholds from approved reference/rig, observed baseline and action intent before assessing; label any proposed thresholds provisional. Record metric definition, sampling rate, baseline, final, limit and verdict; flag suspicious outliers for visual confirmation. Avoid claiming intersection detection or complete visual inspection from only a bone/bounds script.

Runtime test matrix when locomotion affected (flat test floor, fixed input replay if possible): idle hold; idle->run->idle at least 10 repetitions; release mid-start; restart mid-stop; short taps; changes of direction including 90/180 degrees; speed changes, and relevant gameplay slope/equipment cases if supported. Observe at typical frame rate and a lower supported rate to expose timing issues. Track states, capsule speed, root delta, blend weights, foot contacts and visible response. For isolated clip scope, runtime tests may be NOT_APPLICABLE only with reason; for transition tasks real PIE is mandatory. Do not modify unrelated gameplay to force a test to pass.

Report each applicable scenario PASS/FAIL/BLOCKED/NOT_RUN; each issue with time/frame, before/after image/video and metric. No PASS for missing capture, unverified tool calls, or only compilation. Technical check vs style review separate. Existing known unrelated defects report, not silently fix; no regression of protected parts. After two failed corrections of same issue, diagnose alternate layer/tool or BLOCKED. Owner alone accepts artistic quality.

## 6. First activation exercise
When explicitly tasked to activate/train this skill, do a real local exercise on authorized current mannequin: inventory one accessible source; choose one compatible locomotion clip; retarget and save a reversible candidate; reproduce and repair one real defect (or report none observed, do not invent one); inspect full clip and actual Idle/Start/Run/Stop/Idle transitions; interrupt/restart; capture video, trace and measurements. Use existing test map or authorized sandbox. Keep accepted assets unchanged. Record tool/plugin capabilities and source selection; if missing source/rig/PIE/capture, report exactly what is blocked. Reading this playbook is not successful training. Do not automatically execute the exercise as a side effect of unrelated tasks.

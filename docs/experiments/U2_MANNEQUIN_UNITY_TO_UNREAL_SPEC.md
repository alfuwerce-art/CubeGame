## 2. Требуемая конструкция MANNEQUIN-V1 (параметры первичной гипотезы, на ревью)

- **Общий стиль:** компактный, блочный, voxel/pixel 3D; крупная почти квадратная голова ориентировочно 33–35% полной высоты; короткое, не мускулистое туловище; компактные руки; небольшие ступни; нейтральный серый материал, без волос, глаз, одежды, брони, цвета расы, выпуклых бицепсов. Точные измерения в UE единицах — установить после сравнения с донором и референсами, **не объявлять численные пропорции принятыми заранее**.
- **Визуально отдельные** голова, торс/таз, левое и правое плечо, предплечья, кисти, элементы коленей/голеней по требуемому силуэту, ступни. Особенно ноги: допускаются **видимые воздушные зазоры**, а не сплошная человеческая голень; воздушные зазоры остаются при анимации.
- **Скелет непрерывный логически**, несмотря на раздельную геометрию: root/pelvis/spine/neck/head; clavicle→upperarm→lowerarm→hand→пальцы (минимально необходимые для open/fist/grip); thigh→knee→ankle/foot. Допускаются невидимые кости и пустые участки, не допускать «оторванных» трансформов при движении.
- Локальные origin/pivot у суставов согласованы. Геометрия жёстко привязана к соответствующим костям (или использует устойчивое компонентное крепление), без желейной деформации блока; веса на гранях не размывают форму. Скелет и меш могут использовать единый Skeletal Mesh с disjoint mesh islands; разделение в редакторе должно быть объяснимым и проверяемым.
- **Кисти**: читаемые ладони и пальцы, технические состояния open, fist, grip (владельцу показать, какой уровень пальцев реально реализован); крепление оружия через hand socket. Не рисовать пальцы лишь на рендере.
- **Модульность:** раздельные визуальные модули/именованные секции; возможность заменить голову/кисти/ноги/доспех не разрушая скелет. Для V1 достаточно показать **одну физическую замену части** без пересборки всех анимаций.
- **Функциональные проверки:** idle, движение, поворот, прыжок по готовности управления; для боевого теста — атака, реакция на попадание, смерть, простой захват оружия. Переиспользовать одну иерархию для Player и Enemy (разные контроллеры/AI, не разные риги).

## 2A. Unreal 5.9 — основной инструмент создания и исполнения анимаций

**Обязательное требование владельца (2026-11-22):** по максимуму использовать проверенные штатные возможности Unreal Engine; не создавать собственный универсальный анимационный движок/конвейер вместо встроенных средств. Создавать **редактируемые оригинальные UE-анимации и игровые механики**, а не только записывать скрипты или показывать рендер.

| UE-система | Практическая задача |
|---|---|
| Skeletal Mesh / Skeleton / Physics Asset | Единый рабочий скелет для разделённых блоковых частей; физические тела, коллизии |
| Animation Sequence / Animation Editor / Control Rig | Постановка **новых** ключевых поз и движений под собственный риг |
| Animation Blueprint (State Machine, AnimGraph, Blend Space по необходимости) | Idle/Move/Turn/Jump, переходы и смешивание в игре |
| Animation Montage + Anim Notifies | Attack/HitReact/Death, события и активные окна оружия; боевой урон остаётся в C++ |
| IK Rig / Skeletal Controls / Control Rig | Положение ступней, локтей, предплечий и кистей; контроль визуальных зазоров |
| Sockets | Хват и смена оружия/экипировки без переписывания анимаций |
| CharacterMovement / Enhanced Input / C++ Character | Игровая кинематика, управление, поворот, коллизия и режим Player/Enemy |

IK Retargeter допускается **только как локальный диагностический инструмент для изучения возможностей**, но не для переноса исходных чужих анимаций в конечный ассет. Motion Warping, UE animation framework, Pose Search и иные тяжёлые средства подключать **только при доказанной необходимости**, без усложнения U2. Agent должен проверить доступные инструменты редактора/его MCP toolsets, не выдумывать API; если невозможна автоматизация конкретной операции, документировать и выполнять минимальным поддерживаемым способом. Собственный код для игровой логики — C++, Python — редакторский инструмент; визуальные анимационные узлы допустимы, не дублировать доменную логику в Blueprint.

## 2B. Unity-анимации — ориентир поведения, НЕ копировать в новую модель

**Обязательное требование владельца (2026-11-22):** изучить анимации уже перенесённого в Unity персонажа **как пример**, понять принципы движения и сделать **свои**, лучше подходящие новой воксельной геометрии. Никакого слепого воспроизведения старых движений или сохранения идентичных ключевых кадров.

**Внутреннее исследование U2 (только чтение Unity):** установить, существуют ли и доступны ли `AnimationClip`, `Animator` или процедурные движения (включая .scratch/runtime). Для каждого фактически найденного Idle/Walk/Run/Turn/Attack/Hit/Death по возможности описать длительность, опорные фазы и контакты стоп, перенос веса, амплитуды рук/головы/корпуса, повороты и боевые окна. При отсутствии указать `NOT_FOUND`, не изобретать клипы. **Не копировать/публиковать исходные клипы, таймлайны или animation curves.**

**U2/U3 — новая постановка в Unreal:** создать `Idle_New`, `Walk_New`, `Turn_New`, `Move_New` и `Jump_New` по мере U2; затем `Attack_New`, `HitReact_New`, `Death_New` по мере U3. Это **новые авторские позы, фазировка и характер движения**, а не экспорт Unity → FBX → Retarget. Игровая функция может совпадать (шаг, замах, удар), но движения должны учитывать короткие пропорции, визуально плавающие колени/ступни, отдельное предплечье, жёсткие блоковые элементы, Grip-кость/сокет, новый ритм и читаемое ощущение веса. Новая анимация не обязана быть покадрово похожей на Unity.

**Запреты для результата:** не экспортировать/встраивать чужие Unity/Alpha animation tracks, не переносить ключевые кадры/кривые и не ретаргетить исходные клипы на наш новый риг для готовых `*_New`; не публиковать их в репозитории. Любое локальное диагностическое исследование держать отдельно в `NON_SHIPPABLE` без включения в новую игру и без использования в релизе. Для финального контента использовать оригинальные/лицензированные материалы.

**Что принять визуально в Unreal:** устойчивый контакт ступней с землёй, минимальное foot sliding, отсутствие отлетающих частей/пересечений, блоковые грани не тянутся как резина, пальцы управляют захватом, оружие не смещается, hit window совпадает с фактическим касанием, позы читаются с игровой камеры. Сдать видео со сравнением **общего принципа** Unity → новой постановки UE и короткий список отличий; личное ревью владельца обязательно.

Сверять доступность движковых средств по официальной документации UE 5.9: [Animation Blueprint](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprints-in-unreal-engine), [Control Rig](https://dev.epicgames.com/documentation/en-us/unreal-engine/animating-with-control-rig-in-unreal-engine), [Animation System](https://dev.epicgames.com/documentation/unreal-engine/skeletal-mesh-animation-system-in-unreal-engine), [IK Rig](https://dev.epicgames.com/documentation/en-us/unreal-engine/ik-rig-in-unreal-engine).

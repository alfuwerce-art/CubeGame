# CubeGame — анализ референсов и локальные правки
1. Найти конкретный исходный ассет, версию и референс из запроса/паспорта. Указать статус источника (кандидат, принят, владелец разрешил использовать), ракурсы и целевую область. Приватные пути/файлы не публиковать.
2. Сравнить силуэт, основные плоскости, ступени, объём и пропорции в одинаковой позе/камере/масштабе; для недостающего ракурса отметить неизвестность, не придумывать доказательство.
3. Составить ожидаемые изменения и protected regions (все остальные элементы, rig/материалы/пивоты/зависимости). Снять baseline хеши файлов, а для одной сетки — измерения/хеши регионов или сравнение вершин в одинаковой системе координат. Хеш всего файла сам по себе не доказывает сохранение части.
4. Реализовать минимальную необходимую правку исходника/копии. Не заменять исходную модель новой без запроса, не менять принятую геометрию вне зоны. Перед реимпортом проверить shared Skeleton, Rig, Animation Blueprint, материалы и другие зависимости; не сохранять неожиданные dirty packages.
5. Снять одинаковые кадры до/после и целевой референс (фронт, профиль, 3/4, спина, игровая камера по применимости). Проверить область правки и регрессии остальных частей. Сравнивать с целью, а не только с предыдущей неудачной версией. Обозначить ожидаемое/наблюдаемое/серьёзность/доказательство.
6. При двух неудачных попытках одного дефекта остановить повтор той же стратегии: определить причину (сетка, алгоритм, материал, перспектива, skinning и т.п.), выбрать другой подход или BLOCKED. Не ждать владельца после каждой внутренней попытки.
7. Выдать реальный результат в запрошенной среде и краткий отчёт. Не принимать художественное решение за владельца. [Приёмка](ASSET_ACCEPTANCE.md).

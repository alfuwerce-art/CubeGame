# CubeGame — реестр решений 001–036

**Наименование:** CubeGame — рабочее название проекта; окончательное название игры не утверждено.

**Статус:** ответы продюсера подтверждены.  
**Дата фиксации:** 2026-11-02.  
**Назначение:** единый источник требований для архитектора и локального ИИ-разработчика.  
**Важно:** этот документ не означает утверждения технической архитектуры, точных численных параметров, финальной графики или коммерческих условий.

## Принцип проекта

Эволюция существующих удачных идей: исследовать Cube World Alpha 2013 и другие игровые эталоны, сначала воспроизвести основной опыт Alpha в Unity, затем постепенно улучшать его. Не заменять проверенные решения только ради новизны. Технические реализации и заимствование исходного кода — разные вопросы; выбор конкретных внешних компонентов проверять отдельно.

## Решения 01–15: основа проекта

| ID | Решение | Граница / примечание |
|---|---|---|
| D01 | Сначала максимально близкая по поведению версия Cube World Alpha 2013; затем переосмысленная игра. | Не смешивать ошибки воссоздания с результатами новых механик. |
| D02 | Большой процедурный мир с разнообразными, осмысленно уникальными регионами; изменения мира постоянны. | Уничтожение лагеря сохраняется. |
| D03 | Сохранить полезные принципы исходных систем; не переписывать механики без необходимости. | Уточнение D19: новая игра — отдельное прохождение; не предполагается перенос персонажа между разными сохранениями. |
| D04 | Полная симуляция в активной зоне; логика событий и NPC продолжается вдали в облегчённом виде, пока мир запущен. | Отсутствие рядом игрока не «замораживает» его NPC. |
| D05 | Визуально узнаваемый кубический стиль с добавленной геометрией, текстурами, освещением, травой, листвой и взаимодействиями. | Окончательный стиль утверждается по прототипам позднее. |
| D06 | Камера — привычный свободный вид от третьего лица, как в Alpha. | Улучшения камеры только по отдельному решению. |
| D07 | Ориентация на средние и сильные ПК; графические настройки масштабируются. | Целевые FPS и конфигурации утвердить при техпроектировании. |
| D08 | В эволюционной версии класс на старте задаёт начальное оружие и способности; далее свободное развитие и выбор оружия. | Базовая версия сначала воспроизводит ограничения Alpha. |
| D09 | Сначала боевые основы Alpha; новые боевые механики добавляются позднее. | Новая механика — отдельное проверяемое изменение. |
| D10 | Фракции влияют на территории; углублённую политику не реализовывать. | Пользовательские серверы появятся позднее. |
| D11 | Полноценный мультиплеер и серверная инфраструктура — поздний этап; сейчас локальная игра без затрат на хостинг. | Архитектуру отделить от Unity-представления и подготовить к сетевому расширению; отсутствие сети не гарантирует нулевой будущий рефакторинг. Вопросы релизной офлайн-политики/защиты открыты. |
| D12 | NPC: локальная LLM без обязательного платного API; текстовые ответы, текстовый и голосовой ввод, озвучка NPC позже. | Действия и изменения мира верифицирует игровой код. |
| D13 | Квесты: сначала процедурные сюжетные шаблоны, позднее авторские уникальные задания. | Должны быть содержательные задачи, не бессмысленный гринд. |
| D14 | Первый крупный результат — максимально полный перенос игрового опыта Alpha в Unity без готового мультиплеера. Затем версия с улучшениями. | Первый технический прототип не равен первой завершённой версии. |
| D15 | Продюсер определяет игру; ChatGPT проектирует архитектуру и ревью; локальный агент реализует, тестирует, передаёт изменения в GitHub. | Общие версионированные документы; архитектура утверждается отдельно. |

## Решения 16–24: устойчивость мира и организация

| ID | Решение | Граница / примечание |
|---|---|---|
| D16 | Частично разрушаемый мир: отдельные объекты/области, а не тотальная воксельная разрушаемость. | Шахты, лесозаготовки и добывающие NPC — идея, НЕ текущая задача. |
| D17 | Локальный мир останавливается при выходе. Будущий сервер симулирует мир до выхода последнего игрока. | Без фоновой симуляции закрытого мира. |
| D18 | Уничтоженные лагеря могут позже заселяться вновь или менять принадлежность по правилам мира и фракций. | Исходное разрушение и дальнейшие события — разные сохранённые факты. |
| D19 | Новое прохождение = самостоятельный мир и сохранение. В пределах него сохраняются персонаж, регионы, NPC, фракции, задания и последствия. | Не трактовать регионы как отдельные новые игры. |
| D20 | Приёмка первой полной версии по максимально близкому соответствию системам Alpha 2013. | Продюсер планирует получить рабочий экземпляр Alpha для сравнения. |
| D21 | Кубический силуэт обязателен; дополнительные полигоны, скосы, материалы и текстуры допустимы. | Художественные решения утверждать по образцам. |
| D22 | Сначала русский язык; технологически подготовить локализацию. | Строки и диалоги не зашивать непосредственно в логику. |
| D23 | Будущие пользовательские серверы: настройки генерации, моды и плагины по принципу Minecraft. | Полную платформу модов сейчас не строить. |
| D24 | Агент свободен исправлять/рефакторить без изменения поведения; архитектор утверждает архитектурные изменения; продюсер — геймдизайн и визуал. | Запрет выдавать неутверждённые решения за утверждённые. |

## Решения 31–36: создание контента и контроль качества

| ID | Решение | Граница / примечание |
|---|---|---|
| D31 | Гибрид моделей: использовать оригинал как технический/визуальный референс там, где это удобно, и создавать новые модели там, где лучше. | Обязателен узнаваемый кубический силуэт. |
| D32 | Производство модели и анимации — единый процесс. Первая проверка: **одна новая/переработанная модель → старая анимация на новой модели → одна новая анимация на той же модели**. Далее единые риги и контроллеры. | Массовая обработка только после прохождения пилота. |
| D33 | Новое окружение и боевые VFX; множество настроек качества для разного железа. | Художественный стиль VFX утверждать в живой игре, не сейчас. |
| D34 | UI: сохранять удачные элементы оригинала и перерабатывать неудобные по результатам тестов. | Сначала поведение Alpha, затем удобство и визуал. |
| D35 | По одному эталону для категории, затем выпуск партиями; **продюсер просматривает и утверждает каждую переработанную модель**. | Пакетное производство не означает пакетную автоматическую приёмку. |
| D36 | Приёмка: тесты, работающая сборка/демонстрация, показатели производительности, известные ограничения, регрессионные проверки; недопустимые поломки блокируют этап. | Отложить проблему можно только по явному решению продюсера. |

## Явно не принято или отложено

- Финальная стилизация персонажей, архитектуры, интерфейса, освещения и эффектов — утверждается **во время графического производства**, а не на архитектурном этапе.
- Точный список биомов, врагов, классов и процедурных сюжетов.
- Конкретные численные значения боевого баланса и характеристик.
- Рудники, добывающие NPC и физическое развитие/разрушение целых городов.
- Полное стратегическое планирование отдельных фракций и генерация сюжетов из всех событий мира.
- Правила релизного офлайн-доступа, авторизации и защиты от пиратства.
- Конкретный движок сети, способы моддинга, протоколы LLM и форматы файлов — вопросы технического проектирования.

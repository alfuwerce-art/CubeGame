# CubeGame — протокол сотрудничества (предложение)

**Наименование:** CubeGame — рабочее название проекта; окончательное название игры не утверждено.

**Роли:** продюсер — пользователь; архитектор и ревью — ChatGPT; разработчик и оператор ПК — локальный ИИ-агент.

## На входе задачи

Агент **до работы** читает актуальные `DECISIONS_001-036.md`, `ARCHITECTURE_PROPOSAL.md` (только после утверждения — `ARCHITECTURE.md`), `ROADMAP_DRAFT.md` (после утверждения — `ROADMAP.md`), `ACTIVE_STAGE.md`, открытые change requests, технические ограничения и тестовые сценарии.

## Объём свободы

- **Агент самостоятельно:** код, тесты, оптимизация, исправления и рефакторинг внутри принятых контрактов без изменения игрового поведения.
- **Архитектор решает:** API, границы модулей, форматы сохранений, зависимости, стратегию миграции; перед реализацией согласовать, если изменение требует пересмотра утверждённого проекта.
- **Продюсер решает:** геймплей, баланс, новые системы, контент, модели и художественный вид; каждую модель отдельно показывает на приёмку.

## На выходе каждой задачи

- Git-ветка, коммит и перечисление изменённых файлов.
- Сводка того, что сделано и чего не сделано.
- Тесты с фактическими результатами, воспроизводимые шаги ручной проверки.
- Для игровых изменений — сборка, видео/скриншоты или доступный локальный сценарий проверки.
- Измерения производительности для затронутых критических систем.
- Известные дефекты, регрессии, риски и запросы решений.
- Статус: `READY_FOR_REVIEW`, а не самовольное `ACCEPTED`.

## Приёмка и публикация

Архитектор проверяет соответствие контрактам, тестам и утверждённому ТЗ; продюсер оценивает геймплей и художественный результат. Только после проверки этап можно закрыть. Требование, способное сломать другие системы, оформляется отдельным запросом изменения с анализом зависимостей.

## Честность статусов

Писать `TESTED` только для реально выполненных тестов; `IMPLEMENTED` только при наличии проверяемого кода; `ART_APPROVED` только после просмотра конкретной модели продюсером. Отсутствующие результаты нельзя подменять предположениями. GitHub — источник версий и отчётов, но чат не наблюдает за изменениями автоматически между обращениями без отдельной автоматизации.

## 0. Принципы (что эта архитектура обещает)

1. **Ничего принятого не переписывать.** `CubeGame.Core` (S02–S04) и рантайм S05 подключаются как есть;
   новое — только связующие слои и перенос файлов S05 без изменения логики (M0-00A §4).
2. **Одно правило — один владелец.** Каждое изменяемое состояние имеет одного владельца (§3); остальные читают
   снимки или получают события. Анимация никогда не меняет игровое состояние.
3. **Время одно.** Вся симуляция тикает от `GameClock`; `Time.deltaTime` читает только он (R-TIME).
4. **ID Alpha живут только в импорте.** Сырые байты/индексы Alpha (`+0x140`, слоты отрисовки, `item_icon_id`,
   `kind`) переводятся один раз в `AlphaModels.Import`; в `Core`/`Features` — только типы CubeGame (R-ID-1…4).
5. **Неизвестное — явно.** Любое значение без доказательства — именованная константа в одном реестре отклонений
   (`DeviationRegistry`, §9) со статусом и тестом; «как в Alpha» без источника запрещено (B §6.6).
6. **Сейв переживает версии.** Сначала механизм миграций и тест «сейв v1 грузится», потом новые поля (R-SAVE).
7. **Готово = сценарий в одной сборке.** `PASS_ORACLE_VERIFIED`/EditMode-тест не закрывают подэтап; закрывает
   сквозной сценарий `GS-*` в запущенной игре (B §6.6, M0-00 §0.1).

## 1. Сборки (asmdef) и направления ссылок

```text
CubeGame.Core                 (есть)  чистые правила, noEngineReferences; НИ НА ЧТО не ссылается
CubeGame.Persistence          (есть)  I/O сейвов → Core
CubeGame.Features             (НОВАЯ) сценарии/правила игрового цикла поверх Core: GameSession, GameClock,
                                      World/Entities, Hero, Items, Combat, Actions, Creatures; без MonoBehaviour,
                                      noEngineReferences → Core
CubeGame.AlphaModels          (НОВАЯ; перенос tools/.../transfer/unity/Runtime) AlphaRig, VoxelMesh, клипы,
                                      локомоция, контроллер, контракт сущности → только UnityEngine
CubeGame.AlphaModels.Import   (НОВАЯ) загрузка локального кэша Alpha + перевод ID Alpha→CubeGame
                                      → AlphaModels, Core
CubeGame.Presentation         (есть)  MonoBehaviour, сцены, ввод→команды, вид сущностей, HUD
                                      → Features, Core, Persistence, AlphaModels, AlphaModels.Import
Вне игровой сборки: CubeGame.AlphaModels.Verification (probes S05), CubeGame.Editor, *.Tests, просмотрщик
```
* Ацикличность и направления — тест над `.asmdef` (EditMode, без Unity-сцены): `Core` без ссылок,
  `Features` → только `Core`, `AlphaModels` не ссылается на `Core`/`Features`, `Verification` не входит в
  `Presentation`. Тест — первый артефакт M0-01A.
* Почему `Features` отдельно от `Core`: `Core` принят как библиотека формул S02–S04; игровой цикл (сессия,
  сущности, часы, команды) — новый код с другим темпом изменений. Смешение снова сделало бы `Core` «богом».
* Почему `AlphaModels` не знает `Core`: рантайм S05 — отображение; правила о нём не должны знать. Связь —
  через `Presentation` (подписка на события `Features`) и `AlphaModels.Import` (только перевод ID).

## 2. Жизненный цикл: `GameSession` и `GameClock`

```text
Boot ──► MainMenu ──► LoadingWorld ──► InGame ◄──► Paused
            ▲               │              │
            │               ▼              ▼
            └──────────── Unloading ◄── SavingCheckpoint ──► Quit
```
* `GameSession` (Features) — единственный владелец состояния игры: слот, `WorldState`, `EntityRegistry`, герой,
  инвентари, `GameClock`. Создаётся на `LoadingWorld`, уничтожается на `Unloading`. Нет статических синглтонов с
  игровым состоянием (R-STATIC: кэши рендера допустимы, проверяется сброс при «выйти в меню → новый мир»).
* `PilotBootstrap` становится одной реализацией представления состояния `InGame`, а не точкой связности (R-LIFE).
* `GameClock` — фиксированный шаг симуляции (предложение: 30 Гц логики, рендер интерполирует), время в
  целых **миллисекундах игры** (`long`), пауза останавливает часы. Причина: формулы Alpha заданы в мс
  (`combat_getAttackWindup`, таймеры действий, кулдауны 3000/10000), а регрессия S05 доказана на 30/60/120 Гц.
  Контроллер S05 переходит в режим `externalClock`: получает `deltaMs` от `GameClock`, не читает `Time.deltaTime`.
* Детерминизм: случайность — `IRandomSource` с seed из `(worldSeed, система, EntityId)`; `UnityEngine.Random`
  в `Features` запрещён (тест на ссылки, §1).

## 3. Владение состоянием

| Состояние | Владелец | Читают | Меняется только через |
|---|---|---|---|
| Сессия, слот, версия генератора | `Features.GameSession` | все | переходы §2 |
| Мир: seed, версия генерации, дельты регионов | `Features.World` | `Presentation` (чанки) | команды → `ChunkChanged`, `RegionDeltaRecorded` |
| Сущности: `EntityId`, `KindId`, позиция, HP, состояние ИИ | `Features.Entities` | `Presentation`, ИИ | команды/тик → `EntitySpawned/Despawned/Moved` |
| Герой: класс, уровень, HP, ресурс, XP | Core `CharacterSheet` через `Features.Hero` | HUD, анимации | `HealthChanged`, `ResourceChanged`, `LevelUp` |
| Инвентарь, слоты, стаки | Core `EquipmentLoadout` через `Features.Items` | вид оружия/брони | `ItemEquipped/Unequipped`, `InventoryChanged` |
| Действие сущности (фаза, таймеры) | `Features.Actions` | бой, анимация | `ActionStarted/PhaseChanged/ActionResolved` |
| Бой: урон, блок, смерть | Core `Combat*` через `Features.Combat` | VFX, анимация, HUD | `HitResolved`, `EntityDied` |
| Поза/анимация | `AlphaModels` | — | **никогда не меняет игровое состояние** |
| Время | `Features.GameClock` | все | `Presentation` подаёт кадр один раз |
| Отклонения от Alpha | `Features.DeviationRegistry` (данные) | тесты, отчёты | правка данных + тест |

## 4. Контракты (эскизы C#; имена — предложение, не API)

Полные примеры — [M0_00C_CONTRACT_EXAMPLES](M0_00C_CONTRACT_EXAMPLES.md). Ключевое:

* **ID.** `EntityId` (64 бит: регион + индекс спавна + поколение; для героя — слот), `KindId` (тип существа CubeGame;
  для Alpha-видов = `kind`, но как отдельный тип, не `int`), `ItemDefId`, `ActionId` (ID действия CubeGame,
  1:1 с ID действия Alpha там, где доказано; новые — диапазон ≥ 1000).
* **Команды** (вход в `Features`, от ввода/ИИ): `MoveCommand`, `StartActionCommand(entity, actionId, target?)`,
  `EquipCommand`, `UseItemCommand(entity, inventorySlot)`, `InteractCommand`. Команда валидируется владельцем и
  либо порождает события, либо отклоняется с причиной (`ActionRejected(reason)`), никогда не меняет состояние
  молча.
* **События** (выход из `Features`, неизменяемые записи): `ActionStarted(entity, actionId, startMs, phases)`,
  `ActionPhaseChanged`, `ActionResolved(entity, actionId, outcome)`, `HitResolved(attacker, target, damage,
  blocked, killed)`, `ItemEquipped`, `ItemConsumed`, `ProjectileSpawned`, `EffectRequested(effectId, anchor)`,
  `EntityDied`, `EntitySpawned/Despawned`.
* **Фазы действия** — данные, а не анимация: `ActionDef{ id, category, requiredItem, windupMs, strikeMs,
  recoverMs, cooldownMs, resource, animKey, heldItemSlot, projectile?, effect? }`. Длительности — из формул Alpha
  (`base_ms/(haste·speed)`, B C-27) или явное отклонение; удар разрешается **по фазе действия**, не по кадру клипа.
* **Анимация как подписчик.** `Presentation` слушает `ActionStarted` и вызывает контроллер S05
  (`Play(animKey, startMs)`) в режиме `externalClock`. Нет клипа — действие всё равно разрешается (лог
  `ANIM_MISSING`), есть клип без `ActionDef` — не проигрывается. Так `STATIC_OBJECT`/`LOCOMOTION_ONLY` (D69)
  соблюдаются автоматически: у таких видов в реестре нет действий.

## 5. Сквозная цепочка «предмет → экипировка → действие → анимация → попадание»

```text
UseItem/StartAction (ввод или ИИ)
  → Features.Actions: ActionDef по (класс, оружие в руке, ID); проверка ресурса/кулдауна (ability_isUsable, B C-20)
  → ActionStarted(entity, id, startMs, phases)          ── Presentation: клип S05 + предмет в руке (slot)
  → [windup] → strike: Features.Combat.Resolve(attacker, target(s))  ← формулы S03/S04 (не переписывать)
       → HitResolved / ProjectileSpawned (снаряд — сущность мира с собственным тиком)
  → [recover] → ActionResolved(outcome)                ── Presentation: возврат позы (UNITY_TRANSITION)
```
* **Оружие.** Подтип оружия из предмета → `ActionDef` (одноручное/двуручное/лук/посох и т. п.); хват и модель — из
  S05 (`primaryGrip/secondaryGrip`, масштаб ×0.6). Левая/правая рука — §6.2.
* **Расходники/зелья с предметом в руке** (Alpha действие 80, сейчас `BLOCKED_CONTEXT`, B C-33): `ActionDef`
  категории `Consumable` с `heldItemSlot = MainHand`, кулдауном 3000/10000 мс (B C-33) и эффектом через
  `Features.Effects` (лечение — правило CubeGame, если в Alpha не доказано). Анимация — клип 80 после его
  переноса; до того `ANIM_MISSING` и статичная поза, правило работает.
* **Инструменты** (кирка/факел и т. п.): та же модель `ActionDef` + `InteractCommand`; эффекты на мир — через
  `World` (`RegionDeltaRecorded`). Список инструментов Alpha — из финального B (сейчас не выделен).
* **Снаряды/эффекты (R-3).** `ProjectileSpawned` создаёт сущность-снаряд (позиция, скорость, владелец, время
  жизни) в `Features.Entities`; вид — `IEffectView` в `Presentation` (заглушка-примитив с пометкой
  `PLACEHOLDER_NOT_ALPHA` до переноса рендереров `spawnEffectMesh`/`render_build_projectile_mesh`).
  Огонь дракона 51 — `EffectRequested` поверх статичной позы (D69).
* **Динамические части рига (R-8: камень 108, черепаха 72)** — флаг видимости части в `ActionDef`, исполняемый
  `AlphaModels`; до переноса — `BLOCKED` в реестре, действие недоступно ИИ.
* **Восстановление позы.** После `ActionResolved` контроллер возвращается к локомоции переходом
  `UNITY_TRANSITION` (не Alpha; B C-30), длительность — одна константа в реестре отклонений.

## 6. Перевод ID и единиц Alpha → CubeGame (`AlphaModels.Import.AlphaIds`)

### 6.1 Таблица преобразований (единственное место)
| Что | Alpha | CubeGame | Правило/тест |
|---|---|---|---|
| Класс | сырой байт `+0x140` = `classIdx+1` | `CharacterClass` (0-based) | `ClassFromByte(3) == Mage`; таблица на 4 класса + отказ на 0/≥5 (R-ID-1) |
| Специализация | `+0x141` | `Specialization` | тест на 0/1 |
| Слот отрисовки | 10 слотов `drawModel` (D64) | `EquipmentSlot` | §6.2; неизвестный → `UNSUPPORTED` |
| Тип/подтип предмета | сырые байты `+0x00`/`+0x01` (24 типа; r3: 5 Gloves, 6 Boots; подтипы 1 axe…0xf greatsword) | `ItemType`/`WeaponSubtype` — **числа = сырые ID Alpha** (уже так в S04) | §6.4; неподдержанный тип — явный `UNSUPPORTED` (R-ID-3) |
| Вид существа | `kind` `+0x64` (0x00–0x90) | `KindId` | 1:1, но тип отдельный (R-ID-4) |
| Действие | `+0x68` (101 ID, 73 состояния) | `ActionId` | 1:1 для доказанных; статус из реестра S05 |
| Единицы мира | воксели модели, единицы позиции Alpha | 1 блок = 1 ед. Unity | §6.3 |

### 6.2 Левая/правая рука и слоты
* В Core принято 6 слотов (S04); у Alpha 10 слотов отрисовки и 13 слотов экипировки в B (P1-9, Q-8).
  **Архитектура не решает число слотов** (это решение продюсера, Q-8), но фиксирует: расширение `EquipmentSlot` —
  только вместе с миграцией сейва (§8) и таблицей §6.1; S04 не переоткрывается.
* Рука: `MainHand` = правая (Alpha: хват `primaryGrip`), `OffHand` = левая; двуручное оружие занимает обе и
  блокирует `OffHand` правилом Core, а не анимацией. Зеркальная модель правой кисти — правило отрисовки S05
  (`-1.5` по X у `hand_r`), игровые правила о нём не знают.

### 6.3 Масштаб (R-SCALE)
* Меш S05 — в вокселях модели; мир — блоки. Коэффициент блок↔воксель **не подбирать на глаз**: исследование по
  коду Alpha (размещение `placement` в `drawModel` — диагональ `0.086` на воксель в кадре оракула) вместе с OQ-23
  (B P1-3). До доказательства — одна константа `VoxelsPerBlock` в `DeviationRegistry` со статусом
  `PLACEHOLDER_NOT_ALPHA`; ни одна система не хранит свою копию.

### 6.4 `CORE-ENUM-MISMATCH`, `ITEMINSTANCE-TYPE-LIMIT`, `SAVE-EQUIPMENT-GAP` — предлагаемое миграционное решение
**Факт (проверено по коду @ `653b992`).** В S04 числовые значения `ItemType`/`WeaponSubtype` по замыслу равны сырым ID
Alpha (комментарий `ItemEnums.cs`). Сейв v1 (`ItemSaveData`) хранит `type`/`subtype` **числами**, формулы
`ItemStatsCalculator` ветвятся по **числам** (`subtype 3/4/0x0D → ×2; 5 → ×4`). Значит, 10 расхождений DeepSeek
(1 Mace↔Axe … тип 5 Boots↔Gloves) — это **неверные имена членов**, а не неверные данные: старые сейвы и баланс S04
посчитаны по правильным числам. Экипировка в v1 не сохраняется (`SAVE-EQUIPMENT-GAP`), поэтому старых сейвов
«сапоги в слоте ног», которые пришлось бы переносить, не существует.

**Предложение (вариант A′ — уточнение варианта A DeepSeek; решение продюсера в M0-00D, исполнение M0-04A):**
1. **Переименовать** члены по r3 с сохранением чисел (`Axe = 1, Mace = 2, Dagger = 3, Fist = 4, Bow = 6, Crossbow = 7,
   Boomerang = 8, Quiver = 0x0E`; `Gloves = 5, Boots = 6`). Ни одно число в сейве/формуле не меняется. Не «тихий
   рефакторинг»: отдельный коммит M0-04A, решение Dxx, тест-якорь на всю таблицу r3 (числа↔имена); пилот
   `PILOT_ITEMS` переходит с «ровно 10 расхождений» на «0 расхождений».
2. **Совместимость слота и типа** (`EquipmentLoadout.IsSlotCompatible`) — единственное место, где имя несёт смысл:
   слот «перчатки» должен принимать тип 5. После переименования код остаётся `slot Gloves ↔ ItemType.Gloves`, но
   `ItemType.Gloves` теперь = 5. Тесты S04, задающие пары через имена, сохраняют смысл; ожидания `BlockValue` не
   меняются, потому что типы 5 и 6 считаются одной веткой (`case Boots/Gloves`) — это проверить в M0-04A до правки.
3. **Расширение типов** (`ITEMINSTANCE-TYPE-LIMIT`) — только аддитивно: новые члены `Consumable = 1`, `Material = 0x0B`,
   `Quest = 0x15`, `Lamp = 0x18` … с явной ролью «не экипируется в бою» до своего этапа; неизвестный байт при загрузке
   сейва → `UNSUPPORTED` (элемент сохраняется как есть и не теряется), не исключение.
4. **Сейв v2** (§8): секция `equipment` = 13 слотов хранения Alpha (`EquipmentLayout`); миграция `v1→v2` создаёт пустую
   экипировку; тест «экипировка переживает перезапуск» (GS-07/GS-13) — шлюз M0-04D.
5. **Сырые ID Alpha ↔ доменные ID.** Отдельный тип `RawAlphaItemId` не нужен, пока числа совпадают; граница остаётся
   в `AlphaIds` (§6.1). Предметы CubeGame без аналога Alpha получают числа ≥ `0x80`; `AlphaIds` отказывает на них.

**Почему не вариант B (отдельный Alpha-контракт рядом с S04):** две таблицы одних и тех же чисел с разными именами
закрепили бы ошибку в S04 и потребовали бы перевода на каждой границе. A′ не меняет поведения S04, но правка
принятого кода всё равно только по решению продюсера.

**Нерешённое (запрос DeepSeek, #9):** слой предметов @ `1de4bb5` называет подтип `0` «sword», `21–25` — алиасами меча,
а S04 и r3 — `0 = None`, валидация `ItemInstance` отклоняет `0`. Нужно доказательство: встречается ли подтип 0 у
реальных предметов Alpha (спавн/лут/магазин) или это только поведение селектора модели на нуле.

## 7. Данные Alpha и единый источник рантайма S05

* **Один источник рантайма.** M0-01A переносит `tools/alpha_models/transfer/unity/Runtime` в
  `Assets/CubeGame/AlphaModels` (asmdef `CubeGame.AlphaModels`) **копией без изменения логики**; probes/Editor —
  в `Verification`/Editor. После переноса стенды `.scratch` собираются из `Assets` (не из `tools`), иначе две копии
  разойдутся. Удаление копии в `tools` — вопрос продюсеру (M0-00A Q-2).
* **Данные Alpha не в Git** (D54). Один интерфейс `IAlphaDataSource` (`Import`): локальный кэш, генерируемый из
  `D:\Games\Cube world` (только чтение) в каталог вне Git (`%LOCALAPPDATA%\CubeGame\AlphaCache` или `.scratch`);
  в кэше — SHA256 исходников и версия конвертера. Вместо `Application.dataPath` (сейчас только редактор) — путь из
  настроек. Без кэша игра запускается с понятной ошибкой/заглушками (`DATA_MISSING`), а не падает.
* Сборка/релиз: ассеты Alpha в сборку не входят; замена на собственные — отдельный этап (D54).

## 8. Мир, сущности, вне экрана, сейвы

* **Генерация.** Контракт `IWorldGenerator(seed, generatorVersion) → регион`; детерминизм проверяется хэшем
  регионов. Цель генератора (паритет Alpha или собственный по Alpha-иерархии) — решение продюсера (B Q-1);
  архитектура одинакова в обоих случаях. Числа стриминга (B P1-2: 3/5 регионов или 8/10 зон) — решение до M0-02B.
* **Дельты.** Изменённый регион хранит только отличия от сгенерированного (`RegionDelta`: блоки, разрушенные
  объекты, открытые контейнеры) + `generatorVersion`; при смене версии генератора — миграция или отказ загрузки с
  сообщением (без молчаливой порчи).
* **Сущности и ID.** `EntityId = (regionId, spawnIndex, generation)`; спавн детерминирован от seed региона,
  поэтому выгрузка/загрузка не создаёт дубликатов. Класс/спец/оружие NPC — из записи спавна (B P1-6), а не из вида.
* **Вне экрана (B P1-5 — спецификации Alpha нет).** Архитектурная политика: регион вне радиуса активности хранит
  компактные записи сущностей (`alive`, HP, позиция, инвентарь значимых NPC); тик ИИ вне экрана — **нет** (замороженная
  модель) до исследования; инварианты: «нет дубликатов после 100 выгрузок/загрузок», «убитый не воскресает без
  правила респавна». Правило респавна — отклонение/решение.
* **Сейвы (R-SAVE).** Формат `CUBEGAME_SAVE` v2 = секции (`session`, `hero`, `inventory`+`equipment`, `world.deltas`,
  `entities`, `quests`), каждая со своей версией; цепочка миграций `v1→v2→…`; атомарная запись (временный файл +
  замена + резервная копия) и восстановление при обрыве. Тест: «сейв v1 из S04 грузится», «обрыв записи не
  портит последний сейв», «экипировка переживает перезапуск» (B GS-13).

## 9. Неизвестное: `DeviationRegistry`

Одна таблица данных `deviations.json` (в Git, без данных Alpha): `id`, значение, единицы, статус
(`PLACEHOLDER_NOT_ALPHA` / `PRODUCER_DECISION` / `RECONSTRUCTED_FROM_EVIDENCE`), источник, кто использует, тест.
Системы читают значение по `id`; тест падает, если в коде найдено «магическое» число из списка. Стартовый
состав (из B и аудита A): скорость/прыжок (OQ-23, `JumpSpeed=7` сейчас), `VoxelsPerBlock`, базовый шанс
попадания (OQ-01), порядок митигации (OQ-02), правило смерти/возрождения (C-25), длительность перехода позы
(C-30), лимит стака (49?), наценки торговца (F-U5), числа стриминга (P1-2), респавн вне экрана (P1-5).

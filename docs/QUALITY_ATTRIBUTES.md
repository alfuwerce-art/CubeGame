# CubeGame — критерии технического и игрового качества

**Статус:** `REVIEW_CANDIDATE`. Это схема измерений и критериев, **не** новые численные целевые FPS/VRAM и не принятие функций.

| Область | Способ проверки | Где фиксируется |
|---|---|---|
| Работоспособность | компиляция, Editor и Windows Player, реальный игровой сценарий | отчёт задачи |
| Корректность | unit/EditMode/PlayMode и негативные тесты | XML, лог, SHA |
| Сохранения | save → exit → load, стабильный world seed/ID, существенные изменения | тест + воспроизведение |
| Производительность | FPS/frametime, CPU/GPU/RAM/VRAM на согласованном железе и пресете | профайлер/лог, не выдумывать цель |
| Визуал | игровые ракурсы, читаемость и принадлежность к voxel/pixel стилю | скрины/видео + владелец |
| Анимация | клипы walk/idle/attack по задаче, контакт стоп/оружия, отсутствие артефактов | gameplay footage |
| Согласованность | отсутствие дубликатов API, реальные зависимости/ID | code review, LSP/compile |
| Автоматизация | повторяемость, идемпотентность скриптов, rollback, side-effects | smoke + diff |
| Юридическая чистота | авторство и лицензии ресурсов, приватные источники и секреты | asset manifest + diff |

## Граница PASS

Агент заявляет только реальные `PASS / FAIL / BLOCKED / NOT_RUN`. Изолированный тест не доказывает целостную игру; скриншот не доказывает анимацию; PR не равен приёмке. `ACCEPTED` — только владелец.

## Подход к «качеству уровня Claude»

Для одного и того же TASK, одинакового исходного SHA и тестового оракула сравнить `DeepSeek Harness`, при необходимости `Codex/Claude`, фиксируя: выполненные критерии, ошибки, повторные попытки, объём ручных правок, время/лимиты, нарушения scope. Не считать модель слабой или сильной по одному удачному случаю. Harness даёт инструменты и процесс, но не гарантирует равную способность моделей.

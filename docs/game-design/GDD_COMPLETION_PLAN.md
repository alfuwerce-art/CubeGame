# CubeGame — план завершения Game Design Document

**Статус:** DRAFT / редакционный план на 2026-11-06; не новый игровой закон и не разрешение кодинга.  
**Основной GDD:** [GDD_DRAFT.md](GDD_DRAFT.md). **Истина:** Dxx-решения, [ACTIVE_STAGE](../ACTIVE_STAGE.md), [PROJECT_MEMORY](../../PROJECT_MEMORY.md).

## Задача

Сделать **один главный GDD**, по которому разработчик может понять цель игры, отличить принятую механику от предложения, увидеть зависимости и получить ссылку на подробную спецификацию. Не плодить конкурирующие GDD и не выдавать концепт за implementable spec.

## Текущее состояние по GitHub

- **ACCEPTED / принципы:** D59 (жанр/M0→M3), D60 (свободная кампания), D61 (сон/точка возрождения), D62 (право на украденное имущество), D63 (7 рас; Frogman исключены), D64 (индивидуальные убеждения и смешанные фракции), D65 (физический контакт, промахи, перекаты, выбор потери инвентаря), D66 (боевое дерево отменено, магическое дерево, практика, летописи, свитки, руны).
- **Черновики:** конкретные стартовые условия, голод, механика обучаемости, магическое дерево и руны по узлам, формула контактного урона, экономика, фракции, автономные NPC, события, ремесло, UI, баланс.
- **Технически:** M0 Alpha-parity имеет собственную дорожную карту и тесты; новое эволюционное поведение не должно подменять требования M0. S05A-2 REVIEW OPEN, S05B NOT_AUTHORIZED.

## Требование к каждой системе в GDD

Для каждого блока фиксировать: **цель игрока → действия игрока → правила/ограничения → входящие состояния → изменения мира → исключения/ошибки → UI-обратная связь → приёмочные игровые сценарии → точные ссылки на Dxx и детали**.

Не нужно тащить весь код и баланс в основной GDD. Изменяемые числовые параметры хранить в данных/таблицах; правила и объяснения — в GDD; важные подтверждения — в Dxx.

## Обязательная редакционная уборка

1. В главном GDD и AGENTS могут остаться **устаревшие формулировки D65** о боевом дереве и **старые OPEN-пункты**, которые были закрыты D60–D66. Пометить как исторические, а действующим объявить D66. Проверять согласованность перед ТЗ для агента.
2. Не переносить в CubeGame решения из самостоятельного **GAME PROJECT — BASE CONCEPT** (игра с верхней камерой/RTS) без прямого согласия продюсера.
3. Каждую новую механику сначала обсуждать/проверять на совместимость, затем Dxx → правка GDD → отдельное ТЗ активного этапа, без автоматического запуска разработки.
4. **Сохранить исторические исследования Alpha** (например, факт о Frogman), но не включать исключённое в новый игровой контент.

## Минимальный вертикальный срез для обсуждения

Пример (НЕ утверждён): один персонаж, один маленький регион/деревня, один лагерь бандитов, 2–3 вида оружия, одна магическая школа, один контактный бой, один живой товарный маршрут, один NPC с памятью и реакцией, сон/сохранение. Проверить, что механики интересны и связаны, прежде чем строить полную политику и глобальную экономику.

## Критерий завершения GDD

- Каждая существенная система имеет **утверждённый статус**, референс и проверяемое поведение.
- Для связанных систем есть как минимум **один сценарий взаимодействия**.
- Нет действующих противоречий между Dxx, GDD, AGENTS и дорожной картой.
- Принятые игровые правила отделены от тех. гипотез и от будущих идей.
- Продюсер лично подтвердил версию GDD как **дизайн-документ**, что не означает разрешения на реализацию всех механик.

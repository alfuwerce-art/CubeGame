# CubeGame — план завершения Game Design Document

**Статус:** READY_FOR_REVIEW как редакционный план на 2026-11-06; не новый игровой закон и не разрешение кодинга.  
**Основной GDD:** [GDD_DRAFT.md](GDD_DRAFT.md). **Истина:** Dxx-решения, [ACTIVE_STAGE](../ACTIVE_STAGE.md), [PROJECT_MEMORY](../../PROJECT_MEMORY.md).

## Задача

Сделать **один главный GDD**, по которому разработчик может понять цель игры, отличить принятую механику от предложения, увидеть зависимости и получить ссылку на подробную спецификацию. Не плодить конкурирующие GDD и не выдавать концепт за implementable spec.

## Порядок завершения GDD

Чтобы не обсуждать всё вперемешку, закрывать основной GDD лучше в таком порядке:

1. **Первый игровой час + основной цикл** — что игрок реально делает от старта до первой устойчивой петли.
2. **Контактная боёвка + смерть** — правила попадания/промаха/защиты/переката и последствия поражения; числовой баланс отдельно.
3. **Рост героя + магия** — практика, свитки, летописи, одно магическое дерево, руны и границы антиэксплойта.
4. **NPC / социальная RPG / закон** — память, знания NPC, диалоги, вербовка, преступления и реакция мира.
5. **Экономика / фракции / территория** — только после определения локального причинного цикла, без преждевременной «симуляции всего мира».
6. **Квесты / события / данжи** — условия появления, последствия и связь с живым миром.
7. **Сохранения / UI / Art / Audio** — свести уже выбранные правила и ссылки на профильные документы.
8. **Вертикальный срез** — зафиксировать минимальный набор систем, который действительно проверяет философию игры.
9. **Финальная проверка согласованности** — Dxx ↔ GDD ↔ AGENTS ↔ ROADMAP без конфликтов и старых отменённых формулировок.

Это порядок редакционной работы, **не порядок автоматического запуска Unity-этапов**.

## Требование к каждой системе в GDD

Для каждого блока фиксировать: **цель игрока → действия игрока → правила/ограничения → входящие состояния → изменения мира → исключения/ошибки → UI-обратная связь → приёмочные игровые сценарии → точные ссылки на Dxx и детали**.

Не нужно тащить весь код и баланс в основной GDD. Изменяемые числовые параметры хранить в данных/таблицах; правила и объяснения — в GDD; важные подтверждения — в Dxx.

## Обязательная редакционная уборка

1. В главном GDD и AGENTS могут остаться **устаревшие формулировки D65** о боевом дереве и **старые OPEN-пункты**, которые были закрыты D60–D66. Пометить как исторические, а действующим объявить D66. Проверять согласованность перед ТЗ для агента.
2. Не переносить в CubeGame решения из самостоятельного **GAME PROJECT — BASE CONCEPT** (игра с верхней камерой/RTS) без прямого согласия продюсера.
3. Каждую новую механику сначала обсуждать/проверять на совместимость, затем Dxx → правка GDD → отдельное ТЗ активного этапа, без автоматического запуска разработки.
4. **Сохранить исторические исследования Alpha** (например, факт о Frogman), но не включать исключённое в новый игровой контент.

## Время первого игрового среза и режим проверки — D78 ACCEPTED

[Решение D78](../decisions/D78-first-unity-vertical-slice-stage-gated-review.md): первый **интеграционный игровой вертикальный срез** — **после переноса основного игрового опыта Alpha в Unity** и готовности необходимых зависимостей, не на текущем этапе S05A-2. Новые модели и анимации показывать для визуального осмотра в реальной Unity-сцене после интеграции согласованного объёма. Полную игровую и визуальную регрессию проводить по завершении этапа/цельного проверяемого пакета, **не после каждого мелкого нововведения**. При этом сохраняются D67 гейты эталонов семейств и возрастающих партий до масштабирования производства; промежуточные короткие технические тесты тоже обязательны.

**Уточнение D78 (2026-11-06):** после завершения и приёмки этапа моделей/анимаций — **интеграция основной Alpha в Unity**, используя уже имеющиеся компоненты ядра/боя/экипировки S02–S04, и реальное игровое тестирование (мир, управление, камера, экипировка, бой, противники, инвентарь, сохранения). Первый играбельный прогон не равен формальной приёмке полной M0. Исправления и этапная приёмка предшествуют следующим эволюционным расширениям. [D78](../decisions/D78-first-unity-vertical-slice-stage-gated-review.md).

## Минимальный вертикальный срез для обсуждения

Пример (НЕ утверждён): один персонаж, один маленький регион/деревня, один лагерь бандитов, 2–3 вида оружия, одна магическая школа, один контактный бой, один живой товарный маршрут, один NPC с памятью и реакцией, сон/сохранение. Проверить, что механики интересны и связаны, прежде чем строить полную политику и глобальную экономику.

## Критерий завершения GDD

- Каждая существенная система имеет **утверждённый статус**, референс и проверяемое поведение.
- Для связанных систем есть как минимум **один сценарий взаимодействия**.
- Нет действующих противоречий между Dxx, GDD, AGENTS и дорожной картой.
- Принятые игровые правила отделены от тех. гипотез и от будущих идей.
- Продюсер лично подтвердил версию GDD как **дизайн-документ**, что не означает разрешения на реализацию всех механик.

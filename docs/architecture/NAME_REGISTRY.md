# CubeGame — реестр технических имён (source-backed)

**Статус:** `TEMPLATE / NOT_GENERATED`. Создан по идее «словаря имён» из транскрипта. **Не** является перечнем реально проверенных классов/ассетов и не разрешает создавать новые API.

## Назначение

ИИ должен использовать точные имена из **файлов проекта**, включая регистр символов, namespace, asset GUID/path, asmdef и имена контрактов. Реестр — только индекс со ссылками, а **код, Unity meta и сериализованные ассеты остаются источником истины**. Если имя не найдено, искать определения и usages, отмечать `UNKNOWN`, а не угадывать.

## Структура строки

| Поле | Пример значения (не факт проекта) |
|---|---|
| `kind` | class / method / interface / ScriptableObject / prefab / asset / scene / event |
| `exact_name` | только буквально извлечённое имя |
| `namespace_or_path` | файл или полное пространство имён |
| `owner_module` | Core / Persistence / Presentation / actual module |
| `dependencies` | ссылки на фактически найденные определения |
| `source_sha` | коммит при котором проверено |
| `confidence` | `VERIFIED`, `STALE`, `UNKNOWN` |
| `checked_at` | дата аудита |

## Правила

1. Перед правкой выполнить поиск definitions и usages в реальной ветке; LSP предпочтительнее regex.
2. Не полагаться на примерные имена из видео (`Enemy`, `ThirdPersonCharacter`) как на имена CubeGame.
3. При изменении API обновить индекс в PR и запустить сборку/тесты. Слова из устаревших Alpha-отчётов нельзя смешивать с действующими C# именами.
4. Для C# учитывать регистр идентификаторов; для ассетов сверять GUID и связи в `.meta`, а не только отображаемое имя.
5. Реестр нельзя заполнять по памяти ИИ. Источник каждого имени — путь/строка или экспорт инструмента. Не заменять им dependency audit и компилятор.

## Текущий статус

Конкретные записи: **ещё не извлечены** из актуальной ветки Unity. Первый аудит поручается отдельно после ревью D95. До этого агент читает код напрямую. Связанный документ: [DEPENDENCY_MAP](DEPENDENCY_MAP.md).

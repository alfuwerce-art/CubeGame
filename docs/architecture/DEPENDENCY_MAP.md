# CubeGame — карта зависимостей задач и модулей

**Статус:** схема планирования; не утверждает физические имена C# классов или наличие всех модулей. Источники: [ADR-0001](ADR-0001-modular-monolith.md), [Roadmap](../ROADMAP.md), [GDD](../GDD.md). Нормативная архитектурная база — ADR-0001; дополнительные предложения должны пройти отдельное утверждение.

## Принцип

Порядок разработки определяют **контракты и интеграционные зависимости**, а не слепая линейность: например, стрельбу можно прототипировать с тестовым фиксированным оружием до готового UI инвентаря; перед релизом она обязана интегрироваться с реально существующими предметами, экипировкой и сохранением.

| Система | Что должно быть определено до интеграции | Что проверяем после |
|---|---|---|
| Мир/чанки | seed, stable ID, граница state/view | повторяемость, streaming, save delta |
| Персонаж | controller/input, состояние, визуальный adapter | движение, камера, коллизии, сохранения |
| Бой | события/команды, оружие, target, health/damage | попадание, смерть, анимация, регрессия |
| Предметы | schema ID, инвентарь и предметный state | equip/loot/trade/save |
| NPC/фракции | уникальные ID, авторитетное состояние, расписания | симуляция вдали, реакция, персистентность |
| Анимация | модель, скелет, единицы/pivot, runtime adapter | clip playback, контакты, root motion |
| Художественный контент | утверждённый референс и приёмочные признаки | 3 ракурса + игровой кадр + права |
| UI/HUD | подготовленные данные состояния и команды | управление, реальный игровой сценарий |

## Перед каждой задачей

- Записать `requires / supplies / modifies / does_not_touch`.
- Проверить уже имеющиеся API и контракты; не создавать новую параллельную систему ради изоляции.
- Указать влияние на `Data / Game Logic / View / Input / UI / Save-Load / Utils` как **аналитические слои**, не как жёсткие папки.
- Для опасных изменений: тест миграций сохранений и сценарий обратимости.
- В отчёте отделять рабочий локальный прототип от готового взаимосвязанного игрового цикла.

# Универсальный конвейер переноса моделей и анимаций Alpha → Unity

**Статус: DRAFT** (предложение архитектора, не утверждено продюсером). **Дата:** 2026-11-05. **Автор:** Claude Code.
**Исследование-основание:** [UNIVERSAL_ANIMATION_SYSTEM_RESEARCH.md](../research/alpha2013/UNIVERSAL_ANIMATION_SYSTEM_RESEARCH.md). **Результаты прототипа:** [UNIVERSAL_TRANSFER_PROTOTYPE_REPORT.md](../research/alpha2013/UNIVERSAL_TRANSFER_PROTOTYPE_REPORT.md). **Методичка:** [UNIVERSAL_TRANSFER_PLAYBOOK.md](../agents/UNIVERSAL_TRANSFER_PLAYBOOK.md).
**Границы:** локальный исследовательский прототип (D54). Не S05B, не production-Unity; все данные Alpha — только `.scratch`. Перед релизом — собственные/лицензированные ассеты.

## 1. Принцип

В Alpha один «риг» на все существа — функция `Creature_drawModel`, параметризованная **внешностью** вида. Поэтому конвейер строится не «по моделям» и не «по существам», а по **семействам движения**:

* **план тела** — набор непустых слотов внешности → набор блоков отрисовки (частей);
* **семейство движения** — план тела + все параметры движения внешности (масштабы, углы, смещения, флаги, размер) + признак видо-зависимого кода. Равная подпись ⇒ `drawModel` вычисляет равные кадры суставов при равном рантайм-состоянии ⇒ **один набор клипов на семейство**;
* **модель** — любая из вариантов слотов вида; к клипу подключается через якорь блока (кадр сустава не зависит от размера модели в блоках тела).

Идентификатор рига в клипах: `alpha_creature/<sha1(подпись)[:10]>`. Существующий `alpha_humanoid_v1` (S05A-2) остаётся рабочим путём гуманоида и для атак; универсальный путь воспроизводит его ходьбу/покой бит-в-бит.

## 3. Схемы данных

**Статическая таблица** (`cubegame.alpha_static/1`, `.scratch`): `exe_sha256`; `kinds{0xNN: {appearance{flags,size,slots{},scale_*,angle_*,pitch_tail,offset_*}, slot_variants{}, uses_rand, motion_param_variants, name_hint}}`; `registry{idx: name}`; `registry_stats`; `model_sizes{name: [x,y,z]}`; `unresolved_slot_indices`.

**Разрешение рига** (`RigResolution.to_json`): `kind`, `parts[]` (порядок отрисовки), `models{part: idx|"equipment:x"}`, `family_id`, `supported`, `exceptions[]`.

**Клип** (`cubegame.alpha_clip/2`): как `/1`, но `rig = family_id`, `rig_kind_source`, у частей `slot`, в `source` — `kind`, `creature`, `walk_boost_x1_25`, `phase_rate_rad_per_s` (только по устойчивым кадрам). Unity-формат не изменился (тот же `unity_clip`).

**Задание** (`universal/jobs/*.json`, в Git): `kind`, `seed_variant [s2,s3]`, `variant`, опционально `equipment.weapon{model, subtype}`, `clips` (иначе — каталог семейства).

**`rig.json`** (Unity): `rig` = family id, `parts[]{name, model, file, size, anchor ∈ center|tail|weapon, mirrored, expectedVertices}`, `kind`, `placementScale` (= size.x/11.2, справочно).

**Очередь** (`cubegame.universal_queue/1`): `metrics{}`, `families{id: {kinds[], status, parts[]}}`, `queue[]{kind, name_hint, status, family_id, parts, model_variants, reason[]}`.

## 4. Подходы A и B

> **Обновление 2026-11-05:** подход B реализован для ходьбы (состояние 0) — [PARAMETRIC_WALK_SYSTEM.md](../research/alpha2013/PARAMETRIC_WALK_SYSTEM.md), спецификация [PARAMETRIC_LOCOMOTION_SPEC.md](PARAMETRIC_LOCOMOTION_SPEC.md). Формула совпала с захватами трёх планов тела до точности float; 66 из 80 семейств «нужен захват» ходьбы больше не требуют (после одного проверочного захвата NPC-людей). Атаки и действия остаются на подходе A.

| Критерий | A — универсальный захват | B — восстановление вычисления | Гибрид (предлагается) |
|---|---|---|---|
| Достоверность | максимальная: матрицы, которые Alpha отправила в GPU | зависит от полноты переписанной формулы; нужен эталон | A — эталон и клипы; B — только с проверкой против A |
| Сложность разработки | низкая (сделано) | высокая: `drawModel` ≈ 5700 строк, 73 состояния, сглаживание, флаги | низкая сейчас, B — по одному семейству |
| Автоматизация | захват пакетом по видам за сессию; нужен вид рядом с игроком | полная после реализации | 1 захват на семейство, далее автоматически |
| Производительность Unity | клип 200–900 ключей × части; дёшево | дешевле (формула), без памяти клипа | клипы |
| Качество движения | точные кадры Alpha, но только снятые состояния и амплитуда | непрерывно по амплитуде/скорости, переходы | клипы + (позже) параметрическая ходьба |
| Запуск Alpha | на каждое **семейство** (не на модель и не на вид) | нет (кроме проверки) | на семейство |
| Масштабирование | 80 семейств нуждаются в захвате; виды одного семейства — бесплатно | одна формула на «план тела + флаги» | см. §6 |

Почему не только B: успешный захват матриц **не доказывает** восстановление алгоритма. Наблюдение «средний `J` = смещения внешности, масштаб `J` = масштабы внешности» показывает, что параметрическая модель реальна, но без захвата её нечем проверить. Предлагаемый порядок для B: сначала одна функция ходьбы для плана «тело+голова+2 кисти+2 стопы» (42 вида), затем проверка против уже снятых семейств; статус клипов из формулы — `RECONSTRUCTED_FROM_EVIDENCE`, не `TRANSFERRED_FROM_ALPHA`.

## 5. Границы автоматизации

**Полностью автоматически:** вид → внешность → части/слоты/модели/якоря/семейство; модели → Unity-меши с проверкой вершин; клипы семейства → любой вид семейства; валидация; очередь.

**Требует человека (один раз на семейство):** найти в мире Alpha существо нужного вида рядом с игроком (или отвести игрока к нему), запустить `pose_capture --kinds`; для атак/особых действий — вызвать их вводом (только игрок) или дождаться у ИИ.

**Требует исследования (очередь исключений):** непроверенные блоки (крылья `slot_9a` — 13 видов, `slot_98` — 10 видов, экипировка и спецмодели), видо-зависимый код (Mole 0x57, Zombie 0x60, Dragon 0x65), конфликт/пробел реестра (OrcMale — индекс 1300; DarkTroll — индекс 29), особая модель оружия `0x348`.

Порядок наращивания: (1) захватить по одному виду для самых частых непокрытых семейств (план «тело+голова+2 кисти+2 стопы» — 40 видов; четвероногие с хвостом — 10); (2) один захват крылатого вида (Chicken/Crow) закрывает правило блоков `slot_9a` для 13 видов; один захват тролля/голема — `slot_98` для 10; (3) статичные объекты «только тело» (37) — проверить, есть ли у них движение вообще (у кустов/залежей вероятно нет — тогда клип покоя); (4) только после этого — B для самого частого плана тела.

## 7. Расширение новыми семействами без переписывания ядра

* новый **блок** отрисовки: строка в `creature_rig.BLOCKS` (адрес, слот, правило якоря, доказательство, статус) + правило якоря в `creature_rig.anchor` и `AlphaRig.Anchor` + самотест; статус `VERIFIED` — только после захвата;
* новое **семейство** с проверенными блоками: никакого кода — `pose_capture --kinds`, `pipeline build-clips`, задание `jobs/*.json`;
* новое **действие** (атака, прыжок): построитель клипа по времени в `uclip` (по образцу `alpha_clip.build_time_clip`) + проверка повторяемости;
* видо-зависимая ветка: отдельный модуль-адаптер, в подписи семейства уже учитывается (`kind_branch`), поэтому такие виды никогда не делят клипы с другими.

## 8. Риски

* Все адреса взяты из одной сборки `Cube.exe` (SHA256 `84a7a132…30bf`, копия `.scratch\alphatest2` идентична `D:\Games\Cube world`). Сборка закреплена в `alpha_static.EXPECTED_EXE_SHA256`; `scan` и `prepare-unity` на другой сборке завершаются `UnknownBuild` (есть тест).
* Подпись семейства консервативна (любое различие параметров, включая `size`, разделяет семейства) — это может завышать число захватов, но не даёт ложного переноса.
* Клипы ходьбы сняты при одной амплитуде; ИИ меняет скорость — промежуточные амплитуды в Unity не воспроизводятся (нужен B или несколько клипов).

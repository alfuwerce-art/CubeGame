# ADR-0002 — Unreal C++-first architecture (candidate)
**Статус:** `PROPOSED` для новой UE-реализации; принцип модульного монолита ADR-0001 остаётся принят. До U4 не означает решение заменить Unity для релиза.

## Правило разделения
- **C++ runtime — по умолчанию.** Правила мира, бой, предметы, AI, RPG, детерминированная генерация, постоянное состояние, SaveGame. Текстовые исходники и минимальные контракты удобнее независимо ревьюить и проверять через Git.
- **Blueprint — оправданный тонкий слой.** Настройка игровых классов/ассетов, AnimBlueprint, редакторские связи, небольшие визуальные события. Не дублировать доменную логику в графах; для сложных постоянных вычислений использовать C++.
- **Python Editor + Unreal MCP.** Повторяемое создание сцены, материалов, ассетов, инспекция, пакетная проверка; Python не исполняется в PIE/Standalone/cooked игровом runtime.
- **Данные и визуал.** UObject/UDataAsset, DataTable, конфигурационные ассеты и сохранения — только с реальными требованиями. Не предполагать, что бинарные .uasset дают читаемые Git-diff; хранить редакторские скрипты-рецепты, отчёты и осмысленные имена.
- **Существующие средства Unreal.** Gameplay Framework (GameMode/GameInstance/PlayerController/Character/Components), SaveGame, Enhanced Input; PCG/World Partition проверять на G3, не навязывать до появления малой игры. GAS, Mass, StateTree, Replication — исследовать только при подтверждённой задаче.

## Минимальная структура пилота
```text
Unreal/CubeGameTrial/
  CubeGameTrial.uproject
  Config/
  Content/                 # реальные UE ассеты
  Source/CubeGameTrial/
    CubeGameTrial.Build.cs
    Public/                # когда необходим внешний контракт
    Private/               # Character, Combat, Pickups, Save
  Scripts/Editor/          # идемпотентный Python
  Tests/                   # сценарии и диагностика
```
В одном модуле на пилоте без заранее созданных десятков папок/абстракций. После U4 вынос модулей только при реальных зависимостях.

## Контроль состояния
- Логика состояния живёт в C++ и сериализуемых типах, не в Widget или Level Blueprint.
- Стабильные ID для процедурных объектов и NPC; seed и delta изменений не должны зависеть от порядка загрузки акторов.
- SaveGame хранит необходимые игровые данные и версию схемы, а не слепой снимок объекта/сцены.
- Генерация ландшафта и PCG не могут автоматически считаться детерминированным постоянным миром.
- Build UHT/UBT, PIE, Standalone, packaged Win64 и ручной игровой сценарий — разные проверки; нельзя объявить функциональность готовой после одной компиляции.
- При работе ИИ: одно задание → diff C++/скриптов/ассетов → автоматические проверки → запуск → доказательства → решение владельца.

## Шлюз после пилота
`SELECT_UNREAL / CONTINUE_STUDY / KEEP_UNITY` принимает владелец по фактическому уровню автономности ИИ, стабильности, качеству игры, поддерживаемости C++ и FPS/RAM/VRAM. До этого утверждённый дизайн CubeGame и сохранённый Unity-код не изменяются.

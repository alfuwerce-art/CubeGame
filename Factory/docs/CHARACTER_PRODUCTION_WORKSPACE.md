# Производственное пространство Factoria

Factoria владеет производственными исходниками, настройками DCC и техническими измерениями. CubeGame владеет игровым дизайном, составом рас, интеграционным контрактом и игровым экспортом после отдельного решения о приёме. При передаче приводите источник, владельца, SHA-256, версию DCC, идентификатор, импорт и фактические проверки. [Контракт CubeGame](https://github.com/alfuwerce-art/CubeGame/blob/codex/character-production-contracts/docs/architecture/CHARACTER_ASSET_HANDOFF.md).

| Каталог | Назначение |
|---|---|
| `scripts/`, `workflows/` | Воспроизводимые инструменты и графы. |
| `docs/`, `measurements/` | Спецификации, отчёты и разрешённые технические метаданные. |
| `local/sources/<ASSET_ID>/` | Редактируемый исходник кандидата и описание рига. |
| `local/references/<ASSET_ID>/` | Частные референсы владельца и листы сравнения. |
| `local/exports/<ASSET_ID>/` | FBX/GLB, настройки импорта и поставки для проверки. |
| `local/reports/<ASSET_ID>/` | Измерения, хэши, логи и визуальный лист. |

Идентификатор `FAMILY_VARIANT_BASE_Vn` отделяет итерации. При изменении рига в будущей разрешённой задаче повторно проверяются привязки, сокеты, веса и клипы. В существующем наборе [HUMAN_MALE_BASE_V1](HUMAN_MALE_BASE_V1_REVIEW.md) все материалы сохранены как исторический эксперимент `REVIEW_CLOSED / NOT_SELECTED`. Последующие модели используют требования нового поручения.

[Производственная память](PRODUCTION_MEMORY.md) задаёт текущую работу. Старые эксперименты M0/M1, COMFY-STYLE и каталог Alpha используются для исследования. [Индекс производственных карточек](../races/README.md) объясняет их ограничения.

Из корня Factoria запустите `python scripts/verify_character_docs.py` для местных документов. Для согласованной проверки двух рабочих деревьев используйте `python scripts/verify_character_docs.py --cubegame <путь-к-CubeGame>`. GitHub Actions запускает собственную часть проверки на обоих PR.

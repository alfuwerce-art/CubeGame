# Rig and animation — UE 5.9
Read AGENTS.md, active stage, character workflow, authorized mesh/rig revision and the relevant sections of [UE animation playbook](../../../docs/agents/UE_ANIMATION_PLAYBOOK.md) (path relative to skill directory). Use cubegame-art-validation for visual review. Unity import only for explicit Unity integration tasks.

1. **Preflight.** Confirm Git root, HEAD, dirty assets, open .uproject, editor version, MCP/editor capabilities and source/target skeletons. Protect accepted geometry, rest pose, proportions, intentional gaps, equipment sockets and unrelated clips. Never overwrite source assets or silently change shared skeleton. Snapshot before editing; use existing authorized target asset and reversible changes.
2. **Find motion.** Search authorized local library `D:\Projects\скачанные анимации` read-only, Game Animation Sample, Lyra, Content Examples, Third Person Template and Quaternius viewer; identify exact clip, path/version, license, action, phase, direction, fps, root-motion mode. Compare candidates in motion; select closest style/phase; distinguish reference-only from licensed import. No indiscriminate migration. If sources unavailable, report and use verified alternatives or create original movement as appropriate.
3. **Adapt or create.** Establish target rest pose, scale, axes, root/pelvis, mapping, joint offsets and limb contact policy. Use IK Rig/IK Retargeter and retarget pose when suitable; use Control Rig/FK Control Rig, Sequencer/Curve Editor and Animation Sequence tools to correct keys or author motion. Validate source vs retarget vs final; preserve deliberate floating limbs, rigid voxel parts and style, not anatomical realism. No new rig/system if local correction suffices.
4. **Transitions.** Inspect existing AnimBP and gameplay movement before editing. Test Idle -> Start -> Run -> Stop -> Idle and interruption/restart, if relevant. Use explicit start/stop clips or authored poses where appropriate; synchronize contact phases, speed, direction and braking. Consider Sync Markers, Inertialization, Distance Matching and Stride Warping only after confirming compatible rig, motion model and plugin. See playbook. Do not use long blends to hide bad motion; no architecture migration without owner authorization.
5. **Diagnosis and correction.** Reproduce precisely, locate frame/time/state/bone and isolate source, retarget, rig, clip curves, runtime blend, IK or movement cause. Change smallest relevant layer; compare before/after identical view and timing, re-run nearby transitions. After two failed attempts on same defect, investigate and change method or mark BLOCKED, never keep random key edits.
6. **Evidence gate.** Inspect full clips and actual PIE transitions where relevant, at normal and slow speed from front/side/back and gameplay camera. Record both visual and quantitative findings using playbook. Check foot contacts, gaps, collisions, stretch, spikes, loop seam, root/capsule consistency, weapon grip as applicable. Capture video/contact sheets and logs/trace with exact timestamps. Screenshot, compile, key count or script success alone cannot establish animation PASS. Rewind Debugger/Animation Insights for runtime issues where available. Missing visual ability/evidence => NOT_RUN/BLOCKED, not PASS. Technical and artistic verdicts separate; owner alone ACCEPTED.
7. **Handoff.** Report source and target paths/revisions, actual tools called, changed frames/bones/states, baseline/final measurements, scenario test results, before/after evidence, dirty packages, SHA/branch, outstanding defects. Max READY_FOR_OWNER_REVIEW only if mandatory checks pass. Keep source catalog compact; never commit downloaded packs or raw large recordings unless authorized.

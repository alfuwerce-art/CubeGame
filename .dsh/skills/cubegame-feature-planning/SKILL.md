# Task planning
Read required context and only relevant GDD/decisions; distinguish owner decision from suggestion. From plain request infer result, non-goals, scope, protected files/regions, required tests/evidence, actual engine/workspace and dependencies. Use HARNESS_TASK_TEMPLATE and task-gate. Resolve routine implementation choices yourself; ask only about material ambiguity/irreversible risk that blocks execution. Avoid extra features or internal micro-approvals. Report task and final result, not speculative implementation. No stage acceptance or architecture changes by executor.

# cubegame-feature-planning
1. Read current stage, relevant GDD and owner decision.
2. Inspect actual project code and dependencies. Do not invent class names.
3. Produce TASK contract with allowed paths, required inputs, outputs, risks and test oracles.
4. Identify unknown gameplay choices explicitly. Do not pick mechanics or architecture without approval.
5. Return plan and requested decisions; do not implement without task authorization.

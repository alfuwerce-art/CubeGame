# CubeGame — рабочие правила ИИ

## Начало задачи
Владелец описывает желаемый результат обычными словами. Codex/DeepSeek самостоятельно превращает запрос в короткий TASK по [контракту](docs/agents/HARNESS_TASK_TEMPLATE.md). Не требовать от владельца технического ТЗ, не повторять решённые вопросы. Перед изменениями прочитать этот файл, PROJECT_MEMORY.md, docs/ACTIVE_STAGE.md; далее только нужные разделы GDD, решений, ADR и профильные skills по [маршрутизации](docs/agents/SKILLS_INDEX.md). Для визуальной задачи обязательны [Art Direction](docs/art/ART_DIRECTION.md), [стандарт персонажей](docs/art/CHARACTER_STYLE_STANDARD.md) (если персонаж), [референсы](docs/art/REFERENCE_PROTOCOL.md) и [приёмка](docs/art/ASSET_ACCEPTANCE.md).

## Проект и полномочия
Самостоятельная Windows-first 3D voxel/pixel action RPG; текущая практическая разработка на Unreal Engine 5.9 (C++); единственный репозиторий alfuwerce-art/CubeGame, корень D:\Projects\CubeGame. Unity-кандидаты сохранять; не считать миграцию завершённой. Archive — история, не активное ТЗ.
Владелец утверждает продукт, арт, стадии и merge; ChatGPT — архитектура/ревью; Codex и DeepSeek — исполнители. Не выдумывать продуктовые решения, не менять GDD/AGENTS/архитектуру/права без поручения. Не трогать другие проекты, секреты, платные сервисы, ОС, приватные референсы без разрешения.

Для персонажей соблюдать [согласованный порядок разработки](docs/art/CHARACTER_WORKFLOW.md). Локальные правки не должны затрагивать сохранённые элементы; итоговый эталон и размеры не утверждать по промежуточному манекену.

Для всех запросов об анимациях, включая «открой Play Mode», основной и постоянный skill — `cubegame-rig-animation` ([маршрутизация](docs/agents/SKILLS_INDEX.md)). Не уходить в другие навыки для поиска, MCP, UE, отчётов, памяти или архива; `cubegame-art-validation` — только обязательная подчинённая проверка. Встроенные инструменты использовать напрямую в рамках текущего навыка. Новый/заменяемый набор движений: поиск готовых клипов до адаптации, собственное создание только по разрешению. При смене художественного направления остановиться после сравнения базовых циклов для решения владельца, не делать переходы заранее. Для анимаций обязателен [протокол качества](docs/agents/animation/QUALITY_PROTOCOL.md): реестр всех замечаний, checkpoint, режим операции, сравнение защищённых дорожек и пять независимых verdict. Контракт и результат проверяет task-gate; визуальное наблюдение не заменять числовым PASS. Продолжать существующий workstream, а не начинать заново.

## Исполнение
1. Проверить фактический Git root, origin, HEAD, рабочую ветку, локальные изменения, редактор и путь открытого проекта. Не стирать/переключать чужую работу. Запустить preflight и task-gate (см. [Harness](docs/agents/HARNESS_ARCHITECTURE.md)); отсутствие проверенной возможности указать явно.
2. Самостоятельно определить цель, разрешённую область, защищённые элементы, критерии и evidence. При локальной правке изменять только указанную форму/систему; неизменность остального проверять. Не создавать новый ассет вместо редактирования исходного, если этого не просили.
3. Выбрать основной skill по задаче (не все подряд); для анимаций действует фиксированная маршрутизация выше. Установленные инструменты использовать по назначению; сторонние — только после проверки и разрешения. Не выдавать чтение инструкций за использование инструмента.
4. Работать целостно: внутренние проверки без остановок для каждого мелкого шага; уточнение только при реально блокирующем противоречии/необратимом риске. После двух неудачных попыток одного дефекта — диагностика и смена метода либо честный BLOCKED. Не расширять задачу побочными функциями.
5. Проверить реальные результаты и регрессии. Для арта — одинаковые ракурсы с целевым референсом и исходником, отдельно технический и визуальный verdict; для анимации — движение, не только скриншот. Для изменения игры — Windows Player по задаче; для отдельного UE-ассета — разрешённый UE-сценарий, без навязанного импорта Unity. Не маскировать дефекты техническим PASS.
6. Передать TASK, SHA/ветку, diff, реальные журналы/скриншоты/видео, PASS/FAIL/SKIP/BLOCKED/NOT_RUN и блокеры. Максимум READY_FOR_OWNER_REVIEW; ACCEPTED — только владелец. Не force-push, не удалять историю, не merge без явного разрешения. После решения владельца фиксировать точное решение и версию в памяти/паспорте, не объявлять принятым остальное.

Для UE-задач проверить фактический .uproject и версию редактора, использовать встроенные средства UE; для отдельных Unity-задач — ProjectSettings/ProjectVersion.txt. Одна сессия Editor на проект; [ADR-0001](docs/architecture/ADR-0001-modular-monolith.md). [Codex](docs/agents/CODEX_SETUP.md), [DSH](docs/agents/DEEPSEEK_HARNESS_SETUP.md). Скрипты/хуки не заменяют права ОС, реальные проверки и приёмку.

# Обязательное правило изменения проекта — сначала показать «было → станет»

**Утверждено продюсером 2026-11-09. Применяется ко всем агентам, включая ChatGPT, Claude и DeepSeek.**

Перед **каждым предлагаемым изменением** кода, документации, этапов, решений, Git-веток, задач GitHub или конфигурации агент обязан **до записи** сообщить продюсеру:

1. **Где именно** изменение планируется: файл, раздел, ветка, issue и другие затронутые объекты.
2. **Что есть сейчас → на что конкретно предлагается заменить/добавить/удалить**, с точной формулировкой или смыслом правки. Для нового файла — явно указать «файла не было → будет создан» и его содержание/назначение.
3. **Зачем** изменение нужно и как оно влияет на существующие решения, работу агентов, конвейер и следующие этапы.
4. **Что останется без изменений.**

**Сначала показать изменения, затем получить согласие продюсера, только потом вносить и коммитить.** Если пользователь уже однозначно поручил именно эту конкретную правку, повторного вопроса не требуется, но показать «было → станет» **до выполнения** всё равно обязательно. Любые дополнительные изменения, обнаруженные по ходу работы и не входящие в согласованный объём, сначала обсуждаются отдельно; нельзя молча менять утверждённый подход или этапность.

После выполнения указывать фактически изменённые файлы, коммит/SHA и отличия от согласованного плана. Если выполнить согласованное изменение не удалось, сообщить об этом без заявления об успешном коммите.

# CubeGame — правила для AI-агентов

**CubeGame — рабочее название проекта, а не утверждённое название игры.**

## Сначала прочитать
0. **[PROJECT_MEMORY.md](PROJECT_MEMORY.md)** — единая межчатовая память; первым делом прочитать целиком и проверить актуальность статуса в `docs/ACTIVE_STAGE.md`.
1. `docs/ACTIVE_STAGE.md` — только здесь указано, что разрешено делать сейчас.
2. `docs/planning/DECISIONS_001-036.md` + новые решения `docs/decisions/`, особенно **D41** (актуальнее D40).
3. `docs/architecture/ADR-0001-modular-monolith.md` — утверждён принцип, не вся архитектура.
4. ТЗ активного этапа в `docs/stages/`.
5. `docs/planning/ARCHITECTURE_PROPOSAL.md`, `ROADMAP_DRAFT.md`, `WORKFLOW_PROTOCOL_DRAFT.md` — **черновики**, не самостоятельные разрешения на новые решения.

## Роли
- Продюсер: утверждает геймплей, визуал, содержание и начало этапа.
- ChatGPT: архитектура, техническое ревью, приёмка контрактов.
- DeepSeek Harness: основной исполнитель на локальном ПК, анализ исходных игр, Unity/C#, тесты, отчёты и GitHub.
- Codex: возможный дополнительный исполнитель/контролёр на этапе моделей и графики; пока роль не активирована.

## Направление S05 — конвертация моделей и анимаций (D46)

[D46](docs/decisions/D46-asset-conversion-first.md) — утверждён **conversion-first**: перед моделированием с нуля изучить извлечение оригинальных `.cub`, существующие конвертеры и **отдельно** перенос ригов/анимаций. Пилот геометрии: персонаж, существо/враг, оружие/предмет; фактический импорт в изолированный Unity 6.3 и отчёт. Успешный перенос геометрии **не** доказывает перенос анимаций. Только после пилотов — одна переработанная модель и новая анимация по D32, затем, возможно, масштабирование. [План S05](docs/stages/S05_ASSET_CONVERSION_PLAN.md). Статусы: **`S05A-0 → ACCEPTED`** (D48); **`S05A-1 → ACCEPTED`** ([D50](docs/decisions/D50-s05a1-accepted-s05a2-planning.md), 2026-11-04); **`S05A-2 → AUTHORIZED`** ([D51](docs/decisions/D51-s05a2-authorized-evidence-first.md)); **`S05B → NOT_AUTHORIZED`**. Не публиковать исходные/конвертированные ресурсы Alpha, не запускать массовые конверсии, не запускать `Cube.exe` без разрешения.

**S05A-1-REVIEW-FIX-03 → принят; `S05A-1 ACCEPTED` по D50** (2026-11-04, авторизация [D49](docs/decisions/D49-s05a1-authorized.md); исправлены замечания трёх ревью: два прохода при расчёте координат, размещение по исходной сетке с проверкой кожных вокселей, независимая проверка `Transform.parent`, отказ от PlayMode на сломанной сборке, устранённая авария `0xC0000005`, а также корректный жизненный цикл PlayMode с журналом событий и полный контракт привязки аниматора по восьми узлам): собран один технический персонаж-человек из `.cub`-частей, маркеры/тинты/пивоты исследованы, один собственный цикл проверен в EditMode и PlayMode. Отчёт — [CHARACTER_ASSEMBLY_ANIMATION_PILOT](docs/research/alpha2013/CHARACTER_ASSEMBLY_ANIMATION_PILOT.md), код — [tools/alpha_models/character](tools/alpha_models/character/README.md). **По D51 разрешён только следующий ограниченный S05A-2** для одного персонажа: восстановление исходных параметров до подбора прокси, контролируемые Alpha-запуски из отдельной локальной копии и собственный Unity-пилот; S05B/массовая конвертация запрещены. Открытые вопросы: механизм тинта волос, семантика зелёного/синего маркеров, реальные offsets сборки, перенос исходного анимационного цикла.

**Решение D50 (история):** [приёмка S05A-1](docs/decisions/D50-s05a1-accepted-s05a2-planning.md) техническая. **Актуальное решение D51:** [авторизация S05A-2](docs/decisions/D51-s05a2-authorized-evidence-first.md) разрешает исследование одного персонажа и ограниченный Unity-пилот, а также контролируемый запуск Alpha из копии `.scratch`. Приоритет — восстановить исходные scale/offset/pivots/tint; не оставлять неизвестные значения без поиска, прокси возможны лишь с отчётом. C+ head+hair совместно, T3 как запасной tint, личная приёмка по кадрам до/после. Без запуска S05B.

**S05A-2 GRIP (D52, 2026-11-05):** хват выведен из геометрии меча (`primaryGrip`/`secondaryGrip` на рукояти), реализована двуручная атака `two_handed_attack_NOT_ALPHA` с решением левой кисти на `secondaryGrip` (отклонение 0.000, цикл замыкается, клинок не пересекает тело), закрыты FIX-A и FIX-B. Оригинальная атака **не восстановлена** (запуски Alpha не дали кадров) — статус `ORIGINAL_NOT_ALPHA`. Дальнейшие анимации того же гуманоида — отдельными партиями со статусами `TRANSFERRED_FROM_ALPHA`/`RECONSTRUCTED_FROM_EVIDENCE`/`ORIGINAL_NOT_ALPHA`/`BLOCKED`.

**S05A-2 — `READY_FOR_REVIEW` (исполнение по D51 выполнено):** [отчёт](docs/research/alpha2013/CHARACTER_PROPORTIONS_PILOT.md): оружие ×0.6 по найденной в коде константе, голова и волосы сохранены авторскими (движок их не перемасштабирует), tint по маске с проверкой по координатам вокселей, конфигурация с восстановимым baseline. Художественная приёмка — за продюсером.

**S05A-2 — план (история, D51):** [план пилота](docs/stages/S05A2_PROPORTIONS_TINT_PLAN.md) (методы исследования пропорций, Pivot и креплений, конфигурация масштабов, варианты tint волос T1–T4, порядок будущей реализации, измеримые критерии приёмки) и [матрица визуальных пробелов](docs/research/alpha2013/CHARACTER_VISUAL_GAPS_MATRIX.md) (`VERIFIED_ALPHA / PARTIAL / UNKNOWN / PROXY_NOT_ALPHA`). Решения утверждены по D51: C+ связанная группа головы/волос и оружие отдельно; сначала искать исходные Alpha-значения, proxy только после документированного поиска; контролируемый запуск Alpha из локальной копии разрешён; технический T3 при отсутствии достоверного механизма. Исполнение одного персонажа разрешено. Не начинать S05B.

**D52 (2026-11-05):** [хват меча и направление анимаций](docs/decisions/D52-weapon-grip-animation-direction.md): пользователь не утвердил текущий хват; рукоять должна входить в середину основной кисти, двуручную атаку нужно выполнять с обеими кистями на рукояти. Разрешён исследовательский запуск одной атаки Alpha и статическая трассировка её матриц/состояний. После доказанного пилота DeepSeek самостоятельно переносит/воссоздаёт остальные анимации того же гуманоида поэтапно, различая `TRANSFERRED_FROM_ALPHA` и `ORIGINAL_NOT_ALPHA`; **S05B, массовые конверсии и production-Unity по-прежнему не разрешены**. S05A-2 не принят, сначала исправить проверку маски tint и world placement, затем показать продюсеру локальные сравнения и атаки.

**D53 (2026-11-05):** [приоритет доказательного извлечения анимаций Alpha](docs/decisions/D53-original-animation-extraction-priority.md) после просмотра продюсером `attack_phases.png`: нынешняя двуручная атака визуально не одобрена (простое вертикальное махание вместо направленного удара). Исследовать три пути: анимационные данные, исходная цепочка state/time→bones/matrices, безопасный runtime-сбор поз из локальной Alpha. Один POC двуручной атаки с Alpha↔Unity сопоставлением; если невозможно — честно `BLOCKED`, не подменять прокси. Важно: `bladeHits` сейчас не определяет итог, bounds статичны, seam `1−ε→0` не проверен, PlayMode только walk. Закрыть эти тестовые дефекты; S05A-2 READY_FOR_REVIEW, S05B NOT_AUTHORIZED. Не публиковать исходные анимационные данные; для релиза собственные/лицензированные материалы.

## Обязательные границы
- Работать только по утверждённому этапу. **Последний принятый этап — `S05A-1`** (D50; ветка `stage/s05a1-character-animation`). **Следующий `S05A-2` — AUTHORIZED по D51, `IN_PROGRESS` после старта агента**; S05B NOT_AUTHORIZED; `S04-EQUIPMENT-COMBAT` → `ACCEPTED` (D47). См. `docs/ACTIVE_STAGE.md`. `S03-COMBAT-CORE` (D45), `S02-CORE-FOUNDATION` (D44) и `S00-R02` (D43) приняты ранее.
- **S05A-0 → `ACCEPTED`** ([D48](docs/decisions/D48-s05a0-accepted-s05a1-draft.md), 2026-11-04; после `S05A-0-REVIEW-FIX-01`): геометрия `.cub` конвертируется и реально отображается в Unity; валидаторы строгие (Python 42/42, Unity-самотесты 19/19, негативные сценарии распознаются); отчёт [MODEL_CONVERSION_PILOT](docs/research/alpha2013/MODEL_CONVERSION_PILOT.md), инструменты [tools/alpha_models](tools/alpha_models/README.md). Следующий шаг без отдельного решения продюсера запрещён: не расширять пилот на новые модели, не начинать `S05A-1`/`S05B`, не запускать массовую конвертацию. Конвертированные и оригинальные ассеты Alpha — только в `.scratch/` (`.gitignore`), в Git не коммитить.
- **S05A-0 (принятые границы):** три образца — персонаж/часть персонажа, существо/враг, оружие/предмет; только чтение `D:\Games\Cube world`; изолированный Unity-проект; **никакой** массовой конвертации (2857 `.cub` — не обрабатывать); оригинальные и конвертированные ассеты Alpha **не публиковать** в GitHub; не менять код и сцену S04. Исторически до D49 исполнение S05A-1 было запрещено; теперь оно завершено и принято D50. **Сейчас:** S05A-2 AUTHORIZED только для одного персонажа по D51, S05B массовое производство NOT_AUTHORIZED. Утверждение `ACCEPTED` — только от продюсера.
- **Экипировка S04 (принята, не переоткрывать):** использовать существующие вычислители (`ItemStatsCalculator`, `CharacterStats`), не создавать параллельную систему статов и не допускать двойного `levelFactor`; `Armor` и `BlockValue` не смешивать; HP от экипировки не «додумывать» (OQ-25 `OPEN`) — `EquipmentHealthBonus` остаётся явным.
- **S01-PILOT опубликован и технически проверен** (`stage/s01-unity-pilot` @ `a8842783378bf2621e6a39a50e1f9ee2398cf245`); его статус — `READY_FOR_REVIEW` до отдельной приёмки продюсера/ChatGPT. Использование кода пилота как технической основы S02/S03 **не означает** приёмку пилота.
- Открытые вопросы (`OQ-01 OPEN`, `OQ-02 PARTIAL`, `OQ-22 PARTIAL`, `OQ-23 OPEN/BLOCKED`, `OQ-24 PARTIAL`, `OQ-25 OPEN`, `OQ-26 OPEN`) сохраняются; неизвестные числа Alpha не выдавать за восстановленные. Скорости до OQ-23 — `PLACEHOLDER_NOT_ALPHA`. Новые запуски Alpha запрещены без отдельного разрешения.
- Источник Alpha: `D:\Games\Cube world` — **только читать**, пока продюсер не разрешил иное. Путь сообщён, но пока не проверен.
- Игру 2019 не путать с Alpha 2013; вторичные источники маркировать.
- Не изменять чужие проекты, конфиги DSH других пресетов или системные настройки. Никаких `danger-full-access` по умолчанию.
- Не публиковать оригинальные исполняемые файлы, бинарные ресурсы и закрытые ассеты Cube World в публичном CubeGame. Не коммитить ключи/API-токены.
- Не подключать платные серверы, API или другие платные сервисы без решения продюсера. Не обходить защиту программ.
- Проверять `git status` перед изменениями. Новая ветка на отдельный этап. Не делать force push на main; не объединять изменения без принятия.
- Результат задачи: ссылки на файлы/коммит, фактические тесты и статусы, найденные блокеры, известные ограничения, `READY_FOR_REVIEW` — не `ACCEPTED`.
- **Постоянное разрешение продюсера (2026-11-03):** после локальных коммитов автоматически выполнять `git push` **своей рабочей ветки** в GitHub для независимого ревью ChatGPT, без повторного запроса разрешения на push. Это относится и к `stage/s00-deep-research`. Перед публикацией проверять `git status`, состав коммитов и отсутствие закрытых ассетов, исходных бинарников, секретов и личных данных; при обнаружении — сначала очистить историю ветки. **Push не означает ACCEPTED**. Merge в `main`, force push, удаление удалённых веток и публикация запрещённых материалов по-прежнему требуют отдельного решения продюсера. Если push технически невозможен — сообщить причину, не заявлять об успешной публикации.

- Если ТЗ неполное — сформулировать точечный вопрос, не придумывать игру вместо продюсера.

Для Unity CLI обязательно соблюдать [UNITY_CLI_PROTOCOL.md](docs/agents/UNITY_CLI_PROTOCOL.md): редактор 6.3 уже обнаружен, не переустанавливать; Unity 6.6 не открывать для пилота; результаты тестов проверять по артефактам, а не по одному exit code.

Подробная конфигурация DeepSeek: [docs/agents/DEEPSEEK_HARNESS_SETUP.md](docs/agents/DEEPSEEK_HARNESS_SETUP.md).

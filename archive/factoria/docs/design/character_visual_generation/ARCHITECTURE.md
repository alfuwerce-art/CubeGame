# Архитектура Factoria DESIGN-01

**Дата 18 ноября 2026 · READY_FOR_OWNER_ARCHITECTURE_REVIEW**

Предлагается Hybrid с геометрическим шаблоном по умолчанию. Blender задаёт форму тела и границы посадки. ComfyUI исследует внешний вид внутри этих границ. Лицо и материалы используют готовую поверхность, жёсткие элементы получают собственный меш и сокет, одежда получает независимый меш со своими весами. 3D-реконструкция по изображению остаётся исследовательской веткой для сложных отдельных форм. Обоснование и исключения приведены в [сравнении технологий](TECHNOLOGY_COMPARISON.md).

В оригинальную библиотеку входят BODY/MANNEQUIN, FACE (включая пиксельные выражения), HAIR, RACE_FEATURE, CLOTHING, ARMOR, WEAPON, ACCESSORY и MATERIAL/PALETTE. Каталог Alpha пригоден для справки о покрытии и исторических индексах. У нового контента отдельные ID и происхождение. Один меш может ссылаться на несколько палитр или material IDs.

## Единый запуск

Будущий CLI принимает ID категории и параметры либо готовый ASSET_PROFILE. Режим `plan` выводит выбранные версии, ресурсный пресет и ожидаемые артефакты. `compile` разрешает три контракта, сверяет хэши, строит один API-граф на вид и проверяет ноды/допустимые значения через `/object_info`. Слот, карта и маски выбираются по профилю и ревизии пакета. Отсутствие файла, несогласованная камера, неподдерживаемая привязка или неясные права обнаруживаются до очереди.

Разрешённый `image` регистрирует входы в локальном ComfyUI под именами с хэшами, сверяет байты, вызывает `POST /prompt` с уникальным client ID и записывает fingerprint графа, отслеживает конкретный `prompt_id` по WebSocket и `/history/{prompt_id}`, забирает только указанные выходы через `/view`. Один процесс и одна активная генерация. Для повтора после таймаута сначала восстанавливается состояние исходного задания по записанному ID. Если ответ на submit потерян, сверяется очередь/история по client ID и хэшу графа; при неоднозначности нужен разбор вместо повторной постановки. Commit manifest в файловую систему через временный файл и атомарный rename после проверки артефактов. Падение оставляет диагностический manifest и сохраняет предыдущего проходного кандидата. Дополнительный GUI, сервер и очередь не требуются. [ComfyUI Server Routes](https://docs.comfy.org/development/comfyui-server/comms_routes).

`validate` формирует оценку изображения. Будущий `fit` использует Blender CLI, сначала в отдельном процессе после освобождения памяти ComfyUI; генерирует согласованные технические виды и отчёт поз. Результат имеет отдельные статусы изображения, 3D и ревью. Уровень автоматизации заканчивается там, где нет утверждённого шаблона, данных для привязки или проходных измерений.

## Повторное использование

- `compile_character_factory.py` уже связывает каталоги, pack, сокет, размер PNG, хэш носителя и параметры API-графа. Переиспользовать binder, проверку файлов и раздельные шаблоны. Его варианты FACE/HAIRCUT завязаны на Alpha UI option и старый STYLE_LOCK_V1. Для оригинальных рецептов нужен небольшой адаптер и разрешение style recipe, а не подстановка фиктивного номера.
- `compile_mannequin_v3.py` даёт штатный SDXL/VoxelXL/Union-граф и проверку нод. `run_mannequin_v1.py` показывает submit/ожидание и измерение RSS/VRAM. Оба полезны как образцы, каждому предстоит адаптация к универсальным контрактам.
- `mannequin_v3_build.py`, `mannequin_v3_validate.py` и профиль мужского рига пригодны как отправная точка для экспорта pack и поз. Для новых модулей ещё требуются проверки UV, зазоров и покрытий, непрерывных движений и идентичности частей после импорта.
- Frozen JSON остаётся историческим снимком. STYLE_LOCK_V1 предоставляет схему и идеи, а действующий рецепт V3 хранится отдельно. Область дизайна — независимая лаборатория Factoria.

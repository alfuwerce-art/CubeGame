## A / B / C

A — ComfyUI-first и последующая подгонка. B — Geometry-first, существующие форма и UV до генерации. C — Hybrid, общий 3D-манекен и размерные шаблоны, ComfyUI для дизайна, применимый метод 3D выбирается по категории.

| Параметр | A · ComfyUI-first | B · Geometry-first | C · Hybrid |
|---|---|---|---|
| Размеры | Приблизительны в изображении, требуют повторного fit | Фиксированы источником, проверяются на шаблоне | Фиксированы для шаблонов, восстановленная форма проходит те же проверки |
| Стилистика | Самый широкий поиск, drift между видами и объектами | Стабильная форма, разнообразие ограничено шаблонами/UV | Гибкость дизайна с фиксированными условиями стыка |
| Rig | Нужно отделить, построить швы и назначить веса заново | Растёт из существующих сегментов, сокетов и весов | Ветки B повторно используют rig; для свободных форм нужен fit |
| Сложность | Простой старт, дороже сведение видов и постобработка | Начальная стоимость pack, шаблонов и UV | Начальная цена B + правила выбора; первые пилоты используют одну ветку с шаблоном |
| RAM/VRAM | Несколько sampling подряд + отдельная 3D-задача, фактические пики неизвестны | Blender и ComfyUI последовательно, 0 или 1 дизайн-кадр на элемент | Бюджет B по умолчанию, расширенные профили меряются отдельно |
| Скорость | Несколько inference и ручная доработка | Один дизайн + ортопроекции, время UV и шаблона надо измерить | Близко к B на повторяемых слотах, реконструкция может существенно удлинить |
| Повторяемость | Seed повторяет шум, ракурсы и fit нестабильны | Наибольшая для геометрии, deterministic IDs и камеры | Строгая для шаблонов и выходной геометрии, концепты оцениваются отдельно |
| Ручные правки | Риск наибольший — размер, mesh, запечённый свет, отсутствие скрытых поверхностей | Правки шаблона амортизируются, остаются дизайн/проекция UV | Сравнивать минуты ручной правки на прошедший модуль |
| Масштабирование | Слабее при росте числа слотов и тел, больше повторов | Высокое на семействе совместимых шаблонов | Высокое, если свободная форма исключение, а не скрытый fallback на каждый ассет |
| Лицензии | Веса и права на вход/выход AI, для облака отдельные условия | Лицензии исходных мешей/дизайна и используемых моделей | По фактическому маршруту, Tripo и спорные профили выключены до решения |

## Подготовка к 3D

Blender procedural modelling подходит для жёстких выразительных блоков и параметрических деталей, со строгими единицами и сокетами. Voxel-моделирование полезно для ступенчатых волос/рогов и редких сложных контуров; шаг сетки влияет на зазор, толщину и читаемость, дробные крепёжные точки держатся отдельными transform. Шаблон одежды/брони сохраняет UV, стыки, толщину и веса, но ограничивает радикальные изменения фасона. Текстура хранит альбедо, палитру и material ID с контролем запечённого света.

Локальный **TripoSR** восстанавливает форму из одного кадра. Поставщик публикует MIT для кода и предобученных весов, указывает около 6 ГБ VRAM для default single image. Подача нескольких независимых файлов запускает реконструкции отдельных изображений; это не shared-mesh multi-view. **Tripo API** — отдельный продукт с тарифами, условиями обработки входов и правами на выходы по действующему плану. Даже multiview не обеспечивает метрический масштаб, сокеты, независимые части, толщину, voxel topology или веса. Только чистое изолированное изображение, затем ретопология/вокселизация при необходимости, привязка canonical axes, единиц и grips, fit и полный 3D gate. Облачная отправка эталона или закрытых материалов требует отдельного решения. [TripoSR](https://github.com/VAST-AI-Research/TripoSR) · [Tripo API](https://developers.tripo3d.ai/en) · [Условия Tripo](https://www.tripo3d.ai/terms).

Перед первым разрешённым опытом согласовать окно без конкурирующей GPU-задачи. Записать baseline до процесса, перед submit, peak во время cold/warm, max RSS, incremental RSS, minimum system available, swap/OOM, elapsed и визуальные результаты. NVML всей карты с psutil RSS, частота и пропуски выборок явные. Сравнить одинаковый файл pack, профиль и seed, по одному изменению, повторный холодный и тёплый прогоны. Критерий выбора сочетает качество и проход обоих бюджетов. Потребление новых категорий и связок пока `NOT_VERIFIED`.

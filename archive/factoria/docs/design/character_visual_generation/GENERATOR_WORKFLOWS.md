# Генераторы модулей

Общий граф: resolve ASSET_PROFILE + STYLE_LOCK + GEOMETRY_REFERENCE → LoadImage carrier/guide/masks → Canny/Union или masked VAE encode → KSampler → VAEDecode → raw RGB → проверка → composite/fill → review RGB и RGBA/текстура → manifest. Каждый workflow — data-driven рецепт одной категории. Техническая камера берётся из pack. Штатные ноды и шаблоны проверяются по установленной версии. BODY/MANNEQUIN экспортируется из явно выбранного 3D-профиля; ComfyUI опционально визуализирует материал носителя. Выходы технических видов и их depth зависят от Blender.

Шаблон позитивного текста: `{style.prefix}, single {asset.label}, {material}, {feature_terms}, {view}, neutral even diffuse light`. Общий negative: `perspective distortion, multiple objects, sheet, cropped subject, rounded organic sculpting, excessive bevels, noisy fine detail, photorealism, text, watermark, scenery`. Короткие термины дополняются полями ниже. STYLE_LOCK задаёт sampler, вес моделей и допустимые диапазоны. Рецепт меняет только параметры, относящиеся к конкретному виду и зоне. Указанные методы — кандидаты для пилотов.

RGB генерируется отдельно на вид. FRONT face обычно достаточен для UV; боковые нужны для рельефа. Волосы, одежда, броня и объёмные аксессуары при технической приёмке используют FRONT/BACK/LEFT/RIGHT, при необходимости TOP и THREE_QUARTER. Оружие использует ортографический главный план с сохранением grip и как минимум боковую проекцию толщины; полный набор задаёт профиль. Представление пиксельного материала — UV, а не набор ортопроекций. Все retry ограничены [правилами валидации](VALIDATION_DESIGN.md). Типы артефактов и требования к handoff описаны в [контрактах](ASSET_DATA_CONTRACTS.md).

## Одежда на примере HUMAN_MALE_V3 → CHEST_SLOT → MEDIEVAL_TUNIC

1. В Blender построить отдельный shell из воротника, груди, талии, подола и левого/правого рукава. Привязать ключевые сечения к манекену и утвердить ширины/глубины. Поля швов обязаны совпадать с rest-позой и последующей разбивкой корпуса и рукавов. Руки, голова, шея в отверстии, кисти и ноги защищаются. При необходимости покрываемые поверхности тела скрываются отдельной таблицей body occlusion; меш тела и его геометрия остаются самостоятельными.
2. Генерировать worn-дизайн в edit mask поверх RGB carrier и шаблонных границ. Хранить исходный RGB, затем восстановить protected pixels из carrier и показать одежду в контексте. Утечку ткани в горловину и дубли рукавов проверять по raw до маскирования. Маска шаблона детерминированно выделяет видимую поверхность для обзора; утраченные задние/внутренние поверхности задаются шаблоном.
3. Техническое представление — из того же asset revision в Blender с выключенным телом. Переносить утверждённый рисунок на видимые поверхности проекцией в UV с depth/ID visibility, закрывать конфликтные texels по заданному приоритету, невидимые участки заполнять согласованной палитрой или проверенной UV-правкой. Декали привязаны к UV и швам. Сохранять точки стыка, толщину, clearance, закрытую топологию там, где требуется, и веса по sleeve/torso. Технические worn/isolated виды и маски математически согласованы. Вторая независимая генерация «снятой рубахи» может быть вариантом концепта; для технического экспорта служит рендер одного mesh.
4. Worn и isolated имеют разные задачи и два графа обработки: генеративный граф worn-дизайна и детерминированный экспорт. Дорогой повторный sampling не нужен для isolated. Критерий отделимости: меш одежды экспортируется сам, повторно крепится к тому же скелету, тело удаляется без потери одежды, тесты поз проходят с заявленными исключениями контактов.

# Geometry Reference Pack

Единственные утверждённые визуальные ориентиры для этого проекта — Human Male V3 и Human Female V3. Эталон владельца локально совпал с SHA-256 `b95e4666a3b3caae543e3ba4663cce8d7f9ad3d026f381cca2231fee04d841c5`. Из фронтального рендера сняты доли высоты, например блок головы 0.316/0.313, размах рук 0.825/0.752, таз 0.251/0.232. Макушка ровная и чистая, голова квадратная, подбородок ступенчатый, уши маленькие отдельные кубы, таз компактный. Точный метрический масштаб, толщины, глубины суставов и скрытые поверхности задаются 3D-профилем. [COMFY-STYLE-12 V3](../../tasks/COMFY-STYLE-12_V3_STYLE_LOCK_RUN_REPORT.md).

## 3D-источник и допуски

MANNEQUIN-RIG-01 задаёт испытательный мужской baseline 1.4821 × 0.600 × 1.8000 м в T-pose, 18 частей, 29 кубов и 20 костей. Глубина — проектная величина. Тесты поз и GLB пройдены для прототипа, требуется решение владельца о мере каноничности. Женский визуальный эталон есть, женского проверенного 3D-пакета пока нет. Расовые пропорции следуют отдельным профилям. Детерминированное изменение выбранных размеров и повторная проверка швов предпочтительнее inference тела. Совместимость по одному имени расы не допускается. [MANNEQUIN-RIG-01](../../tasks/MANNEQUIN-RIG-01_REPORT.md).

Предлагаемое соглашение продолжает прототип: метры, `+X` анатомически слева, `-Y` вперёд, `+Z` вверх, root на плоскости стоп. T-pose закреплена ревизией. В pack входят rest-матрицы, parent IDs и флаги deform, центры меш-сегментов, head/tail суставов, root/world и bone-local матрицы сокетов. ID кости и ревизия обязательны. Экспортные преобразования осей записываются явно и проверяются round-trip.

| Слот / сокет | Опора | Размерные и стыковочные ограничения |
|---|---|---|
| FACE, SCALP, CHIN | head | Front-face UV, плоскость глаз/рта, кольцо волос, keepout ушей, лба и шеи |
| EAR_L/R, HORN_L/R, TUSK_L/R | head или будущая согласованная кость | Anchor, ориентация, посадочное пятно, минимальная толщина, допустимые пересечения с головой |
| CHEST, WAIST, SLEEVE_L/R, LEGS | spine_02, pelvis и соответствующие конечности | Поперечные сечения плеч, горловины, талии и подола, длины рукавов; диапазон clearance и зазор на швах |
| HEAD_ARMOR, SHOULDER, WRIST, FOOT | head, clavicle/upperarm, lowerarm, foot | Wrap зоны, покрытие, допустимое перекрытие, зоны движения суставов |
| MAIN_HAND, OFF_HAND | hand_r, hand_l согласно профилю | Матрица primary grip, secondary grip для двуручных вариантов, ориентация вида, clearance кисти |
| BACK, BELT, JEWELRY | spine_02, pelvis, профильная кость | Объём, ориентация, допустимое перекрытие одежды и запретные зоны при движении |

Каждый слот задаёт 3D AABB в локальной системе, при необходимости OBB, нижнюю/верхнюю оболочки, зоны обязательного касания, разрешённого проникновения и зазора, швы и `fit_policy` (`uv_overlay`, `rigid_socket`, `segmented_rigid`, `skinned`). Числа и пороги измеряются на сетке утверждённой геометрии и утверждаются по категории. Экспортировать их по evaluated mesh с зарегистрированной позой, без оценки толщины по RGB.

## Камеры и экспорт

Камеры ORTHO смотрят на общий target. Если f — единичное направление **от** объекта **к** камере, камера находится в target + d·f и смотрит по −f. Для боковых/передних видов экранный up = +Z. Правая ось кадра `r = up × f`. Для TOP up = −Y. LEFT и RIGHT анатомические; зеркальность допускается только явным правилом профиля.

| Вид | f | Назначение |
|---|---|---|
| FRONT | (0,−1,0) | Фасад, измерение высот и ширины |
| BACK | (0,+1,0) | Задние швы, затылок, крепления |
| LEFT | (+1,0,0) | Толщина, выступы и смещения |
| RIGHT | (−1,0,0) | Толщина второй стороны, асимметрия |
| TOP | (0,0,+1) | Ширина/глубина локального модуля, при необходимости |
| THREE_QUARTER | normalize(+1,−1,+0.5) | Ревью объёма; также ORTHO, если включён в pack |

Записывать `ortho_width_m` и `ortho_height_m` независимо от API Blender, с `width_m / height_m = W / H` при квадратном пикселе. `px_per_m = W / width_m = H / height_m`. Начало в верхнем левом углу на границе кадра, центры пикселей `i+0.5`. Непрерывная проекция мировой точки `p`: `u=W/2+s·dot(p-target,r)`, `v=H/2-s·dot(p-target,up)` для согласованного ортонормированного up (проекция +Z на плоскость камеры в THREE_QUARTER). Дистанция и near/far сохраняются. Camera matrix и тестовые позиции сокетов валидируют ориентацию и знак. Цена пикселя общая для всех cardinal видов внутри pack, кадрование фиксировано. Локальные packs для головы, chest и оружия имеют отдельные camera revisions, target, масштаб и явно заданное преобразование к полному кадру. Маски не центрируются по отдельности. Поддерживаются привязка RGB к sRGB и сохранение глубины в линейных единицах.

Одна headless Blender-операция должна экспортировать на вид: RGB carrier с фиксированным светом, силуэт/alpha из отдельного прохода, индексные карты сегментов/материалов, edit mask, allowed mask, protected body/keepout, expected matte из меша слота, глубину и при необходимости нормали. Depth выдаётся отдельной EXR/float-картой с определением `dot(p-camera,-f)` в метрах, фоновым validity mask и записанным near/far. Для ControlNet из неё строится отдельная нормализованная conditioning plate с явной полярностью; CN plate сохраняет порядок ближе/дальше и служит подсказкой модели. Нормали содержат пространство (world или camera), единичные векторы и маску валидности. Карты ID и бинарные маски дискретны, без сглаживания категорий, выравниваются по матрицам камеры. Метрика преобразования проходит проверку репроекции опорных точек и калибровочной фигуры известного размера.

## Два маршрута ракурсов

- **A · независимо в ComfyUI.** Быстро получить ранние идеи вида, расход растёт с количеством кадров. Один seed, единый carrier и стиль помогают воспроизводить входы, но сторона, количество прядей, толщина, подол и швы могут разойтись. Проверять 2D-сечения, landmark reprojection и одинаковые теги. Статус `CONCEPT_UNLINKED` сохраняется даже при хорошем совпадении.
- **B · основной вид → геометрия → Blender.** Дополнительная работа над формой/UV окупается строгой идентичностью ракурсов. Worn/isolated/turntable берутся из одного asset revision, rest pose и mesh SHA. При Geometry-first исходный объём уже задан до ComfyUI. Шаблоны, сегменты и сокеты позволяют автоматизировать этот маршрут. Fallback при отсутствии меша — A только для ревью концепта; технический handoff ждёт 3D.

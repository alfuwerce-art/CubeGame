## 2. Функциональные разрывы готового стека (не блокеры, но важно)

| # | Готовый инструмент | Чего он **не** делает | Что придётся написать/настроить позже |
|---|---|---|---|
| F1 | Rigify | не классифицирует анатомию и не находит суставы произвольной модели; не гарантирует экспортную совместимость | `Rig Fitter` (подгонка согласованного skeleton к landmarks и пропорциям) — **отложено по ТЗ** |
| F2 | Blender Automatic Weights | ломает крупные плечи, таз, доспехи, хвосты, необычные тела | правила skinning (rigid vs deform), коррекция весов по семействам |
| F3 | Blender FBX-экспорт | не гарантирует корректность осей/единиц/bind pose/animation для Unity | валидатор экспорта + контракт `CG_*` skeleton (осей, имён, sockets) |
| F4 | Unity Mecanim | не «понимает» нечеловекоидные анатомии без Generic-пути и IK-слоёв | retarget/IK-конфигурация под каждый archetype |
| F5 | ComfyUI (если найдётся) | image-to-3D ≠ контролируемая переработка существующего 3D-меша; даёт черновик с артефактами | отдельный маршрут 3D-to-3D redesign, очистка топологии |
| F6 | AI motion | не даёт финальные боевые клипы с таймингами и контактами | ручная доработка + привязка к gameplay events |
| F7 | — | нет оркестратора партий (статусы, ретраи, регрессии) | Python runner; n8n только при доказанной пользе |
| F8 | Blender Automatic Weights (измерено в PREP-01) | **не нормирует веса**: сумма весов на вершину 0.73–0.9999 (2426 из 3926 вершин ниже 1.0) | шаг нормализации весов + контроль `Limit Total` перед экспортом |
| F9 | Rigify + FBX-экспорт (измерено в PREP-01) | выгружает **весь control rig** (706 костей: DEF+control+MCH+VIS+ORG), а не чистый игровой скелет | выбор/подготовка deform-only скелета и его контракт (PREP-02/PREP-04) |
| F10 | Rigify DEF-кости | напрямую не управляемы: их положение задают constraints от control-костей | позы/тесты делать только через control-кости (`*_ik`, `*_fk` при `IK_FK=1`) |
| F11 | ComfyUI (установлен, PREP-03 → COMFY-STYLE-02/03) | **не содержит обученного стиля** как такового: базовый SD1.5 + текстовый контракт + IPAdapter держат стиль prompt'ом и референсом; между сильно разными персонажами это может «плыть» | сначала измерить, насколько стиль держится (владелец, первая генерация); только затем решение про `Factoria Style LoRA` (отдельное ТЗ) |
| F12 | ComfyUI + 8 ГБ VRAM | пики RAM/VRAM под реальной SD1.5-генерацией **не измерены** (этап COMFY-STYLE-02/03 запрещал генерацию); idle-замеры сделаны | первая генерация владельца + замер через Crystools; лимиты RAM ≤ 15 GB, VRAM ≤ +2 GB |
| F13 | ComfyUI первый запуск | холодный старт ~146 с (миграция SQLite-БД + скан ассетов) — важно для таймаутов будущего оркестратора | в launcher/API-клиенте задавать readiness-timeout ≥ 300 с и не считать «долго стартует» ошибкой |
| F14 | rgthree-comfy в ComfyUI 0.45.0 (измерено 2026-11-13) | при перенаправлении stdout (файл/пайп) печать emoji роняет **весь сервер** `UnicodeEncodeError` на cp1251-консоли | в launcher'ах обязательны `PYTHONUTF8=1` и `PYTHONIOENCODING=utf-8`; не запускать ComfyUI с редиректом вывода без них |
| F15 | ComfyUI UI-формат workflow | widget'ы хранятся **позиционно**; ручное редактирование JSON легко ломает параметры ноды | workflow собирать скриптом `build_factoria_voxel_workflows.py` из prompt-контракта и проверять `validate_factoria_workflows.py` |
| F16 | IPAdapter style transfer | переносит и «личность» референса при большом weight; CLIP Vision ViT-H ≈ 2.5 ГБ | weight 0.75 + `style transfer` по умолчанию; при нехватке памяти — `ip-adapter_sd15_light` (44 МБ) |
| F17 | ComfyUI + SDXL на 8 ГБ VRAM (COMFY-STYLE-04) | SDXL fp16 ≈ 6.9 ГБ весов: при `--reserve-vram 5` карте остаётся ~3 ГБ → постоянный offload; оптимальный режим **не определён** (пики не измерены) | измерить `xl_run_workflow.py` в двух режимах (`--reserve-vram 1` и `--novram --reserve-vram 5`), только потом объявлять режим |
| F18 | SDXL Turbo-модель (DreamShaper XL Turbo) | требует 6–10 шагов и CFG 1.5–2.5; на CFG 2 LoRA работает слабее, детализация ниже, чем у классического DSXL | если владелец отвергнет турбо-качество — отдельная задача на классический DSXL (single-file только с Civitai, нужен токен) или на SDXL 1.0 base |
| F19 | HuggingFace на этой машине | одиночный поток 20–60 КБ/с, 12 параллельных диапазонов ≈1 МБ/с → 13.7 ГБ весов ≈ 4 часа | загрузка сделана перезапускаемой (`<target>.parts`), не терять прогресс; не запускать два экземпляра одновременно |
| F20 | Civitai LoRA `ral-vxl` (Voxel Style [SDXL]) | `allowCommercialUse=RentCivit`, `allowDerivatives=False`, `allowNoCredit=False` → выходы нельзя коммерчески использовать, производные (в т.ч. обучение style-LoRA на них) запрещены | стиль для производства закреплять через собственную `Factoria Style LoRA` на собственных данных или SDXL IPAdapter по утверждённому референсу; эта LoRA — только эксперимент/сравнение (FACT-D21) |
| F21 | Voxel Face Style Lock | BODY/FACE-блоки — только текст одного промпта; независимого регионального управления и inpaint-корректора лица нет | при подтверждённой необходимости: региональные conditioning-ноды или inpaint-workflow (отдельная задача, без установки лишних моделей лица) |

## 3. Ограничения среды, влияющие на конвейер

| Ограничение | Следствие |
|---|---|
| 8 ГБ VRAM (фактически ~6.7 ГБ свободно) | только одна тяжёлая AI-модель за раз; кандидатов оценивать документально до скачивания |
| C: свободно 68.2 ГБ | все веса/кэши — на D: |
| Windows PowerShell 5.1 (нет pwsh 7) | `Tee-Object` пишет UTF-16 → перекодировать в UTF-8; в скриптах избегать `python3` |
| `addon_utils.enable("rigify")` в Blender 5.2.4 | генерация падает (`RigifyParameters ... make_custom_pivot`); использовать `bpy.ops.preferences.addon_enable` |
| Git identity не настроена | commit невозможен до локальной настройки |
| Нет remote Factory-репозитория | `PUSH=NOT_CONFIGURED`; работа локальная |
| Unity на этом этапе запрещён для проверки | экспорт в Unity остаётся `NOT_TESTED`, пока пользователь не разрешит отдельную тестовую среду |
